Author a reusable skill for yourself from the request below. A skill is a SKILL.md playbook that teaches you how to handle a specific task or domain.

The request may mix two kinds of content, in any order: sources to learn from (a folder, a URL, pasted text, "what we just did") and requirements that shape the skill (focus, scope, what to leave out, the angle to take). Every part is load-bearing — prose after a path or link is the user telling you what they want from that source. Gather every source named and honor every requirement; never fetch the first source and ignore the rest.

Use the `skill_manage` tool with operation "create" to write exactly one well-formed skill into your own skill home. Give it a short, descriptive, hyphenated name. The SKILL.md needs YAML front matter with `name` (matching the skill's directory) and a `description` of one or two sentences stating when to load the skill — name the concrete trigger situations, do not repeat the skill name, no filler words. A future session decides from the description alone whether this skill applies, so make the trigger obvious.

Structure the body with clear sections in this order, omitting a section only when it genuinely has no content: Overview (what it is for and what it does not do), When to use (concrete trigger phrases), Prerequisites (required tools, credentials, setup), Steps (the numbered procedure, with commands exactly as they appear in the source), Pitfalls (edge cases, gotchas, things that look broken but are not), Verification (one check that proves the procedure worked). Keep it tight and scannable — around 100 lines for a simple skill, 200 for a complex one; do not re-paste the source.

Frame any tool usage in terms of vBot's actual tools — `read`, `write`, `edit`, `glob`, `grep`, `bash`, `web_fetch`, `web_search`, `process`, `status` — and do not invent tools, commands, flags, paths, or facts that are not in the source. If a source is a folder or URL, read it first with your file/web tools; if it is the recent conversation or pasted text, work from that. Capture only what is genuinely there. A non-trivial script belongs under the skill's `scripts/` directory (written with `skill_manage` operation "write_file") and is referenced from the SKILL.md by relative path, not inlined; longer reference material goes under `references/` the same way.

After creating the skill, tell the user in one or two sentences what skill you created and when it will help. Do not paste the full SKILL.md back.

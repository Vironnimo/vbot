# Bug hunt - 2026-10-23

## Scope and method

The user requested a thorough repository bug hunt with Sub Agents, direct fixes for confirmed bugs, opportunistic dead-code review, and a consolidated list of decisions. The baseline was `265981ea5`. Eight delegated reviews, one focused child review, and the coordinating review covered the main application boundaries in the `bug-sweep` worktree.

Findings were confirmed through source inspection and isolated probes before fixes. Existing behavior tests were extended where possible, then the affected tests were run. No live installation, real Provider request, Channel recipient, or production data was changed. This is a broad targeted review, not a proof that every path is bug-free.

## Decision: Calendar exception collisions

The existing residual Calendar case was reproduced. A Monday/Tuesday series starting on 2026-10-19 has exceptions removing 2026-10-26 and 2026-10-27. Moving its start to 2026-10-20 leaves only the 2026-10-27 exception, so Monday reappears. The current map explicitly specifies that a shifted exception key wins a collision; changing that interpretation needs a user decision.

- A (recommended): refuse changes that collide exceptions, explaining which occurrences need resolution. This preserves existing exceptions until the user chooses.
- B: preserve excluded calendar dates where possible, changing how exceptions follow a moved series.
- C: retain the current shifted-key-wins behavior and accept dropping the colliding exception.

Previously explicit deferrals, including ExternalRun result-persistence acknowledgement, OpenAI mid-epoch Tool listing/cache behavior, installation authenticity and permanent Secret name collisions, were not silently overturned. They are not new findings of this review.

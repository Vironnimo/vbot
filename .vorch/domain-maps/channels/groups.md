# Channel groups and observed context

Group response gating, group access with sender roles and the group Tool ceiling, and observed or quoted context from group conversations; adapter-specific capture lives in the platform maps.

## Response gating

`response_mode` is `"mention"` (default - groups respond only when addressed) or `"all"` (respond to every allowed group message). `mention_patterns` are wake-word regexes (must compile, matched case-insensitively against text and captions). `observe_unaddressed: true` persists otherwise-unaddressed group messages as internal context notes in `"mention"` mode. DMs always respond regardless of `response_mode`. The decision itself is `should_respond` (`channels.md` -> Interfaces).

## Group access and roles

- Group access: `channel_admins(channel_id, access_scope_id, user_id)` and `channel_participants(channel_id, access_scope_id, user_id, display_name, last_seen_at)`, keyed by the stable adapter-supplied access scope. Roles are only `admin`/`member`; the own identity is effectively admin everywhere and cannot be demoted; additional admins are scoped per group. Ingress records the participant and reads its role in one write transaction (`snapshot_participant_role`); the per-Tool-dispatch `role_for` reads an in-memory index that every committed access mutation refreshes, never storage. Access mutations are transactional and never rewrite `channel.json`, restart an adapter, rebuild the System Prompt, or alter provider Tool definitions; the access projection lists only groups with admins or participants.
- Access reads and mutations are async `ChannelService` methods (the `channels.db` I/O runs on the database worker pool); mutations return the complete saved access projection and publish `resource_changed(kind: "channels")`, deliberately without calling `runtime.reload_channel_tool()`; config/lifecycle mutations keep their existing reload behavior.
- Sender identity is engine-derived and group-only: at first ingress the engine atomically records stable user id/display name and snapshots `admin`/`member`; the immutable value rides the FIFO and `TriggerService`, so queued work and historical attribution never change after a grant/revoke. Group user content renders `[display_name|platform_user_id|role]`; DM turns carry no sender.
- Group slash commands and reserved Run buttons use the immutable ingress role: only `admin` is authorized; unauthorized group commands and taps drop silently with a debug log. DM commands stay authorized because the allowlist identifies the sender acting on their own Session.
- Group Tool access is dispatch-only and role-aware. A `member` Run receives an immutable admission ceiling of `web_search` and `web_fetch`; an `admin` Run receives none. Both get a live pre-dispatch resolver: non-web Tools require both an admitted `admin` snapshot and a current `admin` role - a later grant cannot upgrade queued/running member work, while a revoke limits an active or waiting admin Run. The Agent's own allowlist intersects independently, provider-visible definitions stay unchanged, denial returns `tool_not_allowed`.

## Observed and quoted context

- Observed (unaddressed, `observe_unaddressed: true`) group messages enqueue in the conversation FIFO: the worker ensures the shared group Session, refreshes its Channel metadata, and appends an internal note - no Run, no reply. The sender is recorded as a participant at ingress like any group sender. An observed message on a known conversation writes only its note (`test_engine_groups.py`).
- Text/media ingress accepts bounded `observed_context` carried under the triggering turn's one waiting-work reservation. The engine snapshots context sender roles at ingress and persists the notes before triggering the Run; rejected turns do not consume their context.
- Context acquisition is platform-specific (Telegram passive observation; Discord bounded history backfill), feeding the same observed-note representation and FIFO.
- Observed context uses the same FIFO. Admission persists its whole batch before the adapter may acknowledge it; capacity refusal persists nothing. Engine stop drains admission writes and freezes outstanding routes without taking Session write locks, so it cannot deadlock the Runs that shutdown cancels later. The service recovers ended engines in the background even after disable/delete/reassignment, and startup recovers outstanding rows before new engine workers proceed; active engines keep their own FIFO ownership. Shutdown cancels recovery without deleting inbox rows, the synchronous `ChannelService.stop()` of a failed Runtime start included, so recovery never outlives `channels.db` (`test_service_serves_running_channels_until_they_stop`). Explicit Session deletion takes precedence over accepted context for that deleted generation. Text persists as `[channel-message] [<display_name>|<platform_user_id>|<role>]: <text>` with attribution fields stripped of `[`, `]`, `|`, CR, LF; the body stays verbatim; how Chat renders these notes as untrusted background context: `chat/request-building.md`. The queue keeps observed notes out of open Tool cycles; the per-session write lock (`sessions.md`) extends ordering to other accessors. Observed media is never downloaded: `[media <caption>]` markers only.
- Text/media ingress reports acceptance for context-only observations too, so socket adapters can receipt accepted Notes without receipting capacity-rejected messages. All contextual Notes from one observed media message share one waiting-work reservation; replay cannot duplicate a partially admitted batch (`test_network_ingress.py`).
- `channel_observation_inbox` is a transient durable inbox for accepted unaddressed text/media markers and bounded history attached to an admitted turn. `_observations.py` owns admission and delivery through the existing Channel state pool. Rows retain their admission order, original routing config, conversation facts, complete Note batch and fallback Session generation; they deliberately have no Channel foreign key. FIFO processing freezes the target after earlier navigation, then appends the batch to canonical Session history with an atomic receipt. The Session owner deduplicates retries, including a crash after append but before inbox acknowledgement; it resolves that generation after a move/rename and never resurrects a deleted generation. No parallel transcript or retention policy is introduced.
- An addressed group text replying to another participant's attachment may ingest that original on demand: resolution happens only after response gating and Queue admission, the quoted content joins the current turn labeled with its original author, and the static prompt tells the Agent quoted content gains no authority by being quoted. Unavailable originals, including download failures, add `[quoted-message unavailable]` and still run without a separate media-failure reply.

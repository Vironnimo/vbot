# WebUI

The WebUI is vBot's Svelte accessor: it presents server-owned state and sends user intent through the server's HTTP, RPC, WebSocket, and SSE contracts.

## Overview

`webui/src/` owns browser presentation, interaction state, navigation, and transport adaptation - never Chat, Provider, Extension, Project, or persistence semantics. `lib/api.js` is the single raw transport seam: components use its wrappers instead of spelling RPC names or building envelopes. The production server serves `webui/dist/`, so source changes need a build; a missing build stays a safe server state, not a startup failure.

## Ownership

- **Editable configuration and existing-record editors use the shared autosave system** in `webui/src/lib/autosave.js`, including Extension-owned pages. Before adding or changing fields, save controls, or editor-replacing navigation, read `webui/autosave.md`; reuse its input timing, tracked saves, and transition integration. Domain controllers retain validation and response reconciliation.

- **Reorderable lists use the shared `components/ui/SortableList.svelte`** (dnd-kit via `@dnd-kit/svelte`; policy in `components/ui/sortable.js`). Rows drag from anywhere except text entry and `[data-sortable-ignore]`: mouse and pen after 4 px of movement, touch after a 250 ms hold; the other rows slide aside and Escape cancels. Alt+ArrowUp/Down moves the row that holds keyboard focus, with a live announcement, and focus stays on the moved control. No grip handles. The owner receives one `onReorder(from, to)` per completed move and keeps data and persistence; the list shows the moved order until the returned promise settles and refuses new moves meanwhile, and drops a drag whose `items` changed during the gesture. Rows without their own click action show a `grab` cursor through `.sortable-item--draggable`. Users: Agents roster, System Prompt blocks, Project auto-load files. A row with a context menu opens it only for a `contextmenu` event nobody prevented yet: during a drag dnd-kit prevents it, so a touch hold that started a reorder keeps the gesture (`AgentListPane.svelte`). Tests: `ui/__tests__/SortableList.test.js`; pointer drags need a live browser check because jsdom has no layout.
- **Context menus use the shared `components/ui/ContextMenu.svelte`** (helpers in `components/ui/contextMenu.js`); do not build ad-hoc menus. A component menu calls `preventDefault()` on its `contextmenu` event, which also keeps AppShell's Desktop context menu from opening. Contract and caller pattern: `webui/design.md` -> Shared controls, `webui/source-map.md` -> UI primitives.
- **Paths on the server's filesystem are entered through the shared `components/ui/PathField.svelte`**; never a native file dialog or browser file input, because the server may be remote. It wraps `TextField` (always `code`) with inline completion of the typed folder and a Browse... dialog (`ui/PathBrowserDialog.svelte`), both listing through `filesystem.list` (`api.listServerDirectory`); the pure path, completion and listing rules live in `lib/pathPicker.js`. Completion sends the typed name as `prefix`, so the server filters before its entry cap; the field's listing cache (`createListingCache`, one per focus visit) answers a longer prefix from a complete listing of a shorter one. The dialog lists whole folders and filters them by substring itself. A folder accepted by completion ends with a separator so completion continues inside it; when focus leaves the field (not when the window loses focus) and for a value Browse... returns, the field emits the value without trailing separators, except on a root (`/`, `C:/`, `C:\`). Props: `mode` (`directory`/`file`/`any`), optional `root` (navigation stays inside it and values come back relative to it), `projectShortcuts` (Projects among the dialog's places), and `listDirectory` (same params and result as the RPC, so an Extension page can pass its bridge). Users: Add and Re-point Project, Project auto-load files, Agent Workspace, Skill folders, Terminal working directory, MCP program and cwd, Skill install source, the Swarm page's working directories (through its page client), and Task Model text options with a `server_path` hint such as the local speech Model directory (`settings/TaskModelOptions.svelte`). Tests: `ui/__tests__/PathField.test.js`, `lib/__tests__/pathPicker.test.js`.
- **Data tables use the shared `components/ui/DataTable.svelte`**; do not render a raw `<table>`. It owns sortable headers with `aria-sort`, the optional filter with its "N of M" count, the optional row limit with Show all / Show fewer, activatable rows, and the keyboard-scrollable horizontal region, so a wide table scrolls inside itself instead of widening the page; the pure sorting, filtering, and limiting rules live in `lib/dataTable.js`. Callers pass translated column labels, rows, and a stable row key; a column sets `align: 'end'` for numbers, `mono` only for code-like values (paths, commands, codes, opaque ids), and a `cell` snippet called as `(row, column)` for custom markup. Visual rules: `webui/design.md` -> Tables. Tests: `ui/__tests__/DataTable.test.js`, `lib/__tests__/dataTable.test.js`.
- `App.svelte` + `appController.js` own the shell: global loading/availability, server-event routing, resource refreshes, view composition. `lib/navigation.svelte.js` owns the displayed place (view plus view-owned record or sub-page), Back/Forward and browser history (`webui/app-shell.md` -> Navigation). `AppShell.svelte` adds the capability-gated Desktop context menu (global viewport/focus concern); host clipboard/browser launch stay behind `desktopBridge.js`.
- App owns shared Agent selection across views. Chat remains mounted while hidden to reconcile Runs and history, but only an active Chat surface may publish Agent navigation; activation reconciles the latest App-owned selection.
- Chat: `ChatWorkspace.svelte` owns up to two retained areas (Chat or website preview), split geometry, and area-local selection. Each `ChatView.svelte` owns its own `chatState.js` projection/workflows and `chatRunStream.js` reconciliation. Preview polling and the isolated frame belong to `chat/HtmlPreview.svelte` - detailed in `webui/chat.md`.
- Settings forms (`SettingsView.svelte` + panels + `settingsView.js`) submit backend contracts without reinterpreting domain policy. The dedicated Skills management view (`components/skills/`) owns the Skills view: collections (Library filters plus one entry per Identity Agent and Project), the paged package list, the package page (opened in place of its collection) with its editable Access section, row context menus, the Agent and Project Skill selections, one add menu (install through `SkillInstallDialog.svelte`, create, Skill folders), and automatic inventory refresh with no manual Refresh control; behavior in `webui/settings.md` -> Skill manager. `components/skills/skillAccess.js` is the one pure owner of allowlist toggle rules and of the `skill.inventory` access projection as rows; the Agent editor and the Project editor reuse its panels (`AgentSkillsPanel.svelte`, `SkillSelectionPanel.svelte`), and the Agent editor's Skills section also reuses its Agent-row menu, `createSkillActions` and `SkillDialogs` to edit and delete an Agent's own Skills in place - Settings keeps no Skill surface.
- Projects: `projectsView.js` state/controller, `ProjectsView.svelte` rendering. The management Project is separate from Chat's working Project context.
- Archive: the Settings page Archive (no main view) holds the retention setting and `components/archive/ArchiveEntriesPanel.svelte`, which owns listing, restoring and purging archive entries, an entry opening as a sub-page of the page; `lib/archiveView.js` holds its pure rules and `lib/archiveRetention.svelte.js` the app-wide retention projection that the Agent, Project and Session delete dialogs read for their Archive option (`webui/archive.md`).
- Terminals: `terminalsView.js` owns start/errors, live-plus-retained reconciliation with launch history, mutations, geometry, cleanup. Each streamed Terminal has one connection owner, `lib/terminalsView/connection.js`: socket, reconnect, sequence/gap recovery, authoritative TUI-mode snapshots, input batching, and resize requests; input and resize travel over that Terminal's WebSocket, not RPC (`tools/terminal.md`). Hardening: a socket stuck connecting past 8 s force-closes into normal reconnect; PTY frames pass through a stateful sanitizer reassembling escape sequences split across frames (held tails reset on `terminal_ready`) rewriting nothing else - the server-side renderer consumes the same bytes. Tiles rebuild bounded scrollback from the authoritative snapshot after mount/reconnect/resync, size the PTY to the tile used last while other viewers mirror its grid (`tools/terminal.md`), preselect the newest reusable config for new terminals, and render finished retained sessions read-only. Dimensions change only through explicit start or a socket resize request.
- `api.js` preserves the public transport boundary; internal `lib/api/` files separate RPC validation/errors, event subscriptions, binary media and domain request adapters. Raw RPC calls and method literals remain inside this owner; `rpcOwnership.guard.test.js` scans the internal files as part of it. Transport failures normalize as `ApiClientError`; binary attachments stay outside RPC envelopes. `i18n.js` owns visible-string resolution and composes the internal domain catalogs in `lib/i18n/`, rejecting duplicate keys; `registerCatalog(entries)` adds an Extension page's own catalog at page startup and rejects keys the core catalog or an earlier registration already defines.
- `terminalsView.js` preserves its public surface while internal `lib/terminalsView/` modules separate stream coordination (`controller.js`), the per-Terminal connection (`connection.js`), speech, catalog management, PTY protocol and state projections. Close-in-flight tracking remains shared across controller remounts. `TerminalsView.svelte` composes tiles and navigation; its internal `components/terminals/terminalRenderer.svelte.js` owns xterm buffers, geometry, focus and cleanup, while `TerminalDialogs.svelte` owns launch/group form input and calls the same controller. Terminal styles and labels stay in that internal folder.
- Terminal dictation stays in `terminalsView.js`, using Chat's `audioRecorder.js` and `api.transcribeSpeech` with the configured server STT binding. `TerminalsView.svelte` pastes the result through the originating xterm instance; terminal speech lifecycle and input rules are documented in `tools/terminal.md`.
- Extension pages use generic shell routes and `ExtensionPage.svelte`; the opaque frame bridge binds source window, nonce and registration epoch. `extensionPageClient.js` exposes only owner operations, route/toast/context, selected Run/file capabilities and server folder listing. The page route is the view's navigation place: `ExtensionPage` sends `'/' + place.join('/')` (or `''` at the page's start) in init and context; `route.push` becomes `navigation.navigate(place)`, a Back/Forward step, and `route.replace` becomes `navigation.replace(place)`. Both reply `{}`, and the page receives the new route with the next context update. Open dialogs and menus inside a page are layers of the App navigation: the client's `registerLayer({close})` keeps a local stack and sends the one-way `vbot.extension.layers.state {open}` when the stack becomes non-empty or empty, and again after init; while the page reports layers, `ExtensionPage` holds one navigator layer whose close posts `vbot.extension.layers.close`, and the client closes its topmost layer. The host releases that layer on `open: false`, reload, registration change and unmount. A Svelte page calls `provideNavigation({ registerLayer: client.registerLayer })` in its root, so the shared Modal and ContextMenu register themselves. Back/Forward input inside a page reaches the App in the Desktop app: when the navigator handles that input itself (`handlesInput`), `init` carries `forwardHistoryInput: true`; the client then cancels Alt+Left/Right, BrowserBack/BrowserForward and side buttons 3/4 pressed inside the page, by the navigator's rules, and sends the one-way `vbot.extension.history.move {direction}`, which the host accepts only after Ready from the current frame (and only when it asked for forwarding) and turns into the navigator's `back()`/`forward()`. In a browser the page keeps its native handling. These additions are optional on either side, so `BRIDGE_VERSION` and the Extension `API_VERSION` stay unchanged (`ExtensionPage.test.js`, `extensionPageClient.test.js`). Reload/disposal rejects stale replies and closes subscriptions; reconnect refreshes snapshots without replaying mutations. Domain UI stays under its Extension's `ui/`, built by `scripts/build-extension-pages.mjs` with the shared Vite/Svelte dependencies. Page-owned text lives in the Extension's `ui/i18n.js` catalog under its own key namespace, registered from its `ui/main.js` before mounting; shared core keys stay in the core catalog. Tests: `ExtensionPage.test.js`, `extensionPageClient.test.js` and the two independently built fixtures.
- Extension page invalidations arrive as `vbot.extension.invalidate`. An owner-scoped `extensions` change (from `ExtensionHost.publish_change`) reaches only that Extension's open page and carries the optional field `change: {resource, ids, revision}`; descriptor reloads, frame-context replacement and Run-stream recovery invalidate without it. `extensionPageClient.onInvalidation` listeners receive `{reason, change}`, where `change: null` means anything can have changed; a malformed `change` is dropped to `null`. The field is additive, so pages built without it still refresh everything and neither `BRIDGE_VERSION` nor the Extension `API_VERSION` changed (`ExtensionPage.test.js`, `extensionPageClient.test.js`).
- Extension pages can cancel an active Tool Call through `extensionPageClient.cancelToolCall(groupId, runId, toolCallId)`. The host routes the fixed capability to the Extensions RPC edge, which checks current page registration and canonical owned-Run access before calling the existing Run cancellation API. No arbitrary Chat RPC access is granted (`ExtensionPage.test.js`, `test_extensions_methods.py`).
- Extension pages list the server's folders through `extensionPageClient.listDirectory(params)` (bridge method `directory.list`), which takes and returns the `filesystem.list` params and result, so a page passes it to the shared `PathField` as `listDirectory`. `ExtensionPage` checks the params' types and relays them through `api.listServerDirectory`; the reply is bound to the frame like every call, so reload and unmount drop it. A failed listing's `vbot.extension.error` also carries the API error `code` and the listing `reason`, which the client restores as `code` and `details.data.reason`, so the page's field shows the app's translated failures. A page relies on this method, so it is Extension API v12 (`extensions.md`); `BRIDGE_VERSION` stays 1, since the envelope is unchanged and a page built before never sends the method (`ExtensionPage.test.js`, `extensionPageClient.test.js`).
- The isolated Extension iframe permits clipboard writes so shared Copy actions work. Its opaque origin requires `clipboard-write *`; clipboard reads and same-origin access remain ungranted (`ExtensionPage.svelte`, `ExtensionPage.test.js`).
- Extension Run subscriptions relay the verified Run replay watermark (`replay_through_sequence`) with their subscription id. A page can buffer initial replay until that sequence before replacing its displayed History (`ExtensionPage.test.js`, `test_extensions_methods.py`).
- The Extension host's `extensionRunStream.js` refreshes owned Run capabilities after stream errors or 25 seconds without transport activity, with bounded backoff and the last delivered sequence. Successful recovery or an unavailable replay stream invalidates the page's snapshots through the existing bridge; it never replays mutations. Heartbeats reset liveness without becoming page events, terminal events stop recovery, and teardown rejects late callbacks (`ExtensionPage.test.js`).
- Extension page history includes canonical Current Context Usage from the full Session context tail, independently of the visible page. Swarm Activity uses that projection and live Run usage events with the shared Chat usage formatter (`test_extensions_methods.py`, `SwarmPage.activity.test.js`).
- The Extension host unwraps the API subscriber envelope before forwarding canonical Run events (`type`, `run_id`, `sequence`, `payload`). Server-verified `file_urls` from History and Run streams remain available for the selected participant; stream ownership comes from `extensions.page_run.participant_id`. Switching participant/group clears that scope and ignores late prior-scope replies and stream file grants (`ExtensionPage.test.js`).
- Extension pages can register one autosave participant through `extensionPageClient.js`; the host joins the App navigation coordinator and accepts save state/results only from the current frame registration. Reload rejects every pending flush; stale client completions are ignored. Leaving a transition while the frame saves sends the one-way `vbot.extension.autosave.release`, which the client passes to its participant's `release()` before it reports its pending state (`webui/autosave.md`); the message is additive, so `BRIDGE_VERSION` stays unchanged. Tests: `ExtensionPage.test.js` and `extensionPageClient.test.js`.
- Extension bridge commands are capped separately from larger host replies. An oversized operation reply must return an error, never silently disappear; client requests time out without automatic replay. Shared typography loads the bundled Geist Sans/Mono variable `woff2` assets from `styles/fonts/` through `styles/app.css`, so isolated pages need no external font allowance (`build-extension-pages.test.js`).
- `api.js` owns the `data_store.status`, `data_store.snapshot_create`, and `data_store.incident_acknowledge` wrappers (`getDataStoreStatus`, `createDataSnapshot`, `acknowledgeDataStoreIncident`). `App.svelte` loads the safe data-store projection on connection and `resource_changed(kind="data_store")`, keeps the last incident during transient refresh failure, and renders the oldest unacknowledged recovery incident (`incidents[0]`, naming its database) as a sticky global `Banner`; acknowledgement updates state only from the returned authoritative projection.

## Invariants

- JavaScript, no TypeScript; Svelte 5 callback props, no event dispatchers.
- Back/Forward is consistent app-wide (user requirement): a change of the main content (view, selected record, sub-page, page-level tab) is one navigator step with a readable URL, corrections replace the current entry, filters/search/sort/scroll/disclosures/representation tabs are no steps, and Back first closes the topmost open layer. Views never touch `window.history`; they read and move their place through their navigation handle (`webui/app-shell.md` -> Navigation).
- Optimistic continuity is allowed; server responses and events stay authoritative - Queue contents, continuation availability, usage, connection state, and settings reconcile to server truth.
- Run SSE carries one Run's full stream; the app-wide WebSocket carries lifecycle/invalidations only; a selected Terminal uses its dedicated socket, rebuilding from the ANSI snapshot after navigation, reconnect, gaps, TUI boundaries, or end.
- Every browser resource has an owner and cleanup path (EventSource/WebSocket/timers/observers/media/object URLs/listeners/bridge subscriptions). A recovery WebSocket close must retain its close listener so normal reconnect scheduling runs; only an intentional disconnect suppresses it.
- Icon-only controls need accessible names independently of tooltips. Preserve keyboard access, visible focus, WCAG AA contrast for readable text on page/panel surfaces, and reduced-motion handling when revising presentation; these accessibility requirements do not prescribe a particular layout. The `--text-hi`/`--text-med`/`--text-lo` tokens all meet AA on `--bg` and every surface step through `--surface-3`; `--text-faint` is below AA and reserved for decoration, separators, and disabled glyphs.
- Enter/Escape shortcuts on text controls (Chat composer, inline edits, rename, search, add-entry fields) first check `lib/keyboard.js::isImeComposing` (`isComposing` or legacy keyCode 229) and leave those keystrokes to the IME, so confirming a candidate never submits, selects, or cancels.
- Shared dialogs always expose a visible accessible name, isolate background interaction while open, trap keyboard focus, and restore focus on close. Of stacked `Modal`s (a dialog opened from a dialog, such as Browse... in the Add Project dialog) only the newest answers Escape and Tab (`ui/__tests__/Modal.test.js`). Escape already consumed by a nested picker dismisses only that picker; the enclosing dialog retains its draft and closes on a subsequent unhandled Escape. Shared Dropdown variants implement the listbox/combobox keyboard contract with an explicit active option (the simple list adds typeahead; the searchable one filters); callers provide values and callbacks, not bespoke keyboard behavior. The searchable variant's collapsible-group mode switches to the tree pattern: Right opens a group or enters it, Left closes it or returns to its header, Enter toggles a header; callers own which groups are open (`expandedGroups` plus `onGroupToggle`). A Dropdown inside a `FormField` passes the field's `labelId` as `ariaLabelledby`, so its visible label and current value name the trigger; without it the trigger falls back to `ariaLabel` or the placeholder.
- Model selection stays in `modelSelection.js`: connection-aware choices are the default; callers whose contract stores only a Model use its explicit model-only mode with the same suitability filtering. Isolated pages importing app styles must own a bounded scrollport because the shared body/app shell intentionally hides document overflow.
- Shared-component content props are snippet props, callback props use Svelte naming: `Modal.svelte` renders body and footer only through `{@render body?.()}` / `{@render footer()}` - content placed directly inside `<Modal>` without a `{#snippet body()}` wrapper renders nothing (an empty modal). `EmptyState.svelte` renders `icon` and `actions` through `{@render ...}` - passing arrays or strings throws `TypeError: e is not a function` and kills the view. The `Button` component takes `onClick`; a lowercase `onclick` prop on it is silently dead because the primitive spreads `{...rest}` first and then sets `onclick={onClick}` (native HTML buttons keep lowercase `onclick`). Lib-level tests pass all three mistakes - only a component-mount test that mounts the view, clicks, and asserts catches them.
- Invalidation refreshes backing data without yanking active drafts/pickers/modals/forms - controllers defer visible swaps to safe boundaries. Agents invalidations carrying an old->new mapping (an Identity Agent rename, also from another window or the CLI) apply before reconciliation: every owner of Agent-keyed client state re-keys it synchronously, otherwise the roster refresh silently falls back to the first entry and orphans `<old>::` Session and draft keys (`webui/chat.md` -> Identity Agent rename); `memories` invalidation refetches only while its disclosure is open.
- Locales format dates/numbers; editable decimal settings stay text while edited so comma decimals normalize deliberately at payload boundary.
- `dateTimePrefs.svelte.js` owns the app-wide IANA timezone projection seeded from `settings.get.general.timezone`; general settings updates it live, and non-Calendar/Cron timestamp formatters consume it instead of the browser's implicit zone. Calendar and Cron use their server responses' `system_timezone`, which resolves from the same Settings value. Its formatters are cached per locale, options and zone: constructing an `Intl.DateTimeFormat` per call was the largest single cost in Chat streaming Long Tasks, because the Timeline formats every row's times on each render.
- `index.html` paints the canonical `Bg` (`#15130F`) inline before the Svelte bundle loads; keep it aligned with the implemented `--bg` token and the Desktop pywebview background so no white document/native layer appears between paints.
- Shared feedback stays shared (`ToastStack`, hint components, existing lib modules) - extend the owning controller instead of growing views into alternate controllers. Frontend behavior changes bring focused Vitest coverage. Existing visual arrangements are descriptive implementation state, not requirements for new or redesigned views; the task-specific visual companion is indexed below.

## Constraints & gotchas

- **dnd-kit setup in `SortableList`:** the manager gets its plugins and sensors at construction, because rows register before the provider applies its props and a default plugin active at registration leaves its attributes behind. The Accessibility plugin is excluded on purpose (it turns rows into focusable `role="button"`s); the list owns instructions, keyboard moves and announcements. The dragged row floats as a popover, and a Svelte re-order closes it silently, so `keepDragFeedbackVisible` reopens it after each order change. `@dnd-kit/svelte` is pre-1.0: keep its API behind `SortableList`/`sortable.js`.
- Debug UI/RPC access is development-only and gated - production browsers expose no tracing or probe surfaces.
- Only the Chat timeline scrolls Chat; native `title` attributes are not product help; `reasoning_meta` never leaks into rendering or client persistence; untrusted content renders only through safe text/Markdown/media paths, and attachment paths never become filesystem addressing.
- Production builds minify with **Terser**, not Vite's default esbuild: re-minifying xterm 6 corrupts its DEC-mode query handler into a runtime ReferenceError - changing the minifier requires a real built-browser TUI check, not just Vitest.
- Libraries loaded through dynamic `import()` (`@xterm/*` for Terminals, `tldts` for requested addresses) must match no `codeSplitting` group in `webui/vite.config.js`: the `vendor` group's test excludes them, because a group that matches them pulls them into the eagerly loaded vendor chunk (xterm landed there after the Vite 8 migration until 2026-10).
- **No xterm WebGL addon:** at fractional desktop scale its canvas sits one pixel off the cell grid painting white row gaps nothing fully rules out; the DOM renderer is the only path. The historical white lines had a second independent cause fixed server-side (`tools/terminal.md`). Do not reintroduce WebGL or a client-side output rewriter without addressing both - live-check striped TUIs at real desktop scale.
- The English catalog is the only source of UI text; call sites pass no English fallback. `t(key, values)` in `webui/src/lib/i18n.js` renders the active-locale entry, else the English entry, with `{name}` placeholders filled from `values`; a key without an entry renders as the raw key, so every new key needs its entry in `lib/i18n/<domain>.js` (or in the Extension page's `ui/i18n.js`). The one fallback form is `tOr(key, fallback, values)` for a composed key built from a server-sent code (log levels, Local Speech codes, Provider ids, prompt block ids): a code without an entry renders `fallback`, usually the code itself. Composed keys over a fixed WebUI list use `t` and need an entry for every value. Modules import `t` from `lib/i18n.js` and call it directly; no function receives it as an injected parameter. Keys stay statically visible: a table or conditional passes one literal-key `t()` call per entry or branch (label thunks such as `label: () => t('navigation.chat')`), never a key held in a variable. `lib/__tests__/i18nCatalog.guard.test.js` parses every source under `webui/src` and `resources/extensions/*/ui` and fails on a key without non-empty text in the catalogs of its page, a fallback passed to `t()`, `tOr()` over a literal key, a composed key missing from its `COMPOSED_KEYS` table (which lists the values of each `t` pattern), an unused catalog entry, or a placeholder the call's literal params object does not supply. Never reuse a view-specific catalog key for generic text: its view-specific catalog string renders everywhere the key is reused.

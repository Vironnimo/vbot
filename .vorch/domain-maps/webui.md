# WebUI

The WebUI is vBot's Svelte accessor: it presents server-owned state and sends user intent through the server's HTTP, RPC, WebSocket, and SSE contracts.

## Overview

`webui/src/` owns browser presentation, interaction state, navigation, and transport adaptation - never Chat, Provider, Extension, Project, or persistence semantics. `lib/api.js` is the single raw transport seam: components use its wrappers instead of spelling RPC names or building envelopes. The production server serves `webui/dist/`, so source changes need a build; a missing build stays a safe server state, not a startup failure.

## Ownership

- **Editable configuration and existing-record editors use the shared autosave system** in `webui/src/lib/autosave.js`, including Extension-owned pages. Before adding or changing fields, save controls, or editor-replacing navigation, read `webui/autosave.md`; reuse its input timing, tracked saves, and transition integration. Domain controllers retain validation and response reconciliation.
- **Reorderable lists use the shared `components/ui/SortableList.svelte`**; the owner receives one `onReorder(from, to)` per completed move and keeps data and persistence (`webui/shared-controls.md` -> SortableList).
- **Context menus use the shared `components/ui/ContextMenu.svelte`** (helpers in `components/ui/contextMenu.js`); do not build ad-hoc menus. A component menu calls `preventDefault()` on its `contextmenu` event, which also keeps AppShell's Desktop context menu from opening. Contract and caller pattern: `webui/design.md` -> Shared controls, `webui/source-map.md` -> UI primitives.
- **Paths on the server's filesystem are entered through the shared `components/ui/PathField.svelte`**; never a native file dialog or browser file input, because the server may be remote. It completes and browses through `filesystem.list` (`webui/shared-controls.md` -> PathField).
- **Data tables use the shared `components/ui/DataTable.svelte`**; do not render a raw `<table>`. Callers pass translated column labels, rows, and a stable row key (`webui/shared-controls.md` -> DataTable).
- `App.svelte` + `appController.js` own shell loading/availability, server events, refreshes and view composition; `lib/computers.svelte.js` the computer catalog. `lib/navigation.svelte.js` owns the displayed place (view plus record/sub-page), Back/Forward and history (`webui/app-shell.md`). `AppShell.svelte` adds capability-gated Desktop context menus; clipboard: `lib/clipboard.js`; host APIs: `desktopBridge.js`.
- **Access gate:** `main.js` mounts `components/access/AccessGate.svelte` with `App` as a prop; App mounts only once `/api/auth/status` lets the page in, and the gate shows browser pairing or a refusal instead. Every transport reports the access guard's refusals (HTTP 401 `auth_required`, 429 `rate_limited`, 403 `access_denied` and 503 `devices_unavailable` envelopes, WebSocket close 4401/4403/4503) through `lib/api/accessLoss.js`, and the gate takes App down. A new transport or reconnect loop reports them the same way and stops reconnecting on them (`webui/app-shell.md` -> Access gate).
- App owns Agent selection and navigation badges (Chat and Automations). Hidden Chat views reconcile Runs and history; only active Chat publishes navigation. Activation follows App's selection.
- Chat: `ChatWorkspace.svelte` owns up to two retained areas (Chat or website preview), split geometry, and area-local selection. Each `ChatView.svelte` owns its own `chatState.js` projection/workflows and `chatRunStream.js` reconciliation. Preview polling and the isolated frame belong to `chat/HtmlPreview.svelte` - detailed in `webui/chat.md`.
- Settings forms (`SettingsView.svelte` + panels + `settingsView.js`) submit backend contracts without reinterpreting domain policy. Skill management is the dedicated Skills view (`components/skills/`), whose panels and actions the Agent and Project editors reuse; Settings keeps no Skill surface (`webui/settings.md` -> Skill manager).
- Projects: `projectsView.js` state/controller, `ProjectsView.svelte` rendering. The management Project is separate from Chat's working Project context.
- Archive: the Settings page Archive (no main view) and the delete dialogs' Archive option (`webui/archive.md`).
- Terminals: `terminalsView.js` owns the Terminals view; each streamed Terminal has one connection owner, `lib/terminalsView/connection.js`, and input and resize travel over that Terminal's WebSocket, not RPC (`tools/terminal.md`).
- `api.js` preserves the public transport boundary; internal `lib/api/` files separate RPC validation/errors, event subscriptions, binary media and domain request adapters. Raw RPC calls and method literals remain inside this owner; `rpcOwnership.guard.test.js` scans the internal files as part of it. Transport failures normalize as `ApiClientError`; binary attachments stay outside RPC envelopes.
- Extension pages use generic shell routes and `ExtensionPage.svelte`; the opaque frame bridge binds source window, nonce and registration epoch, and `extensionPageClient.js` exposes only owner operations and fixed capabilities, never arbitrary RPC access. A bridge addition that is optional on either side keeps `BRIDGE_VERSION` and the Extension `API_VERSION` unchanged; a method a page relies on raises the Extension API version (`extensions.md`). An Extension page's bundle holds only `styles/app.css` and the stylesheets its imported components import themselves, so a core component that Extension pages reuse keeps its rules in its own `<style>` block or in a stylesheet `app.css` imports. Details: `webui/extension-pages.md`.
- App loads the data-store status and renders the oldest unacknowledged recovery incident as a sticky global `Banner`; from the same read it keeps the Secret Store projection for Settings (`webui/app-shell.md` -> Server connection and events).
- Model selection stays in `modelSelection.js`, for every Model picker (`webui/settings.md` -> Providers and models).

## Invariants

- JavaScript, no TypeScript; Svelte 5 callback props, no event dispatchers.
- Back/Forward is consistent app-wide (user requirement): a change of the main content (view, selected record, sub-page, page-level tab) is one navigator step with a readable URL, corrections replace the current entry, filters/search/sort/scroll/disclosures/representation tabs are no steps, and Back first closes the topmost open layer. Views never touch `window.history`; they read and move their place through their navigation handle (`webui/app-shell.md` -> Navigation).
- Optimistic continuity is allowed; server responses and events stay authoritative - Queue contents, continuation availability, usage, connection state, and settings reconcile to server truth.
- Run SSE carries one Run's full stream; the app-wide WebSocket carries lifecycle and stable output, never audio bytes; a selected Terminal uses its dedicated socket, rebuilding from the ANSI snapshot after navigation, reconnect, gaps, TUI boundaries, or end.
- Every browser resource has an owner and cleanup path (EventSource/WebSocket/timers/observers/media/object URLs/listeners/bridge subscriptions). A recovery WebSocket close must retain its close listener so normal reconnect scheduling runs; only an intentional disconnect or an access-loss close (4401/4403/4503) suppresses it.
- Icon-only controls need accessible names independently of tooltips. Preserve keyboard access, visible focus, WCAG AA contrast for readable text on page/panel surfaces, and reduced-motion handling when revising presentation; these accessibility requirements do not prescribe a particular layout. The `--text-hi`/`--text-med`/`--text-lo` tokens all meet AA on `--bg` and every surface step through `--surface-3`; `--text-faint` is below AA and reserved for decoration, separators, and disabled glyphs.
- Enter/Escape shortcuts on text controls (Chat composer, inline edits, rename, search, add-entry fields) first check `lib/keyboard.js::isImeComposing` (`isComposing` or legacy keyCode 229) and leave those keystrokes to the IME, so confirming a candidate never submits, selects, or cancels.
- Shared dialogs always expose a visible accessible name, isolate background interaction while open, trap keyboard focus, and restore focus on close. Shared Dropdown variants own the listbox/combobox keyboard contract; callers provide values and callbacks, not bespoke keyboard behavior (stacked dialogs, IME and the tree mode: `webui/shared-controls.md` -> Modal and Dropdown keyboard).
- Shared-component content props are snippet props, callback props use Svelte naming: `Modal.svelte` renders body and footer only through `{@render body?.()}` / `{@render footer()}` - content placed directly inside `<Modal>` without a `{#snippet body()}` wrapper renders nothing (an empty modal). `EmptyState.svelte` renders `icon` and `actions` through `{@render ...}` - passing arrays or strings throws `TypeError: e is not a function` and kills the view. The `Button` component takes `onClick`; a lowercase `onclick` prop on it is silently dead because the primitive spreads `{...rest}` first and then sets `onclick={onClick}` (native HTML buttons keep lowercase `onclick`). Lib-level tests pass all three mistakes - only a component-mount test that mounts the view, clicks, and asserts catches them.
- Invalidation refreshes backing data without yanking active drafts/pickers/modals/forms - controllers defer visible swaps to safe boundaries. Agents invalidations carrying an old->new mapping (an Identity Agent rename, also from another window or the CLI) apply before reconciliation: every owner of Agent-keyed client state re-keys it synchronously, otherwise the roster refresh silently falls back to the first entry and orphans `<old>::` Session and draft keys (`webui/chat.md` -> Identity Agent rename); `memories` invalidation refetches only while its disclosure is open.
- Locales format dates/numbers; editable decimal settings stay text while edited so comma decimals normalize deliberately at payload boundary.
- `dateTimePrefs.svelte.js` owns the app-wide IANA timezone projection seeded from `settings.get.general.timezone`; general settings updates it live, and other timestamp formatters use it, not the browser's zone. Calendar and Cron use their responses' `system_timezone` (same Settings value). Its formatters are cached per locale, options and zone, because the Timeline formats every row's times on each render and a new `Intl.DateTimeFormat` per call dominated Chat streaming Long Tasks.
- `index.html` paints the canonical `Bg` (`#15130F`) inline before the Svelte bundle loads; keep it aligned with the implemented `--bg` token and the Desktop pywebview background so no white document/native layer appears between paints.
- Shared feedback stays shared (`ToastStack`, hint components, existing lib modules) - extend the owning controller instead of growing views into alternate controllers. Frontend behavior changes bring focused Vitest coverage. Existing visual arrangements are descriptive implementation state, not requirements for new or redesigned views; the task-specific visual companion is indexed below.

## Constraints & gotchas

- Vitest aliases exactly `svelte/reactivity` to its client implementation: the default Node export has plain, non-reactive `Set`/`Map`. Component tests use this shared resolution instead of per-file mocks.
- In WebUI code, eslint forbids a mutable `Map` in Svelte derived contexts (`svelte/prefer-svelte-reactivity`, enabled by the Svelte plugin's recommended config in `webui/eslint.config.js`) - group with plain objects.
- Debug inspection and probes require Debug Mode; Settings -> Debug remains available while it is off.
- Only the Chat timeline scrolls Chat; native `title` attributes are not product help; `reasoning_meta` never leaks into rendering or client persistence; untrusted content renders only through safe text/Markdown/media paths, and attachment paths never become filesystem addressing.
- Production builds minify with **Terser**, not Vite's default esbuild, which breaks xterm 6 at runtime (`tools/terminal.md`); changing the minifier requires a real built-browser TUI check, not just Vitest.
- Third-party `codeSplitting` groups in `webui/vite.config.js` use `entriesAware` to keep libraries used only by lazy views deferred. Direct dynamic imports (`@xterm/*`, `tldts`) remain outside those groups. Check the full static import graph when changing grouping; individual chunk sizes do not show startup cost.
- I18n (PROJECT.md -> I18n): `i18n.js` owns visible-string resolution and composes the domain catalogs in `lib/i18n/`, rejecting duplicate keys; `registerCatalog(entries)` adds an Extension page's own catalog at page startup and rejects keys the core catalog or an earlier registration already defines. `t(key, values)` renders the active-locale entry, else the English entry, with `{name}` placeholders filled from `values`; a key without an entry renders as the raw key, so every new key needs its entry in `lib/i18n/<domain>.js` (or in the Extension page's `ui/i18n.js`). The one fallback form is `tOr(key, fallback, values)` for a composed key built from a server-sent code (log levels, Local Speech codes, Provider ids, prompt block ids): a code without an entry renders `fallback`, usually the code itself. Composed keys over a fixed WebUI list use `t` and need an entry for every value. Modules import `t` from `lib/i18n.js` and call it directly; no function receives it as an injected parameter. Keys stay statically visible: a table or conditional passes one literal-key `t()` call per entry or branch (label thunks such as `label: () => t('navigation.chat')`), never a key held in a variable. `lib/__tests__/i18nCatalog.guard.test.js` enforces these rules over `webui/src` and `resources/extensions/*/ui`, including unused catalog entries, placeholders the call's literal params object does not supply, and composed keys missing from its `COMPOSED_KEYS` table. Never reuse a view-specific catalog key for generic text: its view-specific catalog string renders everywhere the key is reused.

# Session ownership and provenance

Task-gated detail for `sessions.md`: the Working Project binding, Identity-rename retargeting, Sub-Agent parent links, the Session side of archive scope membership and restore provenance, and the `sessions.0004` compatibility fence. Source: `core/sessions/sessions.py`, `_store_working_projects.py`, `_store_mutations.py`, `_store_values.py`, `_store_archive.py`, `archive_ledger.py`. Tests: `tests/core/sessions/test_sessions_lifecycle.py`, `test_sessions_metadata.py`, `test_store_database.py`, `tests/core/archive/test_archive_service.py`.

## Working Project

- The term: `sessions.md` -> Terms -> Working Project. Reusing its public id for another Project does not restore the binding: the archive marker keeps the old Session unavailable, including after archive purge.
- `working_project(address)` and `working_project_async` return a `SessionWorkingProject` with its effective Project id and original-Project archive state from one live snapshot. Projects combines that binding with the current Project store; metadata alone cannot establish that a reused public id is the same Project.
- `create(..., working_project_id=...)` fixes the Working Project of a Session of an Identity Agent: a Project id (the caller checks that it exists), `None` for the Workspace, or by default `AGENT_DEFAULT_PROJECT`, which asks the provider `set_agent_default_project` installs (Runtime bootstrap: the Agent's `root_project_id`; without a provider, the Workspace). A Project Session accepts only the default or `None` and stores NULL. A Session that `get_or_create`, `ensure_metadata(create_missing=True)` or Run admission creates works in the Agent's default Project (admission: the Run's working Project). Move and fork carry it: `sessions/lineage.md` -> Fork.
- The named migration `sessions.0002_session_working_projects` (`_store_working_projects.py`) gave every Session of an Identity Agent with a `root_project_id`, live or archived, that Project as its Working Project, so it keeps working where its Agent was rooted; an Agent in the archive counts with the `root_project_id` its entry facts record. A root Project that no longer exists is skipped with one WARN (those Sessions keep working in the Workspace), and only Sessions without a Working Project change, so a repeated run changes nothing. Sessions an older vBot creates after the migration keep NULL.

## Sub-Agent links

Sub-Agent links: `subagent_children(parent)` (live Sessions whose `subagent_parent` names *parent*, oldest first) and `subagent_session(subagent_id)` (the live Session with that public id) read the projected `subagent_parent_*` columns through the partial indexes `sessions_by_subagent_parent` and `sessions_by_subagent_id` (`test_store_query_plans.py`). Writing a changed link also captures its live Parent's generation in private `subagent_parent_generation_id`; unrelated metadata writes preserve it. Restore retargets links by that generation through `sessions_by_parent_generation`, including archived children, so an exact old address reused by a replacement cannot claim the originals. Migration `sessions.0004_restore_provenance` identifies legacy links only at addresses with one stored generation; ambiguous links stay unproven. Forks strip `is_subagent_session`, `subagent_parent`, its generation, `subagent_reply_target` and the historical `subagent_taken_over_at`. Reply routing does not change links or controls; semantics: `subagents.md`.

## Identity-rename retargeting

The Identity-rename steps `retarget_identity_agent_sessions` and `retarget_identity_agent_references` change only global Sessions, and bare `subagent_parent` links, that still name the old id, each in one transaction, so repeating one after an interruption finishes it and swapping the ids reverts it. The Sessions step moves live and archived Sessions and the scope `agent_id` of the Agent's `session` archive entries together, so their restore lands at the renamed Agent; archived Sessions that an archived Agent of the old id holds in its own `agent` entry (its restore brings them back with that Agent) or that an Extension manages (only the owner resumes or deletes them) stay. Archived generations may share an address, so only a live address collides; `SessionArchiveLedger.identity_agent_entry_ids(agent_id)` lists the entries holding what a rename from or to that id would move, and the Agent rename refuses a new id that has any (`agent/lifecycle.md` -> Rename). A link of a live or archived child follows its parent Session's address: it moves only when that parent, live or archived, moved to the new id, and a link that recorded its parent's generation only with that generation, so links to a parent that stayed or is missing, including leftovers that already named the new id, stay; the Agent rename owns their order, rollback and recovery (`agent.md`, `test_sessions_metadata.py`). `retarget_metadata_value(agent_id, key, old_value, new_value, matching=)` gives one open metadata key of an Identity Agent's live and archived global Sessions a new value where it still holds the old one and the `matching` keys hold their values, in one transaction (identifier keys; prompt-state keys are refused); the rename uses it for the Librarian Sessions bound to the renamed Agent, matching its `skill_agent_created_at` (`agent/builtin-agents.md` -> Built-in Librarian; `test_agents_rename.py`). The rename's rewrite of Skill package owners in stored entries: `sessions/history-api.md` -> Skill activation cache.

## Archive scope membership and provenance

- `ChatSessionManager.archive(address)` archives one live Session with its review forks (`sessions.md` -> Terms -> Review fork; one with a running Run stays live) as its own `session` archive entry and returns its `ArchiveEntryRef`; `review_forks(address)` lists a live Session's live review forks oldest first, running ones included, so a caller can guard their Runs with the Session's. Archive is asynchronous at the public boundary, runs off the Event Loop, and holds the Session write lock.
- `SessionArchiveLedger.scope_addresses(ArchiveScope)` lists one Agent/Project scope and its recursive live review followers in a single canonical read, including reviews that retained another owner after their source moved. `commit_scope` archives this membership in its existing transaction; idle review followers join with their source, while a newly appeared running review and its followers stay live and whole. Archive owns the corresponding Run/reference guards, resource closure and surviving-owner pointer repair (`archive.md`).
- A Project archive freezes live and archived Identity Sessions' Working Project associations in `session_working_project_archives` (Session key -> archive id), without replacing an earlier archive's association. Move and fork into Identity scope carry it; entering a Project scope selects that live Project incarnation and clears it. `commit_restore` retargets only the restoring entry's associations and clears them atomically with its members' address restoration. Purge leaves the marker on surviving Sessions, so a replacement Project's later archive cannot claim them. History `created_at` and `forked_at` never decide ownership. Already-existing archives have no provable association set: restore-as leaves their Identity Sessions unchanged and warns (`archive.md`; `test_sessions_lifecycle.py`, `test_archive_service.py`).
- `archive_ledger.unproven_parent_link_count(entry_key)` reports child links that a restore-as cannot safely retarget, through `sessions_by_unproven_parent`; archive checks and outcomes expose the partial recovery warning.

## Paired changes

Agents and Projects share the Runtime Session manager (`sessions.md` -> Cross-Domain Rules). Agent create/current-Session repair deletes a newly created Session if later file persistence fails; a reverted rename retargets Sessions back through the same steps; Sub-Agent parent-reference rewrites each use one transaction and leave unrelated Session revisions unchanged; Agent and Project archive and restore move filesystem state around the Session commit and compensate it if that fails (`archive.md`). These pairs hold the snapshot barrier (`database.md` -> Snapshot consistency).

## Compatibility

`sessions.0004_restore_provenance` is an additive Generation 1 migration with `breaks_older=True`. Older Session writers do not maintain the new ownership provenance and could leave trusted stale associations, so the kernel refuses versions lacking this migration without changing or recovering the database. Returning to an older version requires the pre-update data snapshot; there is no generation conversion (`test_store_database.py`).

# Session titles

Task-gated detail for `sessions.md`: immediate local titles, background Model titles for Sessions and Extension groups, the title parser and title callbacks. Source: `core/sessions/titles.py`. Tests: `tests/core/sessions/test_titles.py`. Reasons for the title System Prompt's sentences: `sessions/agent-facing-text.md`.

## Generation

Title generation shares Chat's public `resolve_model_target` for explicit Connection suffixes and per-Model allowed Connection selection.

- Session and group title generation resolves Provider credentials and constructs its Adapter on the `session-title` worker, retaining Adapter cleanup when setup is cancelled. It records each exposed Adapter request through the injected `UsageRecorder`, including the explicit effort retry, before title validation or persistence. Invalid titles and later Session/group deletion keep their known consumption; accounting stores no generated title response content.
- Automatic Session titles read the sole current User entry's content and sequence from one database snapshot, then guard both its sequence and the Session generation in the metadata write. An edited-away source cannot publish a late title, while later appends do not invalidate that title request. A history edit that replaces the first current User entry clears the generated title (`sessions/lineage.md` -> History edit).
- Title generation resolves the Adapter's `request_context_kwargs` from Project/Agent/Session once and forwards it on both attempts. This supplies required Provider routing headers without coupling Sessions to wire fields (`test_reasoning_mandatory_endpoint_retries_with_default_effort`); a synthetic Muse Spark 1.3 title completed through this path on 2026-09-07, before title requests streamed. Both attempts stream through `stream_model_response` (`core/chat/streaming.py`; a completed `send` only when the Provider declares it cannot stream) with `DebugContext.streaming` true; the retry at provider-default effort follows any `ProviderError` of the first attempt.

## Parser and validation

`titles.py` owns immediate local titles and optional background Model titles. The Model is instructed to return exactly one `[title=...]` block. The parser reads only the answer content, whose inline Reasoning the shared response finalization has already split off (`chat.md` -> `split_inline_reasoning`); it takes the first complete, non-empty block despite surrounding commentary or later candidate blocks, tolerates marker case/spacing and straight or typographic quotation wrappers, and joins line breaks inside the block; an unclosed block that ends the response counts as complete (observed: `glm-5.3-flash` stopping before `]`). A response with only incomplete or empty blocks, or an overlength title, is rejected. Without a block attempt, one unambiguous plain-text title is also accepted; it never chooses among multiple candidate lines. Invalid generated content keeps the local title and emits a content-free warning with the rejection reason and no traceback or extra Model request; unexpected failures retain their traceback. A successful generated Session or group title logs only at DEBUG. A generated Session title is stored only on the Session generation it was requested for (`set_auto_title(..., expected_generation_id=...)`, which raises `SessionNotFoundError` otherwise); one that arrives after the Session was archived or deleted is dropped, so a new Session at the same address keeps its own title (`test_a_late_title_only_lands_while_its_first_user_entry_is_current`). Regression coverage lives in `tests/core/sessions/test_titles.py`. `generate_group_title` reuses the same prompt, parser and request path for Extension group titles (Model choice: `extensions/host.md` -> Group titles).

## Callbacks

Title-change callbacks receive the Session address; completion-read callbacks receive the address plus the acknowledged Run id. Callback failures after committed title or completion mutations are logged (ERROR with traceback on `vbot.sessions`, naming the event and Session address) and isolated so callers never receive a false failure for state that already persisted.

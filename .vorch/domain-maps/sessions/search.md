# Session search and FTS

Task-gated detail for `sessions.md`: the integrated FTS indexes, their upkeep and rebuild, and `search_messages`. Source: `core/sessions/_store_search.py`, `_store_fts.py`, `schema.py` (FTS DDL and membership SQL), `store.py` (`search_messages`, write retry). Tests: `tests/core/sessions/test_session_fts.py`, `test_store_query_plans.py`, `test_lineage_model.py`. Recall's use of this search: `recall.md`.

## Indexes

- Both indexes are disposable external-content FTS5 tables over views of the entries that are current in some Session's view (`FTS_MEMBERSHIP_SQL`): `searchable = 1`, and either not superseded or still admitted by some descendant's lineage segment. The rowid is `entry_key`, so each stored entry is indexed once however many Sessions show it. There is no mirrored search-text table.
- `entries_fts` (tokenizer `unicode61`) over `entries_fts_source`: text (`content`) and User block text (`search_text`), the only columns search MATCHes (`{content search_text}`) and the literal check reads. Assistant reasoning, Tool names and arguments and error kinds are not indexed (storage version 2 dropped those never-queried columns). Observation: the Generation 1 plan's settled decision that Tool-call arguments stay searchable as whole words is not implemented; the columns that held them were never matched, and restoring that search needs query and literal-check changes plus a storage version bump.
- `entries_fts_trigram` over `entries_fts_trigram_source`: `content` and `search_text` of `FTS_TRIGRAM_ROLES` (`user`, `assistant`, `compaction_checkpoint`) entries that have text. SQLite builds without the trigram tokenizer create only the standard index (`FTS_SQL_FALLBACK`).
- `searchable` is decided at append (`_message_is_searchable`): only Recall conversation roles (`user`, `assistant`, `tool`, `error`, `compaction_checkpoint`), never persisted Recall results (`session_search`/`session_read` Tool results) or `[skill-context]` Notes, and only entries with content. An Assistant entry with only reasoning or Tool calls is not a member. Entries appended before storage version 2 keep the `searchable` value they were written with; such a member without text has an empty index row.

## Upkeep

- One rule keeps both indexes exact: before a change can end an entry's membership, forget its rows through the source view (`fts_forget`, `fts_forget_keys`), which still returns the indexed values; after the change, index the same candidates again (`fts_index_keys`), and the view admits only those still members. Appends, `finish_run`, materialized copies, history edits and deletion follow it (`sessions/lineage.md`).
- Writers maintain the indexes only while they exist and no rebuild is pending (`_fts_writable`). A write that fails with an FTS error detaches both indexes (drops them, sets the stale marker and a degraded reason in `store_meta`) and the canonical write is retried once without them, so a derived-index failure never blocks canonical persistence (`store.py` `_execute_write`).
- Rebuild runs in the spec's `after_open` hook (`_ensure_fts_schema`): recreate missing or unsupported indexes (`FTS_STORAGE_VERSION = 2`; any other stored version drops and rebuilds both), then backfill in committed windows of 500 entry keys with generation plus target/completed high-water marks taken from `sqlite_sequence` (keys are `AUTOINCREMENT`, never reused), resumable after interruption, and clear the stale marker only after an explicit standard and trigram coverage check. Interruption reports rebuilding/degraded state, never healthy incompleteness.
- Ordinary search availability trusts the lifecycle/version/stale/high-water markers and never runs canonical coverage anti-joins; startup repair, the data-store status health hook and `fts_health()` own coverage validation; data snapshot verification does not check FTS coverage.

## `search_messages`

- Returns a typed `SessionSearchResult` of exact hits (`SessionSearchHit`: address, Message id, role, timestamp, matched text, rank) plus `complete`, `method` (`fts`/`scan`) and `fallback_reason`. Results are bounded by `limit` (default 1,000).
- Eligible Sessions (one `MATERIALIZED` CTE): live Sessions of the requested Project scope (the Identity scope for `project_id=None`) whose Recall visibility the request admits, optionally one Agent and one Session, minus excluded Session ids. Candidates are the current entries of eligible Sessions: their own non-superseded entries `UNION` the ancestor entries their lineage admits, filtered by role and time before any candidate is checked. Each stored entry is one candidate, so a fork never duplicates its origin's hits.
- Attribution (`_REPORTED_SESSION`): a hit is reported for the Session that stores the entry when it is eligible and the entry is not superseded; otherwise for the newest eligible Session (highest `session_key`) whose lineage admits it.
- Index choice: a request that excludes the `tool` role uses the trigram index when every term (or the phrase) has at least 3 characters and the trigram index exists; everything else uses standard whole-token FTS. A standard miss never retries trigram. FTS queries keep the query's Unicode spelling for SQLite's tokenizer (for example a German sharp s); Python case folding belongs only to the literal candidate check, not the FTS expression (`test_fts_query_keeps_unicode_tokenizer_spelling`).
- FTS only enumerates candidates: by bm25 rank (one full `MATCH` scan keeps bm25 statistics whole-index; equal ranks break by recency, then key) or by `created_at` for newest/oldest. Each candidate's conversation text (`COALESCE(content, search_text)`; roles outside the Recall conversation roles and persisted Recall results read as empty) is checked with the literal case-insensitive matcher before it counts, so results are full whenever enough matches exist. Candidates are checked in keyed batches (16-256) that never split a rank; at most `_SEARCH_CANDIDATE_LIMIT` (10,000) are checked, and a result that budget cut short is `complete=False`.
- Fallbacks: a healthy FTS miss that excludes Tool rows returns empty without scanning. A Tool-inclusive FTS miss scans with `fallback_reason` `tool_inclusive`; an unavailable index scans with `fts_unavailable`; an FTS error during the search detaches the indexes and scans with `fts_error`; `use_fts=False` scans directly. Scans order eligible current entries by `created_at` (relevance scans newest first) under the same matcher and budget.
- Time filters (`since`/`until`) canonicalize their input and compare stored canonical text, so `Z`, `+00:00`, equivalent offsets and fractional precision stay equivalent (`test_time_filters_compare_exact_instants_across_timestamp_encodings`).

# Compaction

Policy-driven Context transformation and checkpoint creation for chat Sessions.

## Overview

`core/compaction/` owns the provider-neutral Engine: evaluates Triggers, asks one Strategy for a Plan, performs zero or one Model call, validates the resulting Projection, returns one self-contained `compaction_checkpoint` - never rewriting or deleting prior canonical Session records. The Model call always consumes the adapter's canonical stream through Chat's shared accumulator, without passing normalized content back through a raw Provider response parser: some providers (observed on OpenRouter's stealth tier) reject large non-streaming completions outright while streaming the same payload fine. Summary+Tail keeps the already-built request byte-for-byte through the chosen Tail boundary when the Summary target is the active target, removes the native Tail from the Compaction request, and appends one canonical System Reminder containing only the Compaction instruction. `run_coordination.py` owns Compaction Policy decisions, checkpoint persistence, and manual/automatic Run lifecycle. Chat owns request materialization and recovery through `core/chat/compaction_host.py::ChatCompactionHost`, the implementation of `CompactionRunHost`; the coordinator never imports private Chat symbols or reconstructs Chat request state. Pinned prompt-epoch assembly lives in `core/prompts/pinned_context.py` behind that host; Policy configuration belongs to Settings/Agent/Project/Session layers.

## Data Model & Checkpoint contract

- A resolved Policy is `{enabled, trigger, strategy}`; built-in triggers are `context_ratio{threshold, tokens?}` and `input_tokens{tokens}`. For `context_ratio`, the optional absolute `tokens` cap combines with the ratio and whichever limit is reached first triggers Compaction. Built-in strategies are `summary_tail{tail_tokens, summary_model}` and `continuation`. `CompactionSettings` is the typed runtime view - not a second settings source.
- A `CompactionPlan` is the Strategy/Engine boundary permitting zero or one Model call; the Engine never loops or follows up. The Strategy receives the current effective canonical Context and the corresponding already-built provider request.
- A new checkpoint stores the reference-framed summary in `content`, canonical message `projection`, cumulative compacted-token count (both strategies add only newly compacted messages, never the previous checkpoint notes), before/after context tokens, and Policy/Strategy provenance. The after count builds and structurally estimates the exact projected request (refreshed System Prompt, request-only Context, retained Summary+Tail, same-Run Reasoning/Tool restoration, complete Tool definitions) - explicitly approximate in the UI, never derived by subtracting reclaim from a differently scoped estimate. The Projection constructor guarantees it starts with the matching `[compaction-summary]` note and strips Assistant reasoning fields/meta/scope: vBot Compaction is textual Summary+Tail state, never Provider-native opaque reasoning tokens. The summary is framed as historical reference and ends with an explicit boundary marker; standalone outer System Reminder delimiter lines copied by the Summary Model are discarded before framing. The native Tail follows without an extra serialized copy or Tail-guidance note. Its framing describes the state at the cutoff and directs unfinished work to continue from the summary plus later chronological messages without reissuing historical requests. Chat appends an ordinal reminder that the Session-scoped `history` Tool can retrieve hidden messages and original payloads behind retained Skill-loading digests. Latest checkpoint Projection + later messages = effective Context; hidden history never re-reads into later compaction. Every checkpoint carries a Projection; `ChatMessage` validation rejects one without it.
- Every completed checkpoint also ends one Skill activation epoch: Skill names derive only from post-checkpoint carriers, `[skill-context]` carriers drop from the Projection, retained loading Tool Results become instruction-free digests preserving complete cycles, and one `[compaction-skills]` names-only reminder (replacing any previous) says instructions and environment access are inactive with reload guidance.

The Engine records successful Model-backed work as `usage.model_call = {model, usage}` on the checkpoint, including canonical token counters, the cost snapshot and the stable `usage_call_id` from `core/usage` (`usage.md`). Runtime injects the shared Model registry lookup and Usage recorder; the coordinator passes both full Model references and Run/Extension-group identity so summary-target and active-target accounting cannot be confused. The private `_model_request.py` stream boundary records every exposed Adapter invocation, including partial Usage on failure/cancellation, before checkpoint validation or commit. Rejected summaries, insufficient reclaim and stale results therefore retain their reported consumption independently of checkpoint persistence. Duration and direct before/after Context estimates remain separate checkpoint fields. Zero-call Strategies have no invented Model usage. Coverage: `test_compaction_usage_recording.py`.

## Strategies

- `SummarizationStrategy` slices the already-built provider request immediately before the Tail boundary and calls the resolved Summary Model once after appending one System Reminder through Chat's canonical note renderer. The Reminder contains only the shared automatic/manual Compaction instruction; the Tail is absent from the request and follows the returned summary natively in the Projection. Older steps move wholly into the summarized prefix; User messages and older Assistant messages are never mandatory Tail anchors, and ordinary retained Tool payloads are not shortened. When Summary and active targets match, the native prefix including Provider Reasoning remains unchanged for cache reuse; a different target strips Provider-owned Reasoning from the prefix because that state cannot cross targets.
- `ContinuationStrategy` requires the completed active provider request, appends one canonical System Reminder asking for checkpoint Context, calls the active Model once with the same Tool definitions, and uses the response directly as Projection - the cache-preserving append-only shape. Automatic Continuation runs only where the same Run will continue: before its first Model request or after a complete Tool batch. Manual Continuation uses its separate no-active-Run prompt. Neither path changes Context between an Assistant Tool Call and its correlated Tool Results.
- `find_tail_boundary` selects a chronological suffix at complete User/Assistant step boundaries. The configurable `tail_tokens` is the request-side budget; only the newest indivisible step can exceed it. Runtime planning and the automatic new-context check count slices of the already-built request with the active Adapter's wire estimator, including replayed Reasoning and request-only Tool media. No second compaction Model call is made to repair the size. Opaque Reasoning remains approximate under the existing shared blob reservation; encoded length is not a measured context cost (`core/compaction/compaction.py`, `tests/core/compaction/test_compaction_tail_selection.py`).

## Policy Resolution

Resolved per compaction decision: Session override -> Agent effective (incl. Project member override) -> global settings. For a temporary Agent the Agent level is the `compaction_policy` of its admitted immutable configuration (for example a Swarm profile's override); without one it inherits global settings (`agent.md`, `test_temporary.py`). Absence inherits dynamically - global changes affect existing Sessions without rewrites; a Policy change triggers nothing itself and never reprocesses hidden history. `compaction.py::effective_compaction_policy()` is the single implementation of this chain, used by Run coordination, `session.list` (`compaction_policy_effective`), `session.set_compaction_policy` (`effective`), the Agent payload (`effective_compaction_policy`, no Session override) and `chat.history`, which returns the Session's normalized effective Policy as `compaction_policy` on current (non-`before`) reads so accessors can relate Current Context Usage to the automatic trigger (`tests/server/test_rpc_chat_history.py`). Every reported effective Policy is normalized and complete.

## Cross-Domain Contracts

- Runtime constructs one registry-backed service shared by both chat loops. Automatic Compaction runs inside the current Agentic Run; manual `/compact` starts a dedicated Session Run so admission prevents concurrent work and accessors subscribe immediately. Both emit the shared started/completed/aborted lifecycle. Manual Runs use the same native admission, completion transaction and History Run-completeness projection as Agentic Runs. Checkpoints retain their Run identity; no checkpoint-specific terminal proof is needed.
- Both paths supply the exact Session address and current prompt-cache affinity to the Engine. After selecting the Strategy's active or Summary target, the Engine obtains request-context kwargs from that target Adapter; never copy another Adapter's wire-specific context or omit it for internal Model calls. Compaction uses the pre-checkpoint affinity, and only a committed checkpoint rotates it (`compaction.py`, `run_coordination.py`; `test_chat_loop_compaction.py`, `test_opencode_go.py`).
- Auto-compaction evaluates before the first Model request (and again before a fallback target's first request), after each complete Tool batch, and for Summary+Tail after a final Assistant response. Continuation skips the final-response check because no work remains in that Run. Every decision uses the actual request target's Context Window and the shared Run-local projection: measured Provider input plus selected-wire request changes while the measurement scope matches, otherwise the target Adapter's complete request estimate. A checkpoint resets that measurement scope; manual Compaction always estimates its rebuilt request; raw records removed by a `history_edit` never re-enter a later checkpoint. Summary+Tail defers an otherwise eligible attempt when the newest unconsumed Tool batch contains a freshly loaded Skill (the next Model step must receive that Result first), re-evaluating after the consuming Assistant boundary.
- Chat's `CompactionRunHost` materializes the exact request snapshot and adapters, prepares refreshed prompt-only inputs (full Skill rescan, catalog + seen-Skill set replacement, Working Project rebuild, Config Agent body refresh - while Model target, Connection, Tool policy, Agent identity, working Project identity, and cwd stay Run-stable), closes adapters, builds and counts the projected request, commits the checkpoint with its epoch, and rebuilds after stale results. Compaction coordinates the Strategy call, stamps and conditionally persists the checkpoint, and emits lifecycle completion.
- Manual attempts load one complete snapshot and its cursor under the Session write lock. Automatic attempts never reload complete history: they bring the Run snapshot current with a delta read under that lock and compact its active lineage (`test_automatic_compaction_boundaries_never_reload_complete_history`, `test_edit_run_compacts_only_its_edited_lineage`). Both plan and call Models outside the lock, then re-acquire it briefly for `ChatSession.commit_compaction` (`commit_compaction_async`): one write transaction verifies that the cursor is still current (same generation, history floor, next sequence and newest entry id), appends the checkpoint, writes its `PromptEpoch` (the refreshed prompt pins and seen-Skill set), rotates the prompt-cache affinity id, and returns the delta the automatic Run snapshot advances by. A stale result writes nothing and aborts without a checkpoint or prompt-epoch change; automatic attempts rebuild request state, while manual Runs fail with retry guidance. Concurrent notes remain available. Projected-request failure likewise aborts.
- Automatic checkpoints must reclaim >=4,096 estimated tokens; no per-Run limit - every later safe boundary re-evaluates trigger and usefulness rules. The new-context check runs before any Model call: Summary+Tail needs a non-summary Head; Continuation needs non-checkpoint content added since the latest checkpoint whose estimate reaches that floor (the new summary is assumed no smaller than the one it replaces), so fixed overhead above the trigger never causes a paid Continuation call per boundary (`test_continuation_skips_model_call_without_reclaimable_new_context`). A checkpoint before the first Model request or after a Tool batch is inserted before the next Model step and the Agentic Run continues from it; a Summary+Tail checkpoint after the final Assistant response affects only the next Run, and Stop during that attempt aborts only the Compaction (`chat/run-execution.md` -> Cancellation). Manual `/compact` performs no follow-up Agent Model call.
- Each automatic attempt and each manual Compaction Run is measured as `chat.compaction` on the Session's performance Track with a `trigger` arg (`performance.md`).
- Sessions persists checkpoints plus the optional `compaction_policy` metadata override (each evaluation reads only that value through `metadata_value`); Settings/Agents/Projects validate the same shape as nullable inheritance overrides; server exposes both override and effective values in listings, WebUI edits all scopes.

## Invariants & Gotchas

- Manual `/compact` runs the selected Strategy as the primary active Run and refuses while another Run is active.
- The Chat context-card action requests Compaction inside the exact active Run. It bypasses automatic enablement and token thresholds only; the configured Strategy, complete Tool-cycle boundaries, fresh-Skill deferral, new-context check, minimum reclaim, and cursor validation remain unchanged. Requests coalesce while pending/running; a terminal Run cannot carry a request into its successor. Started/completed/aborted events identify user-requested attempts, including a request that cannot run before completion (`core/compaction/run_coordination.py`, `tests/core/chat/test_chat_loop_compaction.py`).
- Automatic Summary+Tail never re-summarizes only its own previous Summary; it advances within long turns once older cycles move to Head, always governed by threshold/usefulness/reclaim floor.
- If the latest User is before the Tail cutoff, the checkpoint carries its exact canonical JSON in a historical-quote note adjacent to the summary. Angle brackets are escaped at that boundary, preserving decoded content, attribution, and timestamp without allowing quoted reminder delimiters. The summary explains the User's reference and agreed work from the preceding context. Later compactions carry this one quote from the effective checkpoint until a newer User replaces it; a User already in the native Tail needs no duplicate quote. Quote-only history does not count as new compactable work; hidden canonical history is never reopened to reconstruct the quote (`test_historical_user_quote_survives_repeated_compaction`, `test_user_quote_escapes_reminder_delimiters_and_is_replaced_by_newer_user`).
- Model-backed Compaction requires an explicit successful `stop`, non-empty summary text, and no Tool attempts. Truncated, filtered, unsuccessful, unknown, or missing stream finishes abort without a checkpoint; both strategies use this same acceptance boundary.
- Compaction streams use the shared 180-second transport and 900-second Model-progress guards, including local routes. Heartbeats reset only the transport clock. A stalled attempt closes its iterator and cannot produce a checkpoint. A failed automatic attempt or post-compaction request projection never defers the next evaluation: retrying is the only path out of an oversized Context, so every eligible boundary (before a request, after each complete Tool batch) evaluates trigger and usefulness again from scratch. Chat can continue with its existing request state meanwhile. Coverage: `test_compaction_stalled_stream_is_bounded_and_closed` and `test_failed_auto_compaction_retries_at_the_next_boundary`.
- Failed automatic Compaction settles its started row as a visible warning and leaves the Agentic Run untouched; stale-context and insufficient-reclaim skips remove their placeholder. Failure warnings are transient Run events, not persisted checkpoints; failed/cancelled manual Compaction terminates its dedicated Run accordingly - neither path appends a checkpoint nor activates `history`.
- Skill activation state changes only on successful checkpoint append - failed/stale/insufficient attempts retain dedup state and environment grants exactly.
- Temporary Agents refresh from their admitted immutable configuration, never the Identity/Team resolver, and rescan Skills without a private Identity scope. Their Working Project Context pins and refreshes like ordinary Sessions, including temporary self-delegation. Applying a committed refresh replaces SOUL and Memory in the active Run as well as the persisted prompt pins (`core/chat/compaction_host.py`, `tests/core/chat/test_chat_loop_compaction_prompt_epoch.py`).
- Prompt-refresh inputs prepare before persistence (stored after-count covers the request actually used). Their pins and seen-Skill set commit in the checkpoint's transaction, so no checkpoint exists without its epoch pins; a failed refresh preparation still commits the checkpoint and affinity rotation with the previous pins and seen Skills.
- App code knows only projected checkpoints: there is no `tail_boundary_id` field, boundary-based reader, or retired Tail-guidance note. The Generation 1 Session converter (`scripts/converters/persistence_generation_1/sessions.py`) materializes old boundary checkpoints into Projections and drops the retired Tail-guidance note from old Projections. The removed flat Policy shape has no compatibility parser.

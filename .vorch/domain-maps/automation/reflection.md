# Reflection

Read when changing Reflection reviews: the review briefs, Tool gating, the shared review orchestration, the cadence trigger and its counters, manual `/reflect`, and attribution. The boundary and the invariants are in `../automation.md` -> Reflection; the outcome and undo of a review in `learning-changes.md`.

`ReflectionService` exposes `run_review(...)` and the cadence trigger:

The bundled review briefs classify candidates before authoring: durable facts go
to Memory, supported reusable procedures to Skills, and already captured or
low-value material needs no write. A missing write capability never changes the
candidate's destination. Candidates are checked against current Tool reads rather
than inherited prompt snapshots; Skill maintenance replaces obsolete guidance in
the affected passage. These are Model instructions, not semantic runtime guards.
The briefs are assembled per scope from shared fragments by `core/prompts/briefs.py`
(`reflection_brief`; see `prompts/learning-briefs.md`), so shared guidance exists once.
`tests/core/automation/test_reflection.py` checks brief delivery, dispatch scope,
and that each production brief names exactly its scope's Tools.

- **Tool gating:** a review dimension exists only while the effective Agent (Project ceilings and Tool Access Policy denials applied, via `resolve_tool_access`) can call all of its Tools: Memory needs `memory`, Skills need `skill` and `skill_manage`. `available_review_scope(agent, requested)` narrows a requested scope to the callable dimensions (`combined` -> `memory` or `skill`) or returns `None`; it resolves in memory, so `/reflect` calls it on the Event Loop as its pre-check.
- **Shared review orchestration:** requires an Identity Agent and a callable requested scope - otherwise `ReflectionUnavailableError` before forking; `ReflectionResult.scope` names the scope actually reviewed. Assembles the scope's brief (user focus appended) and reads only the source title (`metadata_value_async`) off the Event Loop, then forks same-Agent (always-strip keys applied, pinned Skill catalog kept) with the Agent-display-name title and the scope-specific Run kind committed in the fork's one write transaction, and starts an internal Run in the fork whose admission carries the source Session id. Scope selects brief + dispatch boundary: `memory` -> memory brief with only `memory`; `skill` -> skill brief with `skill`+`skill_manage`; `combined` -> combined brief with all three (briefs: `core/prompts/briefs.py`, wording rows in `prompts/agent-facing-text.md`). No Run-local Tool grant - fork keeps source definitions and prompt unchanged; each brief names the scope's Tools. Both the static restriction and the live denial resolver also permit `load_tools`, whose handler loads only definitions allowed by that same scope (`ToolContext.can_call`); it grants no extra capability. The Run's denial resolver answers any other call with `REVIEW_TOOL_DENIAL_MESSAGE` (denied Tool and the permitted Tools, including the loader, by Model name, "Do not retry this call."). `test_review_run_names_and_reaches_only_the_tools_of_its_scope` verifies loading and execution through Chat for all three scopes, including denied Tools. The Run has no limit of its own: like every Run of the Agent and like a Librarian pass, it runs under Chat's per-Run iteration limit `MAX_TOOL_ITERATIONS` (`chat/run-execution.md`; user decision 2026-10-03). The review is a real Run (admission, cancellation, viewing, history, traces) but produces no attention status; the source Session is untouched. After the review the fork stays a live, Recall-hidden Session that holds the review's result (`reflection_runs`, the Activity panel) and follows its source as a review fork (`sessions.md` -> Terms -> Review fork): archiving, deleting or purging the source takes it along, and while its review runs the archive service refuses to archive the source, so `session.delete` too (`archive.md` -> Interfaces).
- **Cadence trigger** is notified by Chat through the Run completion observer, after terminal persistence and before terminal publication. It uses the settled outcome, so a failed terminal commit cannot count as successful work. The review fork therefore includes the completed Run and its Compaction checkpoints even when Adapter cleanup suspended. The notification is non-blocking, and its Settings read and counter write run on the bounded `reflection` worker pool, never on the Event Loop: internal Runs, empty workspaces, Agents with no callable dimension, Sub-Agent Sessions and Ephemeral Sessions (GLOSSARY -> Ephemeral Session) never count; an uncallable dimension is neither counted nor reset nor reviewed (its counter stays frozen). Each completed visible Run (and each user-cancelled one with >=1 completed Model step) increments counters in canonical Session metadata; a dispatched memory call resets the Memory counter even if the Run later fails; iteration counting uses Chat's canonical count, never derived from messages. Run-end counter advancement preserves notification order, so an earlier Tool reset cannot erase activity from a later Run. Settings read live per boundary; at interval one scoped review fires (both due -> combined). Counts consume only on successful completion - failed reviews stay due; one review at a time per Agent; due Sessions during a review keep counters for next end. While a Librarian pass of the Agent runs (`librarian_running`, wired to `LibrarianService.running`), the Skill dimension is not due: a due Memory dimension is reviewed alone, and the Skill counts stay due for the first Run end after the pass, because both would change the same Skills from texts each read earlier. In turn a pass does not start while an automatic review or a manual Skill review of the Agent is starting or running (`ReflectionService.reviewing`, from the trigger's per-Agent guard; the review Run itself also counts as Agent activity). A manual `/reflect` that includes Skills reserves the Agent's learning state before waiting for an existing Librarian pass, then reviews the full requested scope from current reads. Another pass cannot start during that reservation; concurrent Skill reviews serialize per Agent. Memory-only manual reviews do not wait. Cancelling a review waiting for a pass releases its reservation without cancelling the pass or creating a fork. After its Run starts, cancellation explicitly stops and drains that Run before releasing the reservation, even through repeated cancellation; service close records the shutdown reason. The review being internal never re-triggers accounting; forks strip counters and restart at zero. A review that narrowed when it started (Tool access changed after the Run end) consumes only the dimensions it reviewed; one refused with `ReflectionUnavailableError` logs a DEBUG skip and keeps the counts due. A background review logs one INFO outcome line (Agent, source Session, fork, scope, reviewed turns and iterations) or a WARNING on failure; its closing summary is Model output and never enters the log (`test_reflection.py`).
- Manual `/reflect` snapshots the source counters at its fork and consumes only the dimensions actually reviewed after success. Activity recorded while the review runs remains due. Tool resets and successful reviews advance the counter generation, so overlapping reviews cannot consume the same activity twice; a stale snapshot leaves the current counters unchanged. `aclose()` rejects later notifications and clears per-Agent guards.
- Attribution: the server event bridge stamps the review Run's `source_session_id` onto its payloads (`server/events-and-reconnect.md`); background forks appear in the drawer on next load; manual reviews report via the command change observer projected to `resource_changed(sessions)`. Automation and Chat never import the server event bus.

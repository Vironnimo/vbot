# Models

`core/models/` owns the Model DB: layered on-disk model facts, the **at-load assembly** turning them into effective models, the registry read path, and the typed model contract runtime and accessors consume. A loaded model is always a model at one provider; the canonical id (`lab/model`) is an internal join key used only during assembly - it never goes on the wire.

## Overview - two times, one rule

The system splits cleanly into two moments:

- **Refresh** (`discovery.py` + `models_dev.py`) - the DUMB half. Fetches provider `/models`, the public models.dev `catalog.json`, and any adapter-declared task-capability catalog, projecting results to disk per file - no cross-file merges, no provider joins. Needs network plus a credential for provider catalogs; rare and explicit. Normal `model.refresh_db` starts from a complete copy of the active DB and atomically publishes under `<data_dir>/artifacts/models/`; `scripts/refresh_model_db.py` is the maintainer-only path publishing the same shape to `resources/models/`. Where a `/models` endpoint omits facts, refresh fills them from that provider's own models.dev section ("fill, don't overwrite"); advertised-but-unusable ids drop via `ProviderConfig.catalog_exclusions`. Per-model enrichment (`enrich_discovered_models`, e.g. Ollama `POST /api/show`) and task-capability catalogs (e.g. OpenRouter image/video APIs) are adapter-declared hooks merging typed facts after normalization; failures degrade per model/catalog, never failing the refresh.
- **Load** (`assembly.py` behind `ModelRegistry.load`) - the SMART half. Selects the newer schema-compatible generated root by manifest, then assembles each effective model in memory from generated data plus current bundled Overrides, resolving the canonical join and field-level merge, finally overlaying normalized manual Custom Provider models. No network, no key, frequent. Invalid layer files or individual records log-and-omit independently; a missing runtime manifest falls back to system.

The rule tying them: **Refresh publishes one complete snapshot; Load selects one generated catalog and applies current bundled Overrides.** Overrides apply at Load, never baked into generated files; generated files are not a manual edit surface, while bundled `resources/models/*.overrides.json` files are the hand-correction surface discovered by filename without registration.

## Terms

Domain vocabulary. Core terms (Provider, Model, Reasoning) live in `.vorch/GLOSSARY.md`.

### Canonical id
**Definition:** A models.dev-style `lab/model` identifier naming a model independent of any provider - purely an internal join/DB key during assembly, **never sent on the wire**. A provider model reaches its canonical base via explicit `canonical` pointer or exact wire-id match; resolution is deterministic only.
**Not:** The wire model-id. A missed join is not an error - the model runs on provider + override data.

### Refresh
**Definition:** The DUMB half: fetch feeds, project per file inside an isolated complete copy, publish atomically after validation. Network + credential; rare and explicit.
**Not:** Load. Refresh writes disk from the network; Load selects and assembles without fetching.

### Load
**Definition:** The SMART half (`ModelRegistry.load`): select newer compatible root, assemble canonical/provider projections with current Overrides in memory. No network, frequent (startup, cache invalidation).
**Not:** Refresh, or mixing generated files across roots.

### Reasoning control
**Definition:** How a provider steers reasoning on the wire - `levels` (effort ladder), `on_off` (toggle), or `budget` (token budget with max); derived at refresh from models.dev `reasoning_options` into `capabilities.reasoning.control`.
**Not:** The agent's `thinking_effort` setting - control is the capability, effort snaps against the ladder at request time (wiring in `providers/request-policy.md`).

## Complete Model DB snapshots

The complete refresh on 2026-10-02 updated eight reachable Providers (823 Model records) and the public models.dev mirror. `lmstudio:local` and `ollama:local` were unreachable, so their previous records were retained; Providers without usable authenticated discovery also retain their previous snapshot. GPT-6.1 Sol is exposed through OpenAI API-key/subscription, both Zen Connections, and OpenRouter. Its exact wire/control/replay evidence is in `providers/openai.md`, `providers/opencode-zen.md`, and `providers/openrouter.md`. Zen also admits Claude Sonnet 5.5 on Messages and excludes the live-rejected Fledge free route. Six Go ids reappeared and their verified profiles were restored or supplied; the current endpoint matrix covers all 36 Go ids (`providers/opencode-go.md`). Generated catalogs, canonical facts, pricing, and the manifest form one complete tracked snapshot. Refresh keeps no raw response dumps; nothing read them.

The manual refresh RPC reads the configured bundled root from `runtime.storage.resources_dir`, the same StorageManager initialized at Runtime startup. Do not probe Runtime-private path resolvers; regression coverage exercises both refresh targets against a started Runtime with a custom resources path (`tests/server/rpc/test_model_methods_refresh.py`).

System root is the tracked `resources/models/`; runtime root is `<data_dir>/artifacts/models/`. Each snapshot holds generated catalogs, a bundled Override snapshot, plus `manifest.json` (`schema_version`, UTC `refreshed_at`, source). Staging leaves out the legacy `*.raw.json` dumps older refreshes wrote, so a refreshed root drops them; Load ignores any that remain. Load compares manifests and picks the newer entire root (system wins ties; incompatible/missing runtime manifest falls back to system), then applies current bundled Overrides so an older runtime snapshot cannot hide update changes. Manual and automatic refreshes in one Runtime share ProviderRuntime admission before copying the active snapshot through publication and reload (see `providers/catalog-discovery.md`). Both refresh targets stage and validate before atomic directory replacement - a failed fetch/publish leaves the previous root intact. Staged validation (`ModelRegistry.validate`) collects what Load would ignore without logging it; the live reload after publication logs each ignored entry once, and `model.refresh_db` reports their number as `invalid_entry_count` (result only when non-zero, always in its completion log line). Runtime refresh starts from the active snapshot and replaces staged overrides with the complete current bundled set before discovery writes, preserving additions and removing deletions. `model.refresh_db` with `target: system` writes the shipped root, so it skips Custom Providers (they exist only in this installation's Settings) and refuses one named as `provider_id`; a runtime refresh covers them. A runtime refresh also drops each staged generated `<provider>.json` whose Provider no longer exists (neither in the Provider registry nor among the Settings Custom Providers), such as a deleted Custom Provider's catalog; a catalog file the system root ships is always kept (`begin_runtime_model_database_refresh(provider_ids=...)`). The manual refresh reloads the live registry with `reload_async`; staging copy, validation, and commit still run on the Event Loop.

## The three layers

| Layer | Files | Keyed by | Written by | Holds |
|---|---|---|---|---|
| Canonical | selected-root `models.json` + bundled `models.overrides.json` | canonical id | Refresh / hand | provider-agnostic base: `name`, `family`, `capabilities`, `context_window`, `max_output_tokens`. **No `provider_id`.** |
| Provider | selected-root `<provider>.json` + bundled `<provider>.overrides.json` | wire-id | Refresh / hand | what the provider reports, incl. deviating reasoning ladders, optional `canonical` pointer, wire `metadata` |
| Adapter fallbacks | adapter code | - | - | send-time defaults |

Both canonical inputs may be absent - assembly runs on Provider + Override alone. The `canonical` JSON key is an internal join key: stripped from assembled records, never a `Model` attribute.

## At-load assembly

`ModelRegistry.load` is the single public read surface; everything in `assembly.py` hides behind it (its module docstring is the file-format source of truth).

**The deterministic join** (`resolve_canonical_id`, no fuzzy matching ever): explicit `canonical` pointer wins (manual beats auto); else exact wire-id-in-canonical-keys match; else no join - enrichment, not dependency.

**The merge** (`merge_layers`, "fill, don't overwrite", highest layer wins per field): override > provider > canonical. `capabilities` merges **one level deep** (per sub-field). Inside `capabilities.reasoning` the control description (`supported`, `control`, `levels`, `budget_max`) is **one unit** from the highest layer defining any of those keys - a ladder never mixes layers, and a higher `{"supported": true}` does not inherit a lower ladder - while every other reasoning fact (`mandatory`) merges per field. `metadata` merges **per Provider key, then per field**, so an override states only the fields it corrects. Every other nested object/list (modality lists, `pricing`, `connections`, `task_options`, a metadata field's value) replaces wholesale. A `null` never counts as defining a field at any level, so it cannot un-fill lower layers. Records failing required fields (`name`, `capabilities` with `vision`, `tools`, `json_mode` and `reasoning.supported`) omit individually without hiding siblings or aborting startup; the warning names the missing field path (`missing required field 'capabilities'`). The offline validator (`scripts/validate_model_db.py`) reports dead pointers and redundant manual joins - not part of the read path.

## Typed reasoning

`capabilities.reasoning` is typed: `supported` (the load-bearing flag), `control` (`levels`/`on_off`/`budget`), `levels`, `budget_max`, and `mandatory` (the Provider always reasons and rejects disabling it; default `false`, only valid with `supported: true` - a non-boolean or unsupported `mandatory` is reported and ignored). Derived at refresh from `reasoning_options` - effort option wins over budget over toggle; the canonical ladder lifts from the lab provider only, never unioned across providers; a deviating provider gets its ladder stamped on its provider file while a conforming one inherits canonically. At a canonical join without deviation, refresh keeps an Adapter-reported control description (one with a `control`, e.g. Anthropic's live capability tree) and drops only a bare `supported` flag: sparse Adapters default that flag when the endpoint is silent, so it must not shadow the canonical ladder. Adapter facts outside the control description (`mandatory`, from OpenRouter's `reasoning.mandatory`) survive in every case. The wire profile's catalog layer reads `mandatory` from the capability (`core/providers/wire_profiles.py`); request-time wiring turns `(control, thinking_effort)` into a neutral intent each adapter renders - full wiring in `providers/request-policy.md`.

## Wire selectors and context windows

Per-model wire **facts** live in the Provider-scoped `metadata` blob keyed by underscored provider id (e.g. `metadata.opencode_go.protocol`); replay *scope* is the cross-provider exception configured through overrides (`Model.reasoning_replay`, root provider override) with precedence owned by `providers.md`. `metadata` is frozen after load and limited to wire facts - never payloads, policies, or secrets.

`context_window`/`max_output_tokens` are `int | None`: absent means honestly unknown, never faked. `connection_context_windows` is the optional per-Connection exception when one wire exposes a different Context limit for the same Provider Model id; `Model.context_window_for(connection_id)` returns that exact value or the Model-wide fallback. Chat resolves it from the Connection actually selected for the Run, and Adapters with Connection-dependent output budgeting use the same value. Other readers resolve through the shared chain `resolve_context_window(model value -> provider-config default -> global floor)` living at Provider-config level; non-positive values count as unknown. Flagged-local models (`metadata.<provider>.local`) resolve through `resolve_effective_context_window`: user setting from `local_models.context_windows`, else capped at `LOCAL_CONTEXT_DEFAULT_CAP` - a local endpoint reports theoretical max, not hardware reality; enforced on the wire (Ollama `num_ctx`), in compaction budgets, `/status`, and picker filtering. Connections with `auto_refresh: true` get a throttled background sweep republishing without models.dev fetches, recording reachability (semantics in `providers/catalog-discovery.md`). `recommended_temperature` is a vendor-documented fallback applied only when the Agent sets none, coerced to [0.0, 2.0].

Request building requires the live `Runtime.local_context_windows` getter through `ChatLoopDependencies`. Settings-read recovery belongs to `core/providers/runtime.py::ProviderRuntime`: it logs `StorageError` and returns an empty override map. Request building lets unexpected getter errors propagate instead of silently using default limits.

## Token pricing

`Model.pricing` is optional immutable `TokenPricing` owned by `core/models/pricing.py`. The refresh projection retains USD-per-million input/output/cache-read/cache-write/Reasoning rates with an exact `models.dev:<provider>/<wire-id>` source. Provider rates override the canonical lab price through existing layer assembly; there is no fuzzy name matching. The public-catalog refresh also reprices existing Provider entries without requiring their discovery credentials. A Provider Adapter may instead project a price from its own catalog with a `<provider>:<wire-id>` source - today only OpenRouter embedding Models, from `pricing.prompt`, because models.dev's OpenRouter section lists no embedding Models. Such a price wins: discovery does not replace it with the models.dev price, and the public-catalog repricing skips it. Overrides remain the final hand layer. `ModelRegistry.pricing_for(bare_or_qualified_reference)` returns the effective exact price or None.

Pricing selects Context tiers from the complete input of each request (including cache); explicit `tiers` take precedence over legacy `context_over_200k`. Cache reads/writes are removed from ordinary input before applying their rates. Reasoning is already in output and is split only when a distinct rate exists. Zero is a valid price, absent used bucket rates are unknown, and unsupported tier shapes are not silently treated as flat pricing. A finite Provider-reported amount wins over estimation. Prices value API usage; they do not establish actual subscription charges. Chat and Compaction snapshot this result in canonical Usage; historical aggregation and coverage belong to `statistics.md`.

## Interfaces

- Frozen dataclasses (`Model`, `Capabilities`, `ReasoningCapabilities`); `Capabilities.task_options` holds typed task option specs merged one level deep like other capabilities sub-fields, consumed by `model_tasks.md` option builders. Parameter spec types: `enum`, `range`, `boolean`, and `model` (a tool-capable chat Model of the same Provider on the selected Connection); a spec may carry an optional `default`.
- `Model.model_id` is the exact wire string - no remapping anywhere. `Model.connections` binds a model to a subset of connection ids (empty = all); `allows_connection(id)` is the single source read by target expansion, `model.list`, the Extension host `catalog()`, WebUI filtering, and save guards. `Model.connection_context_windows` is a frozen positive-int map for the rare case where those allowed Connections expose different Context limits.
- `ModelRegistry.load/reload` select one root, assemble with overrides, overlay Custom Provider models (a manual Custom Model wins same-id collisions). **Reload updates in place** so services holding the registry see refreshed catalogs without restart - do **not** rebind `runtime._models` to a fresh `load()`; that rebind was the bug (chat fresh, specialized targets stale). `reload_async` is the Event-Loop-safe variant: it assembles on the `model-registry` worker pool and swaps the contents on the calling loop, so loop readers never see a half-replaced registry. Both reload paths share one generation guard: once a newer reload begins, an older in-flight assembly cannot publish its catalog, replay policy, active root or cache entry. Readers retain the last published state until the newest reload succeeds. Both return whether the swap changed the assembled catalog (`False` for an identical or superseded reload); the local catalog sweep signals Model changes only on `True` (`providers/catalog-discovery.md`).
- `query(model_query)` is the pure filtered read path; credential gating happens outside it (RPC `model.list`, task-target discovery). `get(provider, model)` raises on unknown pairs; `list_for_provider` sorts ascending.
- `model.list` and `model.get` (`server/rpc/model_methods.py`, mappers in `payloads.py`) add `wire_profiles`, keyed by local Connection id over the Model's usable allowed Connections: `{wire_status: verified|configured|inferred, verified_at: <date>|null}`. `model.list` reads the cheap `Runtime.wire_status` (about 2 ms added for the ~875 Model x Connection targets of the bundled catalog); `model.get` resolves `Runtime.wire_profile` and adds `protocol`, `reasoning_dialect`, `reasoning_ladder`, `replay_fidelity` and `learned` (`reasoning_field`, `rejected_parameters`, `rejected_efforts`, `reasoning_returned` from `Runtime.learned_wire_facts`) - facts about fields and values, never request or response content. The WebUI's "verified" picker marker reads the `model.list` statuses (`webui/source-map.md` -> Shared dropdowns).
- Bundled-only registries cache by database locations; supplying `custom_providers` always returns an isolated registry instead of touching the shared cache.

## Capabilities & Tasks

Capabilities are facts about one model through one provider. `task_types` derives from modalities for coarse routing; sparse catalogs default text-in/text-out so conservative providers stay selectable. Speech/audio aliases are intentionally strict: `transcription` -> text+STT, `speech` -> TTS+audio-generation, generic `audio` -> `audio_generation` only (never `text_to_speech`), `embeddings` -> `text_embedding` (Provider catalogs that identify embedding Models normalize them through `text_embedding_capabilities()`, so they derive no chat task; per-Provider facts in `providers/catalog-discovery.md`). `live_voice` is explicit-only: no modality combination derives it, so voice Models declare it in `task_types` through overrides.

`capabilities.unlisted_tool_calls` (default `true` when absent) says whether the route returns calls to Tool names that are not in the request's `tools[]`, such as Tools a System Reminder announced; for a route with `false` Chat also lists every announced Tool in `tools[]` (`chat/request-building.md` -> Tool catalog per prompt epoch). It is a generic route capability (any gateway or constrained-decoding backend can drop calls to names outside `tools[]`), not a one-Provider protocol quirk; Model data is keyed by exactly the Provider/Model entry where it was observed. Set `false` only in the override of an entry with dated evidence: currently OpenCode Go `glm-5.3-flash` (`providers/opencode-go.md` -> Tools announced outside `tools[]`); the same Model on Ollama Cloud keeps the default.

## Constraints & Gotchas

- **Code wins** - `assembly.py`'s module docstring is the load contract; fix this map when they disagree.
- **Refresh is dumb, Load is smart** - never push merge/join logic into Refresh, never make Load fetch.
- The full canonical mirror is intentionally unfiltered; do not add discovery defaults.
- `metadata` merges per Provider key and field, so an override cannot delete a generated field (a `null` never erases); set an explicit value instead. Bundled overrides written under the old wholesale rule still repeat generated fields; those repeats are now redundant.
- `MODEL_DATABASE_SCHEMA_VERSION` (`core/models/database.py`, mirrored in the bundled `manifest.json`) changes when Load starts reading a fact older generated roots lack - no fallback branch reads an old field. An incompatible runtime root is ignored in favor of the system root (v2: `capabilities.reasoning.mandatory`): catalogs that only that runtime root held - Custom Provider discovery, catalogs refreshed with this installation's credentials - are absent until the next refresh, which starts from the system root; `auto_refresh` Connections return with their first sweep.
- A bundled generated `<provider>.json` can be a hand-curated discovery seed (`nous.json`): it stands in for authenticated discovery until a refresh replaces it per Connection. Durable hand facts belong in overrides, but an Override entry always creates its Model, so a Provider whose Model availability depends on the account keeps its seed in the generated layer (`providers/nous.md`). A Provider whose allowlist is fixed in code keeps its hand catalog in overrides (`stepfun.overrides.json`, `providers/stepfun.md`).
- Override-only models/providers load without a generated Provider entry when assembly supplies `name` and `capabilities.reasoning.supported`, directly or through a canonical join. A pin-only entry can therefore load through its canonical base; records still missing required fields are omitted with an "Ignoring invalid Model DB model ..." warning (like every Model DB issue Load reports, logged once per process per distinct message, not on every reload) that marks an entry without a generated Provider entry as Override-only - typically a Model the Provider catalog no longer lists, whose stale Override should be removed. Keep overrides minimal instead of duplicating inherited fields. Evidence: `core/models/models.py` unions Provider/Override ids before assembly; `tests/core/models/test_models.py` covers override-only models/providers.
- Models are immutable after load - change layer files, then invalidate/reload; never mutate a loaded `Model`.

The output modality `decisions` derives only the `decision` task type. It does not make a Model eligible for Chat. OpenRouter discovery fetches this modality separately; both the pinned Jev id and latest alias remain literal Provider wire ids (`model_tasks/decisions.md`).

# Skill Authoring

Write mechanics of `SkillAuthoringService` (`core/skills/authoring.py`), the one validated write core, and the `skill.*` write RPCs that call it. The core rule and the write scopes: `skills.md` -> Authoring & Write Scope; writers, revisions, archive and pins: `skills/history.md`; the Agent Tool: `skills/skill-manage.md`.

## Write core

`SkillAuthoringService` operates on an already-resolved target root with direct install/create/edit/rewrite/delete/write_file/remove_file/publish methods plus `read_text`; each success publishes immediately. The same owner serves `history`, `recorded_revisions`, `records`/`record`, `check_revert`/`revert`, `archived`/`archived_skill`, `restore`, `purge` and `set_pinned` (`skills/history.md`). Install prepares a complete package, preserves original file bytes and frontmatter, and publishes it through the same write lock; it neither executes package contents nor changes access policy. Create/edit/SKILL.md rewrites reuse the loader's lenient document parsing and canonicalize complete YAML frontmatter, stamping `author` (`human` for a person, `agent` for every Agent writer) plus optional `source` under `metadata.vbot` and writing atomically; a missing name fills from the trigger-safe directory name and an explicit different name is rejected. Support-file authoring still accepts UTF-8 only, confined to `scripts/`/`references/`/`assets/`. `create` refuses a Skill name, and `write_file` a new support file or folder name, that Windows reserves (`core.utils.ids.is_reserved_name`: devices such as `con` or `nul.py`, `:`, a trailing dot or space) on every platform; replacing an existing file keeps working. `exclusive()` holds that write lock across several calls, for a caller whose check and write must see the same Skills (`skill_manage` checks, Librarian aging). `rewrite(target_root, name, relative_path, edit)` is the validated read-modify-write primitive: under the write lock it hands `edit` the current `SKILL.md` or support-file text with LF endings, aborts without writing when `edit` raises, validates a rewritten `SKILL.md` like edit, and writes in the file's detected line-ending style. Text matching is not authoring policy: the `skill_manage` Tool owns it (`skills/skill-manage.md` -> Calls). create writes LF; edit/rewrite/write_file preserve an existing file's line endings. edit and write_file replace a file whole, so they also replace an existing file that is not UTF-8 text (written with LF, reported with `before: None`); rewrite refuses it. A written `SKILL.md` gets its front matter re-serialized with the provenance stamp, one line per scalar (no YAML folding), so an Agent's following `patch` copied from its own front matter lines still matches. Every path stays under the target root; protected bundled roots are refused. Folder and Extension packages are never write targets: customizing one means copying it into `<data_dir>/skills`. Failures raise `SkillAuthoringError` with surface-neutral diagnostics. Each result reports the files it changed (`SkillWriteResult.changes`: package-relative path, `created`/`updated`/`deleted`, text with LF endings before and after, `None` for an absent side or text that is not UTF-8 or exceeds 1 MiB); delete moves the package into the Skill Archive and reports every regular file of the package as deleted, root `SKILL.md` first; a link inside it (Windows junctions included) moves as a link, and the files behind it are neither reported nor read.

Mutating an existing package requires its `SKILL.md`, including delete and support-file operations. Package directories, the entry document and support-file path components reject symlink/junction redirects before resolution (other reparse points, such as OneDrive cloud-file placeholders, are ordinary files), so aliases cannot bypass document validation or target a different named package. Installation reuses this authoring boundary (`tests/core/skills/test_authoring.py`).

## Shared-owner invalidation

`SkillRuntime.invalidate_agent_skills(owner_id)` owns the dependency from a private home to its shared receivers and invalidates their cached registries across every Project context. Tool and Accessor writes identify the owner without duplicating that dependency. This includes creating, changing or deleting a package named by an existing share, and archiving or renaming the owning Agent; unrelated Agent caches remain intact (`test_runtime_shared_skills.py`).

## RPC and user Accessors

`skill.read/create/update/delete/write_file/remove_file` scoped `global` or `agent:<id>`, writer `HUMAN_WRITER`; Project/repo scopes reject. `skill.delete` archives and returns the `archive_id`; write responses carry the recorded `revision`. The same scopes serve `skill.history`, `skill.revert`, `skill.archived`, `skill.restore`, `skill.purge` and `skill.set_pinned` (`skills/history.md` -> Surfaces). Global writes reload skills, Agent writes invalidate that agent's registry. The Agent-scope id validates traversal-safe and must name an **existing Identity Agent** - unknown ids reject with `agent_not_found` rather than creating unowned homes.

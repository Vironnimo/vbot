# Temporary files

Filenames and the cleanup sweep of `TemporaryFileManager` (`core/storage/temp_files.py`, `test_temp_files.py`). Categories, retention and leases are in `../storage.md` -> Temporary files.

- New retained filenames use `tmp_` plus 12 lowercase base32 characters and the owner-selected suffix; exclusive file creation retries collisions without truncating existing logs.
- With a running Event Loop every sweep, the first included, runs on the `temporary-files` worker pool, never on the loop (a sweep lists every retained file, more than ten thousand command logs on a busy install); a start without a loop sweeps once inline.
- A sweep refuses links or junctions at `artifacts/`, `temp/` or a category, reads type and modification time from the directory listing (`os.scandir`: no per-file system call on Windows, one stat elsewhere) and confirms each expired regular file with a fresh unfollowed stat before removing it, because listing data can lag behind a file still open elsewhere; links and junctions are never deletion candidates.
- Native Provider transports lease an owner-only `providers/work_<id>/` tree for isolated configuration, history and Tool inventory. A live OS lock keeps even another manager's sweep from removing a live profile. The Provider releases the directory after an isolated turn or when its reusable conversation profile closes. Releasing it removes the entire tree. The sweep reclaims expired orphan work directories without following links inside them.
- The final lease check and removal share the manager lock with `reopen`, including its file recreation, so a producer that reactivates an expired file during a sweep keeps its active file.
- Each successful reopen adds one lease. Retention begins after the last lease finishes, and a failed reopen preserves existing protection. If the file timestamp cannot be written at completion, the manager remembers the time for the retention interval and retries the write before any earlier cleanup.
- A restricted Terminal logs in a launch-scope group inside the Session's owner folder in `terminals`. The group name addresses a bounded record of its hashed permission layers, kept beside the group in the protected owner folder. A shared lease keeps the record alive while any log in that group is active. The sweep visits the scope groups without following links and preserves the record while any log is retained, including after a process crash drops the leases. Older logs remain in place.
- The retired `artifacts/temp/bash` folder follows the configured `commands` retention policy (72 hours by default), unless a caller supplied an explicit policy for that old category, through the same link-safe and lease-aware sweep. Default allocations use `commands`; `reopen` can still protect a surviving old log. Other retention periods and the sweep cadence stay unchanged.
- `stop` ends an in-flight sweep after its current file. `aclose` awaits the sweep even after an earlier `stop`.

# Extension Activity, Group Usage and Session Tree Usage

How Statistics attributes Extension-owned Sessions (`extension:<owner>` actors, participant slices, the report's Extension activity), how `StatisticsService.group_usage` reports one owner group, and how `statistics.session_usage` sums one Session tree.

## Extension activity

- `_extension_sessions()` turns each live owned Session into an index scope whose display key is `extension:<owner>` (Agent ids and `agent@project` never contain `:`) plus a participant slice key. Participant usage/costs use the same durable requests as global accounting; the Extension view covers retained participants, while global totals additionally retain deleted groups and group-level background requests without a participant Session.
- Report rows label these Sessions `"<group title> · <participant name>"` (`extension_session_summary`); `group_usage` indexes the same labelled summaries and Extension owner, and gives the owner's other Sessions their listed summaries (`SessionSource.summary`), so both reads never rewrite a shared index row or its stored flags. A group without a stored title reports `title: null`; the WebUI labels it by a short id, with its start time in the group's meta line.
- Windowed reports keep only groups with in-window Runs, Tool calls, Model calls or errors; all-time keeps every retained group. Runs, Tool calls and errors are each participant Session's own; requests are the ledger's associated with its exact Session generation. `overview.active_agents` excludes Extension actors; `active_sessions` includes the participant Sessions. Deleted groups (`delete_temporary_group`) leave the structural/Extension views while their durable consumption stays in usage and costs.
- Tool calls include every canonical invocation start before its Result exists. `last_activity` includes in-window Tool starts, records and Model requests, even when a later record lies outside the window.
- WebUI: `ExtensionsPanel.svelte` (Extension -> group -> participants), and `agentDisplay` renders `extension:<owner>` as the Extension name with an Extension badge in every per-agent cell. Tests: `test_statistics_extensions.py`, `StatisticsView.test.js`, `statisticsView.test.js`.

## Group usage

`StatisticsService.group_usage(owner_name, group_id, query)` (the Extension API `temporary_agents.usage` behind Swarm's `swarms.usage`) reports one owner group, optionally one participant (`query.participant_id`, the only accepted key).

Selection: canonical Sessions Run-owner records (`_owned_run_page`) list the owned Runs. The read reconciles only the owner's Sessions with their labelled summaries and never prunes normal Statistics scopes (`prune=False`). An owned Run counts only in the Session generation it was recorded in, so a reused Session is never treated as wholly owned and other Runs in it never count. `_group_usage.group_usage` joins the owned Runs (`temp.group_runs`) to `agg_runs` and `agg_run_models` by primary key; unrelated Sessions and requests are never scanned. An owned Run not yet in `agg_runs` (admitted without a subsequent Session revision change; `statistics.md` -> Run visibility) contributes nothing.

Requests are exactly the owned Runs' own: ledger requests for the Run's Session generation and Run id, including auxiliary work and failed attempts, else the usage saved in the Run's records (`statistics/reconcile-and-aggregates.md` -> Run requests). Group-level requests without Run membership stay in global accounting only. After an Agent takeover, durable attribution stays at the original address while exact generation provenance keeps those requests in their original Run totals. A public address or Run id alone never supplies that association.

Response: `{group_id, participant_id, participant_count, owned_run_count, activity, participants: [{participant_id, activity}]}`, one participant entry per participant with owned Runs, in first-seen order. An activity is `{runs: {total, <status>...}, model_steps, tool_calls, tool_rejected, tool_ms, compactions, errors, totals, models}`; `totals` has the report `Totals` shape (`statistics/report-sections.md`; token counts include their estimated parts) and `models` lists `{model, runs, ...Totals}` by cost, `model` being the `provider/model` key. The Swarm Usage page reads `activity.totals`, `activity.models` and `activity.tool_calls` (`resources/extensions/swarm/ui/pageUsage.svelte.js`, `RunUsage.svelte`).

Tests: `test_statistics_groups.py` (owned-Run selection in reused Sessions, paging, participants, unrelated Sessions untouched, incremental equals rebuilt), `test_statistics_accounting.py` (durable requests of owned Runs), `tests/core/sessions/test_sessions_owner_managed.py`, `SwarmPage.usage.test.js`.

## Session tree usage

`statistics.session_usage {agent_id, session_id}` (`session_tree_usage_async`) sums the `agg_run_models` rows of one live Session's own Runs (`session`) and of its Sub-Agents' Runs at every depth (`subagents`, Sessions from the Sub-Agent links), plus `total` and `subagent_count`, each in the report Totals shape; like group usage, requests without a Run stay in global accounting only. It reads with `prune=False` and scopes each Session as the full report does (`_session_scopes`: an Extension-owned Session keeps its owner and labelled summary), so it never shrinks the shared index or rewrites a row's flags (`test_statistics_session_usage.py`). It finds owned Sessions through each Session's `temporary_binding` and lists only those owner groups, never every owned Session (`_owned_sessions`). The Session information panel shows it (`webui/chat.md`).

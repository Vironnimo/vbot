# Skill Usage

The window-free Skill usage reads for the Librarian and the Skill manager (`skill_package_usage`) and how Skill offers and activations are counted. The report's skills section fields are in `statistics/report-sections.md`.

- `skill_package_usage[_async]` reads package-exact use over every surviving identity and Project Session of the roster Agents that counts as use (`skills.py::counts_as_skill_use`, shared with the report's skills section). A Session whose recorded `run_kinds` are all unattended contributes no use; a Project Session counts for its bare Agent id, and Extension participant Sessions are left out. The async read runs on the Statistics index pool.
- The result has one `SkillActivationUse` per qualifying Session, activation name and resolved `SkillPackageRef`, with its latest activation time. `stat_skills` stores the nullable source, package-folder name and location carried by canonical activations; historical rows stay unqualified. The report aggregates by visible Skill name. Librarian aging and package-specific manager views use exact records; they deduplicate by Session even where qualified and historical activations coexist. An Identity Agent rename retargets private-package owners in canonical entries and invalidates affected read cursors so the index rebuilds those histories. Coverage: `test_statistics_skills.py`.
- Offered filters by the offering Session's `created_at` (the seen-Skill set carries no per-Skill timestamps - deliberate approximation); conversion uses only the per-Session offered+activated intersection, staying within 0-100%. The Skill inventory is window-independent; an absent Session `created_at` remains always in-window for Skill offers.
- Sessions without a recorded seen-Skill set contribute activations but no offers - accepted lower bound, never presented as delete candidates.

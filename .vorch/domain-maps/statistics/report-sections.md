# Statistics report sections

Field-level contracts of `StatisticsService.report` sections (`core/statistics/_sections/`). The root map `statistics.md` owns the section API and the domain invariants, `statistics/reconcile-and-aggregates.md` the aggregate tier; this file owns what each section returns, the report-wide shapes, the diagnostics heuristics and which WebUI tab asks which section. The WebUI panels and `vbot statistics` read these fields, so a rename breaks both.

Report-wide rules:

- **Windows** are half-open and hour-aligned: `since` is floored and `until` ceiled to a UTC hour, and `window` echoes the effective bounds. Hour-keyed aggregates and instant-keyed facts select with the same bounds, so all sections of one report cover the same time. `previous` is the window of equal length ending at `since` (none without `since`; an open `until` ends at the end of the current hour). A Run belongs to the window it started in.
- **Series** (overview and usage `series`, runs `daily`, errors `daily`) have one point per bucket, and `window.bucket` names the bucket: `hour` for a window of at most 48 hours (an open `until` counts to the end of the current hour), else `day` (also all-time). A day point is keyed `date` and folds hours into local dates of the IANA `timezone` (`zoneinfo`, DST-correct); an hour point is keyed `hour_start`, the canonical UTC timestamp of the hour, and clients label it in their own zone. Every bucket of the window is filled with zeros; an all-time series starts at the first active hour, an open end runs to the current hour. A zone with a half-hour offset gets its day boundary at the containing UTC hour. The `daily` names stay for hour buckets too. Errors' `by_hour` uses local hours of day.
- **Money** is summed as integer nano-USD and converted to USD floats once. `null` means unknown, never 0: a cost is null when calls exist and none is priced, a Run's cost when every one of its requests is unpriced. Cost rankings put the highest known cost first, unknown cost last, then calls and key.
- **Percentiles** are nearest-rank over `agg_runs` rows (exact; durations and costs of finished Runs only) and approximate for Tools (the histogram's nearest-rank sample placed geometrically inside its bucket, clamped to the bucket and the Tool's `max_ms`).
- **Shared shapes:** `Totals` = `{calls, failed_calls, input_tokens, estimated_input_tokens, output_tokens, estimated_output_tokens, reasoning_tokens, cache_read_tokens, cache_write_tokens, unreported_calls, cost_usd, reported_cost_usd, reported_calls, estimated_cost_usd, estimated_calls, unpriced_calls, retrospective_calls, uncached_cost_usd, speed_calls, estimated_speed_calls, speed_tokens, speed_window_ms, output_tokens_per_second, speed_by_basis, first_token_calls, avg_first_token_ms, duration_calls, avg_duration_ms}`; token, cache and reasoning totals include every call, estimated parts included and an unreported counter as zero, so a hit rate is `cache_read_tokens / input_tokens`; `unreported_calls` counts requests missing either token counter (known partial counters still count in their own buckets), `failed_calls` counts ledger requests whose status is neither `completed` nor `started`, `cost_usd` = reported + estimated (disjoint calls), the reported/estimated/uncached amounts are null without a call of their source, and `avg_duration_ms` is the rounded mean ledger request duration over the `duration_calls` calls that have one (`usage.md` -> Failures), null without any. RunRow = `{agent_id, session_id, session_title, run_id, origin, status, started_at, duration_ms, cost_usd, input_tokens, output_tokens, calls, model_steps, tool_calls, iterations, primary_model, models}`. Every per-Session row (RunRow, top Session, recent call, cache rows and recent Compaction checkpoints) carries `session_title` (the current listing title, `null` when untitled) next to `agent_id`/`session_id`.
- **Output measurements:** Chat's `usage.speed` supplies `speed_by_basis`, an array of nonempty `{basis, calls, estimated_calls, tokens, window_ms, output_tokens_per_second}` groups in `output`, `answer`, `provider`, `unknown` order (`chat/usage.md` -> Output speed). Each rate is `sum(tokens) / sum(window_ms) * 1000`, rounded to one decimal; client-observed `output`/`answer` rates remain approximations even when their token counts are measured. Missing or unrecognized historical bases stay `unknown`; they are never guessed. The legacy scalar `output_tokens_per_second` is null for mixed or unknown bases, otherwise the single known basis's rate. `speed_calls` counts positive measured windows and `estimated_speed_calls` their locally estimated token counts; `first_token_calls` counts observed first-token times, including steps too short to measure throughput. `avg_first_token_ms` is their rounded mean. Coverage counts describe observed Chat measurements, not every request or user-visible answer; only Model rows keep Models separate, while Provider and other rows can mix them. `usage.totals` and every `usage.breakdowns` row additionally return `first_token_p50_ms` and `first_token_p95_ms`, exact nearest-rank percentiles over observed integer milliseconds, null without observations. Other Totals retain the mean and coverage without percentile fields.

Sections (caps and thresholds are constants in each module):

- **overview** - `totals`/`previous`, Run status counts `runs`/`previous_runs`, `user_runs`/`previous_user_runs` (`count`, duration p50/p90, cost p50/p90, `first_visible_p50_ms`), `active_agents` (actors with an in-window Run or request, without Extension actors and standalone requests), `active_sessions` (Session addresses with either), the `series` with Runs and failed Runs, `by_origin` (every in-window ledger request by its request origin, `background` included, plus the Runs started per origin), `top_agents` and `top_models` (5 by cost; models carry the cache fields), and `insights` `{id, severity, values}` emitted only when their condition holds: `uncached_value` (uncached share of estimated value >= 0.25), `cancelled_cost` (cancelled Runs >= 5% of cost), `top_runs_share` (>= 10 priced Runs and the top 10% hold >= 60%), `failed_attempt_burst` (an hour with >= 20 failed attempts), `runaway_runs` (>= 100 iterations), `tool_failure` (>= 20 calls and rejection rate >= 0.25).
- **activity** - the user's days with vBot (`_sections/activity.py`). A day is active when the user started a Run on it (origin `user` or `channel`); Runs of other origins show in the day figures but make no day active. `days` lists only days with a Run or request, ascending, each `{date, runs, your_runs, messages, tokens, cost_usd}` (local date keyed like day series, `tokens` = ledger input + output, `messages` = user messages of the user's Runs); `totals` `{active_days, first_active, runs, your_runs, messages, sessions, agents, tokens, cost_usd, tool_calls, changed_files, lines_added, lines_removed}`; `streaks` `{current, current_start, longest, longest_start, longest_end}` over consecutive active days, where the current streak ends today or yesterday (today does not break it before it is over); `by_hour` (24 local hours) and `by_weekday` (7, Monday first) count the user's Runs by start; `favorite_model` (most tokens, with `tokens`, `calls`, `share` of all tokens) and `favorite_agent` (most of the user's Runs, with `runs`, `share`) or null; `records` with `busiest_day` (most of the user's Runs, the earlier day on a tie), `top_session` (listed Session with most of the user's Runs) and `longest_run` (the user's longest finished Run as a RunRow), each null without evidence. The section follows the report window like every other; the WebUI asks for it without `since`.
- **usage** - `totals`, `breakdowns` by `agent`, `model`, `provider` (Model key before the first `/`), `project` (`""` for Identity usage), `origin` and ledger `kind`, each every row by cost as `{key, ...Totals, runs, sessions}`; the `series` of Totals plus `runs` (the Runs that started in the bucket); `top_runs` and `top_sessions` (50 by cost); `recent_calls` (50 newest) with the stored cost object, `duration_ms`, `failure_class`, `http_status`, `estimated_tokens` and `retrospective` (a catalog-priced call without a saved price snapshot). A row's `runs` counts in-window Runs touching the key (once per Model, Provider and kind the Run used; Agent, Project and Session counts cover listed Sessions only), `sessions` the Session addresses with in-window requests; a row can show Runs without in-window calls. Standalone requests get no fabricated Session or Agent: an empty agent key and null `session_id`/`session_title`.
- **runs** - status `totals`; `by_origin` and `agents` with outcomes, duration and cost percentiles, averages of Tool calls and Model steps (agents add Tool time and change stats); their `cost_usd` sums Run costs (each in-window Run's own requests, whenever made), so it leaves out requests outside any indexed Run that overview `by_origin` and the usage `origin` breakdown count; `duration_buckets` (inclusive edges 10 s ... 1 h plus `null`, finished Runs); `daily` outcomes per series bucket; `longest`, `costliest`, `most_steps` (25 RunRows each); `cancelled` (`runs`, `cost_usd`, `wait_p50_ms`); `errors` (`total` error records, `failed_attempts` from the ledger, `[{key, count}]` by kind, Provider, Model and Agent, `daily`, `by_hour` for all 24 local hours); `previous` (status `totals` and the user-origin `duration_p50_ms`/`duration_p90_ms` of the previous window, null without one).
- **tools** - `totals` (`calls, accepted, rejected, unknown, tool_ms, tools`), per Tool by calls (`rejection_rate`, approximate `p50_ms`/`p95_ms`, `max_ms`, `total_ms`, `time_share`, top 5 codes), `rejection_codes` with their Tools, and `by_agent`. Accepted/Rejected retain the persisted Result's `ok:true/false` meaning (rejection is not malfunction); every canonical dispatch start counts, and calls without a saved Result contribute `unknown`. Declared but unstarted calls are absent; no raw arguments anywhere.
- **skills** - `SkillsSection` (`skills.py`): one row per current-inventory Skill with origins (several on cross-scope collisions - usage keys on the bare name), offered (the Session's `seen_skills` summary value, windowed by Session `created_at`) vs activated (both carrier parsers, windowed by note time) vs their per-Session intersection, usage rate (`null` only without offer evidence), first/last timestamps, per-Agent activations, and evidence-backed delete/improve candidates separated from Skills without offer data. Deleted Skills drop out. Canonical timestamps compare as strings. Background Sessions are not Skill use: a Session whose recorded `run_kinds` are all unattended (`core.runs.UNATTENDED_RUN_KINDS`, reflection reviews and Librarian passes) adds neither offers nor activations; a Session without recorded kinds counts (`skills.py::counts_as_skill_use`, shared with `skill_package_usage`).
- **extensions** - per owner (by name) `name`, `actor_key`, `activity` and `groups` (most recently active first, capped at 25 with `total_groups`/`groups_truncated`), each `{group_id, title, started_at, activity, participants: [{participant_id, name, model, session_id, activity}]}`. An activity is `{sessions, runs: {total, <status>...}, errors, tool_calls, totals: Totals, last_activity}`. See `statistics/group-usage.md` -> Extension activity.
- **diagnostics** - `compactions` (`CompactionsSection`: checkpoint counts and Strategy breakdowns, paired before/after context estimates, non-shrinking checkpoints, duration, intervals in saved Chat Model steps, recurrence within two steps, first subsequent measured input (it includes new request content, so it is no estimator-error measurement), latest 50 checkpoints; missing evidence stays null, an earlier checkpoint outside the window may establish the interval and a later request the next input; legacy count/reclaim fields remain for the CLI), `cache` (`lowest_hit_rate_sessions`: 20 Sessions with >= 2 turns with Usage (`turns`), worst first; `suspected_breaks`: evaluated and suspected turns plus the 20 largest read shortfalls), `data_quality` per Model, `failed_attempts` (`total`; the 10 worst hours with `[{key, count}]` Models, Agents and `classes`; `by_class`, most failures first, as `{key, count, duration_calls, avg_duration_ms, providers, models, http_statuses}` with each list the top 5 `[{key, count}]` and `http_statuses` keyed by the status as text. A failure key is the `failure_class` of a `failed` call, `unknown` for one recorded without it, and the status itself for `cancelled` and `interrupted`, so keys and `total` cover the same calls), `runaway_runs` (<= 50 RunRows: >= 100 iterations or cost >= 20x the median positive Run cost), `open_runs` (in-window Runs still `running`), and `roles` (`chat_messages_by_role`: every user record and Assistant steps with non-blank text; `session_records_by_role`: all ten stored roles zero-filled, including `history_edit`).

Diagnostics heuristics:

- Suspected cache breaks are a heuristic comparing consecutive saved Chat turns with Usage (estimated ones included, an unreported cache read as zero), skipping legitimately explained misses (first turn, checkpoint/takeover boundaries, an Assistant record without Usage, model switches, >300s gaps, previous prompts below 2048 tokens) with a 0.5 read-ratio incident floor - false negatives accepted by design. Reconcile judges each turn against its predecessor in the whole Session (`_rollups.judged_cache_turns_sql`), so a turn's predecessor may lie before the report window. Auxiliary requests never enter the judgement.
- `diagnostics.open_runs` counts canonical Run records still `running`; startup recovery settles Runs a stopped process left running as `interrupted` (`sessions.md`), and a Run reaches the projection with its Session's next revision change, including a Tool start without a Message.
- Error attribution proxies to the Model of the latest saved Chat step before the error in its Session (`unknown` when none).

WebUI tabs: `StatisticsView.svelte` asks `statistics.report` per tab for only that tab's sections, with `since` from the selected range (calendar days start at midnight in the zone, 24 hours is rolling; all time sends no `since`) and the Settings time zone as `timezone`: Overview -> `overview` plus a second all-time report of `activity` for its activity hero (independent of the range), Costs & tokens -> `usage`, Runs -> `runs`, Tools & skills -> `tools` + `skills`, Extensions -> `extensions`, Diagnostics -> `diagnostics`; Limits asks no report. The Extensions tab shows only when that range's `extensions` section lists an Extension; it is asked after the shown tab settles. The retired `compactions` place opens Diagnostics. Report cache, panels and presentation: `webui/source-map.md`, `webui/design.md`.

# Archive and restore operations

Task-gated detail for `archive.md`: the order, outcomes and checks of archiving and restoring an entry, the entry facts, Workspace handling, review members, locking helpers and the listing reads. Source: `core/archive/archive.py`, `_operations.py`, `_restore.py`, `_read_model.py`, `_types.py`. Tests: `tests/core/archive/test_archive_service.py`, `tests/core/sessions/test_archive_ledger.py`, `tests/core/agents/test_agents_archive.py`, `tests/core/projects/test_store.py`, `tests/server/rpc/test_archive_methods.py` and the delete tests of `tests/server/rpc/`, `tests/cli/test_cli_archive.py`.

## Entry facts

`ephemeral_expiry: true` marks a Session entry created by expiry; it commits with the archived Session states, and the sweep retries its permanent deletion regardless of ordinary retention (`archive/purge-and-retention.md`).

Facts (`facts_json`, writers merge and keep unknown keys): `name` and `payload_format` (agent, project: the integer format version, `"older"` or `"newer"`; decides restorability without reading payloads), `roster_index`, `grants` (`[{agent_id, agent_created_at?, index, target_created_at?}]`, recorded before any config is written and merged on re-run; restoration requires the same holder creation stamp, and unstamped grants are skipped; bound grants also retain their original target identity, `agent/delegation.md`), `workspace` (`{path, external, moved}`) and `root_project_id` (agent), `cwd`, `working_project_provenance` (true when archive captured Working Project associations) and `unrooted_agents` (`[{agent_id, agent_created_at?, workspace_before, workspace_reset}]`, written before each unroot) (project), `reason` (owner_group: `extension` or `extension_removed`), `restore_plan` (`{target_id, strip_channel_keys, workspace?, root_project_id?, workspace_destination?}` while `restoring`/`restored`; startup recovery adds `live_path` and `problem` when an interrupted restore cannot finish), `backfill` (`{match: "timestamp"|"none", tree_mtime}`), `user_folders` (backfill: the recorded tree paths that may be folders the user owns rather than copies vBot made - every legacy `files` tree, and a legacy moved Workspace whose folder lay outside the data directory).

## Archive outcomes

`archive_agent(agent_id)`, `archive_project(project_id, copy_identity_files=)`, `archive_session(address)` return `AgentArchiveOutcome` (entry id, Session count, changed delegation holders, the `external_workspace` left in place), `ProjectArchiveOutcome` (entry id, unrooted Agents, copied and backed-up identity files) and `SessionArchiveOutcome` (entry id, `next_session_id` and `was_current` for an Identity Agent's current Session; `next_session_id` is the most recently active remaining Session, or `None` with the pointer cleared when none remains, since no empty Session is created for the landing). `ArchiveSubjectInUseError` carries `references` as `kind:id` labels; for a Project or Session also `details` as `{kind, id, name}`. `archive_session` takes the Session's live review forks along (`ChatSessionManager.review_forks`): the admission guard, the automation reference check and the Terminal and command closing cover them as well, so a review still running refuses the archive like a Run of the Session, and `was_current` is also true when the current Session was one of them. A review fork that appears after the guard was taken joins the entry if it is idle and otherwise stays live.

## Restore checks and outcomes

`restore_check(entry_id, target_id=)` returns every blocker and warning at once and changes nothing; `restore(entry_id, target_id=)` returns `RestoreOutcome` (target id, the restored Session addresses, warnings, and `grant_agent_ids`, the Agents whose delegation lists name the restored Agent again) and raises:
- `ArchiveRestoreConflictError` (with the entry's `kind`) when only taken ids or addresses block (`agent_id_taken`, `agent_id_referenced`: Agent Secret grants another archived Agent keeps still name the target id of an Agent restored under a new id, `project_id_taken`, `session_address_taken`: another target id avoids them);
- `ArchiveEntryBusyError` while another operation holds the entry (blocker `entry_busy`; the error carries the blocker's message as `reason` and its facts as `details`: for an interrupted restore that cannot finish, `path` and `problem` and how to unblock it; for a `purging` entry, that it will not become restorable; otherwise, to retry after that operation finished);
- `ArchiveNotRestorableError` for every other blocker (`kind_not_restorable`, `payload_missing`, `payload_unavailable` (restore access to the archived files and retry), `payload_invalid`, `older_format`, `newer_format`, `invalid_target_id`, `reserved_target_id` (a new Agent or Project id Windows reserves for a device; checked before `*_id_taken`, since Windows reports a device name as present), `project_cwd_claimed`, `scope_missing` with the newest entry that holds the missing Agent or Project (for an Agent, the message names that entry or, when none exists, says to create an Agent with that id; an Identity Agent rename takes its archived Sessions and the scope of its `session` entries along, `sessions/ownership.md` -> Identity-rename retargeting), `workspace_path_taken` naming the folder to move, `external_workspace_missing`, `external_workspace_unavailable`, and `owner_managed` when the commit meets a member Session an Extension manages).

Warnings: `grant_target_missing`, `grant_holder_unproven`, `grant_holder_replaced`, `subagent_parent_unproven`, `working_project_association_unproven`, `root_project_missing`, `workspace_path_taken` (provenance limits and operator actions: `archive/recovery.md` -> Provenance limits). Under a new target id the Sessions lose their Channel routing keys; grants and roots follow only for original holder incarnations, and Sub-Agent parent links and Working Project associations follow only with proven ownership. For a `session` entry the new id names its Session only; its review forks keep their ids (`ArchiveMember.review_fork`), and an entry with several Sessions besides them is `invalid_target_id` (`SessionArchiveLedger.holds_one_session`).

## Reads

`list(filters, cursor=, limit=)` pages entries newest first as `ArchiveListing` (label, `restorable` and `not_restorable_reason` from cheap facts and payload presence checks, `purge_at`, `may_hold_user_folders`, `accepts_target_id`: an Agent or Project entry, or a `session` entry of one Session and its review forks, `_restore.accepts_target_id`; the entry's `session_count` counts every member, its `review_fork_count` the members that are review forks of another member) in an `ArchivePage` that carries `retention_days` and `retention_unknown` (the period cannot be read; then `retention_days` and every `purge_at` are `None`); `show(entry_id, session_limit=)` adds the first member Sessions (each marked `review_fork`), the payload state (`present`, `missing`, `unavailable`, `none`), the full restore check and `user_folders`, the trees the `user_folders` fact names.

## Workspace handling

An Identity Agent's Workspace outside its own directory `agents/<id>/` (also one elsewhere in the data directory) stays where it is (`facts.workspace.external`; the facts keep the stored form, data-dir relative inside the data directory, while `AgentArchiveOutcome.external_workspace` and `ArchiveEntryDetail.external_workspace` name its absolute path), is re-attached on restore, and is never deleted; when it is missing/not a directory (`external_workspace_missing`) or inaccessible (`external_workspace_unavailable`), restore is blocked without changing the archived association. Restore the folder or its access, then retry. A legacy archive's moved Workspace tree (role `workspace`) returns to its folder, or becomes the default Workspace when that folder is in use (warning `workspace_path_taken`; a blocker when both are in use).

Limitation: Workspace files are never in a data snapshot. After a whole-snapshot restore an Agent can be live again with its snapshot `agent.json` while its tree content sits in a recovered payload; restoring that payload then needs another target id.

## Review members

- Agent and Project archives include every live review follower of their Sessions, even after a source moved away from its review's owner. `SessionArchiveLedger.scope_addresses` supplies the canonical recursive membership for the Run/reference guards and resource cleanup; `commit_scope` captures the membership atomically, leaving a newly appeared running review whole. Foreign review owners keep their Agent/Project on restore, including restore-as. Their current Session pointers are repaired before delegation-grant or roster cleanup reads can clear them; outcomes expose `review_addresses` for scoped deletion events and each surviving owner's own landing. Missing foreign Agents, Projects or Team members block the entire restore, including restart recovery. Coverage: `test_scope_archive_carries_moved_reviews_with_their_original_owners`, the restore-recovery contract and the Agent/Project RPC deletion tests.
- A Session archive returns every committed member address in `SessionArchiveOutcome.addresses`, including review forks. Reviews keep their original Agent after a source move; archiving repairs every affected Identity current pointer and `session.delete` publishes each member's own scoped landing, so a window displaying a review fork returns to that Agent. Restore keeps a review belonging to another original owner in that scope and refuses the whole entry until every member's Agent/Project scope exists.

## Locking helpers

The reference lock is the server's `agent_delete_lock` (`server.md`). The server's `archive.restore` runs under `_guard_agent_lifecycle` (`server/rpc/agent_refs.py`: that lock plus the Agent lifecycle mutation lock), like the archive step of `agent.delete`; `project.rm` and `session.delete` hold the reference lock around their archive. The service's own Run admission guards are `agent_admission_guard`, `project_admission_guard` and `session_admission_guard` (over the members' restored addresses).

## Archive order

Tree moves (`core/utils/tree_move.py`) claim a cross-volume destination exclusively
before copying or taking responsibility for cleanup. A target created between the
initial check and the copy is refused and retained; failed-copy cleanup never
removes that independent target (`test_tree_move.py`).

Archive order (`_operations.py`): `ledger.begin` records the entry `archiving` with the tree it will create; the store moves the files; `commit_scope` archives the live Sessions and marks the entry `archived` in one transaction. A failure before that commit moves the files back and deletes the entry only after every payload tree is confirmed absent without following links. A remaining or uncheckable tree keeps the entry `archiving` for recovery; a failed presence check never replaces the original archive error. Once `commit_scope` succeeded, the archive has succeeded. An Agent archive then records and removes its delegation grants, drops the id from the roster and clears `cleanup_pending`; a failure there is logged and leaves `cleanup_pending` for recovery, and when a live Agent has meanwhile taken the id, the cleanup only clears `cleanup_pending`, since the grants naming the id are that Agent's. Skill invalidation, the change notification and Recall eviction follow in every case. Project and Session archives commit `cleanup_pending` with their members, then repair surviving Identity Agents' current pointers; a failure is logged and the committed archive still succeeds. Recovery retries the repair, and restore or purge finishes it before removing the entry. A live Session that reused an archived address keeps its pointer; an unreadable or invalid Agent document leaves cleanup pending. A Project archive records and performs each default-Project reset first (`unrooted_agents`; an Agent whose Workspace was elsewhere gets its default Workspace, optionally with copied identity files) and undoes them on failure. Identity Sessions working in the Project stay live; their Runs are refused until a restore (`projects.md`).

## Restore order

Restore order (`_restore.py`): check (a `session`-kind entry takes the admission guard over all its members), `begin_restore` (`restoring` with `restore_plan`), the store moves the payload to the target and rewrites its `agent.json`/`project.json` to the target id (unknown fields kept), `commit_restore` makes the members live (`restored`). The same transaction retargets live and archived children's links by exact Parent generation for every changed address (Agent, Project or Session restore), and a Project restore retargets only its captured Working Project associations (`sessions/ownership.md`), never inherited history timestamps. Replacements at old public addresses keep their own links and associations. A failure before the commit writes the archived document bytes back before the files return, so a failed restore leaves the payload unchanged; then the idempotent follow-up places the roster position, re-adds grants only to their original holder incarnations, moves the Agent Secret grants to the new id of an Agent restored under one (`move_agent_secrets`, when the grants are this entry's), gives the unrooted Agents their default Project again, prunes empty payload directories and deletes the entry.

# Terminal Conversations

Read this when changing the interactive terminal accessor, its Textual interface, transport or recovery. The shared semantic timeline is owned by `chat/timeline.md`; ordinary CLI commands remain covered by `cli.md`.

## Entry and boundaries

`vbot tui [--agent <address>] [--session <id> | --project <id>]` opens a full-screen Textual application. It accepts the CLI's resolved `--host`, `--port`, `--url` and `--data-dir` target. Terminal stdin and stdout are required; automation keeps using one-shot `vbot chat`. Parser/help paths do not import Textual. `_dispatch_tui.py` lazily starts `cli/tui`; `app.py` owns the Textual shell, widgets and bound actions. Its composed `conversation.py` controller owns navigation, the view/roster catalogs, history snapshots/cache, stream reconciliation and completion receipts; `submissions.py` owns pending sends, draft checkpoints and explicit recovery; `suggestions.py` owns inline completion state/catalogs. These are internal units of the TUI, with composer actions in `composer.py`, `state.py` local conversation state and wire patch application, `activity.py` the server-reported Session activity (status row work line, Session picker marks), `rendering.py` the text of timeline rows (Tool titles and details, message text, file links), `transcript.py` the virtual transcript view and `row_painter.py` its Rich/Markdown row and disclosure painter, `completion.py` the composer's inline suggestions, `dialogs.py` pickers/forms, `agent_secrets.py` Agent Secret requests and the `/secret` form, `theme.py` the accessor's dark/light themes, `commands.py` the palette's command list, and `transport.py` asynchronous HTTP/SSE/WebSocket transport.

The TUI calls the existing server contracts; it owns no Provider execution, durable Sessions or Queue. Internal `actions.py` exposes Session/Tool operations and `models.py` owns Model/effort selection; `drafts.py` owns local draft persistence and conflict preservation. A remote server is reached by its `https://` address (`--url`, with a Device from `vbot devices pair <url>` when it runs in `authenticated` mode) or through SSH or an SSH tunnel to the HTTP target. `textual` is in the CLI and development dependency groups, and packaged server runtimes include the CLI group on Windows and Linux.

## Interaction

The main screen keeps one compact header (the Session's title on the left, its Agent on the right), the transcript, a status row, the composer and one settings row under the composer: the Project the conversation works in and its server-side directory on the left, and the Model, thinking effort and context load (with its share of the context window) on the right, as the WebUI composer's footer shows them. The status row shows only while it has something to say: the displayed Session's work, a transient note until it expires, or what needs attention (connection, uncertain send, Secret request, Queue, Extension requests); a Secret request of the open conversation outranks the working Run, which waits on it. The Session's work is the activity the server reports for it (`working`, `waiting`, `idle`: from the `/ws` hello's `session_activity` and `session_activity_changed`, never reconstructed from Run events): while working, a spinner, the elapsed work span since the Session left `idle` (across Runs and waiting, from `work_started_at`) and the stop key; while waiting, `○ Waiting for 2 Sub-Agents, 1 command`, the span and `F10 stops all`; durations are written as the WebUI writes them. A hello starts over (a Session it does not list is idle); against a server that reports no activity, or while a started Run's working report has not arrived yet, the row counts from the displayed Run's start. Away from the newest lines, a `↓ Jump to latest` control floats over the transcript's bottom-right corner instead of taking a row; it turns accent-coloured when output arrived meanwhile, and a click or F12 returns to the tail, where it disappears. There is no key footer and the composer carries no key hints of its own: its placeholder names the entry points (`/`, `@`, `Ctrl+K`, F1) until the operator types, `Ctrl+K` opens the command palette, which offers every bound action by name, so no key is reachable only by knowing it, and F1 lists the keys and mouse gestures grouped by task. The accessor's own dark/light themes are registered at startup and switched through the palette; both wear the WebUI's warm graphite and amber palette (`webui/src/styles/app/foundation.css`), including the colours Textual would otherwise derive in blue (selection, scrollbars, cursors), and code blocks sit on the theme's surface. Every dialog is one frame with its title in the top edge and its keys in the bottom edge, and its fields carry no frames of their own; a Picker's highlighted choice stays visible while its search field has the focus and says when nothing matches. Searchable pickers select Agents, Projects and Sessions; the Session picker marks a working Session `●` and a waiting one `○` from the `session.list` row's `activity_state` (`has_active_run` from a server without it), and an unread result `•` only while the Session is idle. Drafts, pending attachments, reading positions and navigation remain local per conversation. Reasoning and Tool details expand on demand; Markdown/code remain text. File actions distinguish local uploads/download destinations from server file references. Extension forms use terminal controls; URL requests and Extension pages expose links for a browser.

A Tool row is one line: a status mark (a spinner while it runs, green when it succeeded, amber when cancelled, partial or refused by the Agent's Permission Rules, red when it failed), the Tool's name, what this call worked on, built as the WebUI builds it from the server's display parts (a path keeps its last three segments, other values are shortened by their own truncation rule and length; the plain summary only when no parts exist) followed by its facts (`lines 1-40`, `+12`, `3 matches`), its status only when the call did not finish well, and how long it ran (counting up while it runs; none while it is still prepared), written as the WebUI writes durations (`0.4s`, `12s`, `1m 5s`, `1h 2m`). A long summary is shortened before the time is. Expanding a row shows the complete values: the arguments without the keys the Tool's display hides, its result, and the Tool's own detail blocks (labelled text, found items, notices) as indented `key: value` text rather than raw JSON, at most 400 lines (Ctrl+G copies everything). Reasoning is one line (`Thinking…` while it streams, `Thought for 12s` after) that opens the same way. A finished Run ends with a quiet `Worked for …` line; a failed, cancelled or interrupted one names its status.

The mouse works where it helps: a click on a Tool or Reasoning row opens or closes it with its header kept on the same screen line, hovering highlights it, and a click on a link shows it for copying. Because the app owns the mouse, dragging selects text the terminal way, a double click selects a word (a path or dotted name stays whole, trailing sentence punctuation stays out) and a triple click the paragraph around it within its row: the selection is copied to the clipboard when the drag ends (OSC 52, so the terminal must allow it) and `Ctrl+C` copies it again; the selection keeps each line's text colour under the selection background. From the keyboard, Tab moves into the transcript, Up and Down step through Tool and Reasoning rows, Enter or Space opens and closes one, and Esc returns to the composer.

Enter sends, Shift+Enter and Ctrl+Enter add a line, and Ctrl+S/Alt+Enter stay as send aliases. While the composer offers suggestions, Up and Down choose, Enter takes the highlighted one and Esc closes the list; without a visible list those keys stay with the focused widget, and an open modal screen keeps every one of them out of the main screen. F2 selects a Session, F3 starts a conversation, F4 controls Model/effort, F5 shows activity, F6 the shared Queue/Steer, F7 Secret and Extension requests, F8 files, F9 Commands/Skills. Ctrl+X stops the current Run, F10 invokes Stop all, F11 opens Session/Tool actions and saved drafts, F12 returns to latest output, Ctrl+B navigates to the Parent/back, Ctrl+O loads older history, Ctrl+Space completes commands/files, and Ctrl+Q detaches. Modal controls must not invoke hidden main-screen mutations.

The composer suggests while the operator types, as the WebUI's picker does: `/` at the start of the draft offers Commands and Skills, `/model ` the chat Models, and `@` a server file token anywhere. Rows keep every word of the token, case-insensitively. Taking a Command that declares no argument and choosing a Model submit at once, matching the WebUI; a Command with an argument completes to `/name ` and a chosen file becomes a Mention of its server path. A token whose catalog is still being read makes Enter wait rather than send half a token, and the popup stays out of a modal screen.

Server file snapshots are resolved from the captured submitted text through `files.list`, including quoted paths and explicitly browsed ignored files. The completion cache is never the submission authority. Local paths use a browser/typed-path dialog; a typed path is accepted with Enter or Ctrl+S, a folder where a new file name belongs is refused by name (and choosing a folder in the tree keeps it as the base for the name), and downloads request original bytes and exclusively create their destination. Extension refusal preserves entered values and displays the server error. An unknown form outcome never triggers an automatic resubmission.

Agent Secret values exist in the TUI only in masked form fields and in the one RPC that carries them; `drafts.py::holds_secret` decides what is never kept. Secret requests (`agent_secrets.list`, matched on the open conversation's Agent address and Session) are read again on the `agent_secrets` resource event and on reconnect; F7 opens a form with masked concealed fields and the requested lifetime that answers or declines, and a form whose request went away closes or shows the server's refusal, keeping typed values while the request still waits. A bare `/secret` opens the give form (`agent_secrets.give`) instead of sending and needs the Session a first message creates. A `/secret` with an argument is still sent as the command, but alone (pending attachments wait), as `/secret <argument>` with one space, and never kept: no draft, checkpoint, saved input or input history, and the composer clears once it is accepted; editing a message or queued message into one is refused. The composer does not mask it while typed (Textual's `TextArea` has no password mode). An expanded Tool row lists the server's `secrets_used` and the one-line row counts them.

F4 shows the effective Agent/Team or Session Model and effort before selection. Effort choices use `model.get`'s effective Connection ladder and accepted settings values; a pinned Connection with an account suffix retains that Connection's capabilities. An unavailable pin does not borrow another Connection's ladder.

`chat.work.running` supplies current Sub-Agent and background-command activity independently of loaded History; timeline rows additionally retain completed work. Opening a Child Session is read-only navigation; sending follows existing reply-target rules. Queue editing/removal/Steer remain server operations. Stop Run, Stop all and closing the accessor are distinct actions. Copy/export operates on loaded history; arbitrary HTML, Voice and embedded terminal image/video protocols are outside this accessor.

## Recovery and reply surface

`TerminalClient(target)` maintains HTTP and `/ws` presence (`accessor=tui`), with a timeline stream for the displayed Run. It builds both from `cli/server_client.py` (`cli/server-access.md`), so a `--url https://...` target uses `wss://` with TLS verification and every request carries the target's credential. An access refusal (HTTP 401/403, WebSocket close 4401/4403) becomes a `ClientError` whose code is `auth_required`/`access_denied` and whose text says what to do (`access_refusal`: the `--data-dir` of the right server, or `vbot devices pair <origin>`). The event loop retries a first `auth_required` at once (the credential is read again per connection), then stops reconnecting, marks the header disconnected and shows that text. A 503 `devices_unavailable` (WebSocket 4503) becomes the same kind of `ClientError` with its own explanation, but reconnect waits at least 30 seconds (HTTP also honors `Retry-After`), and the sign-in stays. Timeline recovery preserves the same retry hint and stops after 401/403 rather than polling with a refused credential. Reconnect starts from authoritative server facts and a semantic snapshot. Selection/read generations keep late responses from overwriting another conversation. Patch base mismatches require a new snapshot. No mutation is automatically retried; an uncertain send stays visibly uncertain until inspection/reconciliation, preventing duplicate admission after a lost response.

History catch-up drains every newer page before publishing the snapshot. `transcript.py` is one Textual Line API view (`ScrollView`), not a widget per row: it flattens Run children into independent display rows (a goal row, in a Run or between Runs, is one muted status line: `rendering.py::goal_text`; a Sub-Agent message row is headed by its sender with the message text below), renders a row through `row_painter.py` into cached strips once per width (Markdown through Rich) and paints only the lines on screen, so scrolling, opening a row and streaming cost only the rows they touch and nothing mounts or unmounts. Rows within one screen of the viewport are rendered before they show; rows not rendered yet carry an estimated height (a closed Tool or Reasoning row is exactly one line), and idle ticks measure the rest nearest the viewport first. A reading anchor (row id and line offset) keeps the view still while estimates become exact heights, rows open or close, or earlier rows arrive above; following the tail keeps the bottom in view. Strips of rows more than four screens away are dropped while their heights stay. `row_painter.py` owns palette/Markdown styles and the bounded disclosure body; it receives disclosure/highlight state explicitly and does not access viewport, anchor or strip-cache state. Disclosure state and measured heights belong to the Conversation (per width), so a reopened Session paints at once where it was left. Reopening a retained Session paints its cached content before waiting for reconciliation. Background Run/Queue events refresh only the addressed view; initial roster reads and Session pickers reuse their catalog until invalidated. Completion is acknowledged only after that exact completed Run is rendered at the tail of the focused conversation, outside a modal. Scoped rename, move and deletion events preserve input while updating the addressed conversation.

Both interactive accessors request bounded Run-child deliveries (`chat/timeline.md`). A history gap is a quiet one-line row; once it comes within a screen of the viewport, the transcript asks for the steps before it through `chat.timeline_children`, once per cursor, and asks again only after a page that was not merged (busy or stale). A page merges only while its Run still shows the gap it was read for. Expanding a Tool row with `rawTruncated` reads its whole call through `chat.tool_call` and replaces the row's previews while the conversation is unchanged; search and the expanded body use what is loaded. Reaching the leading edge while reading loads an older Session page. Search matches complete loaded text and Tool details instead of their shortened picker labels, and reveals the selected row. The TUI retains at most eight histories with a 16 MiB serialized-text target, excluding the current view; evicting reconstructible content preserves drafts, disclosure ids, selection and reading anchors. Back navigation retains at most 100 entries. This is a cache budget, not a Python heap limit.

Drafts, attachments, selected overrides and pending-send/edit recovery survive restart in `~/.vbot-tui-state/<server-url-sha256>.json` on the terminal computer, outside the server data directory. `drafts.py` uses Generation 1 JSON helpers, preserves unknown fields, refuses invalid/newer documents, and merges under a cross-process file lock. Conflicting edits from two accessors retain both drafts. Before sending, the addressed submission is checkpointed as uncertain; a new conversation supplies `new_session.session_id` so a lost response remains discoverable by read-only recovery. F11 restores ordinary drafts; uncertain edits are reconciled explicitly through the Edit action. Restoring never submits input.

Interactive sends identify `reply_surface=tui`; Command catalogs use the same surface. Its Model reminder describes terminal Markdown/code and file links without embedded media. A delivered Steer changes the subsequent reply surface; merely opening a terminal does not. Settings lists connected TUI accessors as Terminal. Closing the app releases local connections and leaves server Runs running.

## Agent-facing discovery

The bundled `vbot-docs/references/chat.md` distinguishes human-operated `vbot tui` from script/Agent `vbot chat`. Its explicit prohibition on launching the TUI from an automated shell Tool prevents a blocking interactive process; it does not restrict a human terminal invocation.

## Verification

TUI interaction and transport contracts live under `tests/cli/`; use Textual's mounted test driver for input, modal isolation, streaming, Queue and navigation. `tests/cli/test_tui_transcript.py` covers painting only what shows, disclosure and reading-position stability, and gap loading. `tests/cli/test_tui_completion.py` covers the trigger recognition, filtering and the keys that take a suggestion. `tests/cli/test_tui_agent_secrets.py` covers the Secret forms and that a `/secret` value reaches only its RPC. `tests/cli/test_tui_activity.py` covers the status row's work line across the reported activity states and the Session picker's marks. Live acceptance uses only the isolated checkout target and the workflows linked from `PROJECT.md`.

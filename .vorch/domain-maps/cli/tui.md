# Terminal Conversations

Read this when changing the interactive terminal accessor, its Textual interface, transport or recovery. The shared semantic timeline is owned by `chat/timeline.md`; ordinary CLI commands remain covered by `cli.md`.

## Entry and boundaries

`vbot tui [--agent <address>] [--session <id> | --project <id>]` opens a full-screen Textual application. It accepts the CLI's resolved `--host`, `--port` and `--data-dir` target. Terminal stdin and stdout are required; automation keeps using one-shot `vbot chat`. Parser/help paths do not import Textual. `_dispatch_tui.py` lazily starts `cli/tui`; `app.py` owns interaction with composer actions in `composer.py`, `state.py` local conversation state and wire patch application, `rendering.py` timeline widgets, `transcript.py` the bounded viewport, `completion.py` the composer's inline suggestions, `dialogs.py` pickers/forms, `theme.py` the accessor's dark/light themes, `commands.py` the palette's command list, and `transport.py` asynchronous HTTP/SSE/WebSocket transport.

The TUI calls the existing server contracts; it owns no Provider execution, durable Sessions or Queue. Internal `actions.py` exposes Session/Tool operations and `models.py` owns Model/effort selection; `drafts.py` owns local draft persistence and conflict preservation. The supported remote path is SSH or an SSH tunnel to the HTTP target. `textual` is in the CLI and development dependency groups, and packaged server runtimes include the CLI group on Windows and Linux.

## Interaction

The main screen keeps one compact header (the Session's title and Agent), the transcript, one status line and the composer, with one settings row under the composer: the Project the conversation works in and its server-side directory on the left, and the Model, thinking effort and context load on the right, as the WebUI composer's footer shows them. A transient note replaces the status line's steady facts until it expires. Only the keys an operator uses constantly sit in the footer, and `Ctrl+K` opens the command palette, which offers every bound action by name, so a hidden key never hides an action. F1 documents the available bindings. The accessor's own dark/light themes are registered at startup and switched through the palette. Searchable pickers select Agents, Projects and Sessions. Drafts, pending attachments, reading positions and navigation remain local per conversation. Reasoning and Tool details expand on demand; Markdown/code remain text. File actions distinguish local uploads/download destinations from server file references. Extension forms use terminal controls; URL requests and Extension pages expose links for a browser.

A Tool row is one line: the Tool's name, its display summary for this call (the command, path or query the server recorded) and its status only when the call did not finish well. Expanding a row shows the arguments without the keys the Tool's display hides, its result, and the Tool's own detail blocks (labelled text, found items, notices) as indented `key: value` text rather than raw JSON.

Enter sends, Shift+Enter and Ctrl+Enter add a line, and Ctrl+S/Alt+Enter stay as send aliases. While the composer offers suggestions, ↑↓ choose, Enter takes the highlighted one and Esc closes the list; without a visible list those keys stay with the focused widget, and an open modal screen keeps every one of them out of the main screen. F2 selects a Session, F3 starts a conversation, F4 controls Model/effort, F5 shows activity, F6 the shared Queue/Steer, F7 Extension requests, F8 files, F9 Commands/Skills. Ctrl+X stops the current Run, F10 invokes Stop all, F11 opens Session/Tool actions and saved drafts, F12 returns to latest output, Ctrl+B navigates to the Parent/back, Ctrl+O loads older history, Ctrl+Space completes commands/files, and Ctrl+Q detaches. Modal controls must not invoke hidden main-screen mutations.

The composer suggests while the operator types, as the WebUI's picker does: `/` at the start of the draft offers Commands and Skills, `/model ` the chat Models, and `@` a server file token anywhere. Rows keep every word of the token, case-insensitively. Taking a Command that declares no argument and choosing a Model submit at once, matching the WebUI; a Command with an argument completes to `/name ` and a chosen file becomes a Mention of its server path. A token whose catalog is still being read makes Enter wait rather than send half a token, and the popup stays out of a modal screen.

Server file snapshots are resolved from the captured submitted text through `files.list`, including quoted paths and explicitly browsed ignored files. The completion cache is never the submission authority. Local paths use a browser/typed-path dialog; a typed path is accepted with Enter or Ctrl+S, a folder where a new file name belongs is refused by name (and choosing a folder in the tree keeps it as the base for the name), and downloads request original bytes and exclusively create their destination. Extension refusal preserves entered values and displays the server error. An unknown form outcome never triggers an automatic resubmission.

F4 shows the effective Agent/Team or Session Model and effort before selection. Effort choices use `model.get`'s effective Connection ladder and accepted settings values; a pinned Connection with an account suffix retains that Connection's capabilities. An unavailable pin does not borrow another Connection's ladder.

`chat.work.running` supplies current Sub-Agent and background-command activity independently of loaded History; timeline rows additionally retain completed work. Opening a Child Session is read-only navigation; sending follows existing reply-target rules. Queue editing/removal/Steer remain server operations. Stop Run, Stop all and closing the accessor are distinct actions. Copy/export operates on loaded history; arbitrary HTML, Voice and embedded terminal image/video protocols are outside this accessor.

## Recovery and reply surface

`TerminalClient` maintains HTTP and `/ws` presence (`accessor=tui`), with a timeline stream for the displayed Run. Reconnect starts from authoritative server facts and a semantic snapshot. Selection/read generations keep late responses from overwriting another conversation. Patch base mismatches require a new snapshot. No mutation is automatically retried; an uncertain send stays visibly uncertain until inspection/reconciliation, preventing duplicate admission after a lost response.

History catch-up drains every newer page before publishing the snapshot. `transcript.py` flattens Run children into independent viewport rows, mounts the visible area with overscan (at most 80 rows plus a keyboard-focused row), measures heights and anchors reading by row id. Tool/Reasoning bodies mount on first expansion; disclosure state belongs to the Conversation and survives row unmounting. Reopening a retained Session paints its cached content before waiting for reconciliation. Background Run/Queue events refresh only the addressed view; initial roster reads and Session pickers reuse their catalog until invalidated. Completion is acknowledged only after that exact completed Run is rendered at the tail of the focused conversation, outside a modal. Scoped rename, move and deletion events preserve input while updating the addressed conversation.

Both interactive accessors request bounded Run-child deliveries (`chat/timeline.md`). A history gap loads earlier steps through `chat.timeline_children`; reaching the leading edge while reading loads an older Session page. Search matches complete loaded text and Tool details instead of their shortened picker labels, and reveals the selected row. The TUI retains at most eight histories with a 16 MiB serialized-text target, excluding the current view; evicting reconstructible content preserves drafts, disclosure ids, selection and reading anchors. Back navigation retains at most 100 entries. This is a cache budget, not a Python heap limit.

Drafts, attachments, selected overrides and pending-send/edit recovery survive restart in `~/.vbot-tui-state/<server-url-sha256>.json` on the terminal computer, outside the server data directory. `drafts.py` uses Generation 1 JSON helpers, preserves unknown fields, refuses invalid/newer documents, and merges under a cross-process file lock. Conflicting edits from two accessors retain both drafts. Before sending, the addressed submission is checkpointed as uncertain; a new conversation supplies `new_session.session_id` so a lost response remains discoverable by read-only recovery. F11 restores ordinary drafts; uncertain edits are reconciled explicitly through the Edit action. Restoring never submits input.

Interactive sends identify `reply_surface=tui`; Command catalogs use the same surface. Its Model reminder describes terminal Markdown/code and file links without embedded media. A delivered Steer changes the subsequent reply surface; merely opening a terminal does not. Settings lists connected TUI accessors as Terminal. Closing the app releases local connections and leaves server Runs running.

## Agent-facing discovery

The bundled `vbot-docs/references/chat.md` distinguishes human-operated `vbot tui` from script/Agent `vbot chat`. Its explicit prohibition on launching the TUI from an automated shell Tool prevents a blocking interactive process; it does not restrict a human terminal invocation.

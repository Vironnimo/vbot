# Agent, Project, Session and Automation Commands

Supplementary to `cli.md`. Covers the command shapes and output of the `agent`, `project`, `session`, `cron`, `bootstrap`, `memory`, `skill` and `librarian` areas. What the deleting commands print is in `cli/archive-commands.md`.

## Agent area

- Primary ids positional: `agent create <id> <name>`, `rename <old-id> <new-id>`. `agent create|update --description <text>` sets the Agent's description (`""` clears it); `agent show` prints it. `reorder <id>...` reads the current listing's `order_revision`, appends unlisted agents in their relative order, rejects duplicate ids locally, and prints roster order plus revision.
- Create/update accept the shared Run, Memory, prompt, Skill, delegation (`--subagent-allow`), Agent Policy (`--compaction-policy`), and explicit Tool Access Policy flags (`--tool-access-mode all|selected|none`, repeatable `--tool-allow`/`--tool-deny`); wildcard and empty-array conventions are not part of this surface. `--tools-on-demand on|off|default` replaces the Agent's own On-demand Tools setting (`agent/configuration.md` -> Fields, `tool_loading`): `on`/`off` set the switch, `default` inherits it from Shared defaults, and `--always-loaded` sets the own list (space-separated, empty for none, omitted inherits the list); `default` without `--always-loaded` removes the setting, and `--always-loaded` alone is refused. `agent show` prints the effective value as `tool_loading:` and the Agent's own parts as `tool_loading_own:`. Update additionally exposes clear-model/Policy flags, Workspace relocation (`--workspace` / `--default-workspace`), the Identity Agent's default Project (`--project` / `--clear-project`: where its new Sessions work; existing Sessions keep their Working Project; `agent show` prints it as `default_project:`), name, and current Session.
- Rename is its own RPC because the id change coordinates the complete Identity Agent tree and live references; never fold it into ordinary update flags. Location flags preserve the core separation: Project controls cwd for relative file/shell work, Workspace stays the SOUL/Memory home.
- `--copy-workspace-files` requires a Workspace destination in the same command. Clear/default flags send JSON `null` (or the stored empty-model sentinel); literal domain values such as `--thinking-effort none` remain distinct from clearing the field.
- A full Agent response without effective Model persists successfully (onboarding resource) but appends an explicit cannot-run warning plus recovery commands (`model list --task chat`, `agent update --model`).
- `agent create|update --librarian true|false` sets `librarian_enabled`; `agent show` prints it, and for the built-in Librarian a `builtin: librarian (...)` line saying which fields can change (its wording: `automation/librarian.md` -> Agent-facing text).

## Project area

- `project add/list/show/set/set-override/clear-override/detect/rm`. `detect [<path>]` reports detected Agent and Skill Sources with ids, paths, counts and problems, and answers a nonexistent path explicitly. `add`/`set --sources` replace the complete ordered selection as a JSON array; `--model-mappings` replaces the Model-wish table as a JSON object. Both use the shared strict CLI JSON readers. `--auto-instructions`/`--folder-instructions on|off` set the instruction switches (`projects.md` -> Project Context). `show` and mutations print Source order/switches, both instruction switches with the main file found and missing additional files, Model mappings, Team status, translations and shadowed definitions. Override mutations target one Team Agent field without editing the repo (`compaction_policy`, `tool_access` and `tool_loading` take a JSON object); a Tool override replaces the scanned repository Tool policy inside the Project Tool Whitelist (resolution tiers: `projects/resolution.md`). `rm` output: `cli/archive-commands.md`.
- Project work is stateless - there is no current-Project flag; Projects ride the `agent@project` address form (`cli.md` -> Interfaces).

## Session area

- `session list` returns one page of up to 100 Sessions by default; `--limit` and JSON `--cursor` select a page, and `--all` follows pages with repeated-cursor protection. `session fork` optionally re-homes the fork via `--target-agent`; `set-compaction-policy` sets a full JSON Session Policy or clears it to resume inheritance and prints override/effective/source; `delete` archives or deletes (`cli/archive-commands.md`); `link-channel` links a Channel to an identity-owned session.
- Extended Session inspection is documented in the bundled `vbot-docs/references/session-search.md`: `session list` locates the Session, then the Skill's read-only script `scripts/sessions.py` (stdlib, Python 3.9+) prints transcripts, substring matches and exact Tool Results from the Session database. There is no CLI transcript command.

## Cron and Bootstrap

- `cron create <agent-id> --prompt <text> [--name <name>]` requires exactly one of `--cron <expression>`, `--every <minutes>` (recurring), `--at <iso-datetime>` (one-time), `--event <event-id>` (every occurrence of a calendar event), or `--webhook` (each request to the job's URL, `automation/cron-webhooks.md`); `--repeat` bounds future fires. `--event-time` passes the event time (`start - 30m`) through as RPC `event_time` for the server to parse; on create it needs `--event` (refused before RPC), on update it alone changes an event job's time. `show` selects the full saved record from `cron.list` (with `delivery`, `last_run_silent`, `last_result`, and `watch`, `last_checked_at`, `last_changed_at`, `last_check_error`); rows expose Session target and last error. `--deliver app|chat|none` sets `delivery` (`automation/cron.md` -> Delivery); `--channel` and `--chat` (with optional `--thread`) name the chat, imply `--deliver chat` when it is omitted, and are refused before RPC beside another kind or when one of the two is missing. `--watch <command-or-url>` sets `watch` (an `http://` or `https://` value is a URL, anything else a command; `automation/cron-watch.md`) and `update --clear-watch` removes it. Omitted, `create` stores neither and `update` keeps both. Rows show `delivery` and `watch`, a webhook job's schedule as `webhook[<url or path>]`. A `create` or `update` that gives a job the webhook schedule appends the secret lines through `cron.webhook_secret`: `url:` with who can reach it, `secret:`, how a request proves it and, for a URL services on the internet cannot reach, a `Note:`; an unreadable secret becomes a `Note:` naming `vbot cron secret <id>`. `cron secret <job-id> [--rotate]` shows the same lines (`cron.webhook_secret`) or replaces the secret first (`cron.rotate_webhook_secret`); a job without a webhook or an unknown id exits 1. `update --clear-session` clears a pinned Session; omission preserves it. Cron expressions and offset-free Once values use the server timezone; the CLI has no timezone flag. `update` accepts the same flags plus `--status active|paused` and rejects empty updates before RPC.
- `bootstrap list|show|create|update|delete|enable|disable` uses Bootstrap RPCs (`show` selects one full record from `bootstrap.list`) and is the only Bootstrap management surface. Create requires `--mode once|always` plus either a positional Agent address (optional `--session`) or `--current-session`, which reads `VBOT_RUN_AGENT_ID`, `VBOT_RUN_SESSION_ID`, and optional `VBOT_RUN_PROJECT_ID` as injected by the Bash Tool from its `ToolContext`; conflicting explicit targets, missing Run context, and remote server targets are rejected. Update supports `--clear-session`; completed one-shots remain immutable server-owned history.

## Memory

`memory list|add|replace|remove <agent-id>` selects `--scope agent|user`, takes text from `--content` or `--file`, needs `--yes` for remove. `list` shows both Memory scopes unless an explicit `--scope agent` or `--scope user` filters it, and prints entry ids per scope so follow-ups can address entries; mutations default to the Agent scope (`test_cli_memory.py`). `memory history <agent-id> [--scope] [--limit 20]` prints revisions newest first with their changes (`+`/`-`/`~ ... ->`); `memory show <agent-id> <revision>` and `memory diff <agent-id> <from> [<to>]` inspect past states; `memory revert <agent-id> <revision>...` takes changes back all or none (contract in `memory/history.md`). Failure recovery for these points to `memory history`.

## Skill

- `skill` writes only `global` / `agent:<id>` scopes (Project/bundled/Extension unwritable), takes content from a local `--file`, and requires `--yes` for `delete`, `file remove` and `purge`; `delete` archives the Skill and prints its archive id with the restore command. `inventory` reports every scanned package with origin, owner, status, warnings, shared-with receivers, exact package ids, and editable scopes, plus creator (`created_by`) and pin state of editable packages, last use when the server's Statistics answer, and the archived packages of every editable scope. `inspect <id>` reads any inventory package's original full Skill without activation; `read [name] --scope ...` optionally filters editable content.
- `skill install <source> --scope own|global|agent:<id>` is an RPC client of `skill.install`; the `own` scope, local and remote source paths, `--dry-run`, `--path`, `--ref` and `--replace --yes`: `skills/installation.md`. Output distinguishes saved packages from effective Agent access.
- `skill history [<name>] --scope ... [--limit 20]` prints revisions newest first (what, when, actor, Session and Run ids, changed files) and the revert command; `skill revert <revision>... --scope ...` reverts all or none and prints the recorded revisions, while a refusal names the later revision to revert together. `skill archived --scope ...` lists archived packages with the restore and purge commands; `skill restore <archive-id>`, `skill purge <archive-id> --yes` and `skill pin|unpin <name>` take `--scope` (contract: `skills/history.md`).

## Librarian

`librarian status [<agent-id>]` and `librarian run <agent-id>` (`cli/librarian_management.py`) print what `automation/librarian.md` -> Surfaces describes. Without an Agent, `status` reads `librarian.overview` and prints one row per recent pass (`- <finished>; <name> (<id>); <trigger>; ...; session <id>`). `librarian run` starts a pass now (`librarian.run`); its refusals: a running pass, a busy Agent or Librarian, an Agent whose `librarian_enabled` is off or that has no Skills of its own, the Librarian itself, an unavailable Librarian. The per-Agent `not scheduled: ...` line names the fix where one exists (the `agent update <id> --librarian true` command for a switched-off Agent). Contract: `automation/librarian.md`.

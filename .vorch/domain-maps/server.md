# Server

FastAPI transport and public protocol edge around the core vBot kernel.

## Overview

`server/` owns HTTP routing, the RPC envelope, SSE, WebSocket transport, request/response validation and mapping, process startup, and optional static WebUI serving. It imports runtime/core services but owns no business rules - Agent, Chat, Run, Session, Provider, Project, Tool, Skill, Extension, Prompt, Channel, and storage semantics stay in their domains.

`app.py` keeps HTTP routes, upload/JSON input limits and the FastAPI lifespan. Internal `_app_lifecycle.py` owns app-state initialization, core-event subscriptions and cleanup helpers; `_streams.py` owns stream delivery, reconnect projections and presence; `_origins.py` and `_bind.py` own Origin policy and bind resolution. `_http_dependencies.py` keeps optional framework availability in one place. These remain parts of the same transport edge.

RPC bodies group by owning surface under `server/rpc/*_methods.py`; envelope dispatch, validation, payload sanitation, expected-error mapping, and event bridging live in focused support modules. The registered method tables are the source of truth for names/parameters/return shapes - do not mirror the method catalog here.

`rpc/_mutations.py` owns cancellation-safe mutation sequencing: Settings and Skill handlers each use a state-local lock that spans persistence, live refresh and publication. Cancelling a waiting caller starts no mutation; cancelling an admitted caller waits for its sequence to settle before releasing the lock.

Failures while settling a cancelled mutation remain observable: expected RPC errors log only their code, while unexpected errors retain their traceback. Request parameters are never added to these logs.

Private Skill mutations (including archive uploads) and sharing acquire the existing Agent reference lock before the Skill mutation lock. Scope validation, persistence, invalidation and publication remain protected against Agent rename/delete, including cancellation settlement; cancellation while waiting for either lock starts no mutation. Global Skill writes do not acquire the Agent reference lock (`tests/server/rpc/test_skill_methods.py`).

Agent create/update/rename/delete likewise enter through the reference lock before cancellation-safe mutation admission; each Agent store operation, including its Session work, runs as one unit on the Session database's pool (`ChatSessionManager.run_async`) while resource publication stays on the Event Loop. `agent.list`/`agent.get`/`agent.reorder` run on the same pool because Agent reads verify, and may repair, a current-Session pointer. An admitted operation finishes its worker mutation, Skill invalidation and resource publication before cancellation propagates; a caller cancelled while waiting for the reference lock changes nothing (`tests/core/runtime/test_runtime_skill_lifecycle.py`).

## Transport contracts

- Unexpected dispatch failures are logged with traceback and rethrown internally; the HTTP edge returns status 500 with the normal error envelope, code `internal_error`, and a generic message that withholds exception details (`tests/server/test_app_http.py`).
- `POST /api/rpc` accepts `{method, params?}` JSON, returns `{ok:true,result}` or `{ok:false,error:{code,message}}`; non-JSON media types fail 415 before dispatch.
- `GET /api/runs/{id}/events` is the per-Run SSE stream (complete events plus deltas). The shared `/ws` socket is server-push only: lifecycle summaries, reconnect state, presence, `resource_changed`. Both preserve explicit `contributes_to_agent_activity: false` while omitting the default true - transport never decides attention. Reflection Runs carry `source_session_id` from their admission for attribution.
- `/ws/logs` (handoff in `logs.md`) and `/ws/terminals/{id}` (ANSI snapshot then ordered PTY events; control via `terminal.*` RPCs) are dedicated streams outside the shared bus.
- `server/main.py` disables per-message compression for all incoming WebSocket connections (`ws_per_message_deflate=False`), avoiding synchronous DEFLATE work on the Event Loop at the cost of larger wire payloads. Message contents, ordering and replay contracts are unchanged. This server setting does not configure outbound Provider connections or HTTP/SSE compression. Startup coverage: `tests/server/test_main.py`.
- Binary data stays outside RPC: dedicated attachment/speech/image/Skill-archive endpoints (semantics in their maps) plus `GET /api/files/{token}` serving Assistant-referenced originals - the token is a stateless per-process HMAC capability over the canonical path, never a caller-supplied path or copied blob. Non-image Markdown links include the canonical native path as an escaped title for accessor display/copy; the signed URL remains the delivery address (`tests/server/test_file_delivery.py`).
- Static website previews extend `file_delivery.py`: `file.preview_open` in `operations_methods.py` accepts an absolute HTML entry path or an existing signed file URL and grants a domain-separated, per-process capability to the entry's parent directory. `file.preview_revision` scans a bounded website tree off the Event Loop; `/api/preview-assets/{token}/{path}` serves allowed website file types, rejecting traversal, hidden/private paths, symlinks/junctions and excluded dependency folders. Relative assets, modules, data fetches, subpages and HTTPS presentation assets work; server execution and root-relative website routing are outside this contract. Opening a delivered HTML file redirects to the same website URL; standalone pages poll the capability-scoped `.revision` endpoint for live updates, while embedded pages leave polling to the WebUI. Unavailable standalone pages retain a visible HTTP status and probe their own URL with HEAD until it returns; recovery connections require a valid signed capability even while the directory is temporarily missing, and each asset request still validates the current tree. HTML responses announce their location to the parent for reload recovery; the WebUI validates that message against the active frame and capability prefix. Evidence: `tests/server/test_file_delivery.py`.
- **`/health` identity contract:** HTTP 200 with body exactly `{"status":"ok"}` is what CLI/Desktop probes require before treating a listener as vBot. Built WebUI assets serve as SPA when present; the entry document sends no-store so persistent Desktop WebView profiles always refresh, individual static files keep ordinary delivery.
- `POST /_vbot/control/shutdown` is the private cooperative lifecycle edge letting the local CLI trigger normal lifespan teardown; it requires the current per-process secret from `<data_dir>/runtime/server-<port>.json`. The transport-neutral `core/utils/server_control.py` owns secret comparison, atomic persistence, PID plus process-creation-time identity for the post-listener shutdown window, and exact-owner cleanup.
- `application.maintenance_begin`, `application.maintenance_status`, `application.maintenance_end`, and `application.update_continuation` are private application-control RPCs. They require the current server-control token and exact update operation id; maintenance delegates admission and drain facts to Runs, while a handoff ticket supplies the one permitted origin Run. A ticket is honored only when its Session durably holds the named Tool call with its result, checked by Sessions' single indexed `tool_result_persisted_async` probe off the Event Loop rather than a transcript load.
- `application.update_handoff_mint { handoff_token }` -> `{ handoff_ticket }` (absolute ticket path) is the one application RPC without the server-control token: the live Bash token from `VBOT_UPDATE_HANDOFF` is its whole authorization and only accepted parameter, and ticket identity comes solely from the server-side record of the issuing Tool call. Unknown or released tokens fail with `invalid_request`; repeated claims return the same ticket. Lifecycle -> `cli/windows-application.md` -> Agent handoff.
- `server/main.py` also supplies an optional app-state restart callback. It reuses
  the detached CLI lifecycle helper for its exact bind/data directory, waits for
  its own PID to exit, and schedules cooperative shutdown after the RPC response.
  Local-speech setup admits restart only after verification; embedded apps without
  this callback report restart unavailable. See `model_tasks/speech.md` and
  `tests/server/test_main.py`.

## Source routing

- Handler modules map one-to-one to product surfaces (`agent_methods`, `session_methods`, `chat_methods`, `project_methods`, `channel_methods`, `automation_methods`, `connection_methods`, `model_methods`, `provider_usage_methods`, `settings_methods`, `task_model_methods`, `extensions_methods`, `catalog_methods`, `skill_methods`, `operations_methods`, `terminal_methods`, `performance_methods`, debug/statistics/clients); add handlers to the domain-appropriate registry - never a parallel dispatcher over `methods.dispatch_rpc`. `dispatcher.py::dispatch_method` measures every registered method as `rpc.<method>` (`performance.md`); unknown names are rejected before measurement so request input cannot add metric names.
- `session_methods.py` owns canonical Session RPCs (listing, activity/read state, create/delete/fork, title, Compaction policy and Channel link). `session.activity_list` answers every requested Agent address from one Sessions read without resolving Agents; an address without completed live Sessions, including an unknown Agent, returns an empty list. `session.get` point-reads one live Session's list summary (`{session: null}` when absent) without Compaction Policy or active-Run fields. Channel-link and Compaction Policy changes use Sessions' atomic `mutate_metadata_with_previous` rather than replacing an earlier metadata snapshot; that mutation also rejects a missing Session, so neither handler reads the Session first. A Project Agent's delete landing is Sessions' `newest_session_id`. `session.delete` names the archived and landing Session ids in its scoped `sessions` invalidation so other windows can leave the archived Session (`server/events-and-reconnect.md`). Agent configuration/lifecycle stays in `agent_methods.py`. Both run their blocking Session and Agent store work on the Session database's pool (`ChatSessionManager.run_async`, or the Sessions async API) and resolve Agents through `AgentResolver.resolve_agent_async`; the RPC layer owns no pool for Session work, so a closed Session database surfaces as `domain_error` (`tests/server/rpc/test_session_methods_reads.py`). `model_methods.py` owns Model catalog/routing/database-refresh handlers and their background refresh tasks; connection/credential mutations stay in `connection_methods.py`. Task-model and local-speech handlers live in `task_model_methods.py`. All three tables register directly in `methods.py`, preserving one dispatcher and the existing RPC names.
- `data_store_methods.py` exposes the operator-safe `data_store.status`, `data_store.snapshot_create` (`reason`: `manual`, `rpc`, `update` or `recovery`; returns `{snapshot}`; a failed attempt's error carries the recorded snapshot-health reason), `data_store.incident_acknowledge` (returns the new status; an unknown incident is `invalid_request`), and `data_store.unregister` (`name` of a registered Extension database; returns `{unregistered: {name, database_id, quarantine}}` via `Runtime.unregister_extension_database`; a core or unregistered name is `invalid_request`, an open database `domain_error`) RPCs. It delegates to the database kernel (`database.md`) with `Runtime.canonical_databases()` on its own bounded worker pool, returns no database content, and publishes `resource_changed(kind="data_store")` after successful mutations. `error_mapping.py` maps every kernel `DatabaseError` to `domain_error` and a superseded acknowledgement (`IncidentConflictError`) to `invalid_request`.
- Non-obvious module contracts: `chat_methods` must not match command names or mutate command-owned state (generic projection only), re-aims an Identity Agent's `current_session_id` on plain sends/edits so restarts reopen the last-written session, and obtains each paged folded-History response plus whole-Session Usage from one Sessions read snapshot; `next_before` is the older-page continuation; `next_after` requests bounded appended History records. The whole read, including Compaction Policy, background-status records and reflection Runs, is one Session-pool hop (plus one to resolve an Identity Agent's current Session when `session_id` is omitted); projecting a changed page (file capabilities, background statuses, Context Usage) then runs on the `chat-rpc` pool, which otherwise only expands `@`-mentions, and an unchanged page skips it. An `after` read that finds nothing appended returns only the cursor fields and omits `session_usage`, `context_usage`, `background_bash_statuses`, `compaction_policy` and `reflection_runs`; callers keep their values. Every other read carries `session_usage` and `context_usage` (null when none). `background_bash_statuses` is the complete map on a replacement read and the appended records' delta on an incremental read; a `before` page omits it and `compaction_policy`; `reflection_runs` accompany only reads with neither cursor (`tests/server/test_rpc_chat_history.py`). Responses carry generation, per-record sequence/Run attribution, incremental/reset mode and `has_newer`; an edit or generation change requires snapshot replacement. A public Message id remains accepted for older-page input. `chat.edit` delegates idle-only edit admission to Chat and never falls back to Queue. `agent_refs.py` owns the cross-domain rename transaction under reference lock plus both Run guards, compensating completed steps on failure and publishing agents invalidation before Sessions/Channels/Cron so accessors remap selection first; `agent.reorder` serializes against rename/delete via the same lock with stable conflict errors; `payloads.py` owns common projections, recursive opaque-metadata stripping, and uniform `output_files` -> Markdown URL replacement; `error_mapping.py` converts typed domain errors to stable codes clients branch on instead of message text - missing resources use `<resource>_not_found` (`AgentNotFoundError` -> `agent_not_found`; Skill handlers raise `agent_not_found` for unknown owner/receiver/scope Agents and `skill_not_found` for unknown or unowned Skills), and resolver failures for a missing Agent or Project (`ResolutionAgentNotFoundError` / `ResolutionProjectNotFoundError`) map to the same `agent_not_found` / `project_not_found` codes wherever a handler surfaces the resolver error (chat send/stream/edit, `prompt.preview`, Session and command methods, Bootstrap and Cron jobs), while other resolution failures (plain `AgentResolutionError`: no usable Model, unavailable temporary Session) stay `domain_error`; bare `KeyError` stays unexpected - logged with traceback and rethrown as internal failure, never a domain envelope; `file_delivery.py` signs/verifies capabilities keeping no token registry and writing no bytes.
- Statistics methods validate windows, cache the service on app state, and offload reconciliation to workers without owning index semantics. The app wires Session title/completion-read callbacks onto `resource_changed(kind="sessions")`.

## Invariants & conventions

- Both Settings mutation surfaces call `Runtime.apply_settings_change` after persistence; RPC handlers own validation/projection and publish Command invalidation from its result, never decide which live reload subsumes another.
- The server is an edge, not a second business layer: validate/map, call the owning domain, coordinate cross-domain mutations only where the public operation requires it, publish invalidation after success.
- The browser-origin guard runs before routing on HTTP and WebSocket: foreign/opaque/malformed/duplicate origins fail closed. A concrete bind accepts its configured origin; a wildcard bind accepts an IP-literal Origin only when it exactly matches the request scheme, Host authority, and configured port, which preserves LAN IPv4/IPv6 access without admitting DNS-rebinding hostnames. Origin-less requests (CLI, Desktop Voice) stay valid. Never replace this with CORS response headers - they do not stop CORS-simple requests.
- Opaque-origin exceptions are GET/HEAD under `/api/preview-assets/` and `/api/extension-assets/`; each verifies its own domain-separated capability and file boundary. Responses allow CORS only for `Origin: null`, without credentials. Extension assets additionally bind the current owner/page registration and permit only their exact built static subtree; external connections, nested frames, forms and workers remain blocked. Website previews retain their HTTPS presentation allowance. Opaque-origin RPC, ordinary file delivery, health and WebSocket access remains rejected.
- Extension page operations and selected Run streams use `extensions_methods.py` and short-lived owner/page capabilities. `extensions.page_run` and the Run SSE route read ownership once, then re-verify the page registration before exposing the Run (the replay watermark is read after that check). Canonical history and owned Run detail pass through the existing public payload sanitizer; page metadata is not authority to select another owner or arbitrary RPC method. Coverage: `test_extensions_methods.py`, `test_app.py`, `test_file_delivery.py`.
- Clients command through RPC/HTTP, never `/ws`; `/ws` must not bridge SSE-only deltas. Public payloads recursively strip `reasoning_meta`, `output_files`, and internal data through one shared projector (signing `/api/files/` URLs when delivery is available); ordinary history filters notes while visible errors/checkpoints/summaries/dividers follow the Chat history contract.
- Handlers projecting history/prompts/catalogs/statistics use named bounded pools, never the Event Loop or default executor - long projections cannot stall SSE/WebSocket delivery. Prompt editor read/write/projection operations use a single-worker RPC pool to preserve serialization; Skill RPCs offload scans and persistence, then apply registry invalidation and publish events on the Event Loop; mutations remain serialized through refresh and publication, including after caller cancellation (`tests/server/rpc/test_operations_methods.py`, `test_skill_methods.py`, `test_skill_manager_methods.py`).
- Session creation is explicit at this boundary; busy sends delegate to the shared Queue rather than accessor-local state. Replay buffers are bounded and process-local - durable recovery uses Session history.
- `ServerEventBus.publish` may be called from any thread, including worker pools and core callbacks: the bus hands off-loop events to its own Event Loop, so publishers and bridges never marshal themselves (`server/events-and-reconnect.md`).
- Tool display `image_files` references use the same signed original-file delivery. Public projection removes raw references and emits compact `images` URLs; it stats the original without reading or copying image bytes, and missing originals still get URLs so the ordinary 404 reaches the WebUI placeholder. RPC, SSE, and WebSocket share this projection; without FileDelivery, internal references are stripped.
- Original-file URLs are process-local capabilities regenerated from canonical History after restart. Signed claims include the path and its observed stat revision (device/inode, size, nanosecond modification/change times), so a new Tool result or History projection changes the browser image identity after overwriting the same path. Responses use `no-store`. Revision is cache identity, never a snapshot or a freshness precondition: old URLs still serve the current original; deletion/tampering 404s. Unchanged files keep stable URLs, and reprojecting a restored file replaces a failed thumbnail. Existing mounted images are not polled for external writes. Coverage: `tests/server/test_file_delivery.py` and the mounted Tool-thumbnail revision test.
- `file_delivery.py` separates Chat image embedding from browser disposition: HTML/SVG, PDF, text and recognized media open inline, other binaries download; `?download=true` forces saving with the original filename. Only sniffed text is refined by HTML/SVG suffix. Active documents receive a shared opaque-origin CSP sandbox allowing scripts and HTTPS presentation assets, but blocking application API connections, frames and forms. HTML redirects into the bounded website capability described above; forced downloads preserve the original bytes without injecting the preview bridge. Keep this isolation when extending previews (coverage: `tests/server/test_file_delivery.py`).
- Multipart endpoints enforce limits before spool writes and cover bodyless requests with a total-body bound; JSON RPC and speech-synthesis bodies are also read incrementally against their shared limit before JSON materialization; MIME validates before core services run.

## Constraints & Gotchas

- FastAPI/uvicorn/websockets/multipart are optional dependencies; construction fails clearly when absent.
- Static serving never shadows reserved paths (`/api/*`, `/ws`, `/health`, `/_vbot/control/*`); missing `webui/dist/index.html` unmounts `/` instead of breaking startup.
- A stale control record is not authority: while the listener exists its PID must match, and after the listener closes both PID and process creation time must match the live process. Startup replaces the record atomically; cleanup requires PID and secret ownership. Never expose the token through health/RPC/logs/payloads.
- Runtime stubs must provide the services the server reads directly - no silent fallback construction. Secrets, tokens, and opaque metadata never enter logs or payloads. Endpoint-specific business logic in `app.py` or dispatcher helpers is an ownership error.

Server startup holds `core.utils.server_control.server_control_claim` for the lifetime of its exact data-directory/port target. Because the claim writes into the data directory, `server/main.py` first creates a missing data root with `initialize_data_directory` (data-store bootstrap marker included); an existing root is left to Runtime startup, which refuses it without a marker (`tests/server/test_main.py`). A competing launch cannot publish or remove the existing process's shutdown authority, including when the existing process predates this lock. Regression coverage lives in `tests/core/utils/test_server_control.py`.

# Server

FastAPI transport and public protocol edge around the core vBot kernel.

## Overview

`server/` owns HTTP routing, the RPC envelope, SSE, WebSocket transport, request/response validation and mapping, process startup, and optional static WebUI serving. It imports runtime/core services but owns no business rules - Agent, Chat, Run, Session, Provider, Project, Tool, Skill, Extension, Prompt, Channel, and storage semantics stay in their domains.

`app.py` keeps application assembly, the FastAPI lifespan and the remaining transport routes. `_speech_routes.py` owns speech endpoints, progress/playback streaming and disconnect cancellation; `_upload_routes.py` owns attachment and Skill archive transfers; `_request_bodies.py` enforces their shared bounded JSON and multipart ingress; `_cron_webhooks.py` owns the Cron webhook route `POST /api/hooks/<job id>` and its base URL (`automation/cron-webhooks.md`). These modules register directly on the same app and read its existing Runtime services. Internal `_app_lifecycle.py` owns app-state initialization, core-event subscriptions and cleanup helpers; `_streams.py` owns stream delivery, reconnect projections and presence; `_origins.py` and `_bind.py` own Origin policy and bind resolution. Who may connect at all (Access Modes, credentials, paired Devices, direct TLS) belongs to `server/access/`, which this map does not cover: see `access.md`. `_http_dependencies.py` keeps optional framework availability in one place.

RPC surfaces register their tables in `server/rpc/methods.py`; focused helpers own validation, payloads, errors and event bridging. `chat_methods.py` keeps submission/Run control; `_chat_reads.py`, `_chat_input.py` and `_chat_queue.py` own reads, input/commands and Queue operations. They retain parsed `SessionAddress` through internal helpers and invalidation until transport serialization. Tables define names/parameters/return shapes - do not mirror the catalog here.

`rpc/_mutations.py` owns cancellation-safe mutation sequencing: Settings and Skill handlers each use a state-local lock that spans persistence, live refresh and publication. Cancelling a waiting caller starts no mutation; cancelling an admitted caller waits for its sequence to settle before releasing the lock.

Failures while settling a cancelled mutation remain observable: expected RPC errors log only their code, while unexpected errors retain their traceback. Request parameters are never added to these logs.

The Agent reference lock (`app.state.agent_delete_lock`) is `Runtime.automation_references.lock` (`automation.md`), so core callers that check or create references, such as the Agent Takeover and the cron and calendar Tools' reference changes, serialize with the RPC handlers below.

Private Skill mutations (including archive uploads) and sharing acquire the existing Agent reference lock before the Skill mutation lock. Scope validation, persistence, invalidation and publication remain protected against Agent rename/delete, including cancellation settlement; cancellation while waiting for either lock starts no mutation. Global Skill writes do not acquire the Agent reference lock (`tests/server/rpc/test_skill_methods.py`).

Agent create/update/rename/delete likewise enter through the reference lock before cancellation-safe mutation admission; each Agent store operation, including its Session work, runs as one unit on the Session database's pool (`ChatSessionManager.run_async`) while resource publication stays on the Event Loop. An admitted operation finishes its worker mutation, Skill invalidation and resource publication before cancellation propagates; a caller cancelled while waiting for the reference lock changes nothing (`tests/core/runtime/test_runtime_skill_lifecycle.py`).

## Transport contracts

- Unexpected dispatch failures are logged with traceback and rethrown internally; the HTTP edge returns status 500 with the normal error envelope, code `internal_error`, and a generic message that withholds exception details (`tests/server/test_app_http.py`).
- `POST /api/rpc` accepts `{method, params?}` JSON, returns `{ok:true,result}` or `{ok:false,error:{code,message,data?}}`; non-JSON media types fail 415 before dispatch. `data` appears only on refusals that carry structured facts for accessors to present in their own words (`RpcError(..., data=...)`; for example `session_in_use`, the four archive codes (`archive/rpcs.md`) and a directory listing's `data.reason` (`server/path-pickers.md`)); clients branch on `code`, never on `message` text. `app.py::_rpc_response` encodes every answer as FastAPI would; one whose text holds lone surrogates gets U+FFFD for each instead of failing (`test_rpc_answers_replace_lone_surrogates_instead_of_failing`).
- `GET /api/runs/{id}/events` is the per-Run SSE stream (complete events plus deltas). Run RPC responses (`chat.send`, `chat.edit`, `chat.cancel`, ...) carry the Run's retained `events` and `controls_sequence` (`Run.last_sequence`); once the Run finished, both SSE replay and those `events` hold only its settled ending (`runs.md` -> Finished-Run replay retention), so accessors take earlier output from live streams or durable History. The shared `/ws` socket is server-push only: lifecycle summaries, reconnect state, presence, `resource_changed`. Both preserve explicit `contributes_to_agent_activity: false` while omitting the default true - transport never decides attention.
- `/ws/logs` (handoff in `logs.md`) and `/ws/terminals/{id}` (ANSI snapshot then ordered PTY events; the operator's input and resize requests arrive on the same socket and are applied in order by `server/_terminal_socket.py`; other control via `terminal.*` RPCs) are dedicated streams outside the shared bus.
- Binary data stays outside RPC: dedicated attachment/speech/image/Skill-archive endpoints (semantics in their maps) plus capability URLs such as `GET /api/files/{token}`, a stateless per-process HMAC over the canonical path, never a caller-supplied path (`server/browser-capabilities.md`).
- **`/health` identity contract:** HTTP 200 with body exactly `{"status":"ok"}` is what CLI/Desktop probes require before treating a listener as vBot.
- `POST /_vbot/control/shutdown` is the private cooperative stop edge of the local CLI: it requires the current per-process secret from the owner-only `<data_dir>/runtime/server-<port>.json` and is therefore exempt from the access guard's credential check. Never expose that token through health, RPC, logs or payloads.
- `server/main.py` owns the process's single INFO start line and single stop line (`logging.md`) and its exit statuses, which a supervisor must not answer with a restart (`server/process-lifecycle.md`).

## Source routing

- Register RPC handlers in the domain-appropriate tables of `server/rpc/methods.py`, never a parallel dispatcher. `dispatcher.py::dispatch_method` measures registered methods as `rpc.<method>` (`performance.md`); unknown names are rejected before measurement. `dispatch_rpc` logs refusals at WARNING using registered names or fixed unknown/invalid categories. `_OWNER_LOGGED_ERROR_CODES` suppresses expected refusals already logged by their owner (currently `settings_conflict`, `settings.md`); a `routine` `RpcError` logs at DEBUG (currently path-picker failures, `server/path-pickers.md`).
- Feature RPC contracts: the server's own files are in References; archive -> `archive/rpcs.md`; Librarian -> `automation/librarian.md`; access and Devices -> `access/accessor-contracts.md`; credentials -> `secrets.md` -> Credential RPCs; Agent Secrets -> `secrets.md` -> Agent Secrets; Live -> `model_tasks/live.md`; Portals -> `tools/portal.md`. `model_methods.py` handles Model/routing RPCs; ProviderRuntime owns refresh policy/tasks (`providers/catalog-discovery.md`); connection/credential mutations stay in `connection_methods.py`. Task-model and local-speech handlers live in `task_model_methods.py`.
- `payloads.py` owns common projections, recursive opaque-metadata stripping, and uniform `output_files` -> Markdown URL replacement; `error_mapping.py` converts typed domain errors to stable codes clients branch on instead of message text - missing resources use `<resource>_not_found` (`AgentNotFoundError` -> `agent_not_found`; Skill handlers raise `agent_not_found` for unknown owner/receiver/scope Agents and `skill_not_found` for unknown or unowned Skills), and resolver failures for a missing Agent or Project (`ResolutionAgentNotFoundError` / `ResolutionProjectNotFoundError`) map to the same `agent_not_found` / `project_not_found` codes wherever a handler surfaces the resolver error (chat send/stream/edit, `prompt.preview`, Session and command methods, Bootstrap and Cron jobs), while other resolution failures (plain `AgentResolutionError`: no usable Model, unavailable temporary Session) stay `domain_error`; bare `KeyError` stays unexpected - logged with traceback and rethrown as internal failure, never a domain envelope.

## Invariants & conventions

- Both Settings mutation surfaces and the `task_model.update`/`task_model.patch_options` binding mutations call `Runtime.apply_settings_change` after persistence under the shared `_settings_mutation_lock` and publish invalidation from its `SettingsChangeEffects`; RPC handlers never decide which live reload subsumes another (`settings.md`, `runtime.md`).
- The server is an edge, not a second business layer: validate/map, call the owning domain, coordinate cross-domain mutations only where the public operation requires it, publish invalidation after success.
- The access guard (`access.md`) runs first on every HTTP request and WebSocket, including its Host-name check against DNS rebinding, then the browser-origin guard, then routing. The browser-origin guard runs before routing on HTTP and WebSocket: foreign/opaque/malformed/duplicate origins fail closed. A concrete bind accepts its configured origin. Every bind also accepts the access guard's known server names, and wildcard binds accept IP literals, when Origin exactly matches the request scheme, Host authority and configured port; this supports LAN names and IPv4/IPv6 without admitting DNS-rebinding hostnames. Origin-less requests (CLI, Desktop Voice) stay valid. In the Access Mode `authenticated` the configured public origin is accepted as well. Never replace this with CORS response headers - they do not stop CORS-simple requests.
- Opaque-origin requests (`Origin: null`) are admitted only for GET/HEAD under `/api/preview-assets/` and `/api/extension-assets/`, each verifying its own capability; opaque-origin RPC, ordinary file delivery, health and WebSocket access stay rejected (`server/browser-capabilities.md`).
- Clients command through RPC/HTTP, never `/ws`; `/ws` must not bridge SSE-only deltas. Public payloads recursively strip `reasoning_meta`, `output_files`, and internal data through one shared projector (signing `/api/files/` URLs when delivery is available); ordinary history filters notes while visible errors/checkpoints/summaries/dividers follow the Chat history contract.
- Settings, Connection and Extension management reads/persistence use bounded workers; live registry installation, readiness callbacks and event publication stay on the Event Loop. Public Settings/Connection catalogs share the Settings mutation lock across their complete read projection, so a concurrent Custom Provider deletion cannot mix old identifiers with a replacement registry. Internal mutation response builders reuse the caller's lock. `server/rpc/_mutations.py::serialized_read` and `state_lock` expose this ordering; read cancellation still drains any admitted worker before releasing it.
- Handlers projecting history/prompts/catalogs/statistics use named bounded pools, never the Event Loop or default executor - long projections cannot stall SSE/WebSocket delivery. Prompt editor read/write/projection operations use a single-worker RPC pool to preserve serialization; Skill RPCs offload scans and persistence, then apply registry invalidation and publish events on the Event Loop; mutations remain serialized through refresh and publication, including after caller cancellation (`tests/server/rpc/test_operations_methods.py`, `test_skill_methods.py`).
- Session creation is explicit at this boundary; busy sends delegate to the shared Queue rather than accessor-local state. Replay is process-local; Sessions owns durable History and ordinary input receipts (`server/chat-rpcs.md`).
- `ServerEventBus.publish` may be called from any thread, including worker pools and core callbacks: the bus hands off-loop events to its own Event Loop, so publishers and bridges never marshal themselves (`server/events-and-reconnect.md`).
- Multipart endpoints enforce limits before spool writes and cover bodyless requests with a total-body bound; malformed multipart syntax returns 400, and failed, incomplete or cancelled parsing closes every unclaimed spool. JSON RPC and speech-synthesis bodies are also read incrementally against their shared limit before JSON materialization; MIME validates before core services run.

## Constraints & Gotchas

- FastAPI/uvicorn/websockets/multipart are optional dependencies; construction fails clearly when absent.
- The built WebUI serves as SPA (without `webui/dist/index.html`, `/` stays unmounted); its document sends no-store so Desktop WebView profiles refresh, other files keep ordinary delivery. The fallback uses the access guard's `is_server_path` predicate to avoid shadowing reserved paths (`access.md` -> Constraints & Gotchas). A WebUI path with a backslash, colon, NUL, empty or dot segment is refused from its text before any file access (`_webui_relative_parts`): on Windows, resolving a UNC path contacts its host.
- Runtime stubs must provide the services the server reads directly - no silent fallback construction. Secrets, tokens, and opaque metadata never enter logs or payloads. Endpoint-specific business logic in `app.py` or dispatcher helpers is an ownership error.
- The lifespan initializes the event bus, Client registry, Agent reference lock and normalized server bind before serving requests. Their consumers require those fields; bridge unsubscribe handles are callables until cleanup sets them to `None`. Test doubles follow the same Runtime and app-state contract (`tests/server/test_app.py`, `test_websocket_handshake.py`).

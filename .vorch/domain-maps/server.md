# Server

FastAPI transport and public protocol edge around the core vBot kernel.

## Overview

`server/` owns HTTP routing, the RPC envelope, SSE, WebSocket transport, request/response validation and mapping, process startup, and optional static WebUI serving. It imports runtime/core services but owns no business rules - Agent, Chat, Run, Session, Provider, Project, Tool, Skill, Extension, Prompt, Channel, and storage semantics stay in their domains.

`app.py` keeps HTTP routes, upload/JSON input limits and the FastAPI lifespan. Internal `_app_lifecycle.py` owns app-state initialization, core-event subscriptions and cleanup helpers; `_streams.py` owns stream delivery, reconnect projections and presence; `_origins.py` and `_bind.py` own Origin policy and bind resolution. `_http_dependencies.py` keeps optional framework availability in one place. These remain parts of the same transport edge.

RPC bodies group by owning surface under `server/rpc/*_methods.py`; envelope dispatch, validation, payload sanitation, expected-error mapping, and event bridging live in focused support modules. The registered method tables are the source of truth for names/parameters/return shapes - do not mirror the method catalog here.

`rpc/_mutations.py` owns cancellation-safe mutation sequencing: Settings and Skill handlers each use a state-local lock that spans persistence, live refresh and publication. Cancelling a waiting caller starts no mutation; cancelling an admitted caller waits for its sequence to settle before releasing the lock.

Failures while settling a cancelled mutation remain observable: expected RPC errors log only their code, while unexpected errors retain their traceback. Request parameters are never added to these logs.

The Agent reference lock (`app.state.agent_delete_lock`) is `Runtime.automation_references.lock` (`automation.md`), so core callers that check or create references, such as the Agent Takeover and the cron and calendar Tools' reference changes, serialize with the RPC handlers below.

Private Skill mutations (including archive uploads) and sharing acquire the existing Agent reference lock before the Skill mutation lock. Scope validation, persistence, invalidation and publication remain protected against Agent rename/delete, including cancellation settlement; cancellation while waiting for either lock starts no mutation. Global Skill writes do not acquire the Agent reference lock (`tests/server/rpc/test_skill_methods.py`).

Agent create/update/rename/delete likewise enter through the reference lock before cancellation-safe mutation admission; each Agent store operation, including its Session work, runs as one unit on the Session database's pool (`ChatSessionManager.run_async`) while resource publication stays on the Event Loop. `agent.list`/`agent.get`/`agent.reorder` run on the same pool because Agent reads verify, and may repair, a current-Session pointer. An admitted operation finishes its worker mutation, Skill invalidation and resource publication before cancellation propagates; a caller cancelled while waiting for the reference lock changes nothing (`tests/core/runtime/test_runtime_skill_lifecycle.py`).

## Transport contracts

- Unexpected dispatch failures are logged with traceback and rethrown internally; the HTTP edge returns status 500 with the normal error envelope, code `internal_error`, and a generic message that withholds exception details (`tests/server/test_app_http.py`).
- `POST /api/rpc` accepts `{method, params?}` JSON, returns `{ok:true,result}` or `{ok:false,error:{code,message,data?}}`; non-JSON media types fail 415 before dispatch. `data` appears only on refusals that carry structured facts for accessors to present in their own words (`RpcError(..., data=...)`; today `session_in_use` and the four archive codes below); clients branch on `code`, never on `message` text. A directory listing's `domain_error` carries `data.reason` (`filesystem.list`, `files.list`; Source routing).
- `GET /api/runs/{id}/events` is the per-Run SSE stream (complete events plus deltas). Run RPC responses (`chat.send`, `chat.edit`, `chat.cancel`, ...) carry the Run's retained `events` and `controls_sequence` (`Run.last_sequence`); once the Run finished, both SSE replay and those `events` hold only its settled ending (`runs.md` -> Finished-Run replay retention), so accessors take earlier output from live streams or durable History. The shared `/ws` socket is server-push only: lifecycle summaries, reconnect state, presence, `resource_changed`. Both preserve explicit `contributes_to_agent_activity: false` while omitting the default true - transport never decides attention. Reflection Runs carry `source_session_id` from their admission for attribution.
- `/ws/logs` (handoff in `logs.md`) and `/ws/terminals/{id}` (ANSI snapshot then ordered PTY events; the operator's input and resize requests arrive on the same socket and are applied in order by `server/_terminal_socket.py`; other control via `terminal.*` RPCs) are dedicated streams outside the shared bus.
- `server/main.py` disables per-message compression for all incoming WebSocket connections (`ws_per_message_deflate=False`), avoiding synchronous DEFLATE work on the Event Loop at the cost of larger wire payloads. Message contents, ordering and replay contracts are unchanged. This server setting does not configure outbound Provider connections or HTTP/SSE compression. Startup coverage: `tests/server/test_main.py`.
- Shutdown ordering: `server/main.py` sets the `shutdown_event` injected into `create_app` on control shutdown, scheduled restart or a signal. Ordinary and Extension Run SSE streams end and unsubscribe first; uvicorn then drains HTTP work for at most 5 seconds (`timeout_graceful_shutdown`) before lifespan teardown closes the Runtime and cancels Runs in its dependency order. The deadline bounds transport draining, not the Runtime's service cleanup. Coverage: `tests/server/test_main.py`, `test_sse.py`.
- Binary data stays outside RPC: dedicated attachment/speech/image/Skill-archive endpoints (semantics in their maps) plus `GET /api/files/{token}` serving Assistant-referenced originals - the token is a stateless per-process HMAC capability over the canonical path, never a caller-supplied path or copied blob. Non-image Markdown links include the canonical native path as an escaped title for accessor display/copy; the signed URL remains the delivery address (`tests/server/test_file_delivery.py`).
- Static website previews extend `file_delivery.py`: `file.preview_open` in `operations_methods.py` accepts an absolute HTML entry path or an existing signed file URL and grants a domain-separated, per-process capability to the entry's parent directory. `file.preview_revision` scans a bounded website tree off the Event Loop; `/api/preview-assets/{token}/{path}` serves allowed website file types, rejecting traversal, hidden/private paths, symlinks/junctions and excluded dependency folders. Relative assets, modules, data fetches, subpages and HTTPS presentation assets work; server execution and root-relative website routing are outside this contract. Opening a delivered HTML file redirects to the same website URL; standalone pages poll the capability-scoped `.revision` endpoint for live updates, while embedded pages leave polling to the WebUI. Unavailable standalone pages retain a visible HTTP status and probe their own URL with HEAD until it returns; recovery connections require a valid signed capability even while the directory is temporarily missing, and each asset request still validates the current tree. HTML responses announce their location to the parent for reload recovery; the WebUI validates that message against the active frame and capability prefix. Evidence: `tests/server/test_file_delivery.py`.
- `GET /api/oauth/callback` (`_oauth_callback.py`) is where the browser returns from an Extension's OAuth sign-in: it hands the query to `runtime.oauth_redirects.deliver` (`extensions.md` -> OAuth browser redirects) and answers with a small static page (200 `Sign-in received`, else 400 `Sign-in not found`; a repeated query parameter is refused before delivery). The page loads nothing and sends `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and a `default-src 'none'` CSP, because its address carries the authorization code. The lifespan binds the callback URL from the resolved bind: wildcard and `127.0.0.1` binds publish `http://127.0.0.1:<port>/api/oauth/callback`, `::`/`::1` publish `[::1]`, `localhost` publishes `localhost`, any other listen host publishes none. Evidence: `test_oauth_callback_completes_only_the_awaited_sign_in` in `tests/server/test_app_http.py`.
- **`/health` identity contract:** HTTP 200 with body exactly `{"status":"ok"}` is what CLI/Desktop probes require before treating a listener as vBot. Built WebUI assets serve as SPA when present; the entry document sends no-store so persistent Desktop WebView profiles always refresh, individual static files keep ordinary delivery.
- `POST /_vbot/control/shutdown` is the private cooperative lifecycle edge letting the local CLI trigger normal lifespan teardown; it requires the current per-process secret from `<data_dir>/runtime/server-<port>.json`. An optional `X-VBot-Stop-Initiator` header names the caller (`STOP_INITIATORS`: `cli`, `scheduled_restart`, `tray_stop`, `tray_restart`, `tray_quit`, `update`); a missing or other value reads `unknown`, and `request_shutdown(initiator)` receives it. The transport-neutral `core/utils/server_control.py` owns secret comparison, atomic persistence, PID plus process-creation-time identity for the post-listener shutdown window, and exact-owner cleanup.
- `application.update_continuation` is the private application-control RPC of an update: it requires the current server-control token and exact update operation id. The update stops the server without asking it about its work (`cli/application.md` -> Update operation). A handoff ticket is honored only when its Session durably holds the named Tool call with its result, checked by Sessions' single indexed `tool_result_persisted_async` probe off the Event Loop rather than a transcript load. `application.update_continuation` checks the ticket and creates its Bootstrap job, which selects the ticket's Session, under the Agent reference lock (`tests/server/rpc/test_application_methods.py`).
- `application.update_handoff_mint { handoff_token }` -> `{ handoff_ticket }` (absolute ticket path) is the one application RPC without the server-control token: the live shell-command token from `VBOT_UPDATE_HANDOFF` is its whole authorization and only accepted parameter, and ticket identity comes solely from the server-side record of the issuing Tool call. Unknown or released tokens fail with `invalid_request`; repeated claims return the same ticket. Lifecycle -> `cli/application.md` -> Agent handoff.
- `server/main.py` also supplies an optional app-state restart callback. It reuses
  the detached CLI lifecycle helper for its exact bind/data directory, waits for
  its own PID to exit, and schedules cooperative shutdown after the RPC response.
  Local-speech setup admits restart only after verification; embedded apps without
  this callback report restart unavailable. See `model_tasks/speech.md` and
  `tests/server/test_main.py`.
- `create_app(on_ready=..., on_stopped=...)`: `on_ready(runtime)` runs once at the end of lifespan startup, before uvicorn accepts connections; `on_stopped(runtime_stopped_cleanly)` runs once at the end of lifespan shutdown, after the Runtime closed, even when teardown raised, and receives whether the Runtime shut down without a failed step (`False` too when an earlier teardown step raised before it). The lifespan reports a failed Runtime shutdown only that way and does not raise it: the Runtime already logged each failed step with its name and traceback (`runtime.md` -> Shutdown), and uvicorn would log the same traceback again as `Application shutdown failed`. Only `server/main.py` passes them. Its ready hook sets the GIL switch interval to 0.5 ms (below Windows' 1 ms wait, see `performance.md` -> Constraints & Gotchas), then runs a full `gc.collect()` and then `gc.freeze()` (DEBUG `Startup heap frozen (objects=... collect_ms=...)`), then writes the start line. Later cyclic collections skip the frozen startup objects (modules, classes, Runtime services); otherwise every collection of the old generation traverses them while holding the GIL and stalls the Event Loop. Frozen objects that later become unreachable cyclic garbage are never collected, which bounds the cost to the startup heap. Test and embedded apps omit the hook, so a test process never freezes its heap (`tests/server/test_app.py`, `tests/server/test_main.py`).

## Source routing

- Handler modules map one-to-one to product surfaces (`agent_methods`, `session_methods`, `chat_methods`, `project_methods`, `channel_methods`, `automation_methods`, `connection_methods`, `model_methods`, `provider_usage_methods`, `settings_methods`, `task_model_methods`, `extensions_methods`, `catalog_methods`, `filesystem_methods`, `skill_methods`, `operations_methods`, `terminal_methods`, `performance_methods`, `recall_methods`, `archive_methods`, `learning_methods`, `librarian_methods`, debug/statistics/clients); add handlers to the domain-appropriate registry - never a parallel dispatcher over `methods.dispatch_rpc`. `dispatcher.py::dispatch_method` measures every registered method as `rpc.<method>` (`performance.md`); unknown names are rejected before measurement so request input cannot add metric names. `dispatch_rpc` logs each rejected request at WARNING (`RPC request rejected (method=... code=...)`), except codes in `_OWNER_LOGGED_ERROR_CODES`: expected refusals the caller resolves itself and the owner already logs (today `settings_conflict`, `settings.md`).
- `session_methods.py` owns canonical Session RPCs (listing, activity/read state, create/delete/fork, title, Compaction policy, Agent overrides and Channel link). `session.create` accepts optional `agent_overrides` (`model`, `thinking_effort`, `temperature`, `top_p`; an unusable Model fails before the Session exists) and an optional `working_project_id` (`validation.py::_optional_working_project`; `sessions.md` -> Terms -> Working Project: omitted -> the Agent's default Project, `null` -> the Workspace, a Project id -> that Project; an unknown Project -> `project_not_found`, a default Project that no longer exists -> `domain_error`, any value for a Team Agent address -> `invalid_request`), and its result names the new Session's `working_project_id`; `session.set_agent_overrides {agent_id, session_id, agent_overrides}` sets or clears (`null`) single fields and returns the stored overrides plus their `effective` values; both write through `AgentResolver.update_session_overrides` (`projects/resolution.md`). `session.activity_list` answers every requested Agent address from one Sessions read without resolving Agents; an address without completed live Sessions, including an unknown Agent, returns an empty list. `session.get` point-reads one live Session's list summary (`{session: null}` when absent) without Compaction Policy or active-Run fields. `session.list` and `session.get` rows carry the Session's `working_project_id` (`null`: the Workspace), its stored `agent_overrides` when it has any, and its `change_stats` totals when its Runs changed files, and `session.change_stats {agent_id, session_id}` returns them with the changed files (`{change_stats: null}` when none; `sessions.md` -> Interfaces). Channel-link and Compaction Policy changes use Sessions' atomic `mutate_metadata_with_previous` rather than replacing an earlier metadata snapshot; that mutation also rejects a missing Session, so neither handler reads the Session first. A Project Agent's delete landing is Sessions' `newest_session_id`, `null` when none remains; no Session is created for a landing (an Identity Agent's is its re-aimed current pointer, `archive.md`). `session.delete` names the archived and landing Session ids in its scoped `sessions` invalidation so other windows can leave the archived Session (`server/events-and-reconnect.md`). Under the reference lock it refuses a Session that `Runtime.automation_references` reports as selected by a live Bootstrap job, Cron job or Calendar action (`automation.md`) with `session_in_use`: `message` names them as `kind:id`, `data.references` lists `{kind, id, name}` (job name, or the title of the action's event) for accessors (`tests/server/rpc/test_session_methods_delete.py`). Agent delete and Project removal need no such check: their reference guards (`agent_references` / `project_references` of the same owner) already refuse every live job and action targeting the Agent or Project; server RPC handlers apply no liveness rules of their own. Agent configuration/lifecycle stays in `agent_methods.py`; `agent.update` accepts `current_session_id: null` to clear the pointer (a new conversation, `agent.md`), and Agent payloads carry `current_session_id: null` while it is empty. Both run their blocking Session and Agent store work on the Session database's pool (`ChatSessionManager.run_async`, or the Sessions async API) and resolve Agents through `AgentResolver.resolve_agent_async`; the RPC layer owns no pool for Session work, so a closed Session database surfaces as `domain_error` (`tests/server/rpc/test_session_methods.py`). `model_methods.py` owns Model catalog/routing/database-refresh handlers and their background refresh tasks; connection/credential mutations stay in `connection_methods.py`. Task-model and local-speech handlers live in `task_model_methods.py`. All three tables register directly in `methods.py`, preserving one dispatcher and the existing RPC names.
- `data_store_methods.py` exposes the operator-safe `data_store.status`, `data_store.snapshot_create` (`reason`: `manual`, `rpc`, `update` or `recovery`; returns `{snapshot}`; a failed attempt's error carries the recorded snapshot-health reason), `data_store.incident_acknowledge` (returns the new status; an unknown incident is `invalid_request`), and `data_store.unregister` (`name` of a registered Extension database; returns `{unregistered: {name, database_id, quarantine}}` via `Runtime.unregister_extension_database`; a core or unregistered name is `invalid_request`, an open database `domain_error`) RPCs. It delegates to the database kernel (`database.md`) with `Runtime.canonical_databases()` on its own bounded worker pool, returns no database content, and publishes `resource_changed(kind="data_store")` after successful mutations. `error_mapping.py` maps every kernel `DatabaseError` to `domain_error` and a superseded acknowledgement (`IncidentConflictError`) to `invalid_request`.
- Background activity: `server/activity.py` `ActivityMonitor` (built in `_initialize_app_state` as `app.state.activity`, started and closed in the lifespan) lists the long-running server work Settings > General shows in one place. Once per second it reads, from memory only, the owners' reports - `SpeechService`/`EmbeddingService.local_activities()` (each `LocalSetup.activity()`), `ChannelService.setup_activities()` (WhatsApp support installs) - plus the semantic Recall status the existing Recall listener bridge feeds it (`set_recall_status`), and publishes `activity_status {activities}` only when the list changed. An entry is `{id, kind, label, state, phase, error, message, progress?, target?, task_type?, eta_seconds?}`: `kind` `local_model_install` (id `local_setup:<target>`), `whatsapp_setup` (`whatsapp_setup:<channel>`) or `recall_index` (`recall_index`); `state` `running|action_required|failed|completed`, sorted in that order; `progress {completed, total, unit}` with `unit` `bytes` or `items`. A Recall indexing pass appears only from `RECALL_BACKLOG_SHOWN` (50) waiting texts and then stays until it ends, also while `retrying` (phase `retrying`); a Recall `error` is a failed entry. Owners keep reporting finished work as `completed` (`LocalSetup` after an install in this process, WhatsApp `ready`, Recall `idle`); the list shows it for `COMPLETED_VISIBLE_S` (8 s) only when the same id was running in the previous tick. Work that stops running without such a report, such as a cancelled installation, leaves the list at once. Failed and restart entries stay until the work runs again, is no longer reported, or a client dismisses them; a dismissal hides the entry for every client until then and never changes the work. The list is server memory only. `activity_methods.py` serves `activity.list {}` and `activity.dismiss {id}`, both returning `{activities}`. Cancel goes through the owner (`task_model.local_setup_cancel`, `model_tasks.md`). Tests: `tests/server/test_activity.py`.
- `recall_methods.py` serves `recall.status` and `recall.rebuild_index` (no parameters; both return `IndexStatus.to_dict()` from `Runtime.recall`, the rebuild after dropping every vector) and leaves the indexing schedule to Recall (`recall.md` -> Semantic Indexing). The archive service evicts an archived Agent's scope, or an archived Session, from the Recall index after the archive, best effort (`archive.md`, `tests/core/archive/test_archive_service.py`).
- `archive_methods.py` serves the archive (`archive.md`): `archive.list` (filters `kind`, `agent_id` (an `agent@project` address also sets the Project), `project_id`, JSON `cursor`, `limit` 1-200, default 50) returns `{entries, next_cursor, retention_days, retention_unknown}` (`retention_unknown: true`: vBot cannot read the period, deletes nothing for retention, and `retention_days` and every `purge_at` are `null`), each entry with `origin`, `purge_at`, `restorable`, `not_restorable_reason` and `may_hold_user_folders`; `archive.show` (`session_limit` 1-500, default 100) adds the member Sessions, the payload trees with `user_folder` marks, the recorded details (an external Workspace's `details.workspace.path` is absolute) and the full restore check (`restore.possible`, `target_id`, `blockers`, `warnings`); `archive.restore {entry_id, target_id?}` runs under `_guard_agent_lifecycle`, returns the restored id or Session address, `grant_agent_ids` and the `warnings` (each problem with its facts, like `archive.show`), and publishes the agents, projects or scoped sessions invalidation of what it restored; `archive.purge` takes exactly one of `entry_ids` (1-100) or `all: true` with the list filters and returns `{purged, pending, skipped, gone, kept}`; a pending entry (`{entry_id, reason}`: `usage_import_failed`, `stopped` or the failure's exception class) began its deletion, the retention sweep continues it, and a later purge continues it at once (`archive.md` -> Retention); a skipped entry (`{entry_id, reason, state}`, reason `busy`, `usage_import_failed` or a failure's class) was not deleted and stays as it is; `gone` lists the ids another operation deleted or restored first; `kept` (`{entry_id, reason}`, reason `files` or `user_folders`) lists the matching entries `all: true` never deletes because they may hold the user's folders. Expected archive errors map to `archive_entry_not_found` (`data.entry_ids`), `archive_entry_busy` (`data.entry_id`, `state`; from a restore check or a named purge also `message`, what that state means for the caller, and for an interrupted restore that cannot finish `path` and `problem`), `archive_restore_conflict` (`data.entry_id`, `kind`, `conflicts`, `fix: "target_id"`: retry with another `target_id`) and `archive_not_restorable` (`data.entry_id`, `blockers`); each problem carries `code`, `message` and its facts. `agent.delete`, `project.rm` and `session.delete` accept `permanent: true`: they archive as before, then purge the entry they created after releasing the reference lock (`purge_permanently`), and every delete result carries `archive_entry_id` (always the entry's id), `purged`, `purge_pending` and `purge_reason` (`null` once purged or without `permanent`; the pending reason, `busy`, `gone`, or a failure's class otherwise; a failing permanent purge never fails the delete); `agent.delete` also returns `session_count` and `external_workspace` (the absolute path of a Workspace outside the Agent's own directory, left in place), `project.rm` `session_count`. The CLI reads these deletes, `archive.restore` and `archive.purge` without a response deadline (`cli.md`). Tests: `tests/server/rpc/test_archive_methods.py`.
- `librarian_methods.py` serves `librarian.status {agent_id}`, `librarian.run {agent_id}` and `librarian.overview {}` (`automation/librarian.md`): a busy Agent, a running pass or a busy Librarian -> `agent_busy`; an Agent no pass can run for (the Librarian unavailable, its switch off, no Skills of its own) or the Librarian itself -> `invalid_request`.
- `learning_methods.py` serves the Memory and Skill changes of one Run of an Identity Agent (`automation.md` -> Reflection): `learning.changes {agent_id, run_id}` -> `{agent_id, run_id, summary {memory, skills, undone}, changes}` and `learning.undo {agent_id, run_id}` -> the same shape after the undo. Both resolve the Agent's Workspace under the Agent reference lock and work on the `learning-rpc` pool; undo is a serialized mutation, records its reverts as `rpc`/`human`, and publishes `resource_changed(kind="memories", scope {agent_id})` and, after invalidating the Agent's Skills, `skills` for the stores it changed (both when a failed undo may have written). A refusal over a later change is `learning_undo_conflict` with `data {store, revision, later {revision, at, actor, run_kind?}, scope, text}` (Memory) or `{store, revision, later, skill}` (Skill); a Run that is still running is `active_run` with `data {run_id}`; other learning errors are `domain_error`. `chat_methods` adds each finished review row's `outcome` (the summary) to `reflection_runs` (`server/events-and-reconnect.md` -> Reflection recovery). Tests: `tests/server/rpc/test_learning_methods.py`.
- Chat submission target: `chat.send`/`chat.stream {agent_id, content, input_origin?, file_mentions?}` name exactly one of `session_id` (an existing Session) and `new_session` (an object asking for a new Session), else `invalid_request`. `new_session` accepts only `agent_overrides`, validated like `session.create`'s but without `null` values (`validation.py::_optional_agent_overrides`), and `working_project_id`, validated like `session.create`'s: the new Session's Working Project, where its `@`-mentions resolve too. A plain message for a new Session starts through `ChatLoop.start_run_in_new_session` (`chat.md`), which checks the Agent, an override Model and the Provider before the Session exists, so a refused message leaves none (unusable override Model -> `invalid_request`, unknown Agent -> `agent_not_found`, an unknown requested Project -> `project_not_found`, an Agent without a usable Model -> `domain_error`); `@`-mentions pre-allocate its id (`new_session_id()`) because each file snapshot stamps the Session that read it. The created Session publishes a scoped `sessions` change and, for an Identity Agent, becomes the current one with an `agents` change. A slash command for a new Session runs through `CommandDispatcher.execute_for_new_session` (`chat/commands.md`); a Session it created and kept becomes current the same way. Every response names its Session in `session_id`: Run responses, `{queued, session_id, item}` and `command_handled` responses; only a command for a new Session that created none omits it. `session.create` stays for explicit creation (`tests/server/rpc/test_chat_methods_send.py`, `test_chat_methods_commands.py`).
- Server path pickers: accessor and server may run on different hosts, so `filesystem_methods.py` serves `filesystem.list {path?, root?, include_files?}` (default false: directories only) over the whole server filesystem, one directory per call. The listing is owned by `core/utils/directory_listing.py` (`list_directory`, and `list_directory_sync` for callers already on a worker): `path` null lists the places (`entries` are the filesystem roots, `C:/`-style drives on Windows or `/`, plus `home`; `path` is `""`); otherwise `path` is absolute, `~` or `~/...`, or with `root` relative to that root (`""` = the root, `..` and links or junctions leading outside it are `invalid_request`), and `path`/`parent` come back in the same form with `/` separators (`parent` null at a filesystem root, at `root` and for the places). Result `{path, parent, entries: [{name, kind: directory|file, link, hidden}], truncated, separator, home?}`: directories first, then case-insensitive name; `link` marks symbolic links and junctions, which can be entered; `hidden` marks dot-names and the Windows hidden attribute; at most `DIRECTORY_LISTING_LIMIT` (5000) entries. A listing runs on its own `directory-listing` pool within `DIRECTORY_LISTING_TIMEOUT_SECONDS` (3 s): a directory that does not answer (an unresponsive share) fails with reason `timeout` and its worker finishes unobserved. Failures are `domain_error` with `data.reason` `not_found`, `not_a_directory`, `unreadable` (exists but cannot be read, never reported as missing) or `timeout`; a relative `path` without `root` is `invalid_request`. On Linux `\` is a name character, not a separator. Tests: `tests/core/utils/test_directory_listing.py`, `tests/server/rpc/test_filesystem_methods.py`.
- Chat `@` file picker: `files.list` returns `{root, files, directories, truncated}`, the index of the mention root that `core/chat/file_mentions.py::list_mention_files` builds with the search Tools' ripgrep selection (`chat/request-building.md`); `directories` are the directories of the listed files, and `truncated` marks the `MENTION_FILE_LIST_LIMIT` file cap or the time budget. With `directory` (relative to the root, `""` = the root; outside it or not a string is `invalid_request`) `files` and `directories` are empty and `entries: [{name, kind: directory|file, ignored}]` lists that directory's direct children, ignored ones included and marked (`list_mention_directory` over `directory_listing`, so `truncated` then refers to the entries); its failures carry the same `data.reason` as `filesystem.list`. A missing root lists as empty in both forms. Tests: `tests/server/rpc/test_catalog_methods.py`, `tests/core/chat/test_file_mentions.py`.
- Working Project of chat reads: `chat.commands`, `prompt.preview` and `files.list` take an optional `session_id` (that Session's Working Project counts) or, without one, a `working_project_id` validated as for `session.create` (the Project a new Session would work in); naming both is `invalid_request` (`validation.py::_draft_working_project`). For a Session whose Working Project no longer exists, `chat.commands` offers no Skills, while `files.list`, `prompt.preview` and every Run start fail with `domain_error` and the `WORKING_PROJECT_MISSING_MESSAGE` text (`projects/resolution.md` -> Working Project resolution). Tests: `tests/server/rpc/test_catalog_methods.py`, `test_operations_methods.py`, `test_session_methods.py`.
- Non-obvious module contracts: `chat_methods` must not match command names or mutate command-owned state (generic projection only), re-aims an Identity Agent's `current_session_id` on plain sends/edits so restarts reopen the last-written session, and obtains each paged folded-History response plus whole-Session Usage from one Sessions read snapshot; `next_before` is the older-page continuation; `next_after` requests bounded appended History records. The whole read, including Compaction Policy, background-status records and reflection Runs, is one Session-pool hop (plus one to resolve an Identity Agent's current Session when `session_id` is omitted; an Identity Agent without one gets an empty newest page with `session_id: null` and no Session read); projecting a changed page (file capabilities, background statuses, Context Usage) then runs on the `chat-rpc` pool, which otherwise only expands `@`-mentions, and an unchanged page skips it. An `after` read that finds nothing appended returns only the cursor fields and omits `session_usage`, `context_usage`, `background_command_statuses`, `compaction_policy` and `reflection_runs`; callers keep their values. Every other read carries `session_usage` and `context_usage` (null when none). `background_command_statuses` (terminal id -> `running`/`completed`/`failed`/`stopped`, `tools/shell.md`) is the complete map on a replacement read and the appended records' delta on an incremental read, with recorded `running` entries replaced by the TerminalManager's current status and commands it no longer knows dropped; a `before` page omits it and `compaction_policy`; `reflection_runs` accompany only reads with neither cursor (`tests/server/rpc/test_chat_methods_history.py`). Responses carry generation, per-record sequence/Run attribution, incremental/reset mode and `has_newer`; an edit or generation change requires snapshot replacement. A public Message id remains accepted for older-page input. `chat.edit` delegates idle-only edit admission to Chat and never falls back to Queue. `agent.rename` holds the reference lock plus both Run guards, refuses open Sub-Agent activity, delegates the whole rename to `Runtime.rename_agent` (`runtime.md` -> Identity Agent rename), and publishes agents invalidation before Sessions/Channels/Cron so accessors remap selection first; `agent_refs.py` keeps the reference-lock and reference-lookup helpers plus `_guard_agent_lifecycle` (the reference lock, then cancellation-safe admission on the Agent lifecycle mutation lock) that Agent create/update/rename/delete and `archive.restore` share; `agent.reorder` serializes against rename/delete via the same lock with stable conflict errors; `payloads.py` owns common projections, recursive opaque-metadata stripping, and uniform `output_files` -> Markdown URL replacement; `error_mapping.py` converts typed domain errors to stable codes clients branch on instead of message text - missing resources use `<resource>_not_found` (`AgentNotFoundError` -> `agent_not_found`; Skill handlers raise `agent_not_found` for unknown owner/receiver/scope Agents and `skill_not_found` for unknown or unowned Skills), and resolver failures for a missing Agent or Project (`ResolutionAgentNotFoundError` / `ResolutionProjectNotFoundError`) map to the same `agent_not_found` / `project_not_found` codes wherever a handler surfaces the resolver error (chat send/stream/edit, `prompt.preview`, Session and command methods, Bootstrap and Cron jobs), while other resolution failures (plain `AgentResolutionError`: no usable Model, unavailable temporary Session) stay `domain_error`; bare `KeyError` stays unexpected - logged with traceback and rethrown as internal failure, never a domain envelope; `file_delivery.py` signs/verifies capabilities keeping no token registry and writing no bytes.
- Statistics methods validate windows, cache the service on app state, and offload reconciliation to workers without owning index semantics. The app wires Session title/completion-read callbacks onto `resource_changed(kind="sessions")`.

## Invariants & conventions

- Both Settings mutation surfaces, and the `task_model.update`/`task_model.patch_options` binding mutations, call `Runtime.apply_settings_change` after persistence under the shared `_settings_mutation_lock`; RPC handlers own validation/projection and publish Command/Extension and Skill invalidation from its `SettingsChangeEffects` result, never decide which live reload subsumes another.
- The server is an edge, not a second business layer: validate/map, call the owning domain, coordinate cross-domain mutations only where the public operation requires it, publish invalidation after success.
- The browser-origin guard runs before routing on HTTP and WebSocket: foreign/opaque/malformed/duplicate origins fail closed. A concrete bind accepts its configured origin; a wildcard bind accepts an IP-literal Origin only when it exactly matches the request scheme, Host authority, and configured port, which preserves LAN IPv4/IPv6 access without admitting DNS-rebinding hostnames. Origin-less requests (CLI, Desktop Voice) stay valid. Never replace this with CORS response headers - they do not stop CORS-simple requests.
- Opaque-origin exceptions are GET/HEAD under `/api/preview-assets/` and `/api/extension-assets/`; each verifies its own domain-separated capability and file boundary. Responses allow CORS only for `Origin: null`, without credentials. Extension assets additionally bind the current owner/page registration and permit only their exact built static subtree; external connections, nested frames, forms and workers remain blocked. Website previews retain their HTTPS presentation allowance. Opaque-origin RPC, ordinary file delivery, health and WebSocket access remains rejected.
- Extension page operations and selected Run streams use `extensions_methods.py` and short-lived owner/page capabilities. `extensions.page_run` and the Run SSE route read ownership once, then re-verify the page registration before exposing the Run (the replay watermark is read after that check). Page validation, before and again after each awaited page-scoped call (so a page never receives a result across a reload or live disable), reads the registry's in-memory page table (`ExtensionRegistry.current_page`) on the Event Loop, never the filesystem or a worker pool. Canonical history and owned Run detail pass through the existing public payload sanitizer; page metadata is not authority to select another owner or arbitrary RPC method. Coverage: `test_extensions_methods.py`, `test_app.py`, `test_file_delivery.py`.
- Clients command through RPC/HTTP, never `/ws`; `/ws` must not bridge SSE-only deltas. Public payloads recursively strip `reasoning_meta`, `output_files`, and internal data through one shared projector (signing `/api/files/` URLs when delivery is available); ordinary history filters notes while visible errors/checkpoints/summaries/dividers follow the Chat history contract.
- Handlers projecting history/prompts/catalogs/statistics use named bounded pools, never the Event Loop or default executor - long projections cannot stall SSE/WebSocket delivery. Prompt editor read/write/projection operations use a single-worker RPC pool to preserve serialization; Skill RPCs offload scans and persistence, then apply registry invalidation and publish events on the Event Loop; mutations remain serialized through refresh and publication, including after caller cancellation (`tests/server/rpc/test_operations_methods.py`, `test_skill_methods.py`).
- Session creation is explicit at this boundary; busy sends delegate to the shared Queue rather than accessor-local state. Replay buffers are bounded and process-local - durable recovery uses Session history.
- `ServerEventBus.publish` may be called from any thread, including worker pools and core callbacks: the bus hands off-loop events to its own Event Loop, so publishers and bridges never marshal themselves (`server/events-and-reconnect.md`).
- Tool display `media_files` references (the images, videos and audio of a call's details) use the same signed original-file delivery. Public projection removes raw references and emits `media` items of `url`, `filename`, `kind` (`image`/`video`/`audio`) and, for a file the call started from, `role: source`; it stats the original without reading or copying bytes, and missing originals still get URLs so the ordinary 404 reaches the WebUI placeholder. Entries without an absolute path or a known kind are dropped. Displays persisted before `media_files` carry `image_files`, projected as images; a reference with a `media_type` instead of a `kind` takes the kind from it. `/api/files/` serves media inline with Range support, so video and audio players can seek. RPC, SSE, and WebSocket share this projection; without FileDelivery, internal references are stripped.
- Original-file URLs are process-local capabilities regenerated from canonical History after restart. Signed claims include the path and its observed stat revision (device/inode, size, nanosecond modification/change times), so a new Tool result or History projection changes the browser image identity after overwriting the same path. Responses use `no-store`. Revision is cache identity, never a snapshot or a freshness precondition: old URLs still serve the current original; deletion/tampering 404s. Unchanged files keep stable URLs, and reprojecting a restored file replaces a failed thumbnail. Existing mounted images are not polled for external writes. Coverage: `tests/server/test_file_delivery.py` and the mounted Tool-thumbnail revision test.
- `file_delivery.py` separates Chat image embedding from browser disposition: HTML/SVG, PDF, text and recognized media open inline, other binaries download; `?download=true` forces saving with the original filename. Only sniffed text is refined by HTML/SVG suffix. Active documents receive a shared opaque-origin CSP sandbox allowing scripts and HTTPS presentation assets, but blocking application API connections, frames and forms. HTML redirects into the bounded website capability described above; forced downloads preserve the original bytes without injecting the preview bridge. Keep this isolation when extending previews (coverage: `tests/server/test_file_delivery.py`).
- Multipart endpoints enforce limits before spool writes and cover bodyless requests with a total-body bound; JSON RPC and speech-synthesis bodies are also read incrementally against their shared limit before JSON materialization; MIME validates before core services run.

## Constraints & Gotchas

- FastAPI/uvicorn/websockets/multipart are optional dependencies; construction fails clearly when absent.
- Static serving never shadows reserved paths (`/api/*`, `/ws`, `/health`, `/_vbot/control/*`); missing `webui/dist/index.html` unmounts `/` instead of breaking startup.
- A stale control record is not authority: while the listener exists its PID must match, and after the listener closes both PID and process creation time must match the live process. Startup replaces the record atomically; cleanup requires PID and secret ownership. Never expose the token through health/RPC/logs/payloads.
- Runtime stubs must provide the services the server reads directly - no silent fallback construction. Secrets, tokens, and opaque metadata never enter logs or payloads. Endpoint-specific business logic in `app.py` or dispatcher helpers is an ownership error.
- The lifespan initializes the event bus, Client registry, Agent reference lock and normalized server bind before serving requests. Their consumers require those fields; bridge unsubscribe handles are callables until cleanup sets them to `None`. Test doubles follow the same Runtime and app-state contract (`tests/server/test_app.py`, `test_websocket_handshake.py`).

`server/main.py` owns the process's single INFO start line and single stop line (`logging.md`). The start line (`Server started (...)`, written by the ready hook) carries the version and the Runtime's build identity (`Runtime.build`: short revision, `release=yes` or the branch), the installed version id when the code runs from `versions/<id>/app`, mode (`normal`/`verification`/`test`), pid, listen address, data directory, startup duration since process creation and `Runtime.startup_summary` (Tools, Skills, usable Providers and Connections, loaded Extensions, keep-awake). The stop line (`Server stopped (reason=... uptime=...)`) is written after Runtime teardown and before uvicorn re-raises a captured signal: `control` with its initiator, `restart` (a restart the server scheduled itself), `signal` with its name (Ctrl+C is `SIGINT`, a closed console `SIGBREAK`), or `startup_failed` at WARN. After a failed Runtime shutdown the stop line adds `shutdown=failed` at WARN. Once its log and control record are closed, the process exits with `STARTUP_FAILED_EXIT_CODE` (3) when the application failed to start (current uvicorn raises its own status 3 itself; for older versions, whose `Server.run` returns, `main()` raises it) and with `SHUTDOWN_FAILED_EXIT_CODE` (70) after a stop whose Runtime shutdown failed; a failed bind still exits 1 from uvicorn, and a signal stop still ends by uvicorn re-raising the signal. Both constants live in `core/utils/server_control.py`: they are the statuses a supervisor must not answer with a restart, and the generated systemd unit lists them in `RestartPreventExitStatus` (`cli/application.md` -> Autostart and server supervision). The process owns a `LogManager` created after `uvicorn.Config` (which closes existing handlers while configuring logging); the Runtime's own manager nests inside it. Right after it, the process enables its crash log (`logging.md` -> Crash logs). uvicorn's lifecycle lines and `Server application ready/stopping` are DEBUG (`tests/server/test_main.py`).

Server startup holds `core.utils.server_control.server_control_claim` for the lifetime of its exact data-directory/port target. Because the claim writes into the data directory, `server/main.py` first creates a missing data root with `initialize_data_directory` (data-store bootstrap marker included); an existing root is left to Runtime startup, which refuses it without a marker (`tests/server/test_main.py`). A competing launch cannot publish or remove the existing process's shutdown authority, including when the existing process predates this lock. Regression coverage lives in `tests/core/utils/test_server_control.py`.

# Video Generation

Task-gated reference for the `video_generation` Task Model and OpenRouter Video execution path.

## Boundary

`core/model_tasks/video.py` owns binding resolution, exact configured-Model capability validation, local frame-image loading, provider-error normalization, and caller-owned artifact persistence. `core/model_tasks/video_providers.py` owns OpenRouter's asynchronous `POST /videos` -> same-origin job polling -> authenticated content download wire. `core/tools/media_generation.py` owns only the Agent Tool schema, effective-cwd path resolution, caller-owned default directory, and result projection.

## Discovery and Options

OpenRouter's ordinary `output_modalities=video` catalog supplies the coarse `video_generation` task tag. The dedicated `/videos/models` catalog is an independent fail-soft enrichment source for exact resolutions, aspect ratios, sizes, durations, frame-image positions, audio generation, seed support, and passthrough keys. Dedicated-catalog-only entries become minimal non-chat Models. Targets need a published `duration` choice and exclude router Models. `VideoProfile` decides the per-call Tool fields and validates their values (`model_tasks/media-profiles.md`); the service rejects unsupported values with the offered choices (`VideoOptionError`, `invalid_arguments`). A requested aspect ratio or resolution drops the Settings `size`.

## Execution Contract

Video creation is non-idempotent and uses the shared outcome-unknown retry policy. The initial response must yield a usable job id inside that policy's parser boundary; a success response without one remains an unknown outcome with its operation key and is never resubmitted automatically. The returned `polling_url` and unsigned storage URLs are never followed; vBot takes only the opaque job id, URL-encodes it, and polls/downloads through the configured OpenRouter base URL so credentials cannot be redirected off-origin. Terminal failed, cancelled, or expired jobs fail; a failure reason that names a content refusal raises `ProviderContentRefusedError`, which the service reports as `VideoRefusedError` (`generation_refused`, reason kept). Completed jobs download index `0`; the media type is sniffed from the bytes. `generate_artifact` checks the output folder before the create request (`OutputDirectoryError`) and writes off the Event Loop (`OutputWriteError` on failure). Generated bytes are written exclusively under the caller-selected directory, defaulting to `<Workspace>/video-gen/` for Identity/Rooted calls and `<effective cwd>/video-gen/` for Project Agent calls.

Polling checks the job every 10 seconds (`VIDEO_POLL_INTERVAL_SECONDS`) for at most 20 minutes; the deadline includes poll intervals, active status requests and their retry waits. A transient status failure keeps polling until the deadline and is named in the timeout reason. Expiry, a non-retryable status failure, and a failed download of the finished video raise `VideoJobUnfinishedError` with the job id; the service reports it as `VideoOutcomeUnknownError(job_id=...)`, and the Tool tells the Agent not to request the same video again and to give the user the job id. None of them submits another generation; caller cancellation remains cancellation. The completed-content download has its own request timeout.

Non-null job statuses must be strings before polling logic inspects them. Malformed initial statuses retain outcome-unknown classification; malformed poll statuses fail as ordinary non-retryable Provider errors without resubmission. Missing/null statuses and unknown string values remain pending rather than claiming an unverified terminal meaning.

Durable `video_generation` accounting starts at each create POST attempt. Poll responses may enrich the accepted create call with reported Usage; status and content GETs never add Model calls. Consumption survives a failed download or artifact write. Tool callers pass their internal execution scope; absent Provider counters or costs remain unknown. `test_task_usage.py` covers polling enrichment followed by download failure.

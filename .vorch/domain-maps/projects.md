# Projects

Owns the Project entity, its `project.json` schema, and the data-dir **anchor** lifecycle. A Project is a first-class entity (GLOSSARY → Project), not a bare cwd.

## Overview

`core/projects/` is one deep module. It owns:

- The **Project entity** and `project.json` shape (`projects.py`).
- **cwd normalization, the duplicate-cwd identity key, and slug derivation** for both project and agent ids (`paths.py`).
- The **anchor lifecycle** in the data-dir: layout, CRUD, archive-on-remove (`store.py`).
- The **pluggable scanner** (`scanners/`), the **scan report** (`scan_report.py`), and **uniform agent resolution + the model chain** (`resolver.py`) — see Scanning & Resolution below.

It does **not** own field validation — that lives in the central settings validator (`core/settings/validation.py`), the same way Agents and Channels validate. The `project_id` backbone through sessions/runs/tools/chat is owned by those domains (see their maps); this module only feeds the project anchor path and cwd into them. The project RPC surface (`project.*`, `server/rpc/project_methods.py`) and the CLI `project` area (`cli/`) call into this module but live in their own domains.

The anchor holds **no run config** — only Sessions ownership and the local agent id. An agent's config comes live from the scan/repo, never from the anchor (design decision #4).

## Data Model

**Project** (frozen dataclass, `projects.py`): `project_id` (stable slug key), `display_name` (changeable), `cwd` (the repo dir tools resolve against — stored in the file, *not* the directory name, so the repo can move without breaking the key or Sessions), `default_agent`, `default_model` (optional pointers; empty string = fall through the resolution chain), `default_temperature` (optional `float|null`) and `default_thinking_effort` (optional `str|null`; `null` = fall through, `""` = provider default) — the project tier of the resolver's temperature/thinking chains, validated through the canonical `core.settings` rules, `source_format` (the project's single coding-agent ecosystem, `"opencode"` or `"claude"` — GLOSSARY → Source Format; default `"opencode"`, vocabulary owned by `core.settings.PROJECT_SOURCE_FORMATS` for the same import-cycle reason as `PROJECT_ID_PATTERN`; an old `project.json` without the field loads at the default), `auto_load` (ordered file list; `AGENTS.md` is seeded as its first entry at creation — see Interfaces), `created_at`/`updated_at` (UTC ISO 8601, `Z` suffix). The minimal valid Project is just a cwd — team and auto-load are all optional (`AGENTS.md` is seeded into `auto_load` at creation but stays a normal removable entry).

**Whitelist fields** (the project as a trust boundary — GLOSSARY → Project Tool Whitelist / Project Skill Whitelist / Ceiling): `allowed_tools` (the Tool Whitelist — the hard ceiling for the team's config agents), `skills_bundled_enabled`, `skills_global_enabled`, and `skills_project_disabled` (the Skill Whitelist *rule*, not a resolved set — `skills_bundled_enabled`/`skills_global_enabled` opt named bundled/global skills in, `skills_project_disabled` turns the project's own scanned skills off). `allowed_tools` seeds and falls back (a field-less old `project.json`) to the **single** base-list constant `PROJECT_DEFAULT_ALLOWED_TOOLS` (`read, write, edit, glob, grep, bash, process, web_fetch, web_search, status, subagent, skill`); an explicit `[]` is a real value (every tool off) and is preserved (`project_from_dict` distinguishes absent from `[]` via an `isinstance(list)` check, never `or`). `skill` is an ordinary, default-on project tool; `memory` (runtime-derived) and the identity-only `skill_manage` are never project tools — the editor hides them via the frontend `PROJECT_TOOL_WHITELIST_EXCLUDED`, and even if `allowed_tools` were ever widened to literally include `skill_manage` (nothing server-side rejects the name), the dispatch-time allowlist (`effective_agent_allowed_tools`) still strips it for any empty-`workspace` agent. The three skill lists default to `[]`. No migration: an old project simply ends up at the base list. These fields are edited only through `project.set` (not `project.add`, which seeds defaults).

**`overrides`** — the per-agent vBot-owned override layer (`dict[str, dict[str, Any]]`, default `{}`), keyed by scanned `agent_id` → an override object with any subset of `{"model", "temperature", "thinking_effort"}`. `model` is a user-facing `<provider>/<model-id>[::connection]`, `temperature` a number, `thinking_effort` an effort string (`""` = force provider default). vBot-owned and data-dir only (never the repo); the resolver applies each overridden field as the **top** tier of the matching config-agent chain (override → repo value → project default → global), so an overridden value wins over the repo-declared one. `OVERRIDE_FIELDS` (in `projects.py`) is the field set; an empty override object is invalid (must set at least one field). File validation is shape-only for `model` (non-empty string, configured-ness is the set-time gate, exactly like `default_model`), and reuses the canonical agent validators for `temperature`/`thinking_effort` (so ranges/levels can never drift). **Not a generic `update`/`project.set` field**: it has its own atomic per-field seam (`set_override` / `clear_override`); `update` only carries the existing map through unchanged so an unrelated edit never drops an override. The model override is set via the `/model` command; the Projects tab shows the model override (with an `x` to clear) per team row.

**Anchor layout** in the data-dir (never in the repo):

```
<data_dir>/projects/<project-id>/
    project.json                 ← the entity above
    agents/<agent-id>/
        sessions/                ← project-scoped session ownership
        workspace/               ← only for a rooted identity agent; config agents never have one
```

`<project-id>` is the directory name and the stable key; the cwd path lives inside `project.json`. Identity agents stay separate under the existing top-level `agents/` — untouched.

## Interfaces

`ProjectStore(data_dir)` — CRUD over anchors:

- `create(project_id, display_name, cwd, *, default_agent, default_model, default_temperature, default_thinking_effort, auto_load)` → `Project`. Rejects a duplicate id and a cwd already claimed by another project. The cwd folder need not exist yet (a bare/missing repo is an open-time concern, not a create-time one). **Seeds `AGENTS.md` as the first `auto_load` entry** (`seed_default_auto_load` in `projects.py` — case-insensitive, idempotent): creation-only, so `update` never re-seeds and a user's removal sticks. Unconditional (seeded even when no `AGENTS.md` exists on disk yet) — rendering is lazy, so a not-yet-present entry costs nothing and loads the moment the file appears.
- `get(project_id)` → `Project` (raises `ProjectNotFoundError`); `exists(project_id)` → bool.
- `list()` → `list[Project]` sorted by id; a single corrupt `project.json` is skipped with a logged warning rather than aborting the listing.
- `find_by_cwd(cwd)` → `Project | None`. The project whose repo cwd equals `cwd`, matched on `cwd_identity_key` (the same realpath + Windows-only case-fold rule as the duplicate-cwd guard), so symlinks/path-case differences still match. cwd is unique across projects, so at most one matches; an empty or unresolvable path yields `None` rather than raising. This is the primitive behind **rooted-identity-agent** detection (an identity agent whose workspace IS a registered repo — see `chat.md`).
- `update(project_id, **changes)` → `Project`. `project_id` is immutable (passing it is an "unknown field" error). Changing `cwd` re-normalizes and re-checks the duplicate guard. Rebuilds through `build_project` so there is one validation path.
- `delete(project_id)` → archive `Path`. Archives the subtree, does not hard-delete.
- `set_override(project_id, agent_id, field, value)` / `clear_override(project_id, agent_id, field)` → `Project`. Atomic per-field read-modify-write over `overrides` (get → copy map → merge/del one field on the agent's override object → rebuild through `build_project` preserving identity/timestamps → atomic write), leaving every other agent and field intact. `set_override` validates the field's shape via `build_project` (a model's configured-ness is the caller's gate, not enforced here). `clear_override` drops one field; clearing the agent's **last** field removes the entry entirely, and clearing an absent field/agent is a no-op success (project returned unchanged, no write). These are the single seam the `/model` command and the `project.set_override`/`project.clear_override` RPCs write through.
- `sessions_dir(project_id, agent_id)` / `workspace_dir(project_id, agent_id)` → the per-agent anchor paths for a project's sessions and rooted workspace.

`paths.py` helpers (the cwd contract):

- `normalize_cwd(cwd)` → `Path`: the **stored, display-facing** absolute cwd — symlinks and `.`/`..` resolved (`os.path.realpath`), trailing separator dropped, **case preserved**. This is what tools resolve against and what the user sees.
- `cwd_identity_key(cwd)` → str: the **comparison key** for duplicate detection. Same resolution as above, then case-folded **only on Windows** (`os.name == "nt"`, NTFS is case-insensitive); POSIX stays case-sensitive (`/srv/A` ≠ `/srv/a`).
- `cwd_exists(cwd)` → bool: whether the cwd currently resolves to a directory (drives the "repo not found → re-point" product behavior).
- `slugify_project_id(display_name)` → str: lowercase → NFKD transliterate/strip non-ASCII → non-`[a-z0-9_-]` runs → single hyphen → trim edge separators → truncate to 64. Raises `ValueError` when nothing slug-worthy remains (caller surfaces as a "not slugifiable" finding).

**Validation seam** (`core/settings/`): `validate_project_data` / `validate_project_file` / `load_validated_project_json` enforce field rules fail-fast with JSON-path diagnostics, mirroring `validate_agent_data` / `validate_channel_data`. `validate_data_dir_config` (the `vbot doctor config` sweep) now also collects `projects/*/project.json`. The store reads through `load_validated_project_json` and maps `SettingsValidationError` → `ProjectError`. The canonical slug rule lives once in `core/settings/settings.py` as `PROJECT_ID_PATTERN` / `is_valid_project_id` (alongside `AGENT_ID_PATTERN`) — placed there, not in `core/projects/`, to avoid an import cycle (`validation.py` needs the pattern; `core.projects` imports from `core.settings`).

## Conventions

- One validation path: both `create` and `update` go through `build_project`, which normalizes the cwd and validates fields; the store never hand-rolls a second check.
- `project.json` is written atomically (temp file + `os.replace`).
- Errors are a small hierarchy on `ProjectError(ValueError)`: `ProjectAlreadyExistsError`, `ProjectNotFoundError`, `InvalidProjectIdError`.

## Constraints & Gotchas

- **cwd normalization is host-explicit, not host-default.** Deployment is Linux, dev is Windows — duplicate detection must agree across both. Stored cwd preserves case; only the identity key folds case, and only on Windows. Changing this risks either false duplicates on POSIX or missed duplicates on Windows.
- **Removal archives, it does not delete.** `delete` mirrors `AgentStore.delete`: `shutil.move` into `<data_dir>/archive/projects/<project-id>/`, replacing any existing archive for the same id (own `projects/` subtree, like the agent (`archive/agents/`) and session (`archive/sessions/`) archives — every archive family lives in its own named root, so ids can never collide across families). **The repo (cwd) is never touched** — removing a project is not deleting a repo.
- **The cwd folder is not validated for existence at create/validate time** — a project key is the slug, not the path, so a moved/missing repo is detected later (`cwd_exists`) and offered a re-point, without losing the project.
- **`project_id` is immutable.** It is the anchor directory name; `update` rejects it as an unknown field rather than silently moving the anchor.
- **Path-traversal in `project_id` is rejected at the path-building choke point, not only at config validation.** The id becomes a path segment under `<data_dir>/projects/`, and `delete` archives that directory with `shutil.move` (over a `shutil.rmtree` of the prior archive) — a separator or `..` id (`../agents`, `/etc`) would let an operation escape the projects subtree and move/remove an arbitrary directory. `_validate_project_id` enforces `PROJECT_ID_PATTERN` inside `_project_dir` **and** the module-level `project_sessions_dir`, the two seams every store and session-path call funnels through (`list()` globs real children, so it needs no guard). Every created id is a `slugify_project_id` slug, so only crafted input is rejected. Tighten id handling here, never just at `project.*` RPC validation. The **agent id** segment is guarded the same way: `_validate_agent_id` enforces `AGENT_ID_PATTERN` inside `project_sessions_dir` and `_agent_anchor_dir`, so `sessions_dir`/`workspace_dir` cannot be made to escape the anchor — defense-in-depth behind the RPC address validation (`parse_agent_address`), mirrored at the session-manager choke points (`ChatSessionManager.sessions_dir`/`_archive_dir`).

## Scanning & Resolution

**Scanner** (`scanners/`) — pluggable, one detector per format, the same seam shape as provider adapters (a new format is a new detector, not a rewrite). `AgentDetector` (`Protocol`) exposes `format_key` + `detect(project_root) -> list[DetectedFile]`; the registry carries an explicit format **rank** (OpenCode = 0, Claude = 1). `scan_project(project_root, *, registry=None, source_format=None) -> ScanResult(team, report)` runs each detector at its known location; when `source_format` is set (the project's single-format truth — GLOSSARY → Source Format), **only the matching detector runs**, so the other format's agents are invisible to every consumer (`None` keeps the unfiltered all-detectors behavior for detection/tests). Each detector stays confined to its known location: OpenCode reads only `.opencode/agents/` non-recursively; the **Claude detector** (`scanners/claude.py`) reads `.claude/agents/**/*.md` **recursively within that directory only** (Claude Code allows subfolders), sorted by relative POSIX path. Nested repos are never swept in. The detector parses its format into one internal **`ScannedAgent`** profile (`agent_id` slug, `display_name`, `description`, raw `model` 1:1, `temperature`, `thinking_effort` (OpenCode's `reasoningEffort`, defensively normalized to vBot's effort ladder; unknown/empty → `None`), verbatim `body`, `denied_tools` (frozenset, default empty), `source_format`, `source_path`); the resolver maps that to the runtime agent. Shared fail-open Markdown/YAML frontmatter helpers (`split_front_matter`, `parse_front_matter`, `string_field`) live in `scanners/base.py`. This is the seam for *all* agent formats — a future identity-bearing format adds a detector that also produces a workspace.

**Claude detector mapping** (`scanners/claude.py`, max-agency, fail-open): `agent_id` = slugified frontmatter `name` when non-empty, else the filename stem. `model` is **always dropped** (`""`) — Claude's vocabulary (aliases like `sonnet`, bare Anthropic ids, `inherit`) is never vBot's `<provider>/<model-id>` form, so dropping avoids `BAD_MODEL` noise; the vBot way to pin a model is the per-agent override layer. `temperature=None`, `thinking_effort=None` (Claude agents carry neither). `denied_tools` = mapped vBot tools of every `disallowedTools` entry ∪ (when a `tools` allow-list is present) the mapped vBot tools of every *mappable* Claude tool NOT named in it (omitted `tools` = inherit all). Tool map (case-insensitive, trimmed): `Read/Write/Edit/Glob/Grep→same`, `Bash→bash+process`, `WebFetch→web_fetch`, `WebSearch→web_search`, `Task→subagent`, `Skill→skill`; unknown names ignored, vBot tools without a Claude counterpart (e.g. `status`) are never denied. `tools`/`disallowedTools` accept both a comma-separated string and a YAML list; malformed shapes fail open.

**Format detection** (`detect_project_formats(project_root)` in `scanners/base.py`) — the creation-time presence report behind `project.detect` and the add dialog: per registered format a `FormatPresence(agents, skills)` (present = ≥1 parsed agent OR ≥1 loadable skill; skills counted via `core.skills.project_skills_dir` — core.skills imports nothing from core.projects, so the direction is cycle-free) plus context-file facts (`agents_md` at repo root; `claude_md` relative path — root `CLAUDE.md`, else `.claude/CLAUDE.md`, else `None`). Read-only and fail-soft; the "suggest CLAUDE.md" rule lives in the WebUI, not here.

**Tool denials (`denied_tools`).** OpenCode is deny-by-exception (all-on except denied) with no clean allow-list form, so the profile carries what an agent turns **off**, not an allow-list (no more `tools=("*",)`/`skills=("*",)`). The OpenCode detector parses *both* the per-agent `permission` map and the `tools` map (the global OpenCode config file is **out of scope**) and unions the mapped vBot tools: `edit`→`edit`+`write` (the permission key covers both; `tools.write` denies `write` alone), `bash`→`bash`+`process`, `read`/`grep`/`glob`→same, `webfetch`→`web_fetch`, `websearch`→`web_search`, `task`→`subagent`; `list`/`lsp`/`todowrite`/`question`/`external_directory`/`doom_loop`/`skill` have no vBot counterpart and are ignored. Granularity collapses to one bit (max-agency reading): a tool is denied only on an *effective full deny* — the scalar `"deny"`, or a granular map whose every value is `"deny"`; any `allow`/`ask` anywhere (or an absent key) leaves it on, and `ask` is never a per-call gate. Any foreign/unknown shape fails open (not a deny) and never crashes the scan. Skills are no longer narrowed per agent (`permission.skill` is out), so the profile carries no skill list.

**Scan report** (`scan_report.py`) — collects only what is *unclean under what exists* (an empty folder / no team / no AGENTS.md is normal → clean empty report). `FindingType`: `SLUG_COLLISION`, `UNSLUGIFIABLE_NAME`, `BAD_MODEL`, `ORPHAN`. **Collision is deterministic:** two files on one `agent_id` are resolved by `(rank, filename)` — format precedence first, then stable by filename, **never filesystem order** (Windows ≠ Linux); the loser becomes a `SLUG_COLLISION` finding. `BAD_MODEL` findings are fed in by the resolver (`with_model_findings`) and pointer/orphan findings by the anchor (`with_pointer_findings`) — the structural findings (collision, unslugifiable) the scan produces itself.

**Resolver** (`resolver.py`) — `AgentResolver.resolve_agent(project_id, agent_id) -> RuntimeAgent` is the single run-path seam (details and the model chain in `agent.md` → Uniform Agent Resolution). It holds a per-project team-scan cache (`rescan_project` / `invalidate_team_cache`), reads each agent's config fresh per resolve, and runs the model chain with `ModelConfigurationChecker` (provider registered + model in catalog + a usable credential on a connection the model's `connections` allowlist permits; a pinned `::connection[:account]` suffix is checked verbatim — mirroring run-time connection resolution, so an accepted model never fails the connection pick at run time). The chain's **top** tier is the agent's model **override** (`project.overrides[agent_id]["model"]`) ahead of the repo value, kept behind the same `is_configured` gate as every tier, so an overridden model whose credential later vanished degrades to the repo value rather than erroring. `is_model_configured(model)` is the public seam over that same checker rule, reused by the `/model` command's set-time validation so the accepted-model rule and the scan's `BAD_MODEL` rule can never drift.

**Provenance seam** (`resolver.py`) — `AgentResolver.effective_config(project_id, agent_id) -> {field: {value, source}}` is the provenance-aware companion to `resolve_agent`, sharing the *same* per-tier chain logic (one owner) so the two can never drift. Config agents (`project_id` set) report `model`/`temperature`/`thinking_effort` with `source` in `override`/`agent`/`project_default`/`global_default`/`null`; unlike `resolve_agent`, a model chain that fully falls through returns `{value: null, source: null}` **without raising** (an unknown project/agent still raises `AgentResolutionError`). Identity agents (`project_id None`) report `model`/`fallback_model`/`temperature`/`thinking_effort` with `source` `agent`/`global_default`/`null`, no `is_configured` gating — mirroring `AgentStore._apply_defaults` (a default applies when the raw value is `""`/`None`). It reads the identity agent's un-baked values through `AgentStore.get_raw` (see `agent.md`). `effective_config_for_member(project, scanned)` is the cheap seam behind the team listing: it runs the same config-agent chain from an already-scanned member so a team response never re-scans the repo once per member.

**Effective tools/skills for a config agent.** The resolver intersects the project ceiling with the agent's denials: `allowed_tools = [t for t in project.allowed_tools if t not in scanned.denied_tools]` (the agent can only narrow, never widen; an empty project ceiling yields no tools). `allowed_skills = sorted((project_skill_names − skills_project_disabled) ∪ skills_bundled_enabled ∪ skills_global_enabled)` — the project's own scanned skills active by default, the named ones off, plus opted-in bundled and global skills (the global opt-in is the only path from a project agent into the user's global pool; default none). Project-skill **names** arrive through an injected `ProjectSkillNamesProvider` protocol (wired in `build_agent_resolver` to `runtime.project_skill_names`), so the resolver still never imports `core.runtime`; an absent provider degrades to bundled-only. For a config agent it also resolves `temperature` and `thinking_effort` through the **same three-tier chain** as the model — agent value → project default → global `defaults.agent` → provider default (see `agent.md` → Uniform Agent Resolution). The global tier is read once per resolve as the whole `defaults.agent` map (`global_agent_defaults` callable, wired to `runtime._global_agent_defaults`) and fed to all three chains. `scan_project_report(project)` returns team + the full report including `BAD_MODEL` findings. Wired into the runtime as `runtime.agent_resolver` (built from `agents`, `projects`, `models`, providers, credentials, `global_agent_defaults`); the resolver imports `core.runtime` not at all — it depends on small local `Protocol`s.

**Prompt-feeding free functions** (in `resolver.py`, exported from the package): `runtime_agent_body(agent)` maps the two agent forms onto the prompt builder's `agent_body` (ConfigAgent body, else `""`). `resolve_prompt_project(projects, project_id, agent)` is the single **rooting policy** shared by the chat loop and the prompt-preview RPC so they can never drift: `project_id` set → `projects.get(project_id)`; `project_id is None` → the project the identity agent is **rooted** in via `projects.find_by_cwd(agent.workspace)` (workspace == a registered repo), else `None`. `resolve_skill_scope(project_id, prompt_project, agent_id)` is its pure companion — the single **skill-scoping policy** shared by the chat loop, the prompt-preview RPC, and `$`-autocomplete: it takes the already-resolved prompt project and returns `(skill_project_id, identity_agent_id)` for `runtime.skills_for(...)` — the run's own project (or a rooted identity agent's home project) plus the private-skill layer for identity runs only (a config agent's project-local slug must never resolve a same-named identity agent's private home). All are free functions here, not on `AgentResolver`, so prompt assembly stays on its Protocols and never learns the rules itself; the caller passes the results in as explicit arguments.

## Scope boundary (what is *not* here)

The project RPC surface (`project.*`, `server/rpc/project_methods.py`) and the CLI `project` area (`cli/`) live outside this module and call into it — they are not in this domain. The override surface there: `project.set_override` (params `project_id`, `agent_id`, `field`, `value`) and `project.clear_override` (params `project_id`, `agent_id`, `field`) wrap the store's `set_override`/`clear_override` and return the updated project + a fresh scan (no cache invalidation — `project.json` is read fresh per resolve). `set_override` validates a `model` value through the shared usable-model gate (`_ensure_model_usable`) and `temperature`/`thinking_effort` through the canonical agent validators. The scan's team-member response carries an `overrides` object (the agent's override, or `null`) plus an `effective` map (per-field `{value, source}`). The model override is also settable command-only via `/model` (see `chat.md`); the Projects tab only clears the model override. Channels on project agents and a project-local memory tool are deferred.

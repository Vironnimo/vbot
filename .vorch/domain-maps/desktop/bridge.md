# Desktop bridge

Read when adding or changing a Desktop bridge method, a capability, the page policy that gates a method (confirmations, the connection screen's key), the error codes a method rejects with, or a push into the page. The bridge's invariants every Desktop task needs are in `desktop.md` -> Python<->JS bridge.

## Methods

- Capabilities: `getDesktopCapabilities()` - `{wakeword: true, voiceApi: 3, microphone: true, serverSelection: true, contextMenu: true, liveHotkey, dictation, zoom, secureOrigins, restart, signIn}` (`dictation` where the global shortcut can be registered, i.e. Windows; `zoom` where the window applies it, i.e. Windows; `restart` only for a packaged launch; `signIn` when server selection exists: `selectServer` may open a login ticket or the pairing offer). The WebUI enables Voice only for `voiceApi === 3`.
- Clipboard/browser: `setClipboardText`, `getClipboardText` (bounded plain text; asked for on another server's page), `openExternalUrl` (validated absolute HTTP(S) only).
- Servers: `connect(host, port, screen)` and `selectServer` return prepared outcomes - `{status, url?}` or inline error fields - and never navigate themselves; `url` is `about:blank` when the window signs in first or, with status `pairing_required` from `selectServer`, shows the connection screen's pairing offer next. `connect` answers a server that needs pairing with `offer: {host, port, server, origin, name, title, body}` instead. `startPairing(host, port, name, screen)` answers `pairing: {code, server, origin, title, body}` or error copy. `listServers` (`{host, port, scheme, label?, active, signed_in}`), `addServer` (`{host, port, scheme, label?}`), `removeServer` (also forgets the sign-in), `cancelPairing()` (`{cancelled}`), `forgetSignIn(host, port, screen)` (`{forgotten}`). An HTTPS server's `host` is its `https://` address, an IPv6 host its compressed literal without brackets; its port follows the address. The connection screen's JavaScript only calls `connect`, `startPairing`, `cancelPairing` and `forgetSignIn`; `_connection_lock` serializes server-selection calls.
- Microphone (`desktop/voice.md` -> Capture and microphones): `getMicrophone`, `setMicrophone`, `listMicrophones`; the setting applies to Voice and dictation.
- Voice (`desktop/voice.md` -> Bridge methods): `getVoiceStatus`, `setVoiceEnabled`, `updateVoiceConfig`, `listWakewordModels`, `importWakewordModel`, `deleteWakewordModel`, `retryVoice`, `stopVoiceRecording`, `startVoiceCalibration`, `restartVoiceCalibration`, `stopVoiceCalibration`.
- Live voice shortcut: `getLiveHotkey` / `setLiveHotkey` (`desktop/live-voice.md`).
- Dictation: `getDictation` / `setDictation` (`desktop/dictation.md` -> Bridge and status).
- Window zoom: `getZoom()` / `setZoom(percent)`, both answering `{supported, percent, levels, default}`; a value that is no level rejects as `zoom_invalid` (`desktop/window.md` -> Window zoom).
- Update restart: `getDesktopUpdate()` (`{pending, restarting, failed}`), `restartDesktop()` (`{accepted: true}`; rejects `no_update_pending`, `restart_unavailable`) - `desktop/update-restart.md`.
- Computer sharing: `getComputerSharing` / `setComputerSharing`, capability `computerSharing`; public local status and per-server grants (`desktop/computer-sharing.md`). Enabling a remote server's capability needs native consent for its still-loaded page, and no registration key reaches this bridge.

## Error contract

`_reject_with_error_codes`, applied to every public method: an exception whose `error_code` is a stable code (`[a-z][a-z0-9_]*`) is logged at WARNING (with its `field`, if any) and rejects the Promise with a `BridgeError` whose message is exactly that code; the WebUI reads it with `desktopErrorCode`. Any other failure is logged with its traceback and keeps its own message; a message that would look like a code is replaced by `The Desktop could not complete <method>`, so only deliberate codes reach the page as codes. The bridge marks these logged exceptions; a narrow pywebview logger filter suppresses its duplicate exception report while preserving unrelated native failures.

## Page policy

`desktop/page_permissions.py`, `PagePermissions`: every server the Desktop connects to serves the page in its one window, so a page is trusted only as far as the user chose its server.

- The page of the installation's own server (`ServerAccess.is_installation_server`: the server that gets the local access token) is trusted like the Desktop itself: that server already runs with the user's rights on this computer.
- Any other server's page needs the user's yes in a native dialog (`Window.create_confirmation_dialog`, shown from the bridge call's thread) to add a server (`addServer` or `selectServer` of a server not remembered; selecting adds it), to remove a remembered one with its sign-in (`removeServer`), to read the clipboard (`getClipboardText`, asked once per origin while the Desktop runs) and to install a wake word model (`importWakewordModel`, after the content decoded). A no, or a dialog that fails, rejects with `declined`; the WebUI shows nothing for it (`isDesktopDeclined`).
- `connect`, `startPairing` and `forgetSignIn` need the connection screen's key and reject any page with `connection_screen_only` (`desktop/sign-in.md` -> Who may call the sign-in bridge methods).
- The page's origin is the window's top-level URL (`Window.get_current_url`) and counts only while it equals the origin recorded at the last pywebview `loaded` event (`PagePermissions.page_loaded`): a page that calls the bridge and at once navigates the window to the own server is not taken for that server's page, because the window's URL changes when the next document commits, well before it has loaded. A call between two pages is shown as "A page" and asked for.
- Open to every page on purpose: writing the clipboard and `openExternalUrl` (what any web page can do), `restartDesktop` (only restarts into a version already installed, which the Desktop also does by itself), `cancelPairing`, and the Voice, microphone, dictation, shortcut and zoom settings. The microphone is granted without a prompt only to the window's server (`_windows.allow_server_microphone`), and only the user puts a server there: on the connection screen, on the command line, or through one of these confirmations.

## Page pushes

Computer sharing adds `vbot-desktop-computer-sharing`, carrying one coalesced public status snapshot (`desktop/computer-sharing.md`). It does not carry commands or own the native connection.

`desktop/page_events.py` (`PageEventDispatcher`) dispatches window events through `Window.evaluate_js`: `vbot-desktop-live` (cancelable Live voice requests, `desktop/live-voice.md`), `vbot-desktop-voice` (Voice status snapshots and events, `desktop/voice.md` -> Events and push), `vbot-desktop-dictation` (`detail` `{recording}`: whether a dictation records, so the page holds a Live voice call, `desktop/dictation.md`), `vbot-desktop-open-session` (cancelable, `detail` `{agent, session}`: open that Session, from a handed-over `--open-session`; the WebUI acknowledges with `preventDefault()`, see `webui/app-shell.md` -> Startup and availability), `vbot-desktop-update` (update restart status) and `vbot-desktop-restart` (cancelable restart request after an update; the result reaches the restart as handled or not) - both `desktop/update-restart.md`. One daemon thread (`vbot-desktop-page-events`, started with the first push) delivers every push in order; producers never block, and the queue is bounded (at most 4 Live requests, one waiting Voice status, one waiting dictation state, and one waiting update status, one waiting Session request replaced by a newer one, one waiting restart request, 64 events). Pushes before `attach_window` are dropped. Delivery failures log one warning per failure streak; `close()` discards waiting pushes. A page without handlers (the connection screen) ignores the events.

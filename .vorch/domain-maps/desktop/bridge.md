# Desktop bridge

Read when adding or changing a Desktop bridge method, a capability, the page policy that gates a method (confirmations, the connection screen's key), the error codes a method rejects with, or a push into the page. The bridge's invariants every Desktop task needs are in `desktop.md` -> Python<->JS bridge.

## Methods

- Capabilities: `getDesktopCapabilities()` - `{wakeword: true, voiceApi: 4, microphone: true, serverSelection: true, contextMenu: true, liveHotkey, dictation, zoom, taskbarBadge, secureOrigins, restart, signIn}` (`dictation` where the global shortcut can be registered, i.e. Windows; `zoom` where the window applies it, i.e. Windows; `taskbarBadge` where the taskbar button shows a count, i.e. Windows; `restart` only for a packaged launch; `signIn` when server selection exists: `selectServer` may open a login ticket or the pairing offer). The WebUI enables Voice only for `voiceApi === 4`.
- Clipboard/browser: `setClipboardText`, `getClipboardText` (bounded plain text; asked for on another server's page), `openExternalUrl` (validated absolute HTTP(S) only).
- Servers: `connect(host, port, screen)` and `selectServer` return prepared outcomes - `{status, url?}` or inline error fields - and never navigate themselves; `url` is `about:blank` when the window signs in first or, with status `pairing_required` from `selectServer`, shows the connection screen's pairing offer next. `connect` answers a server that needs pairing with `offer: {host, port, server, origin, name, title, body}` instead. `startPairing(host, port, name, screen)` answers `pairing: {code, server, origin, title, body}` or error copy. `listServers` (`{host, port, scheme, label?, active, signed_in}`), `addServer` (`{host, port, scheme, label?}`), `removeServer` (also forgets the sign-in), `cancelPairing(screen)` (`{cancelled}`), `forgetSignIn(host, port, screen)` (`{forgotten}`). An HTTPS server's `host` is its `https://` address, an IPv6 host its compressed literal without brackets; its port follows the address. The connection screen's JavaScript only calls `connect`, `startPairing`, `cancelPairing` and `forgetSignIn`; `_connection_lock` serializes server-selection calls.
- Microphone (`desktop/voice.md` -> Capture and microphones): `getMicrophone`, `setMicrophone`, `listMicrophones`; the setting applies to Voice and dictation.
- Voice (`desktop/voice.md` -> Bridge methods): `getVoiceStatus`, `setVoiceEnabled`, `updateVoiceConfig`, `listWakewordModels`, `addWakewordModel`, `cancelWakewordModelDownload`, `importWakewordModel`, `deleteWakewordModel`, `retryVoice`, `stopVoiceRecording`, `startVoiceCalibration`, `restartVoiceCalibration`, `stopVoiceCalibration`.
- Live voice shortcut: `getLiveHotkey` / `setLiveHotkey` (`desktop/live-voice.md`).
- Dictation: `getDictation` / `setDictation` (`desktop/dictation.md` -> Bridge and status).
- Window zoom: `getZoom()` / `setZoom(percent)`, both answering `{supported, percent, levels, default}`; a value that is no level rejects as `zoom_invalid` (`desktop/window.md` -> Window zoom).
- Taskbar badge: `setTaskbarBadge(count)` answers `{count}`; 0 removes the badge, anything but a whole number >= 0 rejects as `badge_invalid` (`desktop/window.md` -> Taskbar badge).
- Update restart: `getDesktopUpdate()` (`{pending, restarting, failed}`), `restartDesktop()` (`{accepted: true}`; rejects `no_update_pending`, `restart_unavailable`) - `desktop/update-restart.md`.
- Computer sharing: `getComputerSharing` / `setComputerSharing`, capability `computerSharing`; public local status and per-server grants (`desktop/computer-sharing.md`). `reloadDesktopExtensions()` rescans only fixed local package roots and accepts no code or paths. Enabling a remote server's capability or requesting native Extension reload needs native consent for its still-loaded page, and no registration key reaches this bridge.

## Error contract

`_reject_with_error_codes`, applied to every public method: an exception whose `error_code` is a stable code (`[a-z][a-z0-9_]*`) is logged at WARNING (with its `field`, if any) and rejects the Promise with a `BridgeError` whose message is exactly that code; the WebUI reads it with `desktopErrorCode`. Any other failure is logged with its traceback and keeps its own message; a message that would look like a code is replaced by `The Desktop could not complete <method>`, so only deliberate codes reach the page as codes. The bridge marks these logged exceptions; a narrow pywebview logger filter suppresses its duplicate exception report while preserving unrelated native failures.

## Page policy

`desktop/page_permissions.py`, `PagePermissions`: every server the Desktop connects to serves the page in its one window, so a page is trusted only as far as the user chose its server.

- The page of the installation's own server (`ServerAccess.is_installation_server`: the server that gets the local access token) is trusted like the Desktop itself: that server already runs with the user's rights on this computer.
- Another selected server needs a native confirmation to add, select or remove a server, list remembered servers (once per origin per Desktop launch), read the clipboard (also once per origin), replace it, change native Voice/dictation, microphone or global shortcut settings, or install/delete a wake word model. A refusal or stale document aborts the protected action. WebView2 automatically allows microphone requests only from the active installation server; another selected origin uses the browser permission prompt.
- The pinned pywebview 6.2.1 adapter in `desktop/_webview_bridge.py` issues one credential per document, matching the native renderer URL to the selected server origin before installing the normal JS stubs. Navigation invalidates old credentials. Only public facade methods are dispatched, and native replies use a direct document- and origin-bound script. WebView2 also authenticates the message source and invalidates on navigation start. The shell document can only connect, start or cancel pairing and forget a sign-in; all four require its separate Connection screen key.
- Capability discovery exposes only the calling origin's secure-context status. Displaying computer names, native Extension inventory and sharing diagnostics needs one read grant per origin per Desktop launch. Direct calls and pushes disclose these details only after the grant; changing grants, the computer name or reloading Extensions follows `desktop/computer-sharing.md`. Window zoom, badge, opening HTTP(S) links and restarting into an installed update remain available to a selected WebUI.

## Page pushes

Computer sharing adds `vbot-desktop-computer-sharing`, carrying one coalesced public status snapshot (`desktop/computer-sharing.md`). A granted origin receives the push through a direct origin-checked script. Voice events and status, Live starts and Session handoffs likewise carry their producing server origin through the queue; a handoff replaced while waiting also replaces its destination.

`desktop/page_events.py` (`PageEventDispatcher`) dispatches window events through `Window.evaluate_js`: `vbot-desktop-live` (cancelable Live voice requests, `desktop/live-voice.md`), `vbot-desktop-voice` (Voice status snapshots and events, `desktop/voice.md` -> Events and push), `vbot-desktop-dictation` (`detail` `{recording}`: whether a dictation records, so the page holds a Live voice call, `desktop/dictation.md`), `vbot-desktop-open-session` (cancelable, `detail` `{agent, session}`: open that Session, from a handed-over `--open-session`; the WebUI acknowledges with `preventDefault()`, see `webui/app-shell.md` -> Startup and availability), `vbot-desktop-update` (update restart status) and `vbot-desktop-restart` (cancelable restart request after an update; the result reaches the restart as handled or not) - both `desktop/update-restart.md`. One daemon thread (`vbot-desktop-page-events`, started with the first push) delivers every push in order; producers never block, and the queue is bounded (at most 4 Live requests, one waiting Voice status, one waiting dictation state, and one waiting update status, one waiting Session request replaced by a newer one, one waiting restart request, 64 events). Pushes before `attach_window` are dropped. Delivery failures log one warning per failure streak; `close()` discards waiting pushes. A page without handlers (the connection screen) ignores the events.

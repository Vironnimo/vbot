# Desktop window

Read when changing the Desktop window and process itself: startup order, the single-instance guard and the launch request handoff, window size, zoom and monitor scaling, native clipboard and browser actions, icons and title, the per-user settings store's mechanics, and the Desktop's own log files. The update restart's handoff is in `desktop/update-restart.md`; connecting to a server is in `desktop/connection.md`.

## Window-first startup

The window is created before the GUI loop with the connection screen as initial content; `load_url`/`load_html` may only run once the loop is live. Its pywebview `background_color` is the canonical WebUI `Bg` (`#15130F`), so WebView2 exposes the app foundation instead of its white default during startup, navigation, restore, or renderer repaint gaps (`webui.md` -> Invariants keeps `index.html` aligned). The `shown` callback connects first (the first attempt; a launch wait goes on in the background), then starts Voice (`voice.start()`, a no-op while disabled), the Live voice shortcut, and dictation (`dictation.start()`, which registers its shortcut only when enabled). With Voice disabled, startup never imports the capture, detection, command, echo, or speech-detection modules or the ML/audio dependencies (the package root loads `VoiceController` lazily; dictation imports the capture module per take). A startup daemon prepares the Desktop's TLS context and httpx's lazy transport imports while the window starts, before dictation creates a client. Fresh-process coverage: `tests/desktop/test_main.py` (`test_disabled_voice_and_dictation_build_their_bridge_without_the_audio_stack`).

## Single instance

Windows only, `desktop/_windows.py`: before creating a window, `launch_desktop` claims a named mutex scoped to the Desktop config directory (`Local\vBot.Desktop.<digest>.instance`, digest = the first 16 hex characters of the SHA-256 of the resolved directory). A later launch for the same directory signals the running instance through the named auto-reset event `Local\vBot.Desktop.<digest>.activate` and returns without a window (an explicit `--host/--port` without `--open-session` is logged and ignored); the running instance's daemon listener brings its window to the front, restoring a minimized window (maximized again if it was). Different config directories (tests, portable setups) never collide; a failure to create the guard logs and continues unguarded; other platforms have no guard. A second process would share the WebView2 profile (differing browser arguments leave a blank window) and compete for the microphone and the global shortcut.

## Request handoff

`claim_desktop_instance(request=...)`: a later launch with `--open-session` first writes `<config-dir>/activation-request.json` in one atomic replace, `{created_at, request: {host, port, agent, session}}` (`created_at` in wall-clock seconds; `host`/`port` are the launch's `--host`/`--port`, missing half filled as for a launch target, or both null), and only then signals. On each activation the running instance's listener reads and deletes the file; a missing, malformed, or more than 60 s old (in either direction) request reaches it as none, so a file left over from an ended instance expires on its own. The running instance then asks the page to open the Session through the `vbot-desktop-open-session` push (`desktop/bridge.md` -> Page pushes) when its window shows the requested server (`ConnectionController.is_active_server`, host case-insensitive) or, with null host/port, any connected server; the window comes to the front either way.

## Window sizing

First-run window at roughly 80% of the primary display capped at 1440x960 logical pixels (1280x800 if discovery fails), resize floor 800x600. Normal close persists width/height only (`window: {width, height}` in `<config-dir>/settings.json`); startup restores clamped to the current primary display's work area. The primary screen is the one containing origin (0,0) - never assume `screens[0]` - and is passed via pywebview's `screen=` parameter for correct centering and DPI conversion. Position is deliberately not persisted so OS centering keeps the window reachable after monitor changes.

## Window zoom

`desktop/zoom.py`, Windows: one stored level from `ZOOM_LEVELS` (50-200 percent, Chromium's page zoom steps; missing or unknown reads as 100; stored as `zoom: {percent}`) scales everything the window shows, like a browser's page zoom, and belongs to this Desktop, never a server. `DesktopZoom` stores and applies it; `_windows.bind_window_zoom` turns WebView2's own zoom inputs off (`IsZoomControlEnabled`, after pywebview's initialization handler turns them on), because a zoom the user makes there lasts only for the current page, applies the stored factor once WebView2 is initialized (a host-set `ZoomFactor` stays across navigations), and applies later changes on the GUI thread. The page owns the inputs: Settings -> Appearance and the shortcuts Ctrl + Plus/Minus/0 and Ctrl + mouse wheel (`webui/settings.md` -> Onboarding and appearance) send the chosen level through `setZoom`. On other platforms the capability `zoom` is false.

## Windows monitor scaling

`desktop/_windows.py` establishes PerMonitorV2 before pywebview screen discovery. The Python-hosted .NET Framework also needs the `windows.config` opt-in and an explicit .NET 4.8 target before WinForms loads; Windows awareness alone leaves dynamic layout disabled. WinForms/WebView2 then handle monitor DPI changes, including native and browser layout. Primary screen/work-area snapshots from pywebview are physical pixels in this mode and are converted to logical pixels before sizing and centering. This bootstrap applies to packaged and source Desktop entrypoints. Regression coverage: `tests/desktop/test_windows.py` (DPI bootstrap) and `tests/desktop/test_main.py` (physical-to-logical primary screen).

## Native system actions

`desktop/system_actions.py`: serialized clipboard/browser operations with payload-size validation and absolute HTTP(S)-only external URLs. A page's new window (`target="_blank"`, `window.open`) opens through the same check in the default browser: `main.py` sets pywebview's `OPEN_EXTERNAL_LINKS_IN_BROWSER` (the other choice loads it in this window, bridge included), and `guard_page_windows` replaces `webbrowser` in pywebview's backend modules once the GUI loop runs, so a `file:`, `ms-settings:` or other registered handler never starts (a refused one is logged with its scheme only); Windows uses the native Unicode clipboard API, macOS `pbcopy`/`pbpaste`, Linux wl-copy/xclip/xsel with an operational failure when none exists. This boundary exists because a remote HTTP WebUI cannot reliably use the secure-context Clipboard API.

## Icons and title

Platform icons come from `desktop/icon.ico` (Windows; WinForms requires ICO - PNG input is rejected by `System.Drawing.Icon`) and `desktop/icon.png` (other platforms), passed to pywebview when present with a platform-default fallback. The window title is `vBot`; no native application menu is attached. The window enables document text selection (`text_select=True`), so the WebUI's Desktop context menu can copy selected text.

## Per-user settings store

The contract owners rely on (`read_section`/`update_section`, location) is in `desktop.md` -> Interfaces. Mechanics of `desktop/settings.py`: reads tolerate missing/broken files with empty defaults and drop malformed entries individually; writes are atomic same-directory replacements preserving unrelated top-level keys, each section write holding one process-wide transaction lock across its read-modify-write. An unreadable existing file, invalid UTF-8/JSON or non-object JSON rejects section mutations without replacing the original bytes; startup reads still use defaults. Transient I/O retries a few times; a final failed write logs and re-raises so bridge callers reject instead of faking success. Section owners: `microphone` `desktop/speech/microphone.py` (`desktop/voice.md` -> Capture and microphones), `wakeword` `desktop/wakeword/config.py` (`desktop/voice.md` -> Stored settings), the shortcut sections `live_voice` and `dictation` `desktop/hotkey.py` through a `HotkeyPreference` (`desktop/live-voice.md`, `desktop/dictation.md`), `servers`/`last_used` the connection (`desktop/connection.md` -> Remembered servers), `window` and `zoom` this file.

## Standalone logging

`desktop/main.py` attaches the `vbot.*` logger tree to daily files under `<config-dir>/logs/` in the server's format. Voice logs each actual state change (`Voice state: <state> (<error_code>)`), listener starts, readiness changes, and command outcomes with codes and ids; unchanged states stay silent. Dictation logs starts, ends, lengths, and failure codes. Logs never contain transcripts. This is Desktop-local because a Desktop Client has no server `data_dir`. Fatal errors of native libraries (WebView2 through .NET, PortAudio, the wake word and speech models) go to `<config-dir>/logs/desktop-crash.log` (`logging/pipeline.md` -> Crash logs).

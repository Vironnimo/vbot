# WebUI shared controls

Read when using or changing the behavior of the shared `LazyContent`, `SortableList`, `PathField`, `DataTable`, `DateField`, `TimeField`, `Button`, `Modal`, `ImageLightbox` or `Dropdown` controls. The rule to use them is in `webui.md` -> Ownership; their appearance is in `webui/design.md` -> Shared controls and feedback, their files in `webui/source-map.md` -> UI primitives.

## LazyContent

`components/ui/LazyContent.svelte` renders a dynamically imported component through its `children(Component)` snippet, preserving the caller's props, bindings and context. Pass a stable module-scope `load` function returning `import(...)`; `lib/lazyContent.js::loadComponent` shares pending imports and returns a cached component synchronously on revisits. The same helper lets an owner await its component before calling a bound instance. Loading and failure feedback stays in the shared primitive; navigation never waits for an abandoned import and late results cannot display a previous view. A failed import offers an explicit Reload page action: browsers can cache a failed module fetch for the document, so simply calling the same import again is not reliable recovery. `showFeedback` hides pending/error feedback for a retained but hidden child. The caller owns whether the loaded child stays mounted (Chat and visited Settings editors retain their existing continuity contracts). Tests: `ui/__tests__/LazyContent.test.js`.

## SortableList

`components/ui/SortableList.svelte` (dnd-kit via `@dnd-kit/svelte`; policy in `components/ui/sortable.js`). Rows drag from anywhere except text entry and `[data-sortable-ignore]`: mouse and pen after 4 px of movement, touch after a 250 ms hold; the other rows slide aside and Escape cancels. Alt+ArrowUp/Down moves the row that holds keyboard focus, with a live announcement, and focus stays on the moved control. No grip handles. The owner receives one `onReorder(from, to)` per completed move and keeps data and persistence; the list shows the moved order until the returned promise settles and refuses new moves meanwhile, and drops a drag whose `items` changed during the gesture. Rows without their own click action show a `grab` cursor through `.sortable-item--draggable`. Users: Agents roster, Projects list, Chat's by-Project Session groups, System Prompt blocks, Project auto-load files. A row with a context menu opens it only for a `contextmenu` event nobody prevented yet: during a drag dnd-kit prevents it, so a touch hold that started a reorder keeps the gesture (`AgentListPane.svelte`). Tests: `ui/__tests__/SortableList.test.js`; pointer drags need a live browser check because jsdom has no layout.

dnd-kit setup: the manager gets its plugins and sensors at construction, because rows register before the provider applies its props and a default plugin active at registration leaves its attributes behind. The Accessibility plugin is excluded on purpose (it turns rows into focusable `role="button"`s); the list owns instructions, keyboard moves and announcements. The dragged row floats as a popover, and a Svelte re-order closes it silently, so `keepDragFeedbackVisible` reopens it after each order change. `@dnd-kit/svelte` is pre-1.0: keep its API behind `SortableList`/`sortable.js`.

## PathField

`components/ui/PathField.svelte` wraps `TextField` (always `code`) with inline completion of the typed folder and a Browse... dialog (`ui/PathBrowserDialog.svelte`), both listing through `filesystem.list` (`api.listServerDirectory`); the pure path, completion and listing rules live in `lib/pathPicker.js`.

- Completion sends the typed name as `prefix`, so the server filters before its entry cap; the field's listing cache (`createListingCache`, one per focus visit) answers a longer prefix from a complete listing of a shorter one.
- The dialog lists whole folders and filters them by substring itself; it caches nothing, so every navigation lists the folder anew and folders made meanwhile appear (Refresh/F5 lists the open one again). Its trail turns into a path field on a click into its free space or Ctrl+L (an absolute path, or one relative to the open folder or the `root`; a file path opens its folder with the file highlighted where files can be chosen), and an absolute path typed or pasted into the filter moves there. New folder (not in `file` mode) creates a folder in the open one through `filesystem.create_directory` (`api.createServerDirectory`), proposes an unused name (`New folder (2)`), keeps the row with the refusal on failure, and highlights the created folder so Select takes it.
- A folder accepted by completion ends with a separator so completion continues inside it; when focus leaves the field (not when the window loses focus) and for a value Browse... returns, the field emits the value without trailing separators, except on a root (`/`, `C:/`, `C:\`). Without focus, a path longer than the field shows its end, the folder or file it names: the field scrolls to it when the value changes from outside, after focus leaves and when its width changes.
- Props: `mode` (`directory`/`file`/`any`), optional `root` (navigation stays inside it and values come back relative to it), `startPath` (where an empty field starts: Browse... opens at its nearest ancestor that lists, as it does for a value naming a missing folder, and ArrowDown offers that folder; the search stops at a folder that times out), `projectShortcuts` (Projects among the dialog's places), `listDirectory` (same params and result as the RPC, so an Extension page can pass its bridge) and `createDirectory` (same params and result as `filesystem.create_directory`; it defaults to the WebUI API only together with the default listing, so an Extension page, which has no bridge method for it, gets no New folder).
- Users: Add and Re-point Project, Project auto-load files, Agent Workspace, Skill folders, Terminal working directory, MCP program and cwd, Skill install source, the Swarm page's working directories (through its page client), and Task Model text options with a `server_path` hint such as the local speech Model directory (`settings/TaskModelOptions.svelte`).
- Tests: `ui/__tests__/PathField.test.js`, `lib/__tests__/pathPicker.test.js`.

## DataTable

`components/ui/DataTable.svelte` owns sortable headers with `aria-sort`, the optional filter with its "N of M" count, the optional row limit with Show all / Show fewer, activatable rows, and the keyboard-scrollable horizontal region, so a wide table scrolls inside itself instead of widening the page; the pure sorting, filtering, and limiting rules live in `lib/dataTable.js`. Callers pass translated column labels, rows, and a stable row key; a column sets `align: 'end'` for numbers, `mono` only for code-like values (paths, commands, codes, opaque ids), and a `cell` snippet called as `(row, column)` for custom markup. Visual rules: `webui/design.md` -> Tables. Tests: `ui/__tests__/DataTable.test.js`, `lib/__tests__/dataTable.test.js`.

## DateField and TimeField

`components/ui/DateField.svelte` and `TimeField.svelte` replace the browser's date and time inputs, whose wording and theme follow the browser; the guard bans native `date`, `time`, `datetime-local`, `month` and `week` inputs. Values are wall-clock strings without a zone, `YYYY-MM-DD` and `HH:MM` (`''` when empty); the caller adds the zone (Extension input composes `${date}T${time}`, `webui/settings.md` -> Extension input outside Settings). `lib/dateTimeFields.js` formats and parses them in the app language (`activeLocaleTag()`, never the browser's) and computes on UTC dates, so the browser zone never shifts a day. Both report `onChange(next)` as soon as the typed text reads as a value, and `required` keeps the last value when the text is cleared. Their popovers are portaled on the floating layer (`--z-floating`, `styles/app/controls/date-time.css`).

- DateField shows `Wed, Sep 23, 2026`-style text and opens a month grid; `min`/`max` (inclusive) bound typed and picked dates; `today` marks the current day, by default in the application time zone, and gives a date typed without a year its year while the field is empty. ArrowDown or Alt+ArrowDown opens the grid and moves into its days; there the arrows move by day and week, PageUp/PageDown by month, Home/End to the week's ends, Enter or Space picks, Escape closes.
- TimeField reads typed times such as `9`, `930`, `9:30` or `9:30 pm` and lists times every `step` minutes (default 30), opened at the time it holds. Focus stays in the field: ArrowDown/ArrowUp open and move through the list, Enter picks, Escape closes.
- Tests: `ui/__tests__/DateField.test.js`, `ui/__tests__/TimeField.test.js`.

## Modal and Dropdown keyboard

- Escape, Back (the Modal registers a navigation layer) and the close button close a `Modal` unless `closeDisabled`. A backdrop click closes it only when the press started on the backdrop, so a text selection dragged out of the dialog does not close it; once an `input` or `change` event bubbled up inside the dialog, a backdrop click only nudges it (`modal--nudge`) and keeps what the user entered. A Modal opened while another one is open renders stacked (`modal-overlay--stacked`; appearance in `webui/design.md` -> Dialogs).
- The private `components/ui/modalFocus.js` lifetime is shared by `Modal` and `ImageLightbox`: it owns background isolation, focus entry/restoration, the navigation layer and one keyboard stack. The Lightbox focuses its close button. Of stacked modal surfaces (a dialog or image preview opened from a dialog) only the newest answers Escape and Tab (`ui/__tests__/Modal.test.js`). During IME composition the Modal leaves shortcuts to native input; composing Escape also stops before background window handlers, preserving the dialog and its draft. Escape already consumed by a nested picker dismisses only that picker; the enclosing dialog retains its draft and closes on a subsequent unhandled Escape.
- `SearchableDropdown` balances `onOpenChange` for actual state transitions, including closing an open picker on teardown; calling `open()` again while open does not report another opening. This lets catalog owners hold refreshed options until every picker is closed (`SearchableDropdown.test.js`).
- Shared Dropdown variants implement the listbox/combobox keyboard contract with an explicit active option (the simple list adds typeahead; the searchable one filters); callers provide values and callbacks, not bespoke keyboard behavior. The searchable variant's collapsible-group mode switches to the tree pattern: Right opens a group or enters it, Left closes it or returns to its header, Enter toggles a header; callers own which groups are open (`expandedGroups` plus `onGroupToggle`). A Dropdown inside a `FormField` passes the field's `labelId` as `ariaLabelledby`, so its visible label and current value name the trigger; without it the trigger falls back to `ariaLabel` or the placeholder.

## Disabled Button help

`Button.svelte` keeps native controls disabled. With a `disabledReason`, its wrapper becomes the keyboard-focusable disabled control, named from the button and described by persistent hidden reason text; the shared tooltip shows the same reason on keyboard focus or hover. Enabling the button removes that extra tab stop and exposes the native control again (`ui/__tests__/Button.test.js`).

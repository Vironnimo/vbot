# WebUI Archive

Read this reference only for work on the Configure -> Archive view, the Archive option of the Agent, Project and Session delete dialogs, or the Archive section of Settings -> System. The archive itself (entries, kinds, states, restore checks, purge, retention) is owned by the server: `archive.md`; the RPC shapes are in `server.md` -> `archive_methods.py`.

## Ownership

- `components/ArchiveView.svelte` is the view: list and filter state, paging, selection, the shown entry, and every write (`archive.restore`, `archive.purge`) with its confirmation and toast. Its presentation components live in `components/archive/`: `ArchiveEntryList.svelte` (rows), `ArchiveEntryDetail.svelte` (the entry page), `ArchiveRestoreDialog.svelte` ("Restore as") and `ArchiveDeleteOption.svelte` (the delete dialogs' option).
- `lib/archiveView.js` holds the pure rules: filter options and request filters, row facts, retention texts, the restore problem texts, "Restore as" eligibility and the purge confirmation and result texts. Server problem codes map to text through one `switch` (`restoreProblemText`); an unknown code shows the server's `message`.
- `lib/archiveRetention.svelte.js` is the app-wide projection of `archive.retention_days` (`undefined` until read, `null` = never deleted automatically), the same pattern as `dateTimePrefs.svelte.js`. App setup seeds it from `settings.get`, Settings commits update it, and the Archive view adopts the `retention_days` every `archive.list` answer carries. The delete dialogs read it through `archiveDeletionNotice()`; unknown retention shows a neutral "Settings -> System sets how long" line. Another client changing the period updates it only on the next of those reads.
- `components/settings/SettingsArchivePanel.svelte` edits `archive.retention_days` on the System page (Settings below).

## Archive view

- Navigation: the place is `[]` for the list and `[entryId]` for an entry (`webui/app-shell.md` -> Navigation). Opening an entry is a step; Back, the back arrow and the breadcrumb go `up([])`, and focus returns to the entry's row. Filters are not steps.
- List: `archive.list`, newest first, 50 per page with "Load more" (`next_cursor`). Two filters: kind, and one grouped Agent-or-Project scope Dropdown (`agent:<id>` sends `agent_id`, `project:<id>` sends `project_id`), built from the live rosters plus the ids the loaded entries name and the current choice. A filter change clears the selection and reloads. Rows show label, kind, scope (a Session's Agent and Project, an Extension group's Extension), Session count, archive date, and what happens next: "Deleted automatically on <date>" from `purge_at`, "Never deleted automatically" (with the reason in a tooltip) for an `archived` entry without `purge_at` while retention is on, or the running operation (`archiving`, `restoring`/`restored`, `purging`). An `archived` entry with `restorable: false` carries a "Cannot be restored" badge whose tooltip names the reason. The toolbar states the retention period (or that it is off) and links to Settings -> System -> Archive.
- Entry page: `archive.show` (first 100 Sessions; the rest as a count). Restore (disabled with the first blocker as the reason when `restore.possible` is false), "Restore as..." when `canRestoreAs` (an `archived` Agent, Project or single-Session entry whose blockers are only taken ids or Session addresses), and Delete permanently. Blockers and warnings render as banners; a `scope_missing` blocker that names an entry links to it. Details list the deletion state, ID, scope, Extension and reason, repository, root Project, an external Workspace, delegation grants and unrooted Agents; Files list the payload trees and mark `user_folder` trees.
- Restore: `archive.restore` under the entry's own id. An `archive_restore_conflict` for an entry that can take a new id opens "Restore as" with the conflict text (`data.conflicts[].id`); any other refusal is an error toast and the entry reloads. "Restore as" sends `target_id` and shows a refusal inside the dialog. Success toasts the name plus the result's warnings (warn variant when there are any), goes up to the list and reloads it.
- Purge: one entry from its page, the selected rows (`entry_ids` in batches of 100), or every matching entry ("Empty Archive..." without filters, "Delete all matching..." with them; `all: true` with the filters). Each asks a `ConfirmDialog` first. "All matching" first counts the deletable entries across all pages (`archive.list` with limit 200) and says so when there are none. Only `archived` and `purging` rows are selectable. The confirmation warns when an entry may hold the user's own folders (a `files` entry, an entry with `user_folder` trees, or a listed entry kept from retention); those folders are deleted too. The result toast reports `purged`, or the `pending` count that vBot retries automatically (warn).
- Refresh: `archiveRefreshToken` (App, from `resource_changed(kind="archive")` and every replay gap or epoch change) reloads the list, keeping the loaded count (limit up to 200), and quietly reloads the shown entry. The Agents, Projects and full Sessions tokens reload only the shown entry, because live ids decide its restore check; App's scoped `sessionInvalidations` window is not watched, since it changes with every Run. Requests are generation-guarded; an `archive_entry_not_found` entry shows a "no longer in the Archive" page.

## Delete dialogs

- The Agent delete dialog (`AgentsView`), the Project remove dialog (`ProjectDialogs.svelte`, controller `lib/projectsView/dialogs.js`) and the Session delete dialog (`SessionListDrawer.svelte`, `components/sessions/actions.svelte.js`) render `ArchiveDeleteOption`: while unchecked, the line saying when the Archive deletes the item; the checkbox "Delete permanently instead of moving it to the Archive". Each dialog resets the option when it opens and switches its body text and confirm label ("Delete permanently") with it.
- The option sends `permanent: true` on `agent.delete`, `project.rm` and `session.delete` (`deleteAgent`, `removeProject`, `deleteSession` in `lib/api/`; without it no `permanent` field is sent). Toasts and the Project status line distinguish "moved to the Archive", "deleted permanently" and a `purge_pending` result ("vBot finishes removing its data in the background").

## Settings

- The System page's Archive section (`settings.pages` in `SettingsView.svelte`: Server, optional Desktop connection, Archive, Debug) has a Toggle "Delete archived items automatically" (off saves `null`) and, while on, a number field "Days in the Archive" (1-3650; an out-of-range value marks the field and saves nothing; turning the Toggle back on restores the last period, default 30). It autosaves through `createSettingsDraft` with `settings.update {archive: {retention_days}}` plus `base`; a refusal (`invalid_request`) reaches the shared Settings error line. The descriptions say that a lower value deletes older items at the next hourly check and that files from older vBot versions and items that may hold the user's own folders are never deleted automatically.

# WebUI Archive

Read this reference only for work on the Archive page of Settings (the retention setting and the archived items), or the Archive option of the Agent, Project and Session delete dialogs. The archive itself (entries, kinds, states, restore checks, purge, retention) is owned by the server: `archive.md`; the RPC shapes are in `server.md` -> `archive_methods.py`.

## Ownership

- `SettingsView.svelte` owns the Archive page and its places (Archive page below). The Archive is no main view and has no main navigation entry.
- `components/archive/ArchiveEntriesPanel.svelte` is the page's items section: list and filter state, paging, selection, the shown entry, and every write (`archive.restore`, `archive.purge`) with its confirmation and toast. Its presentation components live beside it: `ArchiveEntryList.svelte` (rows), `ArchiveEntryDetail.svelte` (the entry page), `ArchiveRestoreDialog.svelte` ("Restore as") and `ArchiveDeleteOption.svelte` (the delete dialogs' option).
- `lib/archiveView.js` holds the pure rules: filter options and request filters, row facts, retention texts, the restore problem texts, "Restore as" eligibility and the purge confirmation and result texts. Server problem codes map to text through one `switch` (`restoreProblemText`); an unknown code shows the server's `message`. An `entry_busy` blocker and an `archive_entry_busy` refusal share one text: the server's message for an interrupted restore that cannot finish (it names the folder and how to unblock it), "being deleted permanently" for a `purging` entry, otherwise "try again in a moment".
- `lib/archiveRetention.svelte.js` is the app-wide projection of `archive.retention_days` (`days`: `undefined` until read, `null` = never deleted automatically; `unknown`: vBot cannot read the period), the same pattern as `dateTimePrefs.svelte.js`. App setup seeds the days from `settings.get`, Settings commits update them, and the entries panel adopts what every `archive.list` answer carries; only `archive.list` sets or clears `unknown` (`retention_unknown`), because `settings.get` reads a degraded file tolerantly and reports the default. The delete dialogs read it through `archiveDeletionNotice()`, which names Settings -> Archive as where the item stays; a period not yet read points to the period set there, an unknown one says automatic deletion is paused. Another client changing the period updates it only on the next of those reads.
- `components/settings/SettingsArchivePanel.svelte` edits `archive.retention_days` at the top of the Archive page (Retention below).

## Archive page

- Page: Settings page `archive` (label "Archive", between Integrations and System) with the sections "Automatic deletion" (`archive_retention`, `SettingsArchivePanel`) and "Archived items" (`archive_entries`, `ArchiveEntriesPanel`). Settings search finds the page, both sections and the retention rows; the archived items themselves are not indexed (they use no Settings label classes). The panel loads its list only when the page is first shown (`active`), so opening another Settings page reads no archive; archive changes while the page is hidden reload the list once it is shown again.
- Navigation: an entry is a sub-page of the Archive page, place `['archive', entryId]` (the page's `subPages` section; a second segment that names none of the page's sections is an entry id). SettingsView hands the panel a sub-page handle whose place is `[entryId]` or `[]` and whose steps stay below `archive`. A shown entry hides the page heading, the retention section and the items heading; it opens at the top with the focus on the entry page. Opening an entry is a step; Back, the back arrow and the breadcrumb go `up([])` (`['archive']`), the list resumes the scroll position it was left at and focus returns to the entry's row. Filters are not steps. A search result or section deep link on the page leaves an entry like any other place.
- List: `archive.list`, newest first, 50 per page with "Load more" (`next_cursor`). Two filters: kind, and one grouped Agent-or-Project scope Dropdown (`agent:<id>` sends `agent_id`, `project:<id>` sends `project_id`), built from the live rosters plus the ids the loaded entries name and the current choice. A filter change clears the selection and reloads. Rows show label, kind, scope (a Session's Agent and Project, an Extension group's Extension), Session count, archive date, and what happens next: "Deleted automatically on <date>" from `purge_at`, "Never deleted automatically" (with the reason in a tooltip: older files, folders of the user's own, or files found without a record, `origin: recovered`) for an `archived` entry without `purge_at` while retention is on, or the running operation (`archiving`, `restoring`/`restored`, `purging`). An `archived` entry with `restorable: false` carries a "Cannot be restored" badge whose tooltip names the reason. The retention setting above the list states the period; while vBot cannot read it, the retention section shows a warning that automatic deletion is paused, rows show no deletion date and the entry page says so. The list head (selection count and its actions) stays at the top of the Settings content while it scrolls the list (its sticky offset reads `--settings-content-inset-top`, the content's top padding from `styles/settings/pages.css`); focusing a row scrolls it clear of the head.
- Entry page: `archive.show` (first 100 Sessions; the rest as a count). Restore (disabled with the first blocker as the reason when `restore.possible` is false), "Restore as..." when `canRestoreAs` (an `archived` Agent, Project or single-Session entry whose blockers are only taken ids or Session addresses), and Delete permanently. Blockers and warnings render as banners; a `scope_missing` blocker that names an entry links to it. Details list the deletion state, ID, scope, Extension and reason, repository, root Project, an external Workspace, delegation grants and unrooted Agents; Files list the payload trees and mark `user_folder` trees.
- Restore: `archive.restore` under the entry's own id. An `archive_restore_conflict` for an entry that can take a new id opens "Restore as" with the conflict text (`data.conflicts[].id`); any other refusal is an error toast and the entry reloads. "Restore as" sends `target_id` and shows a refusal inside the dialog. Success toasts the name plus the result's warnings (warn variant when there are any), goes up to the list and reloads it.
- Purge: one entry from its page, the selected rows (`entry_ids` in batches of 100), or every matching entry ("Empty Archive..." without filters, "Delete all matching..." with them; `all: true` with the filters). Each asks a `ConfirmDialog` first. "All matching" first counts the deletable entries across all pages (`archive.list` with limit 200) and says so when there are none; it leaves out `archived` entries that may hold the user's own folders (`mayHoldUserFolders`: `may_hold_user_folders` or a `files` entry), which the server keeps, and its confirmation names how many it keeps. Only `archived` and `purging` rows are selectable. The confirmation for one entry or a selection warns when an entry may hold the user's own folders (that flag, or `user_folder` trees on the entry page); those folders are deleted too. The result toast (`purgeResultToast`) reports `purged`, the `pending` count that vBot retries automatically, the `skipped` entries another action holds or that could not be deleted (each warn), entries already `gone` (another action deleted or restored them; info when nothing else happened), and the `kept` entries that may hold the user's folders (no warning).
- Refresh: `archiveRefreshToken` (App, from `resource_changed(kind="archive")` and every replay gap or epoch change, forwarded through SettingsView) reloads the list, keeping the loaded count (limit up to 200), and quietly reloads the shown entry; while the page is hidden it only marks the list for reloading. A period saved in Settings does the same, because every `purge_at` moves with it (the server sends no `archive` change for it); a period that arrives with an `archive.list` answer does not. The Agents, Projects and full Sessions tokens reload only the shown entry, because live ids decide its restore check; App's scoped `sessionInvalidations` window is not watched, since it changes with every Run. Requests are generation-guarded; an `archive_entry_not_found` entry shows a "no longer in the Archive" page.

## Delete dialogs

- The Agent delete dialog (`AgentsView`), the Project remove dialog (`ProjectDialogs.svelte`, controller `lib/projectsView/dialogs.js`) and the Session delete dialog (`SessionListDrawer.svelte`, `components/sessions/actions.svelte.js`) render `ArchiveDeleteOption`: while unchecked, the line saying how long the item stays in Settings -> Archive; the checkbox "Delete permanently instead of moving it to the Archive". Each dialog resets the option when it opens and switches its body text and confirm label ("Delete permanently") with it.
- The option sends `permanent: true` on `agent.delete`, `project.rm` and `session.delete` (`deleteAgent`, `removeProject`, `deleteSession` in `lib/api/`; without it no `permanent` field is sent). Toasts and the Project status line distinguish "moved to the Archive", "deleted permanently", a `purge_pending` result ("vBot finishes removing its data in the background") and a permanent delete whose entry another action took first or that could not be deleted (`permanentDeleteNotice` reads `purge_reason`).

## Retention

- The Archive page's first section, "Automatic deletion", has a Toggle "Delete archived items automatically" (off saves `null`) and, while on, a number field "Days in the Archive" (1-3650; an out-of-range value marks the field and saves nothing; turning the Toggle back on restores the last period, default 30). It autosaves through `createSettingsDraft` with `settings.update {archive: {retention_days}}` plus `base`; a refusal (`invalid_request`) reaches the shared Settings error line. The descriptions say that a lower value deletes older items at the next hourly check and that files from older vBot versions, items that may hold the user's own folders and items found without a record (`origin: recovered`) are never deleted automatically. While `archiveRetention.unknown`, a warning banner above the rows says that automatic deletion is paused.

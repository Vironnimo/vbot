# WebUI Source Map

Per-file / per-component reference for `webui/`: what each Svelte view, `lib/` helper, and UI primitive owns. Read the entry for a component only when you are about to touch it — the always-needed orientation, transport contracts, conventions, and invariants live in `webui.md`.

- `webui/src/lib/api.js` is the semantic transport boundary and the only production owner of raw `rpc(...)` plus server method-name literals. Views/controllers import named operations; `rpcOwnership.guard.test.js` scans production sources to prevent transport or method-name leakage. RPC envelopes go to `/api/rpc`, attachments go through `/api/upload` and `/api/attachments/{id}`, speech audio uses `/api/speech/*`, Run output uses SSE, app-wide lifecycle uses `/ws`, logs use `/ws/logs`, and a selected Terminal Session uses `/ws/terminals/{terminal_id}`. `subscribeServerEvents` also stamps the `/ws` connect with this window's presence identity — a per-tab `connection_id` plus `accessor` query param (defaults resolved from `lib/clientIdentity.js`, overridable for tests) — so the server can register it in the client roster.
- `webui/src/lib/clientIdentity.js` owns the per-window presence identity: `resolveClientConnectionId()` mints a per-tab id (sessionStorage-backed with a module-cache fallback — **never** localStorage, which is shared across a browser's tabs and would collapse N tabs into one row) and `resolveAccessorType()` returns `browser`/`desktop`. The General settings panel matches the same `connection_id` to mark "this window".
- `webui/src/lib/appController.js` owns navigation/browser-history transitions, the app WebSocket connection lifecycle, bounded Run-event and `connection_ready` projections, delayed server availability/recovery state, and every `resource_changed` token/scope projection. It calls injected app actions for Agent/Project reloads, app-error toasts, outage-error cleanup, and onboarding set-aside; `lib/navigationHistory.js`, `lib/connectionState.js`, and `lib/resourceInvalidation.js` remain its focused collaborators.
- `webui/src/App.svelte` is the App View: it renders the Toasted two-pane shell from `appController` state, forwards tab/deep-link/Session actions to the controller, and retains selected-Agent/project persistence, Debug gating, app toasts, Desktop capability loading, onboarding, and the one-time appearance/i18n bootstrap. It passes controller-owned invalidation projections down to consuming Views; it does not route `/ws` branches or mutate refresh tokens itself.
- `webui/src/components/AppShell.svelte` owns the persistent Main menu and global server-availability popup, while `styles/app.css` owns their styling plus the shared `.secondary-pane`, `.secondary-list*`, and standalone-view chrome contracts. The Main menu is a fixed left sidebar from tablet upward and a two-row mobile header (brand/status above one horizontally scrolling navigation row); mobile activation reveals an off-screen active item after direct links or tab changes. Settings, Agents, Projects, Cron, and Terminals consume the same 216px Secondary bar width/surface/divider/title/scroll contract; Agents, Projects, Cron, and Terminals also consume the inset `.secondary-list` selection surface, while their feature styles own only row contents. Master-detail panes stack at the mobile breakpoint. Statistics, Logs, Debug, and System Prompt consume `.view-frame`, `.view-header*`, and `.view-toolbar*`: the header identifies the view, while tabs, filters, scope controls, and contextual actions sit in the toolbar; at the mobile breakpoint the header/actions stack and tab overflow remains local to its scrolling row. The popup's ordinary Retry remains transport-owned; in Desktop mode its optional Switch server callback hides the popup and opens App's bridge-backed server picker outside the inert content.
- `TerminalsView.svelte` and `lib/terminalsView.js` own the Terminals control-desk master-detail surface. The controller starts manual Terminal Sessions, owns start errors, loads live plus temporarily retained finished sessions, preserves a valid selection, reconstructs the selected xterm.js instance from each authoritative scrollback-and-screen ANSI snapshot, applies only contiguous output/state events, reconnects for a fresh snapshot on gaps, batches native xterm keyboard/paste bytes only for live sessions, debounces terminal dimensions, serializes mutations, and releases sockets/timers on selection or view teardown. The component dynamically imports `@xterm/xterm` plus `@xterm/addon-fit`, owns the renderer/ResizeObserver/scroll lifecycle, provides a shared-primitive New terminal dialog whose blank command/workdir select the server user's default shell/home, starts manual sessions in focused direct-control mode, defaults live Agent-owned sessions to observe mode, makes a primary live-terminal click take control and focus xterm, presents finished sessions as read-only retained history, keeps scrollback inside the bounded terminal with an always-visible scrollbar and Jump to latest recovery, prefers each program-announced title in the Secondary list/detail heading with a humanized default-shell fallback, retains the exact command in detail metadata, and confirms process-tree stop through `ConfirmDialog`; it has no secondary text composer, and navigation or socket teardown never owns the Terminal Session lifetime. Backend Terminal semantics live in `tools/terminal_beta.md`.
- **Projects-tab selection seam.** `App.svelte` persists a `managedProjectId` separately from Chat's `selectedProjectId`: a non-empty Chat project seeds/updates the management mirror, while ProjectsView reports its own list choices back without changing Chat. On each ProjectsView mount/list load, a still-valid preferred id opens first; otherwise the first listed Project opens, and an empty list clears the mirror. This state belongs in App because tab navigation unmounts ProjectsView.
- `webui/src/lib/appearancePrefs.svelte.js` is a tiny app-wide reactive singleton (`appearancePrefs.chatWidth`, default `comfortable`, with a coercing `setChatWidth`) for pure display preferences from the appearance section. Chat width has no runtime reload hook — it only drives the `data-chat-width` attribute — so the store is the bridge between App (seeds + passes the prop) and the Appearance panel (updates it on save so the open chat reflows live).
- `webui/src/lib/connectionState.js` owns persistent app WebSocket state: `connected` / `reconnecting` / `disconnected`, reconnect backoff, and `lastSequence` replay handoff.
- `webui/src/lib/resourceInvalidation.js` is the pure, framework-free half of the reload-on-change channel: `tokenKeysForKind(kind)` maps a `resource_changed` kind to the refresh-token group(s) it invalidates (`models`/`providers` → `models`, plus dedicated `agents`, `sessions`, `clients`, `channels`, `debug_traces`, `projects`, `cron`, and `terminals` groups; `queue` has **no** token group — it carries a Session scope the watcher must match, so App routes it directly), and `shouldApplyReloadNow(surface, signals)` / `isSurfaceBusy(signals)` decide whether a reload may swap visible data now (`SURFACE_DISPLAY` always; `SURFACE_FORM` only when not `dropdownOpen`/`focused`/`savePending`). App holds the reactive tokens; each consuming view holds its own editing signals and does the fetch. Form surfaces fetch fresh data on every token bump but defer the visible swap while actively edited, applying the held result at a safe boundary so open selections and drafts are not yanked.
- `chatState.js` is the public Chat state/controller surface: `createChatController` owns roster/history/command loading, durable-history and Queue reconciliation, Agent activity aggregation (`running`/`unread`/`idle`), exact completion acknowledgement, send outcomes, Queue edit/remove, continuation actions, Run/tool cancellation, reconnect-snapshot and server-event forwarding, scoped Queue invalidation, and stream cleanup; `chatRunStream.js` owns SSE/WS reconciliation and subscriptions, including projecting background active Runs without opening their SSE streams. `ChatView.svelte` renders controller state, retains navigation consequences plus view-local presentation/input concerns, and its only direct `api.js` import is the Run subscription primitive needed to construct `chatRunStream`. `chatTimeline.js`, `ChatTimeline.svelte`, `ChatComposer.svelte`, `QueuedMessages.svelte`, and `SessionListDrawer.svelte` own timeline projection, composer input, Queue display, and Session-list presentation; `components/chat/ChatCompactionSeparator.svelte` is the shared live/History Compaction disclosure and exposes exact checkpoint text without interpreting it. The drawer carries the server's unread-completion marker to identify the concrete Session behind a blue Agent. The two-bar project address helpers (`formatAgentAddress`/`resolveAgentAddressing`/`pickProjectAgentSessionId`) remain in `chatState.js`, and `components/chat/ProjectScanBanner.svelte` is the non-blocking unclean-scan banner.
- `AgentsView.svelte`, `agentForm.js`, and `modelSelection.js` own Agent CRUD form state, sparse edit payloads, explicit confirmed Identity Agent rename, canonical roster reorder persistence, backend-backed model/connection selection, Tool/Skill access controls, optional root `tools.subagent` settings, custom prompt toggle, Workspace editing, and memory-mode handling. Agent creation marks and validates only the id as required; ordinary edit keeps it read-only and opens the dedicated `agent.rename` modal instead of feeding an id change through autosave. Blank optional names are omitted so the backend defaults them to the id, while blank name or Workspace edits explicitly restore their Agent defaults. The Sub-Agent target catalog combines bare Identity-Agent ids with project-qualified `agent@project` targets loaded from every registered Project Team; the editor preserves `['*']`/empty/explicit semantics, explains that Rooting does not narrow an Identity Agent, and hides the Tool-settings section while neither Sub-Agent Tool is allowed without deleting its stored values. `AgentListPane.svelte` uses a separate drag/keyboard handle so row clicks remain selection-only, announces keyboard moves through an aria-live region, and uses `modelShortName()` for its compact metadata line, showing only the final model-id segment and omitting the provider path plus persisted `::connection[:account]` suffix; `AgentsView.svelte` keeps selection stable, submits `agent.reorder` with the current revision, defers external roster reloads during the gesture/save, and reconciles server truth on failure. The editor and stored model value remain fully qualified. The thinking-effort dropdown in `AgentEditor.svelte` is gated by the selected model's reasoning facts from the `model.list` payload: it is **disabled** when `capabilities.reasoning.supported === false` (with an explanatory hint), and its options are narrowed to the model's published ladder — when `reasoning.levels` is non-empty the dropdown shows only the default, `none`, and those levels. A model with no ladder (unknown/custom, or a reasoning model whose ladder is not projected) keeps the full effort list because the adapter applies a provider-specific floor the UI cannot see. The `model.list` payload carries `capabilities.reasoning.{supported,control,levels}` for this gating.
- `SettingsView.svelte`, `settingsView.js`, `channelSettings.js`, `taskModelSettings.js`, `desktopBridge.js`, and `wakewordSettings.js` own the Settings surface, settings update payloads, provider OAuth UI state, channel forms, specialized model bindings, Desktop bridge calls, and Voice panel state. `SettingsView` renders **one scrolling document**: every section panel is always mounted, wrapped in a `[data-settings-section]` card with its own header, stacked under mono-caps group labels (Connect / Models / Behavior / System, plus Desktop app when its native capability is present). `DesktopConnectionSettings.svelte` owns the reusable bridge-backed remembered-server manager used both by that conditional group and App's outage modal; `desktopBridge.js` owns its bridge method calls and applies prepared connection navigation only after Promise delivery. From tablet upward the left column is the index — a live search input (DOM-based filter: rows/sections get the `hidden` attribute, match count shown, non-matching index entries dim; a `MutationObserver` re-applies an active filter after panel re-renders) above a grouped table of contents. Click navigation and its rAF-throttled scrollspy share a 32%-from-top reading line; a live scrollport-sized tail lets the final section reach it. Mobile keeps the search but replaces the full table of contents with a compact current-section `Dropdown`; it calls the same scroll-to-section path, while `.settings-content` remains the sole scrolling document region. App retains a section-relative reading anchor across ordinary main-view switches, while deep links (`targetPanelId`/`targetPanelRequestId`) replace that memory and scroll to their requested section. Channels and Extensions both load when their always-mounted panels initialize and reload after their own mutations; neither has a permanent generic Refresh action, while a failed list load exposes a contextual Retry. Channel mutations also reload other windows through `resource_changed(kind:"channels")`; SettingsChannelsPanel defers that external reload while its form or an action is active. The **Reflection** panel (`SettingsReflectionPanel.svelte`, section id `reflection`, ordered after Sub-Agents) edits the `settings.reflection` section (enable toggle + the two cadence intervals) with the Debug panel's pattern: seeded once from the settings prop, 800ms debounced auto-save plus manual Save, partial-merge `settings.update` writes; changes apply live (no restart — the backend reads the section at run end, see `automation.md`). The **Extensions** panel (`SettingsExtensionsPanel.svelte`) keeps **Reload extensions** as a distinct explicit operation that rebuilds the extension layer from disk, then re-lists it. It renders a schema-driven **form** for an extension whose `extensions.list` entry carries a `settings_schema` (text/number/toggle inputs saved together as one `settings.update` config write via `buildExtensionsUpdatePayload`; write-only secret inputs saved/cleared per-field via `extensions.set_secret` then a `loadExtensions()` refresh — never mixed into `settings.update`), and keeps the raw-JSON `config` editor as the fallback for schema-less extensions. The pure form helpers (`normalizeSchemaFields`, `buildSchemaFormState`, `buildSchemaConfigFromForm` — number parsing, empty-omission, toggle-explicitness, secret exclusion — and `hasSettingsSchema`) live in `settingsView.js` and are Vitest-covered. This panel is the **single** place the derived **waiting state** appears (design decision — the tool pickers just omit a not-ready tool): when an extension's `extensions.list` `ready_state === 'waiting'` it shows "On, waiting for configuration" and, via `describeExtensionWaiting(extension, t)`, names the unset secret fields ("Waiting for: <labels>", the schema secret fields where `set === false`). `applyExtensionsPanelList` carries `readyState` and normalizes `capabilities.tools` from the `{name, ready}` shape; `summarizeExtensionCapabilities` still lists tool names only.
- `StatisticsView.svelte`, `components/statistics/LimitHistory.svelte`, and the pure `statisticsView.js` own the Statistics tab's Overview, Usage, Runs & errors, Compactions, Tools, Skills, and Limits subviews. Every subview except Limits renders the local `statistics.report`; Compactions shows persisted-checkpoint counts, per-compacted-Session distribution, Strategy mix, reclaim estimates, and top Sessions. Limits polls live `provider.usage` every 10 seconds only while visible and separately refreshes automatic `provider.usage_history` observations every 60 seconds. The history component charts 24h/7d/30d/all ranges, breaks traces across resets and collection gaps, ranks observed limit changes, confirms full history deletion, and loads time-overlapping local Runs through `statistics.run_activity` only for a selected interval. Local Session aggregation semantics live in `statistics.md`; upstream subscription-limit data and retention live in `providers/usage.md`.
- `SystemPromptView.svelte` owns the System Prompt **block list** and prompt-scope UX; backend prompt semantics live in `.vorch/domain-maps/prompts.md`. Blocks come from `prompt.list` in layout order and are keyed by their stable `id` (never an array index, so autosave timers and DnD/keyboard-reorder identity survive a reorder). The list is **sortable** — native HTML5 drag-and-drop on a per-row handle **and** keyboard reorder (ArrowUp/ArrowDown on the focused handle, with an aria-live announcement and focus that follows the moving row) — and every reorder/toggle persists immediately via `prompt.set_layout`. Editable text blocks render a textarea with 800ms debounced autosave (`prompt.update`) plus a Reset button (`prompt.reset`); **data blocks** (`kind === 'data'`) are read-only with an expandable preview of their current text. Each row shows an **owner hint** — a plain sentence stating the render condition (owner = gate 2 of the prompt filter), e.g. "Always included.", "Included only while the {name} tool is active.", "Included only while the memory tool is on." (`ownerHint()` maps the internal owner token to `systemPrompt.blockList.ownerHint.*`) — `custom`/`auto` badges, and in an agent scope an `inherited`/`modified` **inheritance badge** (an inherited block shows greyed default text; editing it creates the override). Custom `user:` blocks can be **created** (slug prompt, client-side slug pre-check mirroring the backend agent-id rule) and **removed**; a "Reset order & visibility" button calls `prompt.reset_layout`. Both pickers in this view are the shared `Dropdown` primitive (no raw `<select>`): the view-toolbar **scope** picker (Default + enabled identity Agent scopes) and the **preview agent** picker. The preview agent picker combines identity agents (`agent.list`, bare-id values) with project agents (lazily scanned via `project.list` → `project.show` on mount, cached) addressed as `agent@projekt`, built by the shared `lib/agentTargetOptions.js` helper; the selected option value is passed straight to `prompt.preview` as `agent_id` (the backend resolves a project-qualified address). Project agents appear only in the Default-scope preview — an Agent prompt scope is identity-only. The preview pane has Copy but no manual Refresh: it loads on mount/preview-target change and refreshes after successful block text, layout, reset, create, or remove mutations through a short debounce with stale-response protection. Its token chip renders `~{prompt} prompt + ~{tools} tools = ~{total} tokens` when tool definitions are present (from `prompt.preview`'s `tokens`/`tool_tokens`; tooltip explains `tool_count`), or the plain `~{count} tokens` for a tool-less agent.
- `LogsView.svelte` and `logsView.js` own read-only log file selection, local level/search/sort state, and dedicated log-stream reconnect behavior. The catalog and selected file load on mount; append/reset events update entries, catalog events update the file dropdown without switching a still-valid selected file, and reconnect first reloads the catalog before re-reading/subscribing. The header has no generic Refresh action; catalog/read failures expose contextual Retry actions. Backend parsing and socket contracts live in `.vorch/domain-maps/logs.md`.
- `CronView.svelte`, `cronView.js`, and `styles/cron.css` own the **Scheduled Runs** tab (route id remains `cron`) as a control-desk master-detail view. The Secondary list leads with each job's human-readable name and deliberately carries only its health-aware `StatusChip` plus the server-projected next Run; Agent target, raw schedule, and prompt stay out of the master list. Terminal history remains selectable and deletable but has no enable toggle. The detail header carries schedule kind, name, readable target context, StatusChip, and Enabled control; four read-only summary cells project next Run, cadence, last result, and target/Session, while complete execution timestamps, Run id, failures, schedule id, and Delete remain available through Execution details and Technical details disclosures. The required Name/Agent/Prompt fields and Cron/Once timing plus optional existing Session are organized into Task, Timing, and Session cards; ordinary fields use `FormField`, Cron remains an exactly-five-field expression behind a readable preset, there is no per-job timezone control, and Save stays sticky. `cronView.js` converts persisted UTC Once instants to and from the server timezone reported by `cron.list`, never the browser's accidental local zone. Cron `resource_changed` tokens reload the list; an active draft defers the visible swap, clicking the selected row is a no-op, and switching/Add/Cancel asks before discarding edits. Agent/Project tokens refresh target options. While connected, list failures render a contextual inline Retry and suppress false empty/no-Agent states; App passes `serverUnavailable` during a global outage, when Cron suppresses both Agent and job transport errors/retries, renders the ordinary Scheduled Runs `EmptyState`, and leaves AppShell's central Retry as the single recovery action. Mutation success remains app-level toast while save validation/errors remain inline. The preset helpers and shared `agentTargetOptions.js` address behavior remain as before. Scheduler/time/health semantics live in `.vorch/domain-maps/automation.md`.
- `webui/src/lib/agentAddress.js` is the one client-side `agent@projekt` parse/format seam (`formatAgentAddress`/`parseAgentAddress`), mirroring `core/projects/address.py`; Cron, Statistics, and the `agentTargetOptions.js` builder consume it. (`chatState.js` keeps its own Phase-2 `formatAgentAddress` deliberately, in lockstep via the shared `@` separator.)
- `webui/src/lib/agentTargetOptions.js` is the one builder for "agent target" dropdowns — it turns `agent.list` plus lazily-scanned project teams (`project.list` → `project.show` → `projectTeamEntry`/`projectIdsFromList`) into a flat option list mixing identity agents (bare-id values) with project agents (`agent@projekt` values), and `buildAgentTargetDropdownOptions` adds disabled "Identity agents"/"Project agents" group headers only when project agents exist (identity-only stays header-free). Cron and System Prompt both feed it into a `Dropdown`; cron re-exports it under its historical `buildCronAgent*` names for back-compat.
- `ProjectsView.svelte`, `createProjectsState`/`createProjectsController` plus normalization helpers in `projectsView.js`, and `styles/projects.css` own the Projects master-detail management view. The controller owns the reactive workflow state, selection, request ordering, stale-response rejection, detect and auto-save timers, safe catalog swaps, list/scan reconciliation, and every Project mutation; the component renders controller state, computes presentation-only options/labels, and forwards user intents. The thin `project.*` wrappers live in `api.js`; backend behavior is in `.vorch/domain-maps/projects.md`. Read `webui/projects.md` for the management, scan, and Team-row runtime contracts. `ChatView` also imports `projectTeam` for Project-Agent selection, so its `agent_id` and `display_name` projection is a cross-view contract.
- `markdown.js`, `toastState.js`, `audioRecorder.js`, `sessionListView.js`, `clientCaches.js`, and the other small `lib/` helpers should stay pure where practical and are covered by focused Vitest tests under matching `__tests__/` directories. Chat Markdown presentation lives in `components/chat/MarkdownContent.svelte`: it consumes `markdown.js`'s safe HTML/code-block projection and owns the mounted shared `CopyButton` lifecycle for fenced-code headers, so callers do not inject native clipboard controls into `{@html}` output.
- **UI primitives (`components/ui/`)** group the shared design-system controls, distinct from the feature components in `chat/`, `agents/`, `settings/`, `debug/`. Each primitive owns the single canonical CSS class per variant (styling source stays the global classes in `styles/app.css`; the component consumes them and hides the markup) and follows the `Dropdown.svelte` convention (that exemplar and `SearchableDropdown.svelte` live flat in `components/`, **not** in `ui/` — see the shared-dropdowns bullet below) — Svelte 5 `$props()`, callback props (`onClick`/`onChange`/…), no event dispatchers, already-translated content in via `children`/props. `Button.svelte` covers `variant` (`primary`/`secondary`/`tertiary`/`danger`) + `icon` footprint, replacing the ~80 hand-built `btn-*` call sites and collapsing the duplicate class names (`btn-new`/`btn-outline`/`modal-btn-*`/`send-btn`/`icon-btn`/`tl-btn`/`pane-action`) to one per variant. `Modal.svelte` owns the dialog chrome (overlay, overlay-click/Escape close, `role="dialog"`/`aria-modal`, header with title + close button, focus-on-open) behind `title`/`labelledById`/`onClose`/`closeDisabled` props plus `body` + optional shell-wrapped `footer` snippets; the duplicate modals (`AgentCreateModal`, `ProviderConnectModal`, the Projects add/re-point modals) supply only their body/footer. `Toggle.svelte` renders the `role="switch"` button + knob in two sizes (`lg`/`sm`) behind `checked`/`onChange`/`size`/`disabled`/`ariaLabel`, replacing the hand-built `.toggle`/`.tl-toggle` switches — including the Desktop Voice panel's former `voice-toggle` checkbox-slider (the raw-checkbox guard now has no allowlist); only the `stats-toggle` segmented period selector remains a distinct control. `StatusChip.svelte` renders the semantic pill (`variant`: `success`/`warn`/`info`/`error`/`neutral` + `children`), collapsing the `chip-green`/`-amber`/`-orange`/`-red` color aliases into the `chip <variant>` semantic names; the chip-classifying helpers (`channelEnabledChipVariant`, `channelRunningChipVariant`, `extensionStatusChipVariant`, and CronView's `statusChipVariant`) now return variant names. `Badge.svelte` is the metadata-tag counterpart to `StatusChip` — a small pill (`variant`: `neutral`/`info`/`success`/`warn`/`error` + `children`, default `neutral`; canonical `badge badge--<variant>` classes) folding the former bespoke pills (`sp-badge`, `session-row__badge`, `stats-badge`/`stats-skill-badge`/`stats-origin`, `logs-view__stream-chip`, `debug-view__status-chip`, `s-ext-version`) into one primitive; an inline icon rides the `children` snippet (SVGs keep explicit `width`/`height`) and a `use:tooltip` hint rides a wrapping `tooltip-anchor` span since Svelte actions can't apply to a component. `Banner.svelte` owns persistent in-flow feedback (`variant`: `neutral`/`info`/`success`/`warn`/`error` + already-translated `children`; canonical `banner banner--<variant>` classes), including loading feedback, form and RPC errors, warnings, and non-blocking notices; feature classes may adapt placement but never recreate the semantic variants, while known content absence belongs to `EmptyState` and transient app-wide feedback stays in `ToastStack`. `EmptyState.svelte` owns known content absence (`title`/`description`, optional `icon`/`actions`, `density`: `default`/`compact`, optional `fill`; canonical `empty-state*` classes) across Chat, Agents, Projects, Cron, Sessions, Logs, Debug, Statistics, Settings, System Prompt, and Onboarding; it must not represent loading, failure, or warning states. `TabList.svelte` owns local content-view switching across Statistics and Debug: already-translated `{ id, label }` items, caller-owned `value`/`onChange`, canonical `tab-list*` classes, generated tab/panel ids, complete ARIA tab semantics, and automatic Arrow Left/Right/Home/End activation; `appearance` selects `underline` or `segmented`, and `density="compact"` selects the smaller Mono footprint. Period/filter selectors and Chat agent navigation are deliberately outside this primitive. `FormField.svelte` owns ordinary labeled-control anatomy across Agents, Projects, provider connection, Channels, Extensions, and Specialized Models: translated label, required marker, help/error placement, full-grid span, and generated label/help/error ids exposed to the caller-rendered control through its snippet contract; value and validation state remain caller-owned, and optional field actions render after feedback. `TextField.svelte` covers the editable input (`variant` default/modal → `s-input`/`modal-input`), the `invalid` state (`s-input--invalid` red border, replacing the agents-only `agents-view__invalid`), and the read-only `s-value-box` (`readonly`); it uses the `value`/`onInput(next, event)` callback pattern (no `bind:`), so the migrated call sites pass a setter callback instead of two-way binding. `TextArea.svelte` owns ordinary multi-line form fields across Cron, System Prompt, Extensions, Skills, and Specialized Models with the same `value`/`onInput(next, event)` contract; `variant` selects bordered `default` or embedded `inset`, while `code` and `invalid` own JSON whitespace/height and validation styling. Chat Composer and queued-message editing are the only raw-textarea exceptions because they own specialized resize/send/inline-edit behavior. `ConfirmDialog.svelte` builds on `Modal` + `Button` for destructive/irreversible confirmations (`title`/`body`/`confirmLabel`/`cancelLabel`/`danger`/`onConfirm`/`onCancel`; danger confirm by default, overlay/Escape/× route to cancel), replacing every native `window.confirm` across the WebUI — callers own the open state and conditionally render it. `InfoHint.svelte` is the explanatory tier of the two-tier hint system (see the hint-system bullet below): a small "?" dot whose portaled `info-popover` opens on hover/focus, pins on click/tap (touch), and closes on Escape/outside-click; callers pass already-translated `text` (blank lines split paragraphs) and optionally `ariaLabel` (defaults to `common.moreInfo`). A growing Vitest guard (`lib/__tests__/uiPrimitives.guard.test.js`) scans all `*.svelte` and fails if a raw element reintroduces a primitive's class outside its `ui/` owner (including `badge`/`badge--*`, `banner`/`banner--*`, `empty-state*`, `tab-list*`, `text-area*`, and `form-field*` outside their owners, plus retired-alias scans banning the former bespoke pill, feedback, empty-state, content-tab, multi-line field, and form-shell class names so they cannot return), if a native `confirm(` call reappears in any component (use `ConfirmDialog` instead), **and** if a raw lowercase element carries a native `title=` attribute (use the shared tooltip action or `InfoHint` — component `title` props like Modal's are unaffected).
- **Hint and hover-card system (`lib/tooltip.js` + `components/ui/InfoHint.svelte`)** — two hint tiers plus one structured-preview mechanism, with native `title` attributes banned by the guard. Tier 1, the **quick tooltip**, is `use:tooltip={text}` (also the `tooltip` prop on `Button`/`CopyButton`): one shared `#app-tooltip` portaled to `<body>`, styled per DESIGN.md, multi-line via `pre-line`, delayed by `TOOLTIP_SHOW_DELAY_MS` (150ms), and hidden on leave/blur/pointerdown/Escape/scroll. Empty text disables it; while visible it links to the anchor via `aria-describedby`. Disabled controls put the action on a wrapping `.tooltip-anchor`. Tier 2, **`InfoHint`**, is the pinnable "?" explanation dot for concepts that would otherwise become permanent grey prose. Rich or interactive hover content uses **`use:floatingHoverCard`** on the card element: the action takes its initial parent as the anchor, portals the card to `<body>`, positions it with `positionFloating`, keeps one card open across the pointer gap, links descriptive content to keyboard focus, supports `accessible:false` for decorative previews, and closes on Escape, resize, or ancestor scroll. `ToggleChipList` Tool/Skill descriptions and Chat Attachment image previews consume this mechanism; never place a structured hover card as an absolute child of a bounded card or scroll container. (**not** in `components/ui/`): `Dropdown.svelte` is the **simple** picker and `SearchableDropdown.svelte` is the **searchable** picker; both are fixed/portaled, share the callback-prop contract, and position through `lib/dropdownPanel.js` (`computePanelPosition` + `portal`). A Model picker is `SearchableDropdown` fed by `modelSelection.js`, reused by Agents, Cron, and Projects. Design tokens live in `.vorch/DESIGN.md`.

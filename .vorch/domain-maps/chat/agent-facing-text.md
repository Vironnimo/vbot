# Chat Agent-facing Text

Why each sentence of the Compaction checkpoint guidance the Chat domain owns in `core/chat/messages.py`, the `core:permissions` System Prompt block and the permission Run failures (`core/chat/_run_permissions.py`, `core/settings/agent_defaults.py`) exists; the reasons for Chat's steering, interruption, reply-surface and command texts stay in the `## Agent-facing text` sections of `chat/run-execution.md`, `chat/request-building.md` and `chat/commands.md`. Rules for this file: `.vorch/workflows/domain-map-workflow.md` -> Agent-facing text.

| Text | Reason |
|---|---|
| `This is Compaction checkpoint {ordinal}. Some earlier original messages are no longer directly present in active Context; the Session still stores them unchanged.` (`core/chat/messages.py::COMPACTION_CHECKPOINT_GUIDANCE`, appended once to each new checkpoint's summary note) | Tells the Agent that the summary is lossy and that the originals still exist, so it neither treats the summary as the complete record nor assumes earlier wording is lost. It names no retrieval Tool: the stored note outlives any Tool or Skill availability, and the `vbot-docs` Skill's description advertises transcript retrieval where it is available. Replaced the `history` Tool instruction (2026-10-04). |
| `## Permission rules` (heading of `core:permissions`, rendered only for a restricted Run) | Names the section in `[prompt-block-change]` notes; without the block a restricted Agent learns its limits only from refusals, one failed call each. |
| `The user set permission rules for you: every Tool and command refuses access outside these limits.` | Says the limits come from the user and hold for every Tool, so the Agent neither tries another Tool to get around a refusal nor treats a refusal as a fault to retry. |
| `- You can read files only in: {items}.` / `- You cannot read any files.` (only when `read` is limited) | Lets the Agent plan reads inside the readable folders instead of discovering the limit by refusal; folders in `/` form. |
| `- You can change files only in: {items}.` / `- You cannot change any files.` (only when `write` is limited) | Lets the Agent put new files and changes where it may, for example in its Scratch Area, instead of failing a write first. |
| `- You can run only these commands: {items}.` / `- You cannot run any commands.` (only under `commands: listed`) | Lets the Agent choose an allowed command instead of a refused one. |
| `- You can fetch only from: {items}.` / `- You cannot fetch from any host.` (only under `web: listed`) | Lets the Agent pick an allowed source instead of a refused fetch. |
| `- These rules refuse access everywhere: {items}.` (deny rules of every layer, deduplicated) | Deny rules win over every allowed folder; without them the Agent reads the allowed folders as fully open. |
| `This Session's inherited permission rules cannot be read, so it does not run. Ask the user to check the Session.` (`_INVALID_CEILING`, Run failure) | A Sub-Agent Session whose stored ceiling is unreadable must not run unrestricted; the Parent Agent reads the failure and can only hand it to the user. |
| ``defaults.agent.permission_rules in settings.json is invalid, so Agents that inherit it do not run until it is fixed; `vbot doctor config` names the problem`` (`InvalidPermissionRulesDefaultError`, resolution failure) | An invalid default must not grant full access; the text names the setting and the command that shows the problem, for the user or a Parent Agent that relays it. |

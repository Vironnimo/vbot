# Server: path pickers

The directory listings accessors use to pick server paths and chat `@` mentions: `filesystem.*` in `server/rpc/filesystem_methods.py`, `files.list`, and their listing owner `core/utils/directory_listing.py`.

A directory listing's or picker entry creation's failure reason and a listing path the request may not name, such as a link inside a listing root that leads outside it, are `routine` `RpcError`s, which the dispatcher logs at DEBUG (`server.md` -> Source routing): path pickers hit both while the user types or browses.

## Server path pickers

Accessor and server may run on different hosts, so `filesystem_methods.py` serves `filesystem.list {path?, root?, include_files?, prefix?}` (default false: directories only) over the whole server filesystem, one directory per call; a non-empty `prefix` keeps only the entries whose names start with it, ignoring case (Python `casefold`), so completing a typed name reaches entries a listing without it would cut off. The listing is owned by `core/utils/directory_listing.py` (`list_directory`, and `list_directory_sync` for callers already on a worker): `path` null lists the places (`entries` are the filesystem roots, `C:/`-style drives on Windows or `/`, plus `home`; `path` is `""`); otherwise `path` is absolute, `~` or `~/...`, or with `root` relative to that root (`""` = the root, `..` and links or junctions leading outside it are `invalid_request`), and `path`/`parent` come back in the same form with `/` separators (`parent` null at a filesystem root, at `root` and for the places). Result `{path, parent, entries: [{name, kind: directory|file, link, hidden}], truncated, separator, home?}`: directories first, then case-insensitive name; `link` marks symbolic links and junctions, which can be entered; `hidden` marks dot-names and the Windows hidden attribute; at most `DIRECTORY_LISTING_LIMIT` (5000) entries, counted after the `prefix` filter. A listing runs on its own `directory-listing` pool within `DIRECTORY_LISTING_TIMEOUT_SECONDS` (3 s): a directory that does not answer (an unresponsive share) fails with reason `timeout` and its worker finishes unobserved. Failures are `domain_error` with `data.reason` `not_found`, `not_a_directory`, `unreadable` (exists but cannot be read, never reported as missing) or `timeout`; a relative `path` without `root` is `invalid_request`. On Linux `\` is a name character, not a separator.

`filesystem.create_directory` and `filesystem.create_file` take `{path, name, root?}`. Each creates one new folder or empty file inside the existing directory, with the same path forms, root confinement and worker budget as a listing. The returned `{path}` names the new entry in the input form. File creation exclusively opens a new file, so concurrent calls and retries cannot overwrite content. The server accepts a single native name (no separators or `.`/`..`, and no reserved names on Windows). Failures carry `data.reason`: `exists`, `not_found`, `not_a_directory`, `denied`, `invalid_name`, `timeout` (creation may still finish) or `failed`. Tests: `tests/core/utils/test_directory_listing.py`, `tests/server/rpc/test_filesystem_methods.py`.

## Chat `@` file picker

`files.list` returns `{root, files, directories, truncated}`, the index of the mention root that `core/chat/file_mentions.py::list_mention_files` builds with the picker's bundled ripgrep walk (`chat/request-building.md`); `directories` are the directories of the listed files, and `truncated` marks the `MENTION_FILE_LIST_LIMIT` file cap or the time budget. With `directory` (relative to the root, `""` = the root; outside it or not a string is `invalid_request`) `files` and `directories` are empty and `entries: [{name, kind: directory|file, ignored}]` lists that directory's direct children, ignored ones included and marked (`list_mention_directory` over `directory_listing`, so `truncated` then refers to the entries); its failures carry the same `data.reason` as `filesystem.list`. A missing root lists as empty in both forms. Tests: `tests/server/rpc/test_catalog_methods.py`, `tests/core/chat/test_file_mentions.py`.

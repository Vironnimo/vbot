# Server: browser capabilities

What the server serves to browsers by capability instead of credential: signed original-file URLs and Tool media, website previews, Extension page routes, the opaque-origin exceptions and the OAuth callback. Origin guard and transport rules: `server.md`.

## Original-file delivery

- `GET /api/files/{token}` serves Assistant-referenced originals - the token is a stateless per-process HMAC capability over the canonical path, never a caller-supplied path or copied blob. Non-image Markdown links include the canonical native path as an escaped title for accessor display/copy; the signed URL remains the delivery address (`tests/server/test_file_delivery.py`).
- `file_delivery.py` signs/verifies capabilities keeping no token registry and writing no bytes.
- Tool display `media_files` references (the images, videos and audio of a call's details) use the same signed original-file delivery. Public projection removes raw references and emits `media` items of `url`, `filename`, `kind` (`image`/`video`/`audio`) and, for a file the call started from, `role: source`; it stats the original without reading or copying bytes, and missing originals still get URLs so the ordinary 404 reaches the WebUI placeholder. Entries without an absolute path or a known kind are dropped. Displays persisted before `media_files` carry `image_files`, projected as images; a reference with a `media_type` instead of a `kind` takes the kind from it. `/api/files/` serves media inline with Range support, so video and audio players can seek. RPC, SSE, and WebSocket share this projection; without FileDelivery, internal references are stripped.
- Original-file URLs are process-local capabilities regenerated from canonical History after restart. Signed claims include the path and its observed stat revision (device/inode, size, nanosecond modification/change times), so a new Tool result or History projection changes the browser image identity after overwriting the same path. Responses use `no-store`. Revision is cache identity, never a snapshot or a freshness precondition: old URLs still serve the current original; deletion/tampering 404s. Unchanged files keep stable URLs, and reprojecting a restored file replaces a failed thumbnail. Existing mounted images are not polled for external writes. Coverage: `tests/server/test_file_delivery.py` and the mounted Tool-thumbnail revision test.
- `file_delivery.py` separates Chat image embedding from browser disposition: HTML/SVG, PDF, text and recognized media open inline, other binaries download; `?download=true` forces saving with the original filename. Only sniffed text is refined by HTML/SVG suffix. Active documents receive a shared opaque-origin CSP sandbox allowing scripts and HTTPS presentation assets, but blocking application API connections, frames and forms. HTML redirects into the bounded website capability described above; forced downloads preserve the original bytes without injecting the preview bridge. Keep this isolation when extending previews (coverage: `tests/server/test_file_delivery.py`).

## Website previews

- Static website previews extend `file_delivery.py`: `file.preview_open` in `operations_methods.py` accepts an absolute HTML entry path or an existing signed file URL and grants a domain-separated, per-process capability to the entry's parent directory. `file.preview_revision` scans a bounded website tree off the Event Loop; `/api/preview-assets/{token}/{path}` serves allowed website file types, rejecting traversal, hidden/private paths, symlinks/junctions and excluded dependency folders. Relative assets, modules, data fetches, subpages and HTTPS presentation assets work; server execution and root-relative website routing are outside this contract. Opening a delivered HTML file redirects to the same website URL; standalone pages poll the capability-scoped `.revision` endpoint for live updates, while embedded pages leave polling to the WebUI. Unavailable standalone pages retain a visible HTTP status and probe their own URL with HEAD until it returns; recovery connections require a valid signed capability even while the directory is temporarily missing, and each asset request still validates the current tree. HTML responses announce their location to the parent for reload recovery; the WebUI validates that message against the active frame and capability prefix. Evidence: `tests/server/test_file_delivery.py`.

## Opaque-origin exceptions

- Opaque-origin exceptions are GET/HEAD under `/api/preview-assets/` and `/api/extension-assets/`; each verifies its own domain-separated capability and file boundary. Responses allow CORS only for `Origin: null`, without credentials. Extension assets additionally bind the current owner/page registration and permit only their exact built static subtree; external connections, nested frames, forms and workers remain blocked. Website previews retain their HTTPS presentation allowance. Opaque-origin RPC, ordinary file delivery, health and WebSocket access remains rejected.

## Extension pages

- Extension page operations and selected Run streams use `extensions_methods.py` and short-lived owner/page capabilities. `extensions.page_run` and the Run SSE route read ownership once, then re-verify the page registration before exposing the Run (the replay watermark is read after that check). Page validation, before and again after each awaited page-scoped call (so a page never receives a result across a reload or live disable), reads the registry's in-memory page table (`ExtensionRegistry.current_page`) on the Event Loop, never the filesystem or a worker pool. `extensions.page_history` adds shared semantic items; `extensions.page_run` opts into the capability-scoped projected stream with `timeline: true`. Stream delivery revalidates the current registration after awaited projection and closes generators on disconnect/send failure. Canonical history and owned Run detail pass through the existing public payload sanitizer; page metadata is not authority to select another owner or arbitrary RPC method. Coverage: `test_extensions_methods.py`, `test_app.py`, `test_file_delivery.py`.

## OAuth callback

- `GET /api/oauth/callback` (`_oauth_callback.py`) is where the browser returns from an Extension's OAuth sign-in: it hands the query to `runtime.oauth_redirects.deliver` (`extensions/host.md` -> OAuth browser redirects) and answers with a small static page (200 `Sign-in received`, else 400 `Sign-in not found`; a repeated query parameter is refused before delivery). The page loads nothing and sends `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and a `default-src 'none'` CSP, because its address carries the authorization code. The lifespan binds the callback URL: in the Access Mode `authenticated` `<public-url>/api/oauth/callback` (`access.md`); otherwise from the resolved bind: wildcard and `127.0.0.1` binds publish `http://127.0.0.1:<port>/api/oauth/callback`, `::`/`::1` publish `[::1]`, `localhost` publishes `localhost`, any other listen host publishes none. Evidence: `test_oauth_callback_completes_only_the_awaited_sign_in` in `tests/server/test_app_http.py`.

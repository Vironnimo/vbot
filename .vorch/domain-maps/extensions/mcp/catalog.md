# MCP connector catalog

Read for work on the connector catalog: `resources/extensions/mcp/catalog.json`, `_connectors.py`, the `catalog` and `add_from_catalog` management operations, or the WebUI Catalog dialog. Connection ownership, saving, OAuth sign-in and Agent access stay as described in `extensions/mcp.md`.

## Entries (`catalog.json`)

A read-only resource shipped with the Extension: `{"entries": [...]}`. Each entry is a vendor-run MCP server reached over Streamable HTTP that needs either no sign-in (`auth: "none"`) or an OAuth sign-in vBot completes by itself (`auth: "oauth"`: dynamic client registration that accepts vBot's loopback redirect URI). Services that need a pre-registered client, a pasted API key or a Client ID Metadata Document do not belong here. Entries carry no logo: tiles show initials and a color derived from the id (user decision, 2026-10). A live probe on 2026-10-06 confirmed each entry with the pinned SDK up to the vendor's sign-in page (no login, so token exchange and Tools of oauth entries are unverified); entries that needed the OAuth fixes or `redirect_host` were checked again through vBot's own sign-in code. Left out after the probe: Mollie (registration accepts allowlisted clients only), Mixpanel, Amplitude, Datadog, Intercom and Klaviyo (unreachable from the probing network, so unverified), beehiiv, Ramp and Bitly.

Fields (`_connectors.ENTRY_SCHEMA`, no others): `id` (`CONNECTION_ID_PATTERN`, unique), `name`, `description` (English, one line, at most `MAX_ENTRY_DESCRIPTION_CHARACTERS` 120), `category` (`CATEGORIES`: knowledge, productivity, design, development, analytics, business), `url`, `auth`; optional `read_only_url` (the service's read-only address), `redirect_host` (`localhost`, oauth entries only: the connection gets `oauth_redirect_host`, for services that refuse loopback redirect addresses, `extensions/mcp.md` -> OAuth sign-in), `notes` (English one-line hints shown on the tile, such as a required plan or role) and `docs_url`. All URLs are `https://`. The texts are not translated: the WebUI shows them as written.

`load_connectors` validates the file when `MCPService.start` runs: an entry that fails the schema, has a line break in a text, a non-https URL, or does not yield connections (`url` and `read_only_url`) that pass `validate_connection` is left out with an issue (`invalid_entry`), every entry of a duplicated id is left out (`duplicate_id`), and an unreadable file leaves the catalog empty (`invalid_catalog`). Each issue logs one WARNING `MCP catalog entry left out: <issue>`; the Extension starts regardless. A redirect host never freezes a redirect URI into the connection: the URI still comes from the server's callback, so it follows the server's port.

## Operations

- `catalog` (read-only): `{"entries": [...]}`, each entry as in the file plus `connections`, the ids of saved connections whose `url` names the entry's `url` or `read_only_url` (scheme and host compared in any case, a trailing slash ignored, the query compared exactly).
- `add_from_catalog {entry, read_only?}`: saves an enabled Streamable HTTP connection with the entry's `description`, `oauth: true` for an oauth entry, `oauth_redirect_host` from `redirect_host`, and `read_only_url` when `read_only` is true (refused when the entry has none). The id is the entry's id, else `<id>_2`, `<id>_3` and so on (cut to 32 characters); ids of saved connections and of rejected records in `connections.json` count as taken, and the save never replaces (`_save(replace=False)`), so it logs `MCP connection configured` like `save`. Returns the connection's `status`, including `pending_requests`. An unknown entry is refused with a pointer to `catalog`. The new connection starts at once; an oauth entry's sign-in then appears as an `oauth` pending input of that connection (`pending_inputs` change). Like any connection, it reaches no Agent until `mcp_<id>` is enabled for that Agent.

## WebUI Catalog dialog

`webui/src/components/settings/McpCatalogDialog.svelte` with the pure helpers in `webui/src/lib/mcpCatalog.js`; `SettingsMcpPanel.svelte` opens it from the section header's Catalog action, from the empty state's "Browse the catalog" action, and at the sign-in step from a connection row's Sign in action (shown while the row's `pending_requests` hold an `oauth` request). Three steps in one Modal (Escape and Back close it, except while a call runs):

- Browse: reads `catalog` once per opening; a search field (every word must occur in name, description or id) and a category Dropdown (`MCP_CATALOG_CATEGORIES`, mirroring `CATEGORIES`; literal `mcp.catalogCategory.<category>` keys) filter a tile grid. A tile shows the mark (`mcpCatalogMark`: the name's initials on `hsl(<hue> 55% 42%)`, the hue hashed from the id), name, "Sign-in required" or "No sign-in", description, each note, a "Connected" badge while `connections` is not empty (tooltip names the ids; connecting again adds `<id>_2`), a Read-only checkbox when the entry has `read_only_url`, the `docs_url` link and Connect (`add_from_catalog`, `read_only: true` only when checked).
- Sign in (oauth entries and the row action): `mcpSignInPhase(status, lastRequest, now)` derives `connected`, `waiting` (the `oauth` request in `status.pending_requests`), `timeout` (that request, or the last one seen once the connection failed, ran past `expires_at`; a timer re-evaluates at the expiry), `failed` (the row's problem advice through `mcpProblemText`, else `error`) or `preparing`. The dialog reads `status` again on each `connections` or `pending_inputs` change of owner `mcp` and on owner-less invalidations; it reads the request from `status` rather than `extensions.requests`, since one call carries both the request and the connection state. Waiting shows `RequestedUrl` (its safety rules unchanged) and, behind "Signing in with a browser on another device?", a write-only field whose redirected address goes to `respond` (`inputResponse`). Failed and timeout offer Try again: `reauthorize` when `status.oauth.signed_in`, else `reconnect`. `connected` moves on to the grant step; a `none` entry goes there straight after Connect.
- Grant: loads `agent.list` and `tool.list`; lists the Identity Agents (built-in Agents left out, `mcpAgentAccess`), an Agent that already has `mcp_<id>` checked, disabled and marked "Has access". "Allow access" saves `agent.update {id, tool_access}` per chosen Agent with `mcpGrantedToolAccess` (`setToolAccessPreference` from `lib/toolAccess.js`, so the Tool joins `granted`, and `allowed` in selected mode; a None-mode Agent switches to selected with only this Tool, as in the Agent editor). Skip saves nothing. Either closes the dialog and expands the new connection's row.

The global Extension request banner (`ExtensionRequests.svelte`) still offers the same sign-in; answering it in either place ends the request for both.

# Computer Use Extension

Read this reference for the bundled `computer_use` Extension, its opt-in `computer` Tool, desktop input, observations, and operator stop.

## Ownership and prerequisites

The existing service's internal files separate Tool schema/argument validation (`_arguments.py`) from owned Session view records and pure reference selection (`_session_views.py`). `extension.py` retains live authority checks, Driver lifecycle and effect dispatch; the extracted reference helpers cannot authorize or send input. Tool descriptions and recovery wording are unchanged.

`resources/extensions/computer_use/extension.py` owns validation, live authority checks, observation ownership, dispatch, and registration. `driver.py` owns the persistent Cua MCP connection and emergency hotkey. `windows.py` owns Windows physical display geometry, screenshots, modal-window resolution, and foreground input through Pillow/Win32. `observations.py` owns original images, coordinates, crops, and bounded results. `skills/computer-use/SKILL.md` supplies the workflow through ordinary loaded-Extension Skill discovery and allowlisting; it does not grant Tool access. The manifest remains version 1.0.0 and requires Extension API v5.

`computer` requires explicit opt-in; Project whitelist membership alone does not grant access. Policy is checked after lock admission, connection/session setup, and before subsequent actions. Independent Bash permission remains outside this boundary.

The installed Cua Driver must be stable 0.23.2 or newer. Registration snapshots executable availability; installation requires Extension reload. The Extension does not install or update it. Input dispatched to Cua uses its tagged `target` contract; window cursor movement omits the unsupported delivery field. Cua screenshots, including Windows background captures, require `max_image_dimension=0`; Windows foreground Pillow captures are independent of this setting. No source patch or compiler is required.

## Desktop behavior

- `pid`/`window_id` select a window; an owned `view_id` infers the target for input, capture, wait, verify, and zoom, including from a sequence's coordinate steps. A complete current element ref also selects its window, including in the first sequence step. Numeric indices need window ids or a window view; unqualified ambiguous refs refuse before dispatch. Without a reference or window ids, the target is the desktop. Explicit targets must match the reference. Observations default to vision; `som` adds compact window elements and `ax` returns only elements. Supplying `query` or `limit` requests window elements unless an explicit incompatible vision mode is rejected. Cua matches query as one case-insensitive literal substring and includes ancestors; regex and OR syntax are not supported. Browser windows are ordinary native windows, with no CDP or browser-specific actions in this Tool.
- Input executes by default; explicit `apply=false` previews without input and returns execution guidance. New window targets default to Cua background input and capture; the desktop uses foreground input. Omitted delivery uses the explicit view/element setting, otherwise the target's last setting within the Run. Explicit true/false changes that preference, which survives input without a post-input capture. Coordinate input must match the capture's foreground setting; zoom preserves it. Window/display geometry is checked around background capture and before pixel input. Desktop background input, background timed holds, and background modifiers refuse before dispatch. There is no automatic foreground retry.
- Windows capture includes all monitors or one selected display. `coordinate`/`to_coordinate` pairs refer to the returned image and map to physical virtual-desktop coordinates, including negative origins; resize uses a screen position and `size` pair. Target selection is derived from window IDs or their omission, with no public scope field. Changed window/display geometry refuses input. DPI awareness is thread-local and restored after use.
- Windows foreground vision skips UIA. Foreground window `som` queries Cua elements without a screenshot, then captures native pixels last; `ax` skips the image. Foreground screenshots reject a target that is not foreground before or after capture, preventing another application's pixels from being labeled as the target. Other platforms retain Cua capture/input and explicitly refuse Windows-only monitor selection and foreground timed input.
- Background window captures use Cua's own image coordinates and capture backend; background vision bounds Cua's required UIA query to one level/element and omits that intentionally incomplete query's degradation flags. Background drags preserve explicit duration up to 2000 ms, defaulting to 250 ms. A target that becomes foreground during a background action is reported and stops the remaining sequence. This detects an observed focus change; it cannot prevent application-driven activation or prove that an unverified background action had an effect.
- Sequences contain up to eight mouse/key/text/wait actions with one final observation. Coordinate steps inherit a top-level `view_id` when omitted locally; it must not become a coordinate request on key/text steps. Retained crops may be combined only for the same target and delivery setting. Only the first step may reference an element. All steps validate before input. Results include total/completed counts and compact numbered step outcomes; expected and unexpected input failures preserve completed steps, stop subsequent steps, and attempt a recovery observation. Observation failure never authorizes replay.
- Windows resolves a disabled owner to its visible modal popup only within the same process. Input to a blocked owner refuses before dispatch; post-input capture follows the popup and returns its actual target plus the requested owner, so further input can use the dialog's view directly. Arbitrary foreground windows never substitute for the requested target.
- `capture_after=false` skips the automatic image after successful input or sequence, preserves the dispatched outcome, and invalidates all prior observations; further input needs a new capture. Partial sequences still attempt an observation. `wait` is interruptible, defaults to one second, is bounded to ten seconds, and captures afterward (only at the end when inside sequence).
- Windows foreground coordinate click/drag/scroll supports held modifiers. They span the whole action, including both clicks of a double-click, and release on completion, failure, or stop. A requested modifier already held by the user refuses before pointer movement. Unsupported modifier routes refuse rather than silently ignoring keys.
- Foreground `type` on Windows supports explicit `text_mode=keyboard` for raw-key applications. It maps the entire text through the active keyboard layout before the first character, refuses unavailable characters, dead-key composition, and already-held keys, respects Caps Lock, and releases owned keys on interruption. Dead-key preflight does not alter Windows' pending composition state. Unicode remains the default; keyboard mode never falls back to Unicode or background delivery. `type`, `key`, and `set_value` may use an owned `view_id` solely for target and delivery selection without coordinates.
- Windows monitor results include `scale_percent`; the capture/input fingerprint includes per-monitor scaling as well as physical geometry. Failure to enter per-monitor DPI awareness or a screenshot/geometry size mismatch refuses capture. Model coordinates stay image-local; no additional DPI multiplier is applied.

## Lifecycle and stop

Internally named Driver sessions belong to Project/Agent/Session/Run. Explicit close, Run completion, and Extension shutdown close only owned sessions. One service lock serializes input. Cancellation ownership tokens prevent late callbacks from interrupting a later call. Interruption kills the owned `cua-driver mcp --direct` worker, never a shared daemon.

A named session enters the cache only after its start succeeds; selecting a replacement worker also discards cached session references. Closing the last owned session closes the worker and its implicit transport session. Other active Runs retain their connection. Cleanup transport loss discards the stopped worker's sessions without starting a replacement. Every MCP call other than start/end explicitly starts or renews its named or implicit Driver session before dispatch. Long native input can leave the named MCP session idle. Revival clears that session's cached background geometry: reads proceed, while pending input refuses with `computer_session_expired` before dispatch and requires a fresh capture. Driver expiry errors use that same public recovery code instead of exposing a Driver-only action. This adds a local lifecycle call, never a replay of requested input.

Operator stop runs outside the service lock. Windows checks a stop event before short input batches; timed key holds and drag waits are interruptible and release owned keys/buttons on completion, error, and stop. A stopped native adapter is not reused. Already delivered OS events cannot be rolled back. Normal user clicks do not introduce a new foreground-input abort mechanism; the Skill explains shared input and possible user/application changes without attributing them automatically to Tool defects.

Stop interrupts only the active Tool call and reports `computer_use_interrupted`; it never changes Tool permission or persists a paused state. Later calls, including calls from other Agents or after restart, remain available without a resume operation. The user-only `control` operation exposes status/stop. Status carries a fresh `call_id` for the active invocation; stop must address that exact reference so a stale UI request cannot interrupt its successor, even if Provider Tool-call ids are reused. `ComputerUseControl.svelte` shows Stop only during an active call, with a transient stopping state while it drains. Stop sources and Run/Tool-call ids are logged without attributing every interruption to the user.

`EmergencyHotkey` owns a Windows keyboard hook for two physical Esc presses within 600 ms, with key-up between them; repeats and injected input are ignored, and events pass through. It is armed only for the active invocation. A separate worker receives that invocation's ownership token, so delayed hotkey callbacks cannot stop later calls. A pending request ends remaining steps of its own call before worker dispatch. Idle Stop, Run completion, and Extension shutdown never create a persistent interlock.

## Observations and verification

Captures live under the caller's `tmp/computer-use`. Original PNG limits are 32 MiB / 40 million pixels; overviews use at most 1600 pixels on the long edge and 1.5 million pixels. `original` preserves full resolution and `zoom` crops original pixels. Omitted resolution inherits the selected view or target's latest observation setting within the Run; explicit `auto` resets it. The preference survives input without a post-input capture. A crop retains its parent's full-target resolution preference. `view_id` binds images to transforms. New views use `view_` plus 12 lowercase base32 characters; view images, originals (`orig_`), and overflow state (`state_`) use exclusive collision-retrying file creation through `core/utils/ids.py`. Read-only zoom returns its parent reference and local-coordinate guidance, retaining parent/recent sibling views within a 16-view Session bound. An explicit zoom `foreground` must match its view. Capturing the same target retires its previous views; mutations invalidate prior observations across Runs, and transport loss clears them without input replay. Reference validation failures before dispatch preserve the current observation. Zoom retains the canonical full-target observation and its element refs. The Run remembers bounded issued-element and retired-view ownership to distinguish stale from unknown refs and attach an explicitly retained (not freshly captured) recovery observation when available; it never resolves a target from another owner's refs. Arbitrary Driver-supplied file paths are never read.

`ToolContext.result_media` carries the displayed image; `presentation_images` exposes the original. Model results contain image dimensions, view id, target, mode and foreground setting, without duplicate image paths or backend geometry. Requested elements expose one `element` ref with role/label and available control state; tree text and duplicate indices/tokens are omitted. Text overflow retains a complete state file and reports the actual published element count. Target discovery removes duplicate Driver lists. Input results retain effect/verification/escalation signals, including `verified=false`. A zero-completion failure retains the standard failure envelope and carries recovery state in a `computer_observation` artifact, preserving the image's actionable view and target without changing the shared error schema.

Automatic post-input observations wait one interruptible second after dispatch (once after a sequence), without polling pixels. `capture_after=false` skips that delay too. The result explicitly distinguishes dispatch and an observation from application completion; a fixed delay cannot prove completion. `verify` waits for explicit window/element predicates before capturing; `wait` obtains a later observation for visual outcomes. No observation or verification path replays input.

When a capture fails or input omits its observation, `extension.py` returns the requested target and delivery plus executable read-only `recovery` arguments, inside a `computer_observation` artifact for failure envelopes. Recovery preserves observation options, routes unavailable windows to discovery and foreground/visibility failures to desktop capture, and never activates a window or replays input. Owned retired refs can supply recovery context but remain invalid for execution; conflicting targets, another Run's refs, cancellation, and revoked access do not supply recovery authority. The Skill teaches desktop selection followed by a fresh foreground window capture, local crop coordinates, and generic focus/selection transitions. Regression coverage lives in `test_computer_use_recovery.py`.

The `tests/resources/extensions/test_computer_use*.py` suites separate observations, coordinates, sequences, elements, recovery, contracts, cancellation, sessions, and transport. Shared fake Driver state lives in `computer_use_helpers.py`. `test_computer_use_windows.py` covers native geometry, Unicode events, and interrupted key/drag cleanup through a controlled OS boundary. The Provider probe matrix uses the production definition without sending input.

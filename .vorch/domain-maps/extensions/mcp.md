# MCP Extension

The bundled `resources/extensions/mcp/` package is a vBot MCP host/client. Its package entry point exports registration; API v4 supplies management, host capabilities, and live Tool publication. It runs external MCP processes on the vBot server machine; accessors do not launch helpers on their own machines.

## Ownership and invariants

`_definitions.py` holds the fixed connection Tool description/schema and operation constants; `extension.py` keeps the existing live service and registration. This internal split preserves the registered definitions and remote Tool naming.

`extension.py` owns connection CRUD, live Tool declarations, and asynchronous management jobs. `config.py` validates and atomically persists `<data-dir>/mcp/connections.json`. Persisted connections load independently: unknown top-level fields produce structured warnings and are excluded from runtime configuration; invalid records and duplicate ids are skipped without suppressing healthy connections. `list.configuration_issues` and startup logs identify the affected record and reason without configuration values. Management input remains strict. Saves preserve unknown fields and rejected records belonging to other connections; an explicit replacement can repair a rejected id. Invalid JSON or a non-array document cannot be loaded or overwritten through normal management. Credential references are configuration; values use the host credential store. Transport changes close and replace the connection.

The connection Tool is `mcp_<id>`, with fixed search/describe/call/read arguments. Remote Tools remain registered with `deferred=True` for authorization and dispatch, but never enter Provider definitions or System Prompt Tool lists. Search returns bounded summaries; describe returns only the selected definition and arguments schema as an ordinary Tool result. Target fingerprints reject changed definitions. The parent is published before connection startup and its readiness depends on saved enablement, not transient connectivity. Catalog growth, discovery, and reconnects therefore leave the existing Tool-definition prefix unchanged; explicit connection/Tool-policy changes can still alter it. Remote Tools receive deterministic bounded names and follow that parent Tool's activation. The parent declares `requires_opt_in=True`: its ordinary Tool switch adds an explicit `tool_access.granted` entry. All mode and Project ceilings never opt in; selected mode also requires the parent in `allowed`. There is no connection-level Agent list or grant/revoke operation. Explicit Tool denials, selected Tool policies, and Project ceilings still apply. Direct CLI invocation and the `explore` management operation resolve that Agent's effective policy and use ToolRegistry dispatch. Chat propagates Run restrictions and the live denial resolver through ToolContext so calls delegated by the parent cannot bypass them. Remote schema changes fail stale calls rather than applying old arguments to a new definition.

`client.py` uses the pinned official MCP SDK for stdio, Streamable HTTP, and legacy SSE. One task owns each connection's SDK context; invocations serialize per connection, while different connections run independently. Cancellation is not a promise to undo a remote mutation, and mutations are never automatically replayed. Transient failures of read operations retry at most three times with exponential backoff and jitter; authorization and validation failures do not retry. Connection-owner cancellation exits an active request and releases its pending inputs. Discovery preserves all catalog pages and their standard metadata. Catalog notifications trigger republishing; Resource subscriptions acknowledge before success and expose changes through bounded sequenced events, with explicit gap counts. Stderr is drained and configured credentials are redacted before diagnostic retention. Closing a connection cancels its task and waits at most `CONNECTION_CLOSE_TIMEOUT_SECONDS` (15s); a task that has not stopped by then is abandoned with a warning, and disable/remove still retire that connection's Tools (an abandoned runner can no longer publish). Coverage: `test_stopping_a_connection_that_ignores_cancellation_still_removes_its_tools` in `tests/resources/extensions/test_mcp.py`.

Sampling uses the invoking Agent's configured Model and only the server's explicitly supplied context. It does not copy Session history or other connections into the request. Sampling requests, the selection policy, and usage are available in connection events; these auxiliary requests do not currently contribute to the parent Run's main response usage counters. Roots use the invoking work directory. Elicitation and OAuth are resumable pending inputs available to the CLI and global WebUI request dialog; OAuth tokens use host credentials. Legacy callback and current `input_required` flows are exercised through real SDK connections.

`content.py` preserves standard structured content, annotations, `_meta`, and Resource/Prompt content. Binary extraction visits only protocol content positions, never media-shaped application JSON, schemas, or metadata. Binary blocks become durable files; image/audio attachment artifacts use normal Chat media routing. If attachment delivery cannot accept a binary, its file and the delivery error remain available. New result ids use `res_` plus 12 lowercase base32 characters, claimed through exclusive file reservation inside the saving worker; the reader accepts bounded safe opaque ids. Input requests and management jobs use `req_`/`job_` with catalog collision checks; external MCP and correlation ids stay unchanged. Successfully prepared results are durably saved under `mcp/content/results/<result_id>.json` with Agent/Project ownership and their source connection/Tool. The result envelope carries a bounded receipt and a complete file path, including on MCP errors; binary artifacts continue through normal media delivery. The reader supports JSON Pointer, offsets, limits, and field projection, rechecks ownership and effective Tool access, and falls back to the file for an oversized view. Expansion actions for projected array rows retain the requested fields. No preview is a complete-result claim. Snapshots outlive a Run and Extension reload; no loaded-schema Session state or history rewriting is involved. The complete protocol catalog remains explicitly callable, but does not automatically include every operation schema.

## Agent discovery and operator inspection

Remote Tools use `catalog_visible=False`: general Tool selectors and Extension capability summaries expose only `mcp_<id>`, including the catalog consumed by Swarms. The MCP `inspect` projection still lists the original remote Tool names without generated dispatch-name suffixes. Hidden catalog entries remain registered for discovery, policy resolution, and dispatch. Coverage: `tests/resources/extensions/test_mcp_discovery.py`.

Search ranks partial word matches and places application Tools before protocol operations on an unfiltered page. Results include policy-filtered capability counts, external server guidance, discoverable Prompt summaries, and executable continuation arguments. Long guidance has an explicit incomplete marker and a saved-result read for its remainder; empty searches offer a Tool browse without asserting that the task is unsupported. After connection startup republishes Tools, discovery resolves access again before filtering the new catalog. Describe returns a call target alongside the selected schema. A Tool invocation that fails without a result reports `mcp_call_unconfirmed`; it does not claim that remote effects were undone.

The same failure boundary covers calls to protocol operations. Discovered target arguments first receive shared schema-guided repair against that target's exact schema, including protocol operations; arbitrary application data and external field names/enum identifiers stay intact. Remote schemas alone do not establish typo aliases or call wrappers. Only the locally owned `logging/setLevel` protocol vocabulary explicitly accepts field/level formatting. Ambiguous encodings and genuinely invalid target arguments return `mcp_invalid_arguments` with a JSON Pointer and bounded validation detail before invocation. Expected storage/media preparation failures after a received result return `mcp_result_unavailable`, independently from an unconfirmed call; neither path replays the operation. Event diagnostics redact decoded string values and keys before retention so JSON escaping cannot hide a credential or corrupt an event. Coverage: `tests/resources/extensions/test_mcp_execution.py` and `test_mcp_oauth_and_cancellation.py`.

The read-only `inspect` management operation returns the cached, paged Tool catalog, server guidance, and Prompts. It does not connect or execute an application Tool. Access is configured through the shared Agent or Swarm Tool editor; connection management does not maintain a second roster. The Settings inspector uses this projection without duplicating policy resolution and discards stale or closed inspection requests.

`scripts/probe_provider_tool_call.py --scenario mcp_workflow` runs an actual Model against the production MCP entry point and an inert application served through the official SDK. Cases cover indirect render intent, recovery from an empty search, and selective reading of a large result. The fixture never evaluates generated Python or renders a real Blender scene. Structural call-shape coverage remains in the existing `mcp` scenario; deterministic host and probe tests protect the evaluation machinery.

`ExtensionHost.resolve_tool_agent(context)` resolves the actual calling Session through Runtime, including exact temporary bindings and their execution-owner generation. MCP uses it for fresh policy checks, including queued calls; ordinary management still uses addressed Identity/Project resolution. Sampling uses the same Session-aware resolver. Regression coverage: `test_mcp_access.py` and `tests/core/runtime/test_runtime_mcp_access.py`.

The explicit offline `scripts/converters/mcp_tool_access.py <data-dir> --apply --port <stopped-port>` transfers previous grants into ordinary Tool opt-ins. It is not required merely to load connections containing obsolete fields; those fields have no runtime meaning and do not grant access. Dry-run is the default. Malformed legacy Agent lists reject before changes instead of being interpreted as grants. It backs up changed files/rows, removes connection Agent lists last, retains explicit MCP selections in Swarm profiles/snapshots and temporary bindings, and preserves prior Identity-Agent grants through shared opt-ins. Project overrides with an explicit Tool policy are converted; absent overrides are not synthesized from a ceiling because that would replace repository denials. Those Project Agents must explicitly enable the connection in their Tool editor. Session Messages are untouched; startup never rewrites configuration or interprets obsolete fields.

## Compatibility boundary

The SDK is pinned to `mcp==2.1.1`. The 2026-07-28 protocol removes ping; connection testing reports catalog verification instead when that revision is negotiated. Historical task-augmented Tools require the SDK dispatcher's raw request seam because the high-level SDK wrongly validates task handles as ordinary Tool results. That seam stays inside `ConnectionRunner._task_send`, reuses the existing connection stamping/cancellation/progress machinery, validates task handles, and returns the complete original task payload. Do not replace it with the empty `GetTaskPayloadResult` model or an unparameterized generic Request: those drop payload or argument fields. The real stdio task test protects both cases.

Protocol extensions that the selected SDK cannot interpret must fail explicitly; never advertise a capability that the host does not implement or silently discard unsupported content. External protocol-version compatibility is distinct from prohibited legacy vBot configuration migrations.

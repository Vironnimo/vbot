# Statistics

Incrementally indexed aggregation over persisted Sessions producing the WebUI Statistics tab without reparsing unchanged transcripts.

## Overview

`core/statistics/` derives every local activity figure from canonical `ChatMessage` history while `StatisticsIndex` maintains a disposable typed SQLite read model at `<data_dir>/statistics/session-statistics.sqlite`. The index is a disposable projection opened through the database kernel (`statistics_database_spec`: application id `statistics`, projection version 1; `database.md`), which owns its identity, journal policy and rebuild at open. Every read reconciles the listed Sessions' generation and revision (one batched `list_history_versions` call) through the Sessions-owned append cursor, ingests only validated new tails into typed fact tables, prunes removed scopes, then aggregates in SQL on the same connection. Nothing is hydrated or retained in memory between reads, and an unchanged index with unchanged pricing is read without any write. A projection-version or identity mismatch or a damaged file is rebuilt by the kernel at open; a new generation or an invalid cursor rebuilds that Session's derived rows; neither touches canonical data. Reconciliation and aggregation both run on the kernel writer (aggregation needs temp tables, which read-only pooled readers refuse) with one second of lock patience. The normalized limit observations are Provider-owned upstream data in `provider-usage.db` (`providers/usage.md`); Statistics neither writes nor caches them. Statistics ingests only each Session's own audit (`SessionReadBatch.messages`; `sessions.md` -> Terms), so a fork's inherited history counts as its source's activity and is never ingested for the fork.

`StatisticsService(chat_sessions, agents, projects=None, skill_inventory=None, *, pricing_lookup=None, index=None)` is constructor-injected via minimal Protocols. The Runtime owns one `StatisticsIndex` (`runtime.statistics_index`, built next to `ChatSessionManager`) and injects it into the Statistics RPC service and the Extension host's group-usage service, so every reader shares one index owner; without `index` a service owns a private one. Reporting covers Identity Agents plus every project-scoped Session (project agents under `agent@projekt`, identity bare); composite keys prevent identity/project UUID collisions. Extension-owned participant Sessions (e.g. Swarm) are discovered in one `list_owned_session_summaries` read and count in every section under `extension:<owner>` (see Extension activity below); Agent and Project scope discovery excludes them, so their synthetic `tmp_...` Agents never appear as Agents or leak into Project scopes. The injected exact Model price lookup supports retrospective estimates without network access. Authoritative fallback/subagent attribution and a separate per-Session sub-tab remain outside this projection.

## Report sections

Dataclass tree `{generated_at, window, overview, usage, costs, runs, compactions, errors, tools, skills, extensions}`; report records in `report.py`, Extension slices/rollup in `_extensions.py`, report orchestration in `_aggregation.py` (`ReportBuilder`: unit registration, the overview's record and message counts, Extension slice activity, Skill tally), cross-section tallies (units, slices, Agent/Model/Provider/daily rows) in `_accumulators.py` (`ReportLedger`), one accumulator per SQL-aggregated section in `_usage.py` (call tokens by Model/Provider/day, the cache section, shared token-sum SQL), `_runs.py` (Run summaries and groups, plus `load_run_activity`), `_errors.py` and `_tools.py`, report units, window SQL and Run slices in `_units.py`, typed row projection in `_projection.py`, measured-value normalization in `_measurements.py`, cache accounting in `_cache.py`, per-call cost aggregation and retrospective repricing in `_costs.py`, checkpoint diagnostics in `_compactions.py`, and source contracts/owner scopes in `_sources.py`. `statistics.py` owns service orchestration, `index.py` owns the schema, reconciliation and failure policy, and `skills.py` owns Skill usage. Public imports remain under `core.statistics`. The index stores per-Session cursors plus typed fact tables keyed `(session_key, seq)` (`stat_records`, `stat_calls`, `stat_tools`, `stat_errors`, `stat_checkpoints`, `stat_runs`, `stat_skills`) holding only aggregation-consumed fields - raw text, Reasoning, arguments/result payloads, Skill content never enter it.

- **overview** - structural totals, role counts split into visible Chat messages (`user` always; `assistant` only with non-blank text - Thinking/Tool-only steps don't count) versus all ten canonical stored roles zero-filled, including internal `history_edit` controls, run-status counts, durations, per-agent activity, daily trend with outcome splits.
- **usage** - totals plus per-provider/per-model records with input/output each split measured vs estimated (`total_tokens` only for ranking); cache section with worst hit-rate sessions (minimum reporting floor) and suspected breaks.
- **costs** - separate Provider-reported USD and estimated API value, priced/unpriced call coverage, per-Model/day/Session totals, latest 50 calls, and Compaction-call totals. Cost records contain no Connection/Account suffixes.
- **runs** - status distribution, cancel/failure/interruption rates, percentiles, longest runs, tool-call stats, derived fallback count, per-agent/session/day counts, Agentic-Loop depth (`agent_messages` visible text vs `model_steps` all responses).
- **compactions** - checkpoint counts and Strategy breakdowns, paired before/after context estimates (average, median/P95 remaining, weighted reduction), non-shrinking checkpoints, duration, intervals in saved Chat Model steps, recurrence within two steps, first subsequent measured input, and latest 50 checkpoints. Missing evidence stays null; the first checkpoint has no recurrence interval. An earlier checkpoint outside the selected window may establish the interval, and a subsequent request outside it may supply the selected checkpoint's next input. Next input includes new request content and is not an estimator-error measurement. Legacy count/reclaim fields remain for CLI consumers.
- **errors** - by kind/provider/model/agent/UTC-hour/daily.
- **tools** - per name: calls, Accepted/Rejected rates (`ok:true/false` - rejection is not malfunction), durations, top error codes, busiest sessions. No raw arguments anywhere - name, timing, envelope code only.
- **extensions** - per owner (sorted by name): `actor_key`, activity totals, and groups (most recently active first, capped at 100 with `total_groups`/`groups_truncated`) with participant rows. See Extension activity.
- **skills** - one row per current-inventory Skill joined at build time: origins (multiple on cross-scope collisions - usage keys on bare name deliberately), offered (the Session's recorded seen-Skill set, read as the `seen_skills` summary value) vs activated (both carrier parsers) vs their intersection, usage rate (`null` only without offer evidence), first/last timestamps, per-agent activations, evidence-backed delete/improve candidates separated from missing-data Skills. Deleted Skills drop out entirely.

## Interfaces

Both report RPCs (`report_async`, `run_activity_async`), group usage and startup warmup (`warm_index_async`) run on the Statistics index database's bounded worker pool (`StatisticsIndex.run_async`), including the Session reads a reconcile makes; there is no separate Statistics pool.

- `statistics.report {since?, until?}` validates ISO windows strictly; the service caches on RPC state over the Runtime's shared index and offloads reconciliation so filesystem/SQLite work never blocks the loop. A busy or locked index raises `StatisticsUnavailableError` (a `VBotError`, so RPC returns `domain_error` "Statistics are busy; retry shortly") and never discards the index. Startup warmup (`server/_app_lifecycle.py`) runs only for a Runtime exposing `statistics_index` plus the Session, Agent, Project and pricing methods Statistics reads; it reconciles the index without building a report.
- `statistics.run_activity {since, until}` returns Runs overlapping the requested interval (newest first, cap 200) for temporal correlation with usage changes - explicitly not causality attribution.
- WebUI renders eight sub-views from one mount-time call plus refresh or a shared 7/30/90-day/all-time selection through the existing report window. A failed selection retains the previous report and its scope; Limits keeps its independent live/history windows. The `StatisticsView` owner retains report/range/tab state while internal `components/statistics/*Panel.svelte` components render each local section; chart granularity survives tab changes. Shared report snippets, timeline labels and namespaced styling stay under that owner. Formatting/rollup logic stays in pure unit-tested `statisticsView.js`; bounded charts fill missing UTC periods, share one scale for measured/estimated tokens, and keep structural inventory outside the activity totals (`StatisticsView.test.js`, `statisticsView.test.js`). Presentation labels preserve visible vs records, absent vs zero evidence, and derived heuristics.
- CLI `vbot statistics compactions` formats the same section without rescanning.
- **Limits crosses two owners:** `components/statistics/ProviderLimits.svelte` owns live state, single-flight polling, visibility and cleanup independently of local report loading/errors. Statistics navigation remains available before a report succeeds; while visible, the component polls Providers-domain `provider.usage` immediately then every 10 s; `LimitHistory` separately refreshes Provider-owned history every 60 s; its uniquely named presentation rules live in adjacent `limitHistory.css`. Selecting an interval requests the Statistics-owned Run projection. Statistics performs no network access and writes only its disposable index.

## Cost accounting

- Canonical Assistant Usage stores a per-call cost snapshot; committed checkpoints carry separate `usage.model_call` data. Statistics sums these records once, only from each Session's own audit (never inherited fork history), and applies the same timestamp window as other activity. Checkpoint Model usage contributes to token totals but never adds a Chat message or Run. `model_calls` includes both kinds; `assistant_messages` retains its Chat-only meaning at the top level. Provider/Model row counts describe recorded calls.
- A finite non-negative `reported_cost_usd` takes precedence, including zero. Otherwise `core/models/pricing.py` calculates a USD API-equivalent estimate from catalog rates. The two categories cover disjoint calls and remain separate in the UI; neither is a subscription invoice. Unknown rates/counters stay unpriced, never free.
- Saved priced snapshots remain stable across catalog refreshes. Legacy calls without a snapshot use the current exact Model price lookup and are labeled retrospective. They are priced individually before aggregation because Context tiers apply per call, not to cumulative tokens. The index stores these prices: `stat_pricing` fingerprints each Model's pricing, a changed fingerprint reprices that Model's retrospective calls, and unchanged pricing prices only newly ingested calls.
- This is retained Session accounting, not an exhaustive billing ledger: auxiliary title/media/embedding requests, attempts without saved Assistant output, aborted/stale Compaction results, and deleted/archived Sessions are outside the report. Compactions predating nested Model Usage remain visible as checkpoints without invented usage/cost.
- The Overview leads with tokens, Provider cost, API-equivalent estimates and cache hit rate. Usage & costs exposes price coverage, Model/day/Session breakdowns and expandable calls. Compactions leads with remaining Context, reduction and recurrence. Unknown money renders as a dash; exact zero renders as zero, and per-call money retains small decimal amounts.
- Research leads: Hermes `agent/usage_pricing.py` at `165c889e5b4277b56dadd42949a4112c1e6175a6` distinguishes cost evidence and missing buckets; OpenClaw `src/utils/usage-format.ts` at `78f1cf1eab9472bab69288e0c91b77771d099f5d` reinforces per-call tier selection. These informed the design; vBot uses its own canonical Usage and frozen snapshots, including API-equivalent subscription value.
- Regression coverage: `test_statistics_costs.py`, `test_pricing.py`, `test_chat_loop_usage.py`, `test_openrouter_costs.py`, and Statistics component/helper tests.

## Extension activity

- `_extension_sessions()` turns each live owned Session into an index scope whose display key is `extension:<owner>` (Agent ids and `agent@project` never contain `:`) plus a participant slice key. The full report feeds them through the ordinary aggregation, so every section, window and cost rule applies unchanged; a report unit carrying the participant key additionally fills that participant's slice from the same rows, so the `extensions` section always agrees with the global totals.
- Report rows label these Sessions `"<group title> · <participant name>"` (`extension_session_summary`); `group_usage` indexes the same labelled summaries so both reads never rewrite a shared index row. A group without a stored title reports `title: null`; the WebUI labels it by start time and a short id.
- Windowed reports keep only groups with in-window records; all-time keeps every retained group. `overview.total_agents` excludes Extension actor rows; `total_sessions` includes the participant Sessions. Deleted groups (`delete_temporary_group`) leave the report and are pruned from the index.
- WebUI: `ExtensionsPanel.svelte` (Extension -> group -> participants), and `agentDisplay` renders `extension:<owner>` as the Extension name with an Extension badge in every per-agent cell. Tests: `test_statistics_extensions.py`, `StatisticsView.test.js`, `statisticsView.test.js`.

## Extension group projection

`group_usage` uses canonical Sessions Run-owner records and explicit Message Run ids
to restrict the existing index and aggregators to one owner/group, optionally one
participant. A group report returns participant breakdowns from the same indexed
index read and Run slices; clients need no per-participant report fan-out. The
read reconciles only the owner's Sessions and never prunes normal Statistics
scopes; `materialize_run_slices` then copies each owned Run's rows, selected by
explicit Run id through the `stat_records_run` index, into same-named temp tables
keyed by slice so the ordinary `ReportBuilder` aggregates them. Unrelated Sessions
are never loaded, and Messages from other Runs in a reused Session are excluded by
identity. The facade runs on the index database's worker pool and
returns the existing usage, Tools, Compaction and Run projections without costs,
account data or separate counters. Generation checks and own-audit ingestion
remain in force (`statistics.py`, `index.py`; `test_statistics_groups.py`,
`tests/core/sessions/test_run_ownership.py`).

## Conventions

- **Run identity:** the compact index retains each Message's stored `run_id`; aggregation and group usage select that exact identity. Run completion projections supply status and duration. Neighboring footer order never establishes membership. Projection version 1 (typed fact tables over each Session's own audit); the kernel discards and rebuilds an index built for another version or with another table shape, so a schema correction before the Generation 1 cut needs no version bump (`tests/core/statistics/test_index.py`).
- **Canonical-first projection:** Session appends succeed independently; Statistics is never a Chat write dependency. Scope discovery reads normalized Session summaries plus only the `seen_skills` summary value (`metadata_keys=("seen_skills",)`), never complete open-ended metadata. Reconciliation consumes each Session's own audit, superseded entries included, so a Message edit preserves historical Usage, Runs, Compactions, errors, and Tool activity while adding one `history_edit` record. Session summary values (title, `created_at`, `seen_skills`) come from the current listing on every read and are never stored, so metadata-only changes need no history read or index write. Reconciliation ingests ordinary growth from the generation-aware cursor, rebuilds only a new generation or an invalid cursor (a history edit or Agent takeover invalidates it), and deletes missing scopes. A Session that is deleted or archived between scope listing, version lookup, and detail loading is skipped and its old derived rows are pruned. Reports and Run activity share one surviving-Session read boundary. A canonical read failure propagates unchanged and keeps the index. Index failures are classified with the kernel's `projection_failure`: busy or locked raises `StatisticsUnavailableError` and never discards; damage (corruption, a missing table, a violated constraint) discards and rebuilds the file once; an unavailable file (for example an unwritable directory) or a second failure computes the read from a transient in-memory index with the same code, which loads every listed Session. A closed `StatisticsIndex` (Runtime shutdown awaits `aclose()`, which waits for a running read on the pool) is unavailable instead: reads and `run_async` raise `DatabaseUnavailableError`.
- **Inherited fork history excluded** from all activity windows: only the own audit is ingested, so entries a fork inherits (or holds as materialized copies) before its fork point never count; structural counts, current offers, and the fork's own entries count normally. Deleting an origin materializes the inherited prefix into its forks and bumps their `history_revision`, so each fork is read again; its own audit is unchanged, and the origin's activity leaves the report with the origin. This deliberately differs from the store-search and Recall attribution, which report inherited content under a surviving descendant: Statistics counts spend where it was incurred.
- **Real vs estimated tokens never merge:** field-level flags feed matching buckets, and either flag marks the call's cost as estimated; cached tokens are already inside canonical input so cache figures surface separately, never added on top; reasoning tokens are a measured-output subset.
- **Cache figures require field presence and measured input** - a non-caching provider must never read as 0% hit rate; rates divide by cache-reported input; any estimated-input turn breaks cache comparison.
- Windows filter time-derived aggregates at message-timestamp granularity (exact microsecond instants of the canonical stored timestamps, parsed with `core.utils.timestamps.parse_canonical_timestamp`; a non-canonical Session timestamp is bad data and fails the read with `ValueError`, so every indexed fact carries an instant and its day (`NOT NULL` columns, no untimed-record rules); only an absent summary value, such as a summary without `created_at`, is always in window for the Skills tally); structural totals are window-independent snapshots. Percentiles use nearest-rank.
- **SQL aggregation, streamed order-dependent parts:** `ReportBuilder` loads the surviving Sessions in report processing order as `temp.units` and aggregates sections with joins against the typed tables; Sessions whose stored instant range misses the window are skipped. Only order-dependent results stream rows in `(unit, seq)` order: money sums (float addition order must equal sequential summation, so never SQL `SUM` or Python `sum` over amounts), Run groups, cache-break comparisons, Compaction intervals, and tie orders. Report output is contractually identical to sequential aggregation; `recent_calls` is a SQL top 50 and `run_activity` a SQL `ORDER BY ... LIMIT 200` plus a count.
- Offered filters by the offering Session's `created_at` (the seen-Skill set carries no per-Skill timestamps - deliberate approximation); conversion uses only the per-Session offered+activated intersection, staying within 0-100%.

## Constraints & Gotchas

- Every report retry creates a fresh accumulator; totals from an incomplete
  aggregation are discarded before rebuilding or using a transient index
  (`tests/core/statistics/test_index.py`).
- **The SQLite index is not a second source of truth:** replace-not-migrate projection version, deletable on failure, must stay fully rebuildable - no user-owned or non-derivable data in it. Source cursors validate the processed prefix; mismatches rebuild rather than repair.
- **Temp tables shadow fact tables:** group usage creates temp tables with the fact tables' names, and unqualified names resolve to `temp` first. Section SQL must keep fact-table names unqualified; only `materialize_run_slices` reads `main.` explicitly.
- Derived fallback detection (>=2 distinct models per run group) is best-effort and labelled derived - the authoritative event is in-memory only.
- Suspected cache breaks are a heuristic comparing consecutive measured turns, skipping legitimately explained misses (first turn, checkpoint/takeover boundaries, model switches, >300s gaps, small prompts, post-estimated turns) with a 0.5 read-ratio incident floor - false negatives accepted by design.
- `open_run_groups` conflates running with crashed/interrupted; truly active Runs live in memory outside this projection's authority.
- Error attribution proxies to the last assistant model seen (`unknown` when none).
- Sessions without a recorded seen-Skill set contribute activations but no offers - accepted lower bound, never presented as delete candidates.

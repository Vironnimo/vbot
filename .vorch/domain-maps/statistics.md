# Statistics

Incrementally indexed Model consumption and retained Session activity for the WebUI Statistics tab.

## Overview

`core/statistics/` has two canonical sources: `UsageRecorder` in `model-usage.db` supplies durable Model requests (`usage.md`), and Session own-audit history supplies conversational and operational diagnostics (`sessions.md`). `StatisticsIndex` maintains a disposable typed SQLite projection at `<data_dir>/statistics/session-statistics.sqlite` through the database kernel (application id `statistics`, projection version 4; `database.md`). Session generation/revision cursors ingest validated new own-audit tails and prune removed scopes; the recorder's `ledger_id` (Usage database identity plus its latest restore, `usage.md`) and revision cursor replace changed request facts without pruning them with Sessions, reading the ledger in bounded pages. A restart continues from the projected revision; a new `ledger_id` (a restore) rebuilds the accounting projection, so a restored snapshot that has already caught up to the old revision cannot preserve stale calls, and an observed revision rewind also rebuilds it. Fork inheritance never contributes another call.

Reconciliation and SQL aggregation run on the kernel writer, with one second of lock patience because reports create temp tables. Unchanged sources and pricing write nothing to the index; no report is retained in memory. Projection damage/version mismatch is rebuildable from both canonical sources. The normalized limit observations remain Provider-owned upstream data in `provider-usage.db` (`providers/usage.md`); Statistics neither writes nor caches them.

`StatisticsService(chat_sessions, agents, projects=None, skill_inventory=None, *, pricing_lookup=None, index=None, usage_recorder=None)` is constructor-injected. Runtime shares its index and Usage recorder with the RPC and Extension group-usage services. Without a recorder, standalone constructions retain Session-only accounting; without an index, the service owns a private one. Identity and Project Session scopes remain distinct (Project display addresses use `agent@projekt`); Extension participants appear under `extension:<owner>`, never their synthetic Agent ids. Durable calls can outlive those scopes or have no Session. Current Session labels override stored attribution snapshots where available. The injected exact Model price lookup supports retrospective estimates without network access. Model fallback events (Session notes stored in `note_model_fallbacks`, `sessions.md`) are not ingested, and there is no per-Session sub-tab.

## Report sections

`StatisticsService.report(since, until, timezone, sections)` (and `report_async`) reconciles once, then builds only the requested sections from `core/statistics/_sections/`: one module per section (`overview`, `usage`, `runs`, `tools`, `skills`, `extensions`, `diagnostics`), `window.py` (hour-aligned window, previous window, local calendar days) and `common.py` (`ReportContext` with the listed Sessions and the report temp tables, `Totals`, RunRow, ranking rules). Sections read the aggregate tier plus small indexed fact queries (errors, Tool error codes, Skill activations, Extension groups, recent calls, Run lists); only diagnostics Compactions still walk checkpoint rows (`CompactionAccumulator` over a `UnitScan`). The result is `{generated_at, window: {since, until, timezone}, <section>: {...}}` with sections in that order. The WebUI and the CLI read these fields, so renaming one breaks both. Contract tests: `test_statistics_report.py` (every section), `test_statistics_usage.py` (usage, cache), `test_statistics_extensions.py`, `test_statistics_skills.py`.

`statistics.py` owns service orchestration, `index.py` the schema, reconciliation and failure policy, `_rollups.py` the aggregate tier, `skills.py` Skill usage, `_extensions.py` Extension slices and their rollup, `_projection.py` typed row projection, `_measurements.py` measured-value normalization, `_costs.py` retrospective repricing at reconcile, `_sources.py` source contracts and owner scopes, and `_accounting.py` the durable-call projection. Public imports remain under `core.statistics`. The pre-v3 report path remains only behind `group_usage` and `run_activity`: `_aggregation.py` (`GroupReportBuilder`), `_accumulators.py`, `_usage.py`, `_runs.py` (also `load_run_activity`), `_tools.py`, `_errors.py`, `_cache.py` (`load_cache_facts`, sharing the judgement SQL with the cache cubes), `_compactions.py` (also used by diagnostics), `_units.py`, `_call_scan.py` and the records in `report.py`; porting group usage to the aggregates would retire most of them. The index stores per-Session cursors plus typed fact tables keyed `(session_key, seq)` (`stat_records`, `stat_calls`, `stat_tools`, `stat_errors`, `stat_checkpoints`, `stat_runs`, `stat_skills`), canonical Run records in `stat_run_records` keyed `(session_key, run_id)`, all holding only aggregation-consumed fields - raw text, Reasoning, arguments/result payloads, Skill content never enter it.

Report-wide rules:

- **Windows** are half-open and hour-aligned: `since` is floored and `until` ceiled to a UTC hour, and `window` echoes the effective bounds. Hour-keyed aggregates and instant-keyed facts select with the same bounds, so all sections of one report cover the same time. `previous` is the window of equal length ending at `since` (none without `since`; an open `until` ends at the end of the current hour). A Run belongs to the window it started in.
- **Day series** fold hours into local dates of the IANA `timezone` (`zoneinfo`, DST-correct) and fill every date of the window with zeros; an all-time series starts at the first active hour, an open end runs to the current hour. A zone with a half-hour offset gets its day boundary at the containing UTC hour. Errors' `by_hour` uses local hours of day.
- **Money** is summed as integer nano-USD and converted to USD floats once. `null` means unknown, never 0: a cost is null when calls exist and none is priced, a Run's cost when every one of its requests is unpriced. Cost rankings put the highest known cost first, unknown cost last, then calls and key.
- **Percentiles** are nearest-rank over `agg_runs` rows (exact; durations and costs of finished Runs only) and approximate for Tools (the histogram's nearest-rank sample placed geometrically inside its bucket, clamped to the bucket and the Tool's `max_ms`).
- **Shared shapes:** `Totals` = `{calls, failed_calls, input_tokens, estimated_input_tokens, output_tokens, estimated_output_tokens, reasoning_tokens, cache_read_tokens, cache_write_tokens, cache_input_tokens, cache_calls, unreported_calls, cost_usd, reported_cost_usd, reported_calls, estimated_cost_usd, estimated_calls, unpriced_calls, retrospective_calls, uncached_cost_usd}`; token totals include their estimated parts, `unreported_calls` counts requests missing either token counter (known partial counters still count in their own buckets), `failed_calls` counts ledger requests whose status is neither `completed` nor `started`, `cost_usd` = reported + estimated (disjoint calls), and the reported/estimated/uncached amounts are null without a call of their source. RunRow = `{agent_id, session_id, session_title, run_id, origin, status, started_at, duration_ms, cost_usd, input_tokens, output_tokens, calls, model_steps, tool_calls, iterations, primary_model, models}`. Every per-Session row (RunRow, top Session, recent call, cache rows and recent Compaction checkpoints) carries `session_title` (the current listing title, `null` when untitled) next to `agent_id`/`session_id`.

Sections (caps and thresholds are constants in each module):

- **overview** - `totals`/`previous`, Run status counts `runs`/`previous_runs`, `user_runs`/`previous_user_runs` (`count`, duration p50/p90, cost p50/p90, `first_visible_p50_ms`), `active_agents` (actors with an in-window Run or request, without Extension actors and standalone requests), `active_sessions` (Session addresses with either), the day `series` with Runs and failed Runs, `by_origin`, `top_agents` and `top_models` (5 by cost; models carry the cache fields), and `insights` `{id, severity, values}` emitted only when their condition holds: `uncached_value` (uncached share of estimated value >= 0.25), `cancelled_cost` (cancelled Runs >= 5% of cost), `top_runs_share` (>= 10 priced Runs and the top 10% hold >= 60%), `failed_attempt_burst` (an hour with >= 20 failed attempts), `runaway_runs` (>= 100 iterations), `tool_failure` (>= 20 calls and rejection rate >= 0.25).
- **usage** - `totals`, `breakdowns` by `agent`, `model`, `provider` (Model key before the first `/`), `project` (`""` for Identity usage), `origin` and ledger `kind`, each every row by cost as `{key, ...Totals, runs, sessions}`; the day `series` of Totals; `top_runs` and `top_sessions` (50 by cost); `recent_calls` (50 newest) with the stored cost object, `estimated_tokens` and `retrospective` (a catalog-priced call without a saved price snapshot). A row's `runs` counts in-window Runs touching the key (once per Model, Provider and kind the Run used; Agent, Project and Session counts cover listed Sessions only), `sessions` the Session addresses with in-window requests; a row can show Runs without in-window calls. Standalone requests get no fabricated Session or Agent: an empty agent key and null `session_id`/`session_title`.
- **runs** - status `totals`; `by_origin` and `agents` with outcomes, duration and cost percentiles, averages of Tool calls and Model steps (agents add Tool time and change stats); `duration_buckets` (inclusive edges 10 s ... 1 h plus `null`, finished Runs); `daily` outcomes; `longest`, `costliest`, `most_steps` (25 RunRows each); `cancelled` (`runs`, `cost_usd`, `wait_p50_ms`); `errors` (`total` error records, `failed_attempts` from the ledger, `[{key, count}]` by kind, Provider, Model and Agent, `daily`, `by_hour` for all 24 local hours).
- **tools** - `totals` (`calls, accepted, rejected, unknown, tool_ms, tools`), per Tool by calls (`rejection_rate`, approximate `p50_ms`/`p95_ms`, `max_ms`, `total_ms`, `time_share`, top 5 codes), `rejection_codes` with their Tools, and `by_agent`. Accepted/Rejected mean `ok:true/false` (rejection is not malfunction); counts come from persisted Tool Results, so calls without a saved Result are absent; no raw arguments anywhere.
- **skills** - `SkillsSection` (`skills.py`): one row per current-inventory Skill with origins (several on cross-scope collisions - usage keys on the bare name), offered (the Session's `seen_skills` summary value, windowed by Session `created_at`) vs activated (both carrier parsers, windowed by note time) vs their per-Session intersection, usage rate (`null` only without offer evidence), first/last timestamps, per-Agent activations, and evidence-backed delete/improve candidates separated from Skills without offer data. Deleted Skills drop out. Canonical timestamps compare as strings. Background Sessions are not Skill use: a Session whose recorded `run_kinds` are all unattended (`core.runs.UNATTENDED_RUN_KINDS`, reflection reviews and Librarian passes) adds neither offers nor activations; a Session without recorded kinds counts (`skills.py::counts_as_skill_use`, shared with `skill_usage`).
- **extensions** - `ExtensionsSection` (`_extensions.py`): per owner (by name) `actor_key`, activity totals and groups (most recently active first, capped at 25 with `total_groups`/`groups_truncated`) with participant rows. See Extension activity.
- **diagnostics** - `compactions` (`CompactionsSection`: checkpoint counts and Strategy breakdowns, paired before/after context estimates, non-shrinking checkpoints, duration, intervals in saved Chat Model steps, recurrence within two steps, first subsequent measured input (it includes new request content, so it is no estimator-error measurement), latest 50 checkpoints; missing evidence stays null, an earlier checkpoint outside the window may establish the interval and a later request the next input; legacy count/reclaim fields remain for the CLI), `cache` (`lowest_hit_rate_sessions`: 20 Sessions with >= 2 cache-reporting turns, worst first; `suspected_breaks`: evaluated and suspected turns plus the 20 largest read shortfalls), `data_quality` per Model, `failed_attempts` (`total` and the 10 worst hours with `[{key, count}]` Models and Agents), `runaway_runs` (<= 50 RunRows: >= 100 iterations or cost >= 20x the median positive Run cost), `open_runs` (in-window Runs still `running`), and `roles` (`chat_messages_by_role`: every user record and Assistant steps with non-blank text; `session_records_by_role`: all ten stored roles zero-filled, including `history_edit`).

## Interfaces

Both report RPCs (`report_async`, `run_activity_async`), group usage and startup warmup (`warm_index_async`) run on the Statistics index database's bounded worker pool (`StatisticsIndex.run_async`), including the Session reads a reconcile makes; there is no separate Statistics pool.

`skill_usage()` / `skill_usage_async()` (same pool) answer per-Agent Skill use for the Skill manager inventory (`skills/manager.md`): `{(agent_id, skill_name): SkillUse(last_activated, count)}` over every surviving identity and Project Session of the roster Agents that counts as use, with no window. `count` is the number of Sessions that activated the Skill; a Project Session counts for its bare Agent id, and Extension participant Sessions are left out (`test_statistics_skills.py`).

Before each read, the recorder's resumable Session-history import catches up retained legacy facts, including archives; embedded `usage_call_id` prevents duplicates with live request recording (`usage.md`). `_accounting.py` maintains the typed durable-call projection that feeds `agg_usage`; `_call_scan.py` reads it for group usage (exact owned Run slices) and overlays durable totals on Run activity. The canonical recorder remains the accounting write owner.

- `statistics.report {since?, until?, timezone?, sections?}` (`server/rpc/statistics_methods.py`) validates strictly and answers `invalid_request` otherwise: ISO-8601 bounds with `since` not after `until`; an IANA `timezone` (`validate_timezone_name`; default the Settings effective zone, `runtime.timezone_name()`); `sections` a non-empty list of known names (default all; duplicates collapse, the result keeps section order). The service caches on RPC state over the Runtime's shared index and offloads reconciliation so filesystem/SQLite work never blocks the loop. A busy or locked index raises `StatisticsUnavailableError` (a `VBotError`, so RPC returns `domain_error` "Statistics are busy; retry shortly") and never discards the index. Startup warmup (`server/_app_lifecycle.py`) runs at every server start outside safe startup mode; it reconciles the index without building a report.
- `statistics.run_activity {since, until}` returns retained Runs overlapping the requested interval (newest first, cap 200) for temporal correlation with usage changes - explicitly not causality attribution. Each returned Run's token totals and Model list include every durable request linked to that exact Session/Run, across the whole Run rather than only the selected interval. If a moved historical Run has no exact ledger match, its retained Session totals and Models remain available.
- WebUI (`StatisticsView.svelte`) asks `statistics.report` per tab for only that tab's sections, with `since` from the selected range (calendar days start at midnight in the zone, 24 hours is rolling; all time sends no `since`) and the Settings time zone as `timezone`: Overview -> `overview`, Costs & tokens -> `usage`, Runs -> `runs`, Tools & skills -> `tools` + `skills`, Extensions -> `extensions`, Diagnostics -> `diagnostics`; Limits asks no report. `lib/statisticsReports.svelte.js` keeps the last answer per (tab, range, time zone) for the page lifetime and revalidates on every visit (stale-while-revalidate); for one key only the newest request settles, and a failure keeps the stale report beside the error. The Extensions tab shows only when that range's `extensions` section lists an Extension; it is asked after the shown tab settles. The retired `compactions` place opens Diagnostics. One component per tab under `components/statistics/` renders its section; pure formatting, rollups, chart columns and insight sentences stay in unit-tested `statisticsView.js`, Limits history logic in `statisticsLimits.js` (`StatisticsView.test.js`, `statisticsView.test.js`, `statisticsLimits.test.js`). Presentation labels preserve absent vs zero evidence and derived heuristics, and tooltips give each value its basis; the presentation rules are in `webui/design.md`.
- CLI `vbot statistics <section>` requests only the report section it prints; `compactions` reads `diagnostics.compactions` and `errors` reads `runs.errors` (`cli.md`).
- **Limits crosses two owners:** `components/statistics/ProviderLimits.svelte` owns live state, single-flight polling, visibility and cleanup independently of local report loading/errors. Statistics navigation remains available before a report succeeds; while visible, the component polls Providers-domain `provider.usage` immediately then every 10 s; `LimitHistory` separately refreshes Provider-owned history every 60 s; its uniquely named presentation rules live in adjacent `limitHistory.css`. Selecting an interval requests the Statistics-owned Run projection. Statistics performs no network access.

## Cost accounting

- The canonical Usage ledger supplies accounting facts, including Chat, Compaction, all Task Models, the delegated Live Voice backend, Session/group titles and Extension sampling. Calls are counted independently of saved responses and accepted checkpoints. Usage nested in Tool Results is not another call source. Assistant/checkpoint Usage remains the deduplicated import source for older retained history; legacy Compactions without nested Model Usage never invent a request.
- A finite non-negative `reported_cost_usd` takes precedence, including zero. Otherwise `core/models/pricing.py` calculates a USD API-equivalent estimate from catalog rates. The two categories cover disjoint calls and remain separate in the UI; neither is a subscription invoice. Unknown rates/counters stay unpriced, never free.
- Saved priced snapshots remain stable across catalog refreshes. Legacy calls without a snapshot use the current exact Model price lookup and are labeled retrospective. They are priced individually before aggregation because Context tiers apply per call, not to cumulative tokens. The index stores these prices: `stat_pricing` fingerprints each Model's pricing once for both `stat_calls` and `stat_usage_calls`, a changed fingerprint reprices that Model's retrospective calls, and unchanged pricing prices only newly ingested calls. Repricing runs at reconcile, before aggregate maintenance, so every `StatisticsIndex.read` caller passes the service's `pricing_lookup`; a reader with another lookup would reprice the shared index.
- Archive/delete/restore/purge changes retained Session diagnostics, never previously recorded consumption: a purge, manual or by retention, first imports its Sessions' usage (`archive.md`). Failed, cancelled, interrupted and pending attempts count as requests; absent counters/prices remain unknown, and dispatch intent is not proof of Provider billing. Older Task requests or deleted history that never retained Usage cannot be recovered. Producer and transport-attempt boundaries are documented in `usage.md`.
- The WebUI leads with cost: Overview tiles (cost, tokens, cache hit rate, Runs, typical Run, cost per Run) compare with the previous period of equal length; Costs & tokens holds the breakdowns and the only explanation of pricing coverage (unpriced, retrospective, unreported, uncached value); Diagnostics holds Compactions, cache, data quality, failed-attempt bursts and runaway Runs, collapsed. Unknown money renders as a dash, exact zero as `$0.00` and tiny non-zero amounts as `<$0.01`; tooltips and per-call rows keep the exact amount.
- Research leads: Hermes `agent/usage_pricing.py` at `165c889e5b4277b56dadd42949a4112c1e6175a6` distinguishes cost evidence and missing buckets; OpenClaw `src/utils/usage-format.ts` at `78f1cf1eab9472bab69288e0c91b77771d099f5d` reinforces per-call tier selection. These informed the design; vBot uses its own canonical Usage and frozen snapshots, including API-equivalent subscription value.
- Regression coverage: `test_statistics_accounting.py` (deduplication, archive/delete, cumulative updates, windows, source failures, restart continuity, restore and revision-rewind rebuilds, owned Runs and cache isolation), `test_statistics_usage.py` (tokens, cache figures, prices and repricing, breakdowns, recent calls), `test_statistics_rollups.py::test_money_sums_are_exact_nano_usd`, `test_pricing.py`, `test_chat_loop_usage.py`, `test_openrouter_costs.py`, and Statistics component/helper tests.

## Aggregate tier

`_rollups.py` maintains derived aggregates over the fact tables in the reconcile write transaction, after Session reconcile, usage reconcile and repricing; a reader never sees aggregates that disagree with the facts. The report sections read them.

- **Tables:** `agg_runs` (one row per Run, key `(session_key, run_id)`: status and timing, Model steps, visible and user messages, `first_visible_ms`, Tool calls and time, Compactions, errors, request totals, Models, request kinds, change stats), `agg_usage` (hourly ledger cube, key `(hour, unit_key, origin, model_key, kind, status)` with `hour = instant // 3_600_000_000` and `unit_key = stat_usage_units.session_key`), `agg_tools` (hourly, key `(hour, session_key, origin, name)`), `agg_tool_latency` (the same key plus `bucket = floor(4 * log2(duration_ms + 1))`, stored on `stat_tools.latency_bucket`), `agg_records` (hourly records and visible Assistant steps per Session and role), `agg_cache` (hourly cache-reporting saved Chat turns per Session: input, cache read/write, evaluated and suspected turns, last instant) and `agg_cache_breaks` (each suspected cache break with its predecessor's input).
- **Maintenance contract:** reconcile records touched units in `RollupChanges` (whole Sessions, Runs, Sessions whose records grew or whose Run identities changed (`fact_sessions`; their Session cubes `agg_tools`, `agg_tool_latency`, `agg_records`, `agg_cache` and `agg_cache_breaks` are recomputed whole), ledger units, `(unit, run_id)` pairs of changed or moved requests and repriced calls, and Session addresses whose ledger units take their origin from that Session). `maintain_rollups` deletes those units' rows and recomputes them from the facts. A full rebuild is the same code with every unit touched (a new index, a ledger restore or a revision rewind). Invariant: incremental maintenance equals a full rebuild after any appends, edits, deletions, ledger updates and repricing (`test_statistics_rollups.py::test_incremental_maintenance_equals_a_full_rebuild`, which also compares the transient in-memory path). A new fact that feeds an aggregate must mark its unit in `RollupChanges` and extend that test, or incremental rows silently diverge.
- **Origin:** every Run, Tool call and request gets one origin, first match wins: `extension` (the Session's `owner_name`, or the request's), `subagent` (Run kind `subagent` or `is_subagent`), `automation` (`cron`, `calendar`), `channel`, `reflection` (background learning: `UNATTENDED_RUN_KINDS`, the three reflection kinds and `librarian`), `system`, `user` (user Runs and unknown kinds). A request of an indexed Run (Session address plus `run_id`) takes the Run's origin; any other request in an Extension or Sub-Agent Session, and a chat or Compaction request anywhere, takes the Session origin (`extension`, `subagent`, else `user`); everything else is `background`. A Tool call takes its Run's origin, else its Session's.
- **Run requests:** a Run's request totals come from ledger requests at its Session address and Run id, failed attempts included; a Run without any uses the usage saved in its own records. `primary_model` has the most input tokens (ties by name); `models` is a JSON array ordered by first use. `first_visible_ms` runs from the Run start (record timing, else admission) to its first visible assistant text.
- **Money is integer nano-USD:** `CAST(ROUND(cost_usd * 1e9) AS INTEGER)` per call (half away from zero), so aggregate sums are exact and order-independent.
- **Projection version:** the kernel's additive schema reconcile creates a new table empty and never fills it, so adding an aggregate or changing what its rows mean must bump `_PROJECTION_VERSION` in `index.py`, which discards and rebuilds every index.
- **Run visibility:** Run admission does not change the Session history revision, so a Run without any Message enters `stat_run_records` and `agg_runs` only with the Session's next history change.

## Extension activity

- `_extension_sessions()` turns each live owned Session into an index scope whose display key is `extension:<owner>` (Agent ids and `agent@project` never contain `:`) plus a participant slice key. Participant usage/costs use the same durable requests as global accounting; the Extension view covers retained participants, while global totals additionally retain deleted groups and group-level background requests without a participant Session.
- Report rows label these Sessions `"<group title> · <participant name>"` (`extension_session_summary`); `group_usage` indexes the same labelled summaries and Extension owner, and gives the owner's other Sessions their listed summaries (`SessionSource.summary`), so both reads never rewrite a shared index row or its stored flags. A group without a stored title reports `title: null`; the WebUI labels it by start time and a short id.
- Windowed reports keep only groups with in-window Runs, Tool calls, Model calls or errors; all-time keeps every retained group. Runs, Tool calls and errors are each participant Session's own; requests are the ledger's at its Session address. `overview.active_agents` excludes Extension actors; `active_sessions` includes the participant Sessions. Deleted groups (`delete_temporary_group`) leave the structural/Extension views while their durable consumption stays in usage and costs.
- WebUI: `ExtensionsPanel.svelte` (Extension -> group -> participants), and `agentDisplay` renders `extension:<owner>` as the Extension name with an Extension badge in every per-agent cell. Tests: `test_statistics_extensions.py`, `StatisticsView.test.js`, `statisticsView.test.js`.

## Extension group projection

`group_usage` uses canonical Sessions Run-owner records and explicit Message Run ids
to restrict the existing index and aggregators to one owner/group, optionally one
participant. A group report returns participant breakdowns from the same indexed
index read and Run slices; clients need no per-participant report fan-out. The
read reconciles only the owner's Sessions and never prunes normal Statistics
scopes; `materialize_run_slices` then copies each owned Run's rows, selected by
explicit Run id through the `stat_records_run` index, into same-named temp tables
keyed by slice so `GroupReportBuilder` aggregates them. Unrelated Sessions
are never loaded, and Messages from other Runs in a reused Session are excluded by
identity. The facade runs on the index database's worker pool and
returns the existing usage, Tools, Compaction and Run projections without costs,
account data or separate counters. With the recorder, usage selects the same
explicit Session/Run identities from durable requests, including auxiliary work;
group-level requests without Run membership remain only in global accounting.
Durable group selection drives indexed reads from the requested Run slices,
then recovers each selected record's source Session key before reading its call
through the existing `(session_key, seq)` index. Unrelated request history is
neither scanned nor temporarily indexed for each group or participant report
(`test_statistics_accounting.py`).
A slice without any exact ledger match keeps its saved Session usage, including
after an Agent takeover. Durable attribution stays at the original address;
there is no canonical address alias to link auxiliary requests across a takeover,
and a Run id alone never supplies one.
Generation checks and own-audit ingestion
remain in force (`statistics.py`, `index.py`; `test_statistics_groups.py`,
`tests/core/sessions/test_sessions_owner_managed.py`).

## Conventions

- **Run identity:** the compact index retains explicit Message and request `run_id`; aggregation and group usage select that identity. Run completion projections supply status and duration. Neighboring footer order never establishes membership. Canonical Run records (`ChatSession.run_records`, read after the history batch) supply Run kind, status, timing, completion reason, iterations and change stats. The projection is disposable and rebuilds on version/table-shape mismatch (`tests/core/statistics/test_statistics_index.py`).
- **Canonical-first projection:** Session appends succeed independently; Statistics is never a Chat write dependency. Scope discovery reads normalized Session summaries plus only the `seen_skills` summary value (`metadata_keys=("seen_skills",)`), never complete open-ended metadata. Reconciliation consumes each Session's own audit, superseded entries included, so a Message edit preserves historical Usage, Runs, Compactions, errors, and Tool activity while adding one `history_edit` record. Session summary values (title, `created_at`, `seen_skills`) come from the current listing on every read and are never stored, so metadata-only changes need no history read or index write. Only the origin flags are stored on `stat_sessions`: `is_subagent` (the `is_subagent_session` summary value) and `owner_name` (the listing Extension scope's owner; it sticks when another scope lists the same Session). A flag change rewrites the flags without a history read and recomputes that Session's aggregates. Reconciliation ingests ordinary growth from the generation-aware cursor, rebuilds only a new generation or an invalid cursor (a history edit or Agent takeover invalidates it), and deletes missing scopes. A Session that is deleted or archived between scope listing, version lookup, and detail loading is skipped and its old derived rows are pruned. Reports and Run activity share one surviving-Session read boundary. A canonical read failure propagates unchanged and keeps the index. Index failures are classified with the kernel's `projection_failure`: busy or locked raises `StatisticsUnavailableError` and never discards; damage (corruption, a missing table, a violated constraint) discards and rebuilds the file once; an unavailable file (for example an unwritable directory) or a second failure computes the read from a transient in-memory index with the same code, which loads every listed Session. A closed `StatisticsIndex` (Runtime shutdown awaits `aclose()`, which waits for a running read on the pool) is unavailable instead: reads and `run_async` raise `DatabaseUnavailableError`.
- **Inherited fork history excluded** from all activity windows: only own audit is ingested/imported, so inherited or materialized prefixes never duplicate calls. Deleting an origin can materialize that prefix into forks and invalidate their Session cursors; the origin's structural activity leaves, but durable consumption remains attributed where incurred. Store-search and Recall instead attribute inherited content to surviving descendants.
- **Real vs estimated tokens never merge:** field-level flags feed matching buckets, and either flag marks the call's cost as estimated; cached tokens are already inside canonical input so cache figures surface separately, never added on top; reasoning tokens are a measured-output subset.
- **Cache figures require field presence and measured input** - a non-caching provider must never read as 0% hit rate; rates divide by cache-reported input; any estimated-input turn breaks cache comparison.
- Windows use exact canonical microsecond instants: Session message timestamps for diagnostics, attempt-start timestamps for durable requests, and retained message timestamps for imported legacy calls. Non-canonical timestamps fail validation. The Skill inventory is window-independent; an absent Session `created_at` remains always in-window for Skill offers.
- **Aggregates first:** report sections aggregate in SQL over the `agg_*` tables and fold only small grouped results in Python; a section that needs a per-row walk over facts belongs in the aggregate tier instead (Compaction intervals are the remaining exception). `ReportContext` loads the listed Sessions and ledger units once per report (`temp.report_sessions`, `temp.report_units`) with their actor, Project and a Session address id shared by a Session and its ledger units. Group usage still loads its Run slices in processing order as `temp.units` and streams only order-dependent parts in `(unit, seq)` order (Run groups, cache-break comparisons, Compaction intervals, tie orders); `run_activity` is a SQL `ORDER BY ... LIMIT 200` plus a count.
- Offered filters by the offering Session's `created_at` (the seen-Skill set carries no per-Skill timestamps - deliberate approximation); conversion uses only the per-Session offered+activated intersection, staying within 0-100%.

## Constraints & Gotchas

- Every read attempt builds a fresh `ReportContext`; totals from an incomplete
  aggregation are discarded before rebuilding or using a transient index
  (`test_statistics_index.py::test_report_recovery_discards_partial_aggregation`).
- **The SQLite index is not a second source of truth:** replace-not-migrate projection version, deletable on failure, must stay fully rebuildable - no user-owned or non-derivable data in it. Source cursors validate the processed prefix; mismatches rebuild rather than repair.
- **Temp tables shadow fact tables:** group usage creates temp Session fact tables, and unqualified names resolve to `temp` first. The separate accounting scan maps call/record table names through `UnitScan.table`; only its explicit no-ledger Run fallback consumes the shadowed Session facts. `temp.units` is replaced between scans, so cache, Skills and other Session diagnostics must finish before constructing the accounting scan. Report sections use their own temp table names and never shadow facts. All temp tables are dropped before and after each read.
- **Open window sides add no condition** (`common._bounds`): an all-time read scans its table instead of walking a time index row by row, which costs tens of milliseconds per query on real data. Keep window conditions in that form.
- Suspected cache breaks are a heuristic comparing consecutive measured saved Chat turns, skipping legitimately explained misses (first turn, checkpoint/takeover boundaries, model switches, >300s gaps, previous prompts below 2048 tokens, post-estimated turns) with a 0.5 read-ratio incident floor - false negatives accepted by design. Reconcile judges each turn against its predecessor in the whole Session (`_rollups.judged_cache_turns_sql`, shared with group usage), so a turn's predecessor may lie before the report window. Auxiliary requests never enter the judgement.
- `diagnostics.open_runs` counts canonical Run records still `running`; startup recovery settles Runs a stopped process left running as `interrupted` (`sessions.md`), and a Run reaches the projection only with its Session's next history change.
- Error attribution proxies to the Model of the latest saved Chat step before the error in its Session (`unknown` when none).
- Sessions without a recorded seen-Skill set contribute activations but no offers - accepted lower bound, never presented as delete candidates.

# Statistics

Incrementally indexed Model consumption and retained Session activity for the WebUI Statistics tab.

## Overview

`core/statistics/` has two canonical sources: `UsageRecorder` in `model-usage.db` supplies durable Model requests (`usage.md`), and Session own-audit history supplies conversational and operational diagnostics (`sessions.md`). `StatisticsIndex` maintains a disposable typed SQLite projection at `<data_dir>/statistics/session-statistics.sqlite` through the database kernel (application id `statistics`, projection version 11; `database.md`). Session generation/revision cursors ingest validated new own-audit tails and prune removed scopes; they hold for one Session history (`ChatSessionManager.history_id`, Session database identity plus its latest restore, kept in `stat_session_state`), and another one (a restore of `sessions.db`) discards every Session projection and recomputes its request associations, including on scoped reads, so each listed Session is rebuilt from its whole history; the recorder's `ledger_id` (Usage database identity plus its latest restore, `usage.md`) and revision cursor replace changed request facts without pruning them with Sessions, reading the ledger in bounded pages. A restart continues from the projected revision; a new `ledger_id` (a restore) rebuilds the accounting projection, so a restored snapshot that has already caught up to the old revision cannot preserve stale calls, and an observed revision rewind also rebuilds it. Fork inheritance never contributes another call.

Reconciliation and SQL aggregation run on the kernel writer, with one second of lock patience because reports create temp tables. Unchanged sources and pricing write nothing to the index; no report is retained in memory. Projection damage/version mismatch is rebuildable from both canonical sources. The normalized limit observations remain Provider-owned upstream data in `provider-usage.db` (`providers/usage.md`); Statistics neither writes nor caches them.

`StatisticsService` is constructor-injected; Runtime shares its index and Usage recorder with the RPC and Extension group-usage services. Without a recorder, standalone constructions retain Session-only accounting; without an index, the service owns a private one. Identity and Project Session scopes remain distinct (Project display addresses use `agent@projekt`); Extension participants appear under `extension:<owner>`, never their synthetic Agent ids (`statistics/group-usage.md` -> Extension activity). Durable calls can outlive those scopes or have no Session. Current Session titles override stored title snapshots only for the same proven generation, including after a move; reused addresses never supply labels or merge Usage groups across generations. Accounting Agent and Project attribution stays unchanged. The injected exact Model price lookup supports retrospective estimates without network access. Model fallback events (Session notes stored in `note_model_fallbacks`, `sessions/storage.md` -> Tables) are not ingested, and there is no per-Session sub-tab.

## Report sections

`StatisticsService.report(since, until, timezone, sections)` (and `report_async`) reconciles once, then builds only the requested sections from `core/statistics/_sections/`, one module per section (`overview`, `activity`, `usage`, `runs`, `tools`, `skills`, `extensions`, `diagnostics`). The result is `{generated_at, window: {since, until, timezone, bucket}, <section>: {...}}` with sections in that order. The WebUI and the CLI (`cli/system-commands.md`) read these fields, so renaming one breaks both. Contract tests: `test_statistics_report.py` (every section), `test_statistics_usage.py` (usage, cache), `test_statistics_extensions.py`, `test_statistics_skills.py`. Public imports remain under `core.statistics`.

Every read (report sections, group usage, Session tree usage, Run activity) works on the aggregate tier. The index's fact tables hold only aggregation-consumed fields - raw text, Reasoning, arguments/result payloads, Skill content never enter it.

Report-wide invariants: windows are half-open and hour-aligned (`since` floored, `until` ceiled to a UTC hour) and every section of one report covers the same window; series count by local dates of the requested IANA `timezone`, or by UTC hours in a window of at most 48 hours; money is summed as integer nano-USD and `null` means unknown, never 0. Exact rules, shared shapes (`Totals`, RunRow) and every section's fields are in `statistics/report-sections.md`.

## Interfaces

Both report RPCs (`report_async`, `run_activity_async`), group usage, Session tree usage, Skill usage and startup warmup (`warm_index_async`) run on the Statistics index database's bounded worker pool (`StatisticsIndex.run_async`), including the Session reads a reconcile makes; there is no separate Statistics pool.

Before each read, the recorder's resumable Session-history import catches up retained legacy facts (`usage.md` -> Interfaces, `import_session_history`). The canonical recorder remains the accounting write owner.

- `statistics.report {since?, until?, timezone?, sections?}` (`server/rpc/statistics_methods.py`) validates strictly and answers `invalid_request` otherwise: ISO-8601 bounds with `since` not after `until`; an IANA `timezone` (`validate_timezone_name`; default the Settings effective zone, `runtime.timezone_name()`); `sections` a non-empty list of known names (default all; duplicates collapse, the result keeps section order). The service caches on RPC state over the Runtime's shared index and offloads reconciliation so filesystem/SQLite work never blocks the loop. A busy or locked index raises `StatisticsUnavailableError` (a `VBotError`, so RPC returns `domain_error` "Statistics are busy; retry shortly") and never discards the index. Startup warmup (`server/_app_lifecycle.py`) runs at every server start outside safe startup mode; it reconciles the index without building a report.
- `statistics.run_activity {since, until}` returns the listed Sessions' Runs, Extension participant Runs included, that overlap the requested interval (newest start first, cap 200, plus the overlap count) from `agg_runs`, for temporal correlation with usage changes - explicitly not causality attribution. A Run still running has no end, overlaps every interval ending after its start and reports null `completed_at` and `duration_ms`. Token totals and the Model list are the Run's request totals (`statistics/reconcile-and-aggregates.md` -> Run requests) across the whole Run rather than only the selected interval (`test_statistics_accounting.py`).
- `statistics.session_usage {agent_id, session_id}` sums one live Session's own Runs and its Sub-Agents' Runs at every depth, and `group_usage` (`temporary_agents.usage`) one Extension owner group: `statistics/group-usage.md`.
- `skill_usage[_async]` and `skill_package_usage[_async]` serve the Librarian and the Skill manager without a window: `statistics/skill-usage.md`.
- The WebUI Statistics tab asks per tab for only that tab's sections (mapping: `statistics/report-sections.md`; cache and presentation: `webui/source-map.md`, `webui/design.md`). Its Limits tab reads Providers-owned `provider.usage` and its history (`providers/usage.md`) and only asks Statistics for `run_activity` of a selected interval; Statistics performs no network access.

## Cost accounting

A finite non-negative `reported_cost_usd` takes precedence, including zero. Otherwise `core/models/pricing.py` calculates a USD API-equivalent estimate from catalog rates. The two categories cover disjoint calls and remain separate in the UI; neither is a subscription invoice. Unknown rates/counters stay unpriced, never free. Retrospective calls are repriced at reconcile, before aggregate maintenance, so every `StatisticsIndex.read` caller passes the service's `pricing_lookup`; a reader with another lookup would reprice the shared index. Call sources, repricing and archive/purge effects: `statistics/cost-accounting.md`.

## Aggregate tier

`_rollups.py` maintains derived `agg_*` aggregates over the fact tables in the reconcile write transaction, after Session reconcile, usage reconcile and repricing; a reader never sees aggregates that disagree with the facts. Tables, maintenance mechanics, origin classification and Run request totals: `statistics/reconcile-and-aggregates.md`.

- **Invariant:** incremental maintenance equals a full rebuild after appends, corrections, edits, deletions, ledger updates and repricing (`test_statistics_rollups.py`). Every new fact or mutation feeding an aggregate must identify its old/new contribution or affected unit and extend that equality contract.
- **Money is integer nano-USD:** `CAST(ROUND(cost_usd * 1e9) AS INTEGER)` per call (half away from zero), so aggregate sums are exact and order-independent.
- **Projection version:** the kernel's additive schema reconcile creates a new table empty and never fills it, so adding an aggregate or changing what its rows mean must bump `_PROJECTION_VERSION` in `index.py`, which discards and rebuilds every index. Additive indexes alone do not change the projection version.
- **Run visibility:** Run admission does not change the Session history revision, so a Run without any Message enters `stat_run_records` and `agg_runs` only with the Session's next history change.

## Conventions

- RPC `report` and `run_activity` require explicit offsets in `since`/`until` through `core.utils.timestamps.parse_timestamp`; the report timezone controls presentation and never supplies a missing offset.
- **Run identity:** the compact index retains explicit Message and request `run_id`; aggregation and group usage select that identity. Run completion projections supply status and duration. Neighboring footer order never establishes membership. Durable requests join diagnostics by captured Session generation plus Run id, so a move retains auxiliary request totals and a reused address cannot borrow them; accounting Agent/Project snapshots remain where consumption was incurred. Canonical Run records (`ChatSession.run_records`, read after the history batch) supply Run kind, status, timing, completion reason, iterations and change stats. The projection is disposable and rebuilds on version/table-shape mismatch (`tests/core/statistics/test_statistics_index.py`).
- **Canonical-first projection:** Session appends succeed independently; Statistics is never a Chat write dependency. Reconciliation reads Session summaries and own audit only (scope discovery and stored flags: `statistics/reconcile-and-aggregates.md`). A canonical read failure propagates unchanged and keeps the index. Index failures are classified with the kernel's `projection_failure`: busy or locked raises `StatisticsUnavailableError` and never discards; damage (corruption, a missing table, a violated constraint) discards and rebuilds the file once; an unavailable file (for example an unwritable directory) or a second failure computes the read from a transient in-memory index with the same code, which loads every listed Session. A closed `StatisticsIndex` (Runtime shutdown awaits `aclose()`, which waits for a running read on the pool) is unavailable instead: reads and `run_async` raise `DatabaseUnavailableError`.
- **Inherited fork history excluded** from all activity windows: only own audit is ingested/imported, so inherited or materialized prefixes never duplicate calls. Deleting an origin can materialize that prefix into forks and invalidate their Session cursors; the origin's structural activity leaves, but durable consumption remains attributed where incurred. Store-search and Recall instead attribute inherited content to surviving descendants.
- **Real vs estimated tokens never merge:** field-level flags feed matching buckets (totals include both; the WebUI shows totals unmarked and the estimated share per Model only in Diagnostics), and either flag marks the call's cost as estimated; cached tokens are already inside canonical input so cache figures surface separately, never added on top; reasoning tokens are an output subset.
- **Every call counts in cache and reasoning figures** (user decision 2026-10-06): an unreported counter is zero, estimated calls included, and a hit rate divides cache reads by all input. A Provider that omits cache counters although it cached is a Provider defect; no Provider's reporting quality is special-cased, so a non-caching Provider reads as 0% hit rate. Only pricing still reads counter presence (`has_cache`: a catalog-priced call without a cache counter may overstate its estimated cost, `uncached_*`).
- Windows use exact canonical microsecond instants: Session message timestamps for diagnostics, attempt-start timestamps for durable requests, and retained message timestamps for imported legacy calls. Non-canonical timestamps fail validation.
- **Aggregates first:** report sections aggregate in SQL over the `agg_*` tables and fold only small grouped results in Python; a section that needs a per-row walk over facts belongs in the aggregate tier instead (Compaction intervals are the remaining exception).

## Constraints & Gotchas

- Every read attempt builds a fresh `ReportContext`; totals from an incomplete aggregation are discarded before rebuilding or using a transient index (`test_statistics_index.py::test_report_recovery_discards_partial_aggregation`).
- **The SQLite index is not a second source of truth:** replace-not-migrate projection version, deletable on failure, must stay fully rebuildable - no user-owned or non-derivable data in it. Source cursors validate the processed prefix; mismatches rebuild rather than repair.
- **Temp tables never shadow fact tables:** unqualified names resolve to `temp` first, so report sections, group usage and Run activity give their temp tables names no index table uses and drop them before and after each read.
- **Open window sides add no condition** (`common._bounds`): an all-time read scans its table instead of walking a time index row by row, which costs tens of milliseconds per query on real data. Keep window conditions in that form.

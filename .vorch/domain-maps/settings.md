# Settings

Public Settings schema parsing, raw `settings.json` validation, whole-data-dir validation orchestration, and the shared contract of durable JSON documents.

## Overview

`core/settings/` owns the public Settings path catalog (`paths.py` - stable accessor boundary resolving dotted segments plus JSON-quoted dynamic keys, effective values with lifecycle metadata, and validated atomic patches), the `settings.update` section schema (`settings.py`), raw-file validation (`validation.py`), and stateless per-section normalization (`normalizers.py`, raising `StorageError`). Agent, Project, Channel, Cron, Bootstrap, Calendar, Skill policy, Terminal, OAuth token, prompt layout, MCP connection, and Task-Model persisted schemas belong to their own domains; `validate_data_dir_config()` only discovers the bundle and delegates each file to its owner. All domains share transport-neutral JSON reports and parsing via `core/config_validation.py` and the versioning, preservation and write-guard mechanics of `core/json_documents.py` (see JSON Document Contract) - manual-edit errors keep consistent diagnostics without making Settings a schema hub.

Storage still owns raw file I/O, process-local locked read-modify-write transactions, atomic writes, and persistence helpers; server delegates own RPC error mapping, runtime-aware validation, catalog expansion for loaded Providers/Extensions, and post-change invalidation. Both public mutation surfaces (`settings.patch`, `settings.update`) validate everything before one locked transaction and then call `Runtime.apply_settings_change(previous, current, refresh_sections=...)` for all live effects - a path update can never silently behave differently from a section update. `settings.set_key` no longer exists: raw top-level mutation is not a public contract.

## Where Settings Code Lives

- Raw key validation -> `validation.py`; public paths/catalog/patch -> `paths.py`; `settings.update` schema -> `settings.py`; section normalization/defaults -> `normalizers.py`, with `_provider_settings.py`, `_compaction_settings.py` and `_json_settings.py` for the larger rule groups; public path records/formatting -> `_path_types.py`, catalog declarations -> `_path_definitions.py`; persistence transactions -> `core/storage/storage.py`.
- Live side effects -> either read-at-use accessors or the shared Runtime Settings coordinator (`core/runtime/_settings.py`) used by both surfaces (OpenRouter routing snapshots per Run, Skills directories reload, Recall reloads backend, Extension directories rebuild, disabled-set applies surgically, `keep_awake` toggles power request, application `timezone` updates Calendar and Cron). Restart-applied paths expose active/pending/restart-required metadata instead of pretending the value is active.
- Shared scalar validators (`validate_temperature`, `validate_thinking_effort`, agent-id rule) are canonical here; Agents/Projects and their RPC boundaries delegate instead of copying rules. Storage-facing temperature normalization delegates to the same validator and translates its error type. Numeric bounds are checked before float conversion so oversized JSON integers remain validation failures.
- The `defaults.agent` field surface has exactly one source of truth: `core/settings/agent_defaults.py`. It owns `AGENT_DEFAULT_FIELDS` (the only literal field set), per-field parse/diagnose/normalize behavior (including the fallback-chain rules: strings, non-empty after strip, capped at `MAX_FALLBACK_MODELS`, no duplicates), the Settings-path catalog entries, and the typed `AgentDefaults` consumed by `AgentStore` baking and the resolver. Baking re-validates every applied default through the registry's normalizers, so a stale settings file cannot bake an invalid value into agents. The `settings.update` parser, raw-file validation, `normalizers.py`, and `paths.py` all derive from it; never hardcode the field list or per-field rules anywhere else.
- The settings domain must not import `core/storage/` (that direction recreates a removed cycle).

## Public surface

- `settings.values` (normalized document), `settings.catalog` (path definitions + known dynamic keys), `settings.get_path` (value/source/default/type/lifecycle), `settings.patch` (atomic `{op: set|unset}` list; overlapping operations rejected so order cannot change meaning). Unset removes an override restoring inherited behavior - distinct from setting JSON `null`. Changing a Task Model target leaf resets prior options before explicit option edits; unsetting that target removes the complete binding and overlaps every option edit for that task. Unchanged effective Task Model bindings skip live catalog validation. Dynamic Extension secret fields are deliberately excluded with a credential-safe CLI hint.
- `settings.json` carries `format_version` 1 (`SETTINGS_FORMAT`); the initial data-dir document (`core/storage/layout.py`), the setup scripts, and the worktree seeding fixture (`tests/e2e/fake-provider-settings.json`) carry it. `load_validated_settings_json` is the strict gate for diagnostics/mutations; `load_runtime_settings_json` is the tolerant consumption gate - malformed files fall back to defaults, schema-invalid top-level keys omit individually while valid siblings stay live, never rewriting source; a missing or other `format_version` counts as a malformed file. Storage reads tolerantly but strictly before every mutation, logging unchanged degradation once. `vbot doctor settings` / `doctor config` remain strict repair diagnostics.
- Raw top-level keys (source of truth `validation.py`): port aliases, appearance, speech transcription profile, skill/extension directories, extensions, upload limits, Sub-Agent limits, compaction, defaults, providers, recall, reflection, web_search, web_fetch, model_tasks, session_titles, local_models, keep_awake, timezone, debug. Every key optional; unknown keys warn rather than error (forward compatibility); present sections validate per field. `timezone` is an IANA name, defaults to the host zone when absent, and is exposed as `server.timezone`; raw stays flat where history requires it while public paths nest consistently - accessors use public paths, `config raw` is diagnostic only.
- Update sections are sparse or full per their semantics; notable contracts: `appearance.language` is required so partial updates never reset display prefs; `extensions` is a **full-replace** write whose disabled-delta routes enable through the full rebuild and disable through surgical deactivation, with config values applying live via each extension's reader; `providers` updates exactly OpenRouter routing (Custom Providers have dedicated RPCs coordinating registry reload and write-only credentials); `recall.backend` defaults to `sqlite_fts` when absent and validates shape only here while membership resolves against the selectable `sqlite_fts`, `vector`, `hybrid` plus Extension backends at the server edge; canonical scan is only an internal fallback; `compaction.trigger` accepts either a pure `input_tokens` limit or a `context_ratio` with an optional `tokens` cap, where ratio and cap combine rather than replace one another; `local_models.context_windows` sparse-merges per key (`null` removes); `model_tasks` validates bindings against loaded Models/targets before persistence so generic mutation cannot bypass task validation; `session_titles` reads live per first message; `web_search` and `web_fetch` load at call time. Web Fetch sparsely merges `provider` (direct/firecrawl/tavily/exa/parallel) and `mode` (fallback/prefer), defaults to direct fetching, and keeps API keys outside Settings; configuration facts live in `core/fetch_config.py`.
- The former `live_voice.enabled` opt-in was removed; the Generation 1 converter drops a pre-Generation-1 `live_voice` key, and any other one only warns as unknown. Live voice visibility follows the `model_tasks.live_voice` binding (`model_tasks/live.md`).
- Custom Provider records under raw `providers.custom` are secret-free; their CRUD is intentionally exposed through `provider.custom_*` RPCs because it coordinates registry reload plus `.env` credentials. OpenRouter routing's full schema lives in `providers/openrouter.md`.

## JSON Document Contract (Generation 1)

Every durable JSON document in the data directory follows one contract owned by `core/json_documents.py` (tests `tests/core/test_json_documents.py`). `DURABLE_DOCUMENTS` there is the single list (kind -> data-dir relative pattern, `*` within one segment) of documents under the contract, each validated by `doctor config`: `settings.json`, `agents/*/agent.json`, `agents/order.json`, `projects/*/project.json`, `cron/jobs.json`, `bootstrap/jobs.json`, `calendar/events.json`, `calendar/actions.json`, `channels/*/channel.json`, `skills/policy.json`, `terminals/launch-history.json`, `terminals/groups.json`, `oauth/*.json`, prompt `layout.json` (default and Agent scopes), the MCP Extension's `extension-data/mcp/connections.json`, and the blob sidecars `artifacts/attachments/*.json` (`attachments.md`) and `artifacts/speech/*.json` (`model_tasks/speech.md`).

- Data snapshots (`database.md` -> JSON document set) capture `SNAPSHOT_DOCUMENTS`: every kind except those in `DOCUMENTS_OUTSIDE_SNAPSHOTS`, today the two blob sidecar kinds. A snapshot holds no blobs, and a set restore would otherwise delete every sidecar created after the snapshot while its blob stays. `snapshot_document_paths`/`is_snapshot_document_path` enumerate and recognize that set.
- Outside the contract: state that is not a JSON document (`.env`, and the SQLite databases, which follow `database.md`: canonical ones such as `channels.db` and `provider-usage.db`, disposable indexes), the refreshed Model DB catalog under `artifacts/models/`, which carries its own `manifest.json` and falls back to the bundled root (`models.md`), the kernel files of `core/database/` (`data-store.json`, the maintenance guard, snapshot manifests and health, recovery incidents; `database.md`), install receipts and markers (Skill install receipts, local speech engine `verified.json`), diagnostics under `artifacts/debug/`, `artifacts/performance/`, and `artifacts/live-calls/` (JSON lines), and transient runtime state that exists only while an operation is in flight and fails safe when unreadable (Cron once-fire claims, `automation.md`). A new JSON file joins the contract unless it belongs to one of these categories; it is then added to this list.

- A document is a JSON object with a required top-level `format_version` (1 for every document today). Collections are named arrays (`jobs`, `events`, `actions`, `entries`, `groups`, `connections`), never bare arrays. `validate_format_version` refuses a missing version (the message ends with the database kernel's Generation 1 conversion step, `generation_1_conversion_hint` in `database.md`), an older one, and a newer one; a file written by a newer vBot is never overwritten.
- Each owner declares the object levels it models as a `JsonShape`: `json_document`/`json_object` (declared fields plus nested shapes), `json_map` (data-keyed objects; `drop_empty=True` for maps whose entries must hold a field: an entry holding only unknown fields loads as `{}` and keeps them, and the writer leaves out an entry still empty after the merge - Project overrides), `json_list(items, key=...)` (entries identified by a key field), `OPAQUE`. Loaders validate, then `strip_unknown_fields`, so records and normalizers see only modeled fields; unknown fields are warnings (`warn_unknown_fields`), never errors.
- Owners persist through `write_json_document(path, body, JsonDocumentFormat)`: it re-reads the file on disk, refuses with `JsonDocumentWriteError` when `format.validate` reports an error, merges the file's unknown fields back into `body` at every modeled level (list entries match by `key`; duplicate keys and entries the owner dropped are not merged; a field the owner writes wins), puts `format_version` first, and replaces atomically. `reset=True` skips guard and merge for an explicit user reset (prompt layout reset).
- Guard choice: single-record documents pass their full validator; collections that keep invalid entries verbatim (Cron, Bootstrap, Calendar events and actions, both Terminal documents, MCP connections) guard only the document root (`validate_collection_root` or an owner root check); they skip invalid entries in their effective view, write them back verbatim, and `doctor config` reports them.
- Version-bump rule: an optional field with a default is additive and needs no bump. Removing, renaming, or changing a field's type or meaning requires bumping that document's `format_version` together with a converter under `scripts/converters/`; the application keeps no old-field branches.
- Tolerance applies only to documents read from disk: RPC and management input normalizers still reject unknown keys.
- `validate_data_dir_config()` (`vbot doctor config`) maps every `DURABLE_DOCUMENTS` kind to its owner's `validate_*_file` and fails fast when a kind has no validator; `settings.json` is always reported, every other document only when present. The CLI (`cli/doctor_management.py`) prints one line per document but folds a directory with five or more valid documents (attachment sidecars) into one `<dir>/: N documents valid` line; documents with diagnostics are always listed.
- `scripts/converters/persistence_generation_1/json_documents.py` converts pre-Generation-1 documents: adds `format_version`, wraps arrays, maps the Skill policy (`version` 2) and Terminal (`version` 1) documents, drops Cron `timezone` and backfills derived Cron names, fills a missing Project `allowed_tools` with the whitelist the pre-Generation-1 application defaulted to, frozen in the converter rather than read from the current `PROJECT_DEFAULT_ALLOWED_TOOLS`, turns Agent `allowed_tools` into `tool_access` (or drops it next to an existing `tool_access`), consolidates retired `grep`/`glob` in Agent policies, Project whitelists and Project overrides into `search_files` without widening access (`tools/search_files.md`), drops Channel `owner_user_ids`, and drops the stored `file_path` and retired `text_content` of attachment sidecars (speech sidecars only gain `format_version`). Other retired fields and values (Agent and `defaults.agent` `fallback_model`, the `jsonl_scan`/`canonical_scan` recall backend, `live_voice`, `reflection.skill_tool_call_interval`, the `core:project_files` prompt block) map to their successors or are dropped: `database/generation-1-conversion.md` -> Retired fields and values. The MCP `mcp/connections.json` moves to `extension-data/mcp/connections.json` (converted or not) and its old path retires; when the new path already exists, the old file stays in place and is reported. Unconvertible documents stay unconverted and are reported. The whole run: `database/generation-1-conversion.md`.

## Constraints & Gotchas

- Public schema errors stay transport-independent inside `core/settings/` (no RPC errors raised there) and distinct from storage-level validation errors, keeping RPC mapping stable. Diagnostics/formatting for agents belongs to CLI doctor commands.
- Unknown raw keys warn because persisted data may temporarily contain unconsumed values; Runtime isolates the owning key instead of rejecting siblings or aborting startup.
- Multi-section payloads and multi-operation patches persist in one locked transaction before lifecycle hooks run; Runtime effects run only after the write succeeds. The RPC mutation remains serialized through refresh and publication, including caller cancellation. Runtime owns the distinction between full Extension rebuild (which refreshes all dependent services) and surgical disable (which must still apply an independent Recall change). Both RPC mutation surfaces serialize through live refresh and finish that sequence even after caller cancellation; Skill-directory refresh uses Runtime's asynchronous reload so scans stay off the Event Loop.
- Server-side schema validation of extension configs happens at the RPC layer where the loaded registry exists - `core/settings/` stays untouched by design.
- `validate_data_dir_config()` imports the MCP validator from `resources/extensions/mcp/config.py` - core's one outward import (loading the MCP Extension package), because Extensions have no doctor hook yet.
- Setup scripts seed new `settings.json` with thinking effort "high" only and leave temperature unset, so `resolve_request_temperature` (`core/chat/model_resolution.py`) falls through to `Model.recommended_temperature`. Install-time seed only - existing instances keep prior behavior until explicitly configured; this is not a runtime fallback.

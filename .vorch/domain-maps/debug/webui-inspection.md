# Debug WebUI inspection

How Settings -> Debug lists and inspects traces; the trace shape and redaction it reads stay in `debug.md`, its visual arrangement in `webui/design.md` -> Debug.

`SettingsDebugPanel.svelte` owns the capture switch and the single trace-limit editor, both using shared autosave with conflict protection; retention stays editable while capture is off. `webui/src/components/DebugView.svelte` renders the Traces section below them and owns selection, stale-request protection and event-driven list refresh. It receives Settings and the trace invalidation token through SettingsView, loads only while its section is active, and reads no trace list or body while capture is off. Status and clearing remain available. Trace selection is a Settings sub-page (`#settings/debug/<traceId>`) using the shared navigator; Back returns to the controls and list. `lib/debugView.js` retains the fetched detail while its id remains in the index; clearing or pruning invalidates pending detail loads. Missing index statuses/durations stay null, not zero. Index status filters describe HTTP/WS codes only: a successful status does not prove that a captured stream completed; full-trace errors remain visible in the detail header.

`components/debug/` owns the searchable Provider/status-filtered list, Request/Response/Metadata inspector and lazy JSON reading view. Detail is request/response-first and must not present stream events as the response. Readable and formatted JSON are presentation-only alternatives; Raw, body Copy, and whole-trace JSON export retain the captured body strings. SSE/WebSocket aggregates remain complete text, never a replacement per-event view. Literal body search switches from the reading view to Raw and highlights one navigable match without dropping surrounding text. The Model Probe stays in a secondary disclosure and is hidden while capture is off. `lib/debugView.js` names a trace by Model, Model Probe or request path (`traceLabel`) and builds the row details card (`traceTooltip`) from list and detail shapes alike. Coverage: `components/__tests__/DebugView.test.js`, `components/debug/__tests__/DebugBody.test.js`, `lib/__tests__/debugView.test.js`, and App debug-invalidation tests.

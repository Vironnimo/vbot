# Agent Configuration

Read when changing an `agent.json` field, its validation or its surfaces, or the roster document `agents/order.json`. The document contract and the fields every change in the domain must respect are in `../agent.md` -> Data Model.

## Tool permission and Tool settings

Tool permission persists as root `tool_access`: mode `all`/`selected`/`none`, `selected` requires `allowed`, any mode may carry explicit opt-ins in `granted` (also used for the vision exception in `tools/image.md`) and absolute `denied` names winning after activation and grants; the retired root `allowed_tools` is an ordinary unknown field (a `doctor config` warning, kept on disk). `memory_prompt_mode` stays independent (prompt Memory, not permission).

- `tool_access` defaults `{"mode":"all"}`; unknown Tool names persist for temporarily unavailable Extensions; `allowed`/`denied` must not overlap; the retired `*` wildcard is invalid. Tool-owned settings live under optional root `tools.<tool>`: `tools.subagent.allowed_agents` lists only *additional* targets (`['*']` default, `[]` self-only, bare or qualified ids); `tools.bash.allowed_env` is the ordered deduplicated permanent env-grant list. Denying an owning Tool deactivates its settings without deleting them. Automatic Tools (`memory`, Session-granted Extension Tools) are not independently selected but explicitly deniable.

## Fields

- `description` (optional, written only when non-empty) says in one line what the Agent is for. The user writes it (WebUI create dialog and editor, `agent create|update --description`); nothing generates or changes it on its own. Writes trim it and refuse line breaks, other control characters and more than 160 characters (`AGENT_DESCRIPTION_MAX_LENGTH`), because it reaches other Agents' System Prompts as one Sub-Agent catalog line (`tools/subagent.md`); readers accept stored text. Built-in Agents keep it fixed. `agent.suggest_description {id}` (`Runtime.suggest_agent_description`, `core/runtime/_agent_description.py`) drafts one with the Agent's own Model from its name, `SOUL.md` (first 4000 characters), own Skills, default Project and its 20 most recent Session titles, and saves nothing: the editor fills the field for the user to review (usage kind `agent_description`). Coverage: `test_agents.py::test_description_persists_as_one_trimmed_line_and_clears`, `tests/server/rpc/test_agent_methods.py`.
- `model` / `fallback_models` are user-facing `<provider>/<model-id>` optionally pinned `::<connection-local-id>[:<account-id>]`; empty resolves against `defaults.agent.model` at read time without rewriting disk. `fallback_models` is the ordered fallback chain (max 5, duplicates rejected at save). Chat owns runtime eligibility and shared retry limits, including exhausted network/timeout recovery; see `chat/run-execution.md`. Unresolvable/unusable candidates are skipped with a warning, and an activated candidate stays for the rest of that Run only without changing the persisted primary Model. The `::connection[:account]` suffix stores the provider-local slug, reconstructed to full runtime form at resolution; Account semantics in `providers/connections.md`.
- `memory_prompt_mode`: `off` | `agent` | `agent_user` (default) controls prompt-visible memory files.
- `workspace` defaults to the data-dir location and stays independent of Project. Resolved paths are always absolute in API/UI; inside the data dir `agent.json` stores a forward-slash relative path anchored to it (making the data dir portable), external workspaces stay absolute. Relocation is always explicit: declining copy repoints with normal SOUL seeding; accepting copy moves only SOUL/USER/MEMORY, backs up replaced destinations, rolls back on failure. A source or destination file that cannot be checked fails the relocation (and rolls it back) instead of counting as missing; seeding creates `SOUL.md` exclusively, so it never replaces one it could not see. The seeded `resources/workspace-templates/SOUL.md` is a short behavior spec (reply sizing, uncertainty, disagreement, checking work) without a name, since the name comes from the display name in the Identity Environment block; existing Workspaces keep the text they were seeded with.
- `current_session_id` repair: a dangling pointer is cleared on load (rewriting during read, one INFO line `Dangling current Session pointer cleared`). `update(current_session_id="")` clears it too (RPC `agent.update` with `null`; `/new` does this); a non-empty value must name a live Session. After a Session leaves via move/delete, `reset_current_after_session_removed` lands on the last-active *remaining* Session instead (Sessions' `newest_session_id`, one bounded page read), or clears the pointer when none remains. `reset_current_after_session_removed` re-homes the current pointer bypassing read-time normalization (otherwise `get` would clear the dangling pointer before landing logic runs). That write-time repair does not close the gap: a failed or interrupted re-aim, a restored Session store, or an offline edit can still leave the pointer dangling, so reads keep verifying it; a roster read verifies every pointer in one Session read (`ChatSessionManager.existing_addresses`), a single `get` in one point read (`test_agents_mutations.py`).
- `tool_loading` (optional, written only when set) switches On-demand Tools (`tools.md` -> Terms): `{"on_demand": bool, "always_loaded"?: [names]}`. Missing means off. Without `always_loaded` the default always-loaded set applies (`DEFAULT_ALWAYS_LOADED_TOOLS` in `core/tools/on_demand.py`); a given list, also `[]`, persists as given, unknown Tool names included, while `*`, duplicates, blank names and a missing `on_demand` are invalid. Unknown nested fields warn in `doctor config` and survive writes; removing the setting (`agent.update` with `tool_loading: null`) drops them. It changes which Tools the Tool list shows, never which Tools the Agent may use, so it stays outside `tool_access`. Built-in Agents, fixed Tool sets and Tool access `none` never load Tools on demand. Surfaces: `agent.create`/`agent.update` and their payloads (`server.md`), `--tools-on-demand`/`--always-loaded` (`cli.md`). Coverage: `test_agents.py::test_tool_loading_persists_as_given_and_clears`, `tests/core/tools/test_on_demand.py`.
- `custom_system_prompt_enabled` gates reading the agent's own prompts directory; disabling ignores files without deleting them. Enabling custom prompts seeds the agent prompt directory once; re-enabling preserves existing files.
- `librarian_enabled` (boolean, default `true`; missing or `null` reads as `true` without a rewrite) is the per-Agent switch of Librarian passes over the Agent's own Skills: off, the schedule skips the Agent and `librarian.run` refuses (`automation/librarian.md`). Only the Librarian reads it; no prompt, Tool or ordinary Session depends on it. Surfaces: `agent.create`/`agent.update` (`server.md`), `--librarian true|false` (`cli.md`), the Agent editor's Librarian row.
- `allowed_skills` (`["*"]` or missing = all, `[]` = none) grants Skills beyond the private and active-Project ones, which it cannot narrow. Optional `excluded_skills` (default `[]`, written only when non-empty, deduplicated; blank names and `*` are invalid) withholds names from that grant, including from `*`, and turns off the Agent's own private Skills of those names; the active Project's set stays granted. Semantics: `skills.md` -> Agent Skill Exclusion.

## Validation

Mutable-field validation lives server/core-side: effort vocabulary `null|""|none|minimal|low|medium|high|xhigh|max` (null inherits, "" = provider default), temperature null or 0.0-2.0 and top_p null or 0.0-1.0 (0.0 real; `agent.json` carries `top_p` only when set), strict policy shape, shell-portable env names.

## Roster order

`<data_dir>/agents/order.json` holds `{revision, agent_ids}` collection metadata: missing preserves id-sort until first materialization, absent valid agents append, stale ids filter out, malformed files never hide agents (`doctor config` reports; explicit reorder replaces). A listing never rewrites an `order.json` it could not load, an unreadable one or one that cannot be checked included.

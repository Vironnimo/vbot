# Web Search Tool

Searches the public web through the configured first-party search provider and returns numbered plain-text results.

`core/tools/web_search.py` owns registration, configuration, result-age resolution, dispatch, and the Model-facing result. Its private siblings keep argument dialects in `_web_search_arguments.py` (spelling-insensitive aliases via `core/tools/_call_vocabulary.py`, shared with `web_fetch`), bounded HTTP and provider failure wording in `_web_search_transport.py`, domain restrictions, `site:` splitting and plain-text normalization in `_web_search_common.py`, and vendor request/result shaping in `_web_search_providers.py`. These remain one Tool implementation; callers use the public registration/handler.

## Interfaces

- Tool name: `web_search`
- Registration: `register_web_search_tool(registry, credential_resolver, settings_resolver=None)`
- Model-facing schema: required non-empty `query`; optional `domains` (one to ten site names), `count` (1-20), `page` (1-10, 1-based), and provider-neutral `recency` (`day`, `week`, `month`, or `year`). When `count` is omitted, the settings default applies (`web_search.default_count`, 12 out of the box), so `count` deliberately has no static schema default. `page` keeps the schema default `1`, which the handler also applies.
- Unadvertised parameters (validated, never offered): `exclude_domains` (up to ten site names), `days` (positive number), `date_after` (date string), and `date_before` (always refused with the reason). They exist so calls written for other search Tools run without a round trip.
- Dialects (`_web_search_arguments.py`, owner argument normalizer, before validation): aliases are matched regardless of case, `_`, `-` and spaces. Examples: `q`/`search_query`/`search_term` -> `query`; `site`/`allowed_domains`/`include_domains`/`search_domain_filter` -> `domains`; `blocked_domains`/`excluded_domains` -> `exclude_domains`; `num_results`/`max_results`/`limit`/`top_k` -> `count`; `freshness`/`time_range`/`tbs`/`search_recency_filter` -> `recency`; `since`/`start_date`/`published_after` -> `date_after`; `before`/`until`/`end_date` -> `date_before`. The alias table in source is the complete list. Two spellings of one field with different values fail with the central conflict error.
- Value repairs that keep exact intent: a one-item query list becomes a string (several queries fail and name parallel calls); domain strings split on commas, whitespace, `;` and `|`; a domain URL becomes its host (a path fails and names the corrected `domains` call); `site:`, `*.` and leading dots are stripped; a `-host` entry in `domains` moves to `exclude_domains`. Recency words (`pw`, `past_week`, `qdr:w`, `Last 24 hours`, `7d`, `1 year ago`, ...) become canonical windows; `any`/`all`/`none` mean no limit. Empty values of optional fields are dropped. A date range in recency and a non-date `date_after` fail with the reason.
- `site:` in `query`: when neither `domains` nor `exclude_domains` is given, `site:host` and `-site:host` operators outside quoted phrases move into those filters; empty parentheses and dangling `OR`/`|` are removed. Operators with a path, invalid hosts, or operators that would leave no search words stay in the query unchanged. A host both required and excluded fails before searching.
- Result age: `recency`, `days`, and `date_after` resolve to one window. `days` of exactly 1, 7, 28-31 or 360-366 map without a note; any other period and every `date_after` use the shortest covering window with a `note` saying so; a period longer than a year searches without an age limit and says so. Arguments meaning different windows fail (`The result-age arguments disagree (...)`), and a future `date_after` fails.
- `domains` is the provider-neutral hard output restriction: entries are IDNA-normalized, case-insensitively deduplicated hostnames. A domain matches itself and its subdomains. The Tool scopes the provider query (`site:` operators for Brave/Serper/SearXNG/DuckDuckGo, native include parameters for Tavily/Exa/Firecrawl/Perplexity), then filters result URLs by parsed hostname so provider leakage and lookalikes cannot escape. `exclude_domains` works the same way in reverse: `-site:` for the query-operator providers, native `exclude_domains` for Tavily, `excludeDomains` for Exa only when no include list is sent, and the hostname post-filter for every provider (the only mechanism for Firecrawl and Perplexity). `count` stays a maximum and may be undershot after filtering.
- Success data (rendered by `_tool_result_text.py` as `name: value` lines, then `content`): optional `domains` and `excluded_domains` (comma-joined), `recency` when applied (DuckDuckGo never echoes one), `note` (age note plus provider warnings, one sentence each), `more` (`More results are available with page N.`, Brave only, only without site filters), and `content`. `content` is numbered blocks separated by blank lines: `N. title`, the URL, then `YYYY-MM-DD - description` (date when the provider reports one; descriptions whitespace-collapsed and cut at 400 characters with `...`). No results -> `No results found. Try ...` with tips matching the active filters. Provider names, ranks, and provider wire values never reach the Agent. `result_schema` requires `content`.
- Result text is flattened with BeautifulSoup: tags stripped, entities unescaped, literal comparisons kept (Brave is additionally asked for undecorated snippets via `text_decorations=false`).
- Display: the primary is a nonblank `description` when present, otherwise the normalized query (so alias calls such as `{"q": ...}` still show their words). A successful call records the `results` count through `context.add_display_count`; failures publish no count.
- Count/page bounds and the built-in default live in `core/search_config.py` (`DEFAULT_WEB_SEARCH_COUNT`, `MIN/MAX_WEB_SEARCH_COUNT`, `MAX_WEB_SEARCH_PAGE`), shared with the settings layer.

## External Dependencies

- Provider selection comes from `settings.json` key `web_search.provider`; supported values are `brave`, `tavily`, `exa`, `serper`, `firecrawl`, `duckduckgo`, `perplexity`, and `searxng`. `web_search.default_count` (integer 1-20) sets the result count used when the call omits `count`. `web_search.py::_PROVIDERS` maps each to its display label, credential key, and adapter.
- Brave Search API uses `BRAVE_API_KEY`, resolved through runtime env/data-dir credential lookup. `page` maps to Brave's zero-based `offset` (in units of `count`); `recency` maps to `pd`/`pw`/`pm`/`py`; dates come from `page_age`/`age`. `more_results_available` is passed on only when true and no domain or exclusion filter is set: it describes Brave's unfiltered result space and would otherwise lure the Agent into paging through empty filtered pages.
- SearXNG uses `settings.web_search.searxng.base_url` and calls `<base_url>/search` with `format=json`; the instance must allow JSON output in its own `search.formats` setting (HTTP 403 says so). An unreachable instance names its address and the Settings fix. `page` maps to `pageno`; `recency` maps to `time_range`; dates come from `publishedDate`. Notes disclose that engines may ignore site restrictions or recency and that SearXNG's own page size can skip results between pages.
- Tavily calls `POST https://api.tavily.com/search` with a Bearer `TAVILY_API_KEY`, pins `search_depth: basic` (1 credit per request), sends `max_results: count`, `time_range` from `recency`, native `include_domains` with `include_domains_mode: filter`, and `exclude_domains`. No paging: `page > 1` serves the first results with a note.
- Exa calls `POST https://api.exa.ai/search` with an `x-api-key` `EXA_API_KEY` header, sends `numResults: count` plus `contents: {highlights: true}` (descriptions are the joined highlights), and `includeDomains` or `excludeDomains`. `recency` maps to `startPublishedDate` 1/7/30/365 days back (UTC, millisecond `Z` format); Exa drops undated pages, which a note discloses. No paging.
- Serper calls `POST https://google.serper.dev/search` with an `X-API-KEY` `SERPER_API_KEY` header. `recency` maps to Google `tbs` (`qdr:d`/`qdr:w`/`qdr:m`/`qdr:y`); domains ride on `site:` like Brave. Serper serves one 10-result page per request, so the adapter fans out over the minimal covering pages to return exact count-sized slices, stopping early on short pages.
- Firecrawl calls `POST https://api.firecrawl.dev/v2/search` (cloud only) with a Bearer `FIRECRAWL_API_KEY`, sending `limit: count`, `sources: [web]`, native `includeDomains`, and `tbs` for `recency`. It reports request-level failures inside a 200 envelope (`success: false`), mapped to non-retryable `provider_request_failed`. Result items are read tolerantly across the vendor's list and field spellings. No paging. HTTP 408 is retried as a Firecrawl-specific transient code.
- DuckDuckGo calls `GET https://html.duckduckgo.com/html` with a browser user agent and `kp=-1`; no key and no API. Result anchors and snippets are parsed in DOM order with BeautifulSoup, and `uddg` redirect links are unwrapped. One response serves all count/page slices client-side (`page > 1` notes that later pages only split it). It cannot filter by age: a requested `recency` is noted as not applied and never echoed. HTTP 202 (rate limit) and bot-challenge pages map to retryable `provider_request_failed` whose message suggests waiting or another provider.
- Perplexity calls `POST https://api.perplexity.ai/search` with a Bearer `PERPLEXITY_API_KEY`, sending `max_results: count`, native `search_domain_filter`, and `search_recency_filter` (canonical values pass through). Dates come from `date`, falling back to `last_updated`. No paging.
- All eight adapters share `_request_bounded` for bounded response reading, retries, and HTTP failures; `_request_json` additionally decodes the seven JSON providers. Search POSTs are side-effect-free but billed per attempt, so only 429/502/503/504 are retried, never 500 (`is_retryable_status` with `idempotent=False`); GET also retries 500.
- Provider failure wording (`_web_search_transport._status_message`) names the provider label, the HTTP status with a short detail (JSON error fields including Brave `meta.errors`, or an HTML page title), what it means, and the next step, in this order: an adapter hint; quota statuses 402/432/433 (`plan or credits may be used up. Tell the user.`); key problems (401/403, or another 4xx whose detail mentions an API key, token, or unauthorized -> `Tell the user to check <KEY> in the .env file of the vBot data directory.`); 429 (wait); 5xx (try again later); other 4xx (`rejected the search`). Transport failures read `Could not reach <label> (<reason>). <guidance>`.

## Constraints & Gotchas

- The Tool always registers. A missing credential produces a `missing_api_key` failure at call time only when its provider is selected; the message names the provider and key and tells the Agent what to tell the user (add the key, or choose another provider in Settings under Web search; DuckDuckGo needs no key).
- Provider choice is not exposed as a Tool argument; the Settings selection is the source of truth so Agents cannot choose a different provider per call.
- Settings are resolved at call time (before `count` parsing, since the default comes from them); an invalid `web_search` settings section returns `configuration_error` telling the Agent to have the user check Settings.
- Handler-level argument problems (missing query, bad domains, overlap, count/page, result-age conflicts) return `invalid_arguments`, the same code central validation uses. Normalizer refusals (several queries, domain with a path, date ranges, `date_before`, conflicting aliases) raise before dispatch reaches the handler.
- Unknown dialect keys without evidence of use (`country`, `language`, `search_depth`, `topic`, ...) are left to central rejection; add an alias only when its meaning is exact.
- Provider/network failures map to `provider_request_failed`.
- Provider response bodies are streamed into a 5 MB bounded buffer before status details or success JSON are decoded. A valid `Content-Length` over the limit is rejected before reading, while the byte counter catches missing or dishonest declarations; oversized responses return non-retryable `response_too_large`.
- Transient-status retries honor a server `Retry-After` hint as a floor (parsed via `core/utils/http_status.parse_retry_after`, delay math via `core/utils/retry.compute_retry_delay`).
- `recency` is the provider-adapter invariant for current and future providers: every adapter must translate `day`, `week`, `month`, and `year` into a real upstream request parameter and echo the canonical value on success. An adapter must never silently omit a requested window. DuckDuckGo is the documented exception: its endpoint has no age filter, so it notes this, returns unfiltered results, and never echoes `recency`.
- The Tool description marks result text as untrusted web content, never instructions to follow; results carry no trust field.
- Tests: `tests/core/tools/test_web_search*.py` (dialects and refusals through `registry.dispatch` in `test_web_search_arguments.py`; one file per provider family; retries and failure wording in `test_web_search_retry.py`). Callers that read the result shape: `scripts/provider_probe/workflow_search_tolerance.py` and `scenario_web.py`.

# Web Search Tool

Searches the public web through the configured first-party search provider and returns normalized results.

## Interfaces

- Tool name: `web_search`
- Registration: `register_web_search_tool(registry, credential_resolver, settings_resolver=None)`
- Model-facing schema: required non-empty `query`; optional `domains` (one to ten non-empty hostnames, each at most 253 characters), `count` (1-20), `page` (1-10, 1-based), and provider-neutral `recency` (`day`, `month`, or `year`). It omits `additionalProperties`; the handler rejects unknown or malformed arguments. When `count` is omitted, the settings default applies (`web_search.default_count`, 12 out of the box), so `count` deliberately has no static schema default. `page` retains the stable numeric schema default `1`, which the handler also applies. Search operators written directly in `query` pass through unchanged when `domains` is omitted.
- `domains` is the provider-neutral hard output restriction: entries are IDNA-normalized, case-insensitively deduplicated hostnames without scheme, port, path, query, or wildcard. A domain matches itself and its subdomains; selecting a specific subdomain narrows that boundary. The tool scopes the provider query - `site:` operators for Brave/Serper/SearXNG/DuckDuckGo, native domain-include parameters for Tavily/Exa/Firecrawl/Perplexity - then independently filters normalized result URLs by parsed hostname so provider leakage, suffix lookalikes, query-string mentions, and malformed URLs cannot escape the requested boundary. Multiple domains share one provider request (Serper may use several page requests to fill one count/page slice); `count` remains a maximum and may be undershot after filtering.
- Success data returns normalized results with provider, rank, title, url, description, optional `page_age` (page publish/age date when the provider reports one; omitted otherwise), and trust metadata; the payload carries canonical `recency` when requested and applied (DuckDuckGo never echoes a `recency` it cannot apply) and, for Brave, `more_results_available`. Provider wire values such as Brave `pm` and SearXNG `time_range` never leak into the Agent contract. A domain-restricted success also returns the normalized `applied_domains` list.
- Result text is flattened to plain text: HTML tags are stripped and entities unescaped (Brave is additionally asked for undecorated snippets via `text_decorations=false`).
- Display: the flexible primary is a future nonblank `description` when present, otherwise `query`. A successful call derives a fixed `results` fact from the result list length; failures publish no count, and the Tool result envelope is unchanged.
- Count/page bounds and the built-in default live in `core/search_config.py` (`DEFAULT_WEB_SEARCH_COUNT`, `MIN/MAX_WEB_SEARCH_COUNT`, `MAX_WEB_SEARCH_PAGE`), shared with the settings layer.

## External Dependencies

- Provider selection comes from `settings.json` key `web_search.provider`; supported values are `brave`, `tavily`, `exa`, `serper`, `firecrawl`, `duckduckgo`, `perplexity`, and `searxng`. `web_search.default_count` (integer 1-20) sets the result count used when the call omits `count`.
- Brave Search API uses credential key `BRAVE_API_KEY`, resolved through runtime env/data-dir credential lookup. Pagination maps `page` to Brave's zero-based `offset` (in units of `count`); `recency` maps `day`/`month`/`year` to `pd`/`pm`/`py`; `page_age` comes from Brave's `page_age`/`age` fields. `more_results_available` is included only when no domain filter is applied: it reflects Brave's unfiltered result space, so with `domains` it is misleading (the filtered result list can be empty while `more_results_available` is true, luring the agent into paging through empty results). When `domains` is set, `more_results_available` is suppressed and a warning explains the omission.
- SearXNG uses `settings.web_search.searxng.base_url` and calls `<base_url>/search` with `format=json`; the SearXNG instance must allow JSON output in its own `search.formats` setting. Pagination maps `page` to `pageno`; canonical `recency` maps directly to `time_range`; `page_age` comes from `publishedDate`. Its configured engines may ignore `site:` syntax or recency, so domain-restricted results carry a completeness warning while the tool's post-filter still guarantees that returned URLs belong to `applied_domains`, and recency-restricted results disclose the engine-level limitation. SearXNG's page size is instance-configured (not tied to `count`), so `page > 1` carries a pagination warning: results between the count-sized slices the agent expects may be unreachable because SearXNG returns its own larger page and the tool truncates to `count`.
- Tavily calls `POST https://api.tavily.com/search` with a Bearer `TAVILY_API_KEY`. The adapter pins `search_depth: basic` (1 credit per request) and sends `max_results: count`; canonical `recency` maps directly to `time_range`; domains ride on native `include_domains` with `include_domains_mode: filter`. Tavily has no result paging, so `page > 1` carries a pagination warning and always serves the first page. `page_age` comes from `published_date` when present.
- Exa calls `POST https://api.exa.ai/search` with an `x-api-key` `EXA_API_KEY` header. The adapter sends `numResults: count` plus `contents: {highlights: true}` (descriptions are the joined highlights; entries without highlights keep an empty description) and native `includeDomains`. `recency` maps to `startPublishedDate`, computed as 1/30/365 days back from now (UTC, millisecond `Z` format); Exa may exclude undated pages, so recency-restricted results carry a warning. Exa has no result paging, so `page > 1` carries a pagination warning and always serves the first page. `page_age` comes from `publishedDate`.
- Serper calls `POST https://google.serper.dev/search` with an `X-API-KEY` `SERPER_API_KEY` header and a JSON body. `recency` maps to Google `tbs` (`qdr:d`/`qdr:m`/`qdr:y`); domains ride on `site:` like Brave. Serper serves one 10-result Google page per request, so the adapter fans out over the minimal covering pages (`page` param, `num` capped at 10) to return exact count-sized slices, stopping early on short pages. `page_age` comes from the organic `date` field when present.
- Firecrawl calls `POST https://api.firecrawl.dev/v2/search` (cloud API only, no self-hosted override) with a Bearer `FIRECRAWL_API_KEY`. The adapter sends `limit: count`, `sources: [web]`, native `includeDomains`, and Google-style `tbs` for `recency`. Firecrawl reports request-level failures inside a 200 envelope (`success: false`), which the adapter maps to non-retryable `provider_request_failed` (detail from `error`, else `message`). Result items are read tolerantly: the first list among `data`, `results`, nested `data.results`/`data.data`/`data.web`, or `web.results` wins, and url/title/description/published fall back across the vendor's field spellings (`sourceURL`, `snippet`/`summary`, `metadata.*`). Firecrawl has no result paging, so `page > 1` carries a pagination warning and always serves the first page. HTTP 408 is retried as a Firecrawl-specific transient code.
- DuckDuckGo calls `GET https://html.duckduckgo.com/html` with a browser user agent and `kp=-1` (moderate safe search, the documented default); there is no key and no API. Result anchors (`result__a`) and their snippets (`result__snippet`, scoped to the next result anchor) are parsed from the HTML; `uddg` redirect links are unwrapped to direct URLs and entities unescaped. One response serves all count/page slices client-side, so `page > 1` carries a pagination warning and pages beyond the fetched results are empty. DuckDuckGo cannot filter by age: a requested `recency` is ignored with a warning and never echoed. HTTP 202 (rate limit) and bot-challenge pages map to retryable `provider_request_failed`; other statuses follow the idempotent GET retry policy (429/500/502/503/504).
- Perplexity calls `POST https://api.perplexity.ai/search` with a Bearer `PERPLEXITY_API_KEY`. The adapter sends `max_results: count` (the tool schema cap of 20 matches the web-search maximum, so no clamp is needed), native `search_domain_filter`, and `search_recency_filter` (canonical values pass through unchanged). `page_age` comes from `date`, falling back to `last_updated`. Perplexity has no result paging, so `page > 1` carries a pagination warning and always serves the first page.
- The five POST adapters share `_post_json_bounded`: one JSON POST streamed through the 5 MB bounded buffer under the shared transient retry policy. Search POSTs are side-effect-free but billed per attempt, so only 429/502/503/504 are retried - never 500 (`is_retryable_status` with `idempotent=False`). HTTP 401/403 answers name the provider's credential key in the failure message.

## Constraints & Gotchas

- The tool always registers. A missing credential produces a `missing_api_key` failure envelope at call time only when its provider is selected; the message names the credential key (`BRAVE_API_KEY`, `TAVILY_API_KEY`, `EXA_API_KEY`, `SERPER_API_KEY`, `FIRECRAWL_API_KEY`, `PERPLEXITY_API_KEY`; DuckDuckGo needs no key).
- Provider choice is not exposed as a tool argument; the Settings selection is the source of truth so agents cannot choose a different provider per call.
- Settings are resolved at call time (before argument-count parsing, since the default comes from them); an invalid `web_search` settings section returns `configuration_error`.
- Invalid `recency` values return `validation_error`; the retired `freshness`, `date_after`, and `date_before` fields are rejected as unknown arguments.
- Provider/network failures map to `provider_request_failed`.
- Provider response bodies are streamed into a 5 MB bounded buffer before status details or success JSON are decoded. A valid `Content-Length` over the limit is rejected before reading, while the byte counter catches missing or dishonest declarations; oversized responses return non-retryable `response_too_large`.
- Transient-status retries honor a server `Retry-After` hint as a floor (parsed via `core/utils/http_status.parse_retry_after`, delay math via `core/utils/retry.compute_retry_delay`).
- `recency` is the provider-adapter invariant for current and future providers: every adapter must translate `day`, `month`, and `year` into a real upstream request parameter and echo the canonical value on success. An adapter must never silently omit a requested window. DuckDuckGo is the documented exception: its endpoint has no age filter, so it warns, returns unfiltered results, and never echoes `recency`.
- The Tool description marks result text as untrusted web content, never instructions to follow; results carry no trust field.

# Tools Agent-facing text

Why each sentence of the shared dispatch texts the Tools domain owns exists: the unknown-Tool, argument-validation and no-arguments refusals, the `tool_execution_error` message, the unknown-field note, the per-code fallback sentences (`core/tools/tools.py`, `contracts.py`, `_tool_results.py`) and the `permission_denied` refusal, whose text `core/permissions/_refusal.py` owns (`permissions.md`). Mechanics and exact conditions: `tools/call-repair.md` and `tools/registry-dispatch.md` -> Failure codes. Rules for this file: `.vorch/workflows/domain-map-workflow.md` -> Agent-facing text; failure modes F1-F6: `tools.md` -> Terms.

| Text | Reason |
|---|---|
| `Unknown Tool: <name>. Call one of the available Tools instead: <names>.` | Names the Tools the caller may use, under their Model names, so the next call picks a real one (F5). |
| `Unknown Tool: <name>. These arguments fit <tool>; call <tool> with them.` | When the arguments fit exactly one offered Tool, naming it saves a choice from the list; the Tool is never run, because the name did not say which Tool was meant. Swarm Sessions, 2026-10-12: 4 of 9 unknown-Tool Calls, such as `pash` with a `command` and `swagger_placeholder` with a Wiki read, fit exactly one offered Tool. |
| `Unknown Tool: <name>. Nothing was run: the call arrived with no arguments at all. If you sent some, the call was garbled on the way: send the complete call again.` | A Provider's parser that splits the Model's tool-call markup wrongly leaves a garbled name and often no arguments; the Model needs to resend the same call, not pick another Tool (F5). Conditional, because a Call to an unknown Tool can also be meant without arguments. Swarm run 2026-10-13: one Model's Provider turned its shell calls into `powerhellsparameter` 15 times, 10 of them with `{}`; the list answer told it to pick another Tool. |
| `... the call arrived with tool-call markup in <its Tool name / the argument name "<key>">, so it was garbled on the way. Send the complete call again.` | Same transit damage, shown by `<`, `>`, `=` or `"` in a name. Swarm run 2026-10-13: `powerthrough` with an argument named `parameter=command`. |
| `The closest available Tool is <name>.` / `Available Tools: <names>.` | Ends the garbled-call message with the Tool the damaged name clearly resembles, or the list when none does; that Tool is never run. |
| Validation failure `<tool> was not run: ...` with the field, the expectation, the received value, a missing parameter's valid values or first description sentence, a suggested parameter for an unknown name, and the parameter list | Every problem at once lets one corrected call succeed (F2, F5). A missing parameter with an `enum` lists its values, because a first sentence that describes the values one by one ends mid-list (eval 2026-10-12, `terminal` `action`). The suggestion is never applied. |
| `<tool> was not run: the call arrived with no arguments at all. Send the complete call again.` plus the parameter list | A refused call that arrived as exactly `{}` lost its arguments on the way, mostly in Tool-call markup a Provider could not read, so naming each missing parameter would miss the point (10 `powershell` calls in the 2026-10-11 review). |
| `<tool> failed while running: <cause> It is unknown how much of the call took effect. Check the current state before you call <tool> again.` | An exception escaped a running handler, so the call's effects are unknown; the Agent must check before repeating a possibly applied change (F3, F4). |
| `"<field>" had no effect: <tool> has no such parameter.` (`ignored_fields_note`) | A dropped unknown field runs the call and tells the Agent that the field did nothing, instead of refusing a complete call (F5) or hiding the drop (F4). Swarm run 2026-10-12: 21 calls were refused for unknown fields, among them complete swarm_board posts with `transition` and `commentary`. |
| Per-code fallbacks for an exception without a message, such as `Tool not allowed: <tool>.` and `Unknown Tool: <tool>.` | Every failure reads as one complete sentence even when the raising code gave no message. |
| `<tool> was not run: <refusal>` (`secret_unavailable`) when a Secret reference in a sink argument cannot be resolved; the refusals are in `secrets/agent-facing-text.md` -> Substitution refusals | The call did not run, which the Agent must know before it retries; the prefix matches the other dispatch refusals (F4, F5). |
| `<tool> was not run: the permission rules refuse <reading / changing / working in / running "<command>" / fetching> <target>, because <reason>.` (`permission_denied`) | Names the refused access, its normalized target and what refused it, so the Agent knows nothing ran and why (F4, F5). The `was not run` prefix matches the other refusals before any effect. |
| `..., which leads to <resolved>, ...` | When a link or junction on the path leads elsewhere, the refusal of a path that looks inside the allowed folders would otherwise read as a contradiction and invite retries (F5). |
| Reasons: `the rule <rule> denies it`; `it is outside the folders this Agent can read` / `can change`; `this Agent can change files only in its scratch folder`; `only commands that match an allow rule can run`; `only hosts that match an allow rule can be fetched`; `it is in vBot's data folder`; `it is part of vBot's installation`; `it is this Agent's own configuration`; `it is the vBot server itself`; `it is vBot's own command line`; `it is a <network path / device path / alternate data stream / drive-relative path> that no allow rule names` | The exact rule or base tells the Agent which other targets will work and lets it tell the user precisely what to change (F5). Protected locations are named as vBot's own, so the Agent does not take them for an ordinary folder outside its area. |
| `, inherited from the Session that started this Sub-Agent,` / `that scheduled this job` / `set by the Extension that runs this Agent` | A ceiling refuses what the Agent's own rules allow; without the source the Agent and the user look for the rule in the wrong place (F5). |
| `The user set these rules for this Agent; every Tool and command refuses the same access, so another way does not work either.` | Without it Agents retry the same access through the shell or another Tool, which the same boundary refuses (F1, F5), or treat the refusal as a defect to work around. |
| `This Agent can read in: <folders>.` / `can change files in:` / `can work in:` / `can run only:` / `can fetch only from:` (or `cannot ... any ...`) | Names what is allowed, so the next call can succeed inside the boundary instead of probing (F5, F6). Left out when the base allows everything. |
| `If the task needs this access, tell the user.` | The only way forward when the task needs the refused access; the user, not the Agent, changes the rules (F5). Left out when the refusal has a `hint`, which names the way forward. |
| Command reasons (`unanalyzable`, `_command_check.py`): `<what the analysis could not resolve, such as the path is computed when it runs> (<the part of the command>), so the check cannot tell what it reads` / `what it changes` / `which folder it works in` / `what it runs` | A command the analysis cannot see into is refused although it may be harmless; naming the part and why it cannot be checked tells the Agent that rewriting it, not another Tool, gets it to run (F5). The `same access` sentence is left out for these refusals: a rewritten command can pass, so it would be false. |
| Hints: `Write each path literally in the command.` / `Change into folders by their literal path, or pass the folder as workdir.` / `Write each command and its arguments literally.` | The concrete rewrite that makes the command analyzable; `workdir` is the shell parameter that replaces a computed `cd` (F5, F6). |
| `vBot could not analyze it to check it (<error>)` with `Run it again; if this repeats, tell the user.` | The analysis failed (helper timeout or crash, fail closed); the command itself may be fine, and the helper restarts, so one retry is the right next step before involving the user (F5). |
| `this vBot cannot analyze commands to check them` | A Tool registry without a command checker cannot run a restricted Session's commands; the Agent learns that no rewrite helps (F5). |

# Tools Agent-facing text

Why each sentence of the shared dispatch texts the Tools domain owns exists: the unknown-Tool, argument-validation and no-arguments refusals, the `tool_execution_error` message, the unknown-field note and the per-code fallback sentences (`core/tools/tools.py`, `contracts.py`, `_tool_results.py`). Mechanics and exact conditions: `tools/call-repair.md` and `tools/registry-dispatch.md` -> Failure codes. Rules for this file: `.vorch/workflows/domain-map-workflow.md` -> Agent-facing text; failure modes F1-F6: `tools.md` -> Terms.

| Text | Reason |
|---|---|
| `Unknown Tool: <name>. Call one of the available Tools instead: <names>.` | Names the Tools the caller may use, under their Model names, so the next call picks a real one (F5). |
| `Unknown Tool: <name>. These arguments fit <tool>; call <tool> with them.` | When the arguments fit exactly one offered Tool, naming it saves a choice from the list; the Tool is never run, because the name did not say which Tool was meant. Swarm Sessions, 2026-10-12: 4 of 9 unknown-Tool Calls, such as `pash` with a `command` and `swagger_placeholder` with a Wiki read, fit exactly one offered Tool. |
| `Unknown Tool: <name>. Nothing was run: the call arrived with no arguments at all. If you sent some, the call was garbled on the way: send the complete call again.` | A Provider's parser that splits the Model's tool-call markup wrongly leaves a garbled name and often no arguments; the Model needs to resend the same call, not pick another Tool (F5). Conditional, because a Call to an unknown Tool can also be meant without arguments. Swarm run 2026-10-13: one Model's Provider turned its shell calls into `powerhellsparameter` 15 times, 10 of them with `{}`; the list answer told it to pick another Tool. |
| `... the call arrived with tool-call markup in <its Tool name / the argument name "<key>">, so it was garbled on the way. Send the complete call again.` | Same transit damage, shown by `<`, `>`, `=` or `"` in a name. Swarm run 2026-10-13: `powerthrough` with an argument named `parameter=command`. |
| `The closest available Tool is <name>.` / `Available Tools: <names>.` | Ends the garbled-call message with the Tool the damaged name clearly resembles, or the list when none does; that Tool is never run. |
| Validation failure `<tool> was not run: ...` with the field, the expectation, the received value, a missing parameter's valid values or first description sentence, a suggested parameter for an unknown name, and the parameter list | Every problem at once lets one corrected call succeed (F2, F5). A missing parameter with an `enum` lists its values, because a first sentence that describes the values one by one ends mid-list (eval 2026-10-12, `terminal` `action`). The suggestion is never applied. |
| `<tool> was not run: the call arrived with no arguments at all. Send the complete call again.` plus the parameter list | A refused call that arrived as exactly `{}` lost its arguments on the way, mostly in Tool-call markup a Provider could not read, so naming each missing parameter would miss the point (10 `powershell` calls in the 2026-10-11 review). |
| `<tool> failed while running: <cause> It is unknown how much of the call took effect. Check the current state before you call <tool> again.` | An exception escaped a running handler, so the call's effects are unknown; the Agent must check before repeating a possibly applied change (F3, F4). |
| `"<field>" had no effect: <tool> has no such parameter.` (`ignored_fields_note`) | A dropped unknown field runs the call and tells the Agent that the field did nothing, instead of refusing a complete call (F5) or hiding the drop (F4). Swarm run 2026-10-12: 21 calls were refused for unknown fields, among them complete swarm_board posts with `transition` and `commentary`. |
| Per-code fallbacks for an exception without a message, such as `Tool not allowed: <tool>.` and `Unknown Tool: <tool>.` | Every failure reads as one complete sentence even when the raising code gave no message. |
| `<tool> was not run: <refusal>` (`secret_unavailable`) when a Secret reference in a sink argument cannot be resolved; the refusals are in `secrets/agent-facing-text.md` -> Substitution refusals | The call did not run, which the Agent must know before it retries; the prefix matches the other dispatch refusals (F4, F5). |

# Web Fetch Tool

Read public HTTP(S) pages and documents without flooding Context. The same Tool reads and searches saved page snapshots; optional extraction services recover difficult pages.

## Interfaces

- Registration: `register_web_fetch_tool(registry, *, attachment_store, temporary_files=None, credential_resolver=None, settings_loader=None)`. Runtime injects the existing Storage temporary-file manager, live Settings loader, and central environment credential resolver. No separate retrieval service or Model summarizer is introduced.
- Public input: `url` (fresh network fetch) or `ref` (saved page or continuation), plus optional literal case-insensitive `find`. Agents choose what to read or find; provider selection, fallbacks, extraction format, view selection and response sizing are backend decisions. Unadvertised (`unadvertised_parameters`): historical `output` / `scope` / `offset` / `max_chars` / `raw` / `include_links`, plus `urls`, `prompt` and `timeout` from other harnesses.
- `_web_fetch_arguments.py` owns argument interpretation (the Tool's `argument_normalizer`, also used by the row display): spelling-insensitive aliases (`link`, `uri`, `href`, `website`... -> `url`; `links` -> `urls`; `reference`, `cursor` -> `ref`; `search` -> `find`; `question`, `query`, `instructions` -> `prompt`; `max_length`, `limit`, `maxChars` -> `max_chars`; `format`, `extract_mode` -> `output` with `html` -> `raw`, `md` -> `markdown`, `txt` -> `text`), URL cleanup (whitespace, `<>`/quote/backtick wrappers, a Markdown link, `//host`, `https:/host`, and a schemeless host such as `example.com/x` or `www.` gets `https://`), a URL passed as `ref`, a copied `next`/`more` object or line lifted into `ref`/`find`, a copied `[ref tmp_...]` label, and the legacy raw/include_links/output intersection. Anything unclear still rejects before any request.
- Several URLs: a one-item `url`/`urls` list is a single fetch. 2-5 URLs (from `urls`, a `url` list, or http(s) URLs named in a `prompt` when no url/ref is given - Gemini CLI style) are fetched concurrently in one call; each page gets `min(max_chars, 24000 / n)` characters (at least 2,000) and its own `[i/n] <url>` section with its facts, `ref` and follow-up, or its `Error (code): message`. The call fails only when every page fails. More than 5 URLs reject before any request.
- `prompt` is never applied (no summarizer); the result carries a note that web_fetch returns page text. `timeout` is ignored because every attempt has its own bounded timeout. `max_chars` is clamped to 200-30,000; a larger request that the token bound cut short gets a note pointing at the follow-up call.
- `url` together with `ref` reads the owned snapshot without network access when the trimmed URL equals its final URL or the originally requested URL (stored as `requested_url`). Mismatches, invalid/expired/cross-owner refs, `output` with `ref`, and `ref` with several URLs reject; an invalid reference never falls back to a new fetch.
- A fresh fetch starts with main content. `find` searches all saved cleaned sections, including navigation, footers and sidebars. Excerpts default to 12,000 characters and are additionally bounded to approximately 4,000 content tokens using the shared estimator. Continuation refs carry their view and position; Agents copy them without calculating either.
- Page results (Model view in order): `url`, `title`, `author`, `published` when known, `ref`, `shown` (`characters a-b of total`, present unless the whole view fits), `more` (remaining characters and the copyable next call, e.g. `Continue with {"ref": "tmp_x.m.12000"}, or search the page with {"ref": "tmp_x", "find": "..."}`), `note` (limitations folded into sentences), then `content`. Extraction `source`, `description`, numeric offsets and warning lists stay in the snapshot. Main-content and embedded-content notes appear only on a view's first read; partial-content and service warnings repeat. Continuation instructions do not appear in the Tool description.
- Find results: `shown` names the passage count and that each passage starts with a `[ref ...]` that reads on from that point; `more` carries `{"ref", "find"}` for further matches; no match says so with the searched size. Search and paging use the saved snapshot, never another HTTP or billable service request. No-match results mean no match in the saved extraction, not proof that an interactive website has no such content.
- Image URLs retain the existing attachment-store and `read_media` artifact contract. Unsupported binaries return a short notice. Neither branch creates a textual page reference.

## Extraction and ownership

- `web_fetch.py` owns routing, document/media detection, and Tool dispatch. DNS and HTTP remain asynchronous; parsing, token budgeting, snapshot I/O and attachment persistence use the Tool worker boundary.
- `_public_http.py` owns public-target validation and the bounded browser-impersonating GET (see Transport constraints below). Its interface is `fetch_public(url, *, accept, max_bytes, what)` (a successful `PublicResponse`, or `PublicFetchError` with `code`, message, `retryable`, `attempts_made` and `recoverable`) and `check_public_url(url)`. `analyze_image` downloads image URLs through the same function (see `tools/image.md`), so a transport or wording change affects both Tools; `what` names the expected content (`page`, `image`) in not-found and redirect messages and in the not-found code (`page_not_found`, `image_not_found`). Tests patch its `_http_get` seam and `_resolve_host_addresses` (`tests/core/tools/web_fetch_helpers.py`).
- `_web_fetch_html.py` uses BeautifulSoup for conservative noise removal and `markdownify` for structural conversion. Code inside lists, nested/ordered lists, table captions, table span annotations, inline spacing, base URLs, lazy images and images without alt text are preserved. Code fences adapt to embedded backticks. Non-fetchable image data becomes a compact notice; image bytes do not inflate Context.
- Main content uses all top-level semantic main/role=main landmarks or articles. Without these, explicit navigation/header/footer/aside landmarks are removed only from the main view. The complete cleaned page is saved separately; the result explains that omitted sections remain searchable. Noise matching uses whole class/id tokens, avoiding false matches in thread/download containers and GDPR articles.
- Hidden elements, scripts, styles, templates and comments are removed. Embedded visuals/interactives are represented by labels or links with an explicit limitation, not claimed as rendered. JavaScript is not executed locally.
- Native Markdown is requested through Accept negotiation. Legacy raw inspection prefers HTML. Missing/mislabelled content types are sniffed for HTML. HTML is limited to 4,000,000 input characters with an explicit partial-content warning; more than 100,000 nodes or depth 200 falls back to visible text with a layout/link limitation.
- PDF/Word/Excel/notebook extraction remains with `read_extract.py`, including its expansion bound. Extracted text uses the same saved-page/paging path; scanned PDFs still report no extractable text rather than promising OCR.
- `_web_fetch_pages.py` owns snapshot format and view coordinates. Temporary files live in `artifacts/temp/web_fetch/` under the existing 72-hour cleanup policy and canonical `tmp_` identities. References require both the originating Session and Agent. Expired, missing, corrupt, unsafe or cross-owner references fail with refetch guidance. Each saved view is capped at 2,000,000 characters with an explicit partial-content warning; limits never masquerade as complete extraction.

## Optional services

`settings.web_fetch` contains only `provider` and `mode`. Defaults are `direct` and `fallback`; an existing API key never opts users into paid extraction. Supported services are Firecrawl, Tavily, Exa and Parallel. Credentials stay in the data-directory environment snapshot (`FIRECRAWL_API_KEY`, `TAVILY_API_KEY`, `EXA_API_KEY`, `PARALLEL_API_KEY`).

- `fallback`: direct fetch first; the selected service can recover transport/access/empty-page failures. Input rejection, blocked redirects, size-limit failures and HTTP 404/410 do not trigger it.
- `prefer`: selected service first for page URLs; failure falls back to direct fetch with an explicit warning. Recognizable image/document filename extensions and raw inspection use the direct route first to retain their media contracts.
- `_web_fetch_services.py` sends one bounded POST to one vendor. No automatic service retry or cascade occurs after uncertain billable delivery. Cancellation propagates. Responses are limited to 12 MB and a 65-second overall deadline. Missing keys, quota/auth errors, empty/malformed responses and service failures remain actionable and secret-free.
- Firecrawl uses `/v2/scrape`, Markdown, all page content and `maxAge=0`; Tavily uses advanced extraction without a relevance query; Exa uses full text and `maxAgeHours=0`; Parallel uses `/v1/extract` with full content and a 600-second maximum cache age, without stale-cache fallback. Full service output is saved rather than silently replaced by excerpts or an LLM summary.
- Service output identifies its source and explains that only the service's extraction is saved. Source sites and services can still omit inaccessible/dynamic sections; no route guarantees access to authentication or interactive challenges.
- Settings -> Tools & Media -> Web Fetch exposes selection, mode, credential presence/setup and official pricing links. The UI explains URL sharing and possible charges. Prices/allowances are not hard-coded. `settings.get` exposes configuration booleans and variable names, never secret values.

## Transport constraints and recovery

- Only public HTTP(S) targets are allowed. Validation rejects credentials in input and redirect URLs and private/loopback/link-local/multicast/reserved targets, including obfuscated IP forms. The direct connection is pinned through curl RESOLVE to a validated address; each redirect is revalidated and repinned. Cookies survive redirect hops.
- Downloads stream into a bounded buffer (50 MB for web_fetch; the caller passes `max_bytes`). Direct GETs retry retryable HTTP statuses and connection failures up to `MAX_RETRIES` with the existing Retry-After/backoff policy; a timeout is retried once, TLS/certificate failures never. Timeout errors report the host and actual attempt count without claiming an elapsed duration or a connection/transfer phase, since either timeout can end an attempt. Redirect cycles and chains over ten hops fail explicitly.
- Failure codes, each message naming the next step: `invalid_url` (not http(s), no host, malformed), `blocked_url` (private/local address, credentials in the URL, redirect to a blocked address), `host_not_found` (DNS), `page_not_found` (404/410), `access_denied` (401/403/407 and bot/login walls), `rate_limited` (429, retryable), `server_error` (5xx, retryable), `request_rejected` (other 4xx; states that the request was a plain GET without custom headers, cookies or body), `unexpected_response`, `redirect_loop`, `timeout` / `connection_failed` (retryable, with `attempts_made`), `tls_error`, `response_too_large`, `no_content` (empty response or JavaScript shell), `invalid_ref`, `page_expired`, `invalid_arguments`, plus `storage_error`, `attachment_error`, `document_too_large`. A failed service recovery keeps the direct failure's code and appends `The <provider> fetch service also failed: ...`; a service selected without its key tells the Agent to tell the user.
- Bot/login walls and empty/JavaScript-only shells do not become successful empty pages. Legacy raw output remains an inspection route. Error guidance offers another source or a browser Tool only if available; it does not require an unavailable web_search Tool.
- Page content is untrusted data. The Tool description states that page text is not instructions; metadata and HTML do not change Tool authority.

## Tests

- `tests/core/tools/test_web_fetch*.py`: direct transport (`_public_http.py`)/media compatibility, SSRF, retries and failure classification, argument repair and harness dialects (`test_web_fetch_arguments.py`), content retention, paging/search bounds, snapshot ownership/expiry, service wire contracts, opt-in/fallback routing and cancellation.
- `scripts/tool_lab/cases/web_media.json`: offline production-dispatch cases for the family (aliases, blocked targets, refs).
- `tests/core/test_fetch_config.py`, Settings/Storage suites and `tests/server/rpc/test_settings_methods_web_fetch.py`: defaults, sparse persistence, public paths and secret-free setup projection.
- `webui/src/components/__tests__/SettingsWebFetchPanel.test.js`: opt-in controls, cost/setup information, autosave, edits during save and failure recovery.

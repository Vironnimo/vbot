# Web Fetch Tool

Read public HTTP(S) pages and documents without flooding Context. The same Tool reads and searches saved page snapshots; the server's own headless browser and optional extraction services recover difficult pages.

## Interfaces

- Registration: `register_web_fetch_tool(registry, *, attachment_store, temporary_files=None, credential_resolver=None, settings_loader=None, browser=None)`. Runtime injects the existing Storage temporary-file manager, live Settings loader, central environment credential resolver, and the Runtime-owned `PageBrowser` (Local browser below). No separate retrieval service or Model summarizer is introduced.
- Public input: `url` (fresh network fetch) or `ref` (saved page or continuation), plus optional `find`, literal text matched case-insensitively against the page as a reader sees it (Find matching below). Agents choose what to read or find; provider selection, fallbacks, extraction format, view selection and response sizing are backend decisions. Unadvertised (`unadvertised_parameters`): historical `output` / `scope` / `offset` / `max_chars` / `raw` / `include_links`, plus `urls`, `prompt` and `timeout` from other harnesses.
- `_web_fetch_arguments.py` owns argument interpretation (the Tool's `argument_normalizer`, also used by the row display): spelling-insensitive aliases (`link`, `uri`, `href`, `website`... -> `url`; `links` -> `urls`; `reference`, `cursor` -> `ref`; `search` -> `find`; `question`, `query`, `instructions` -> `prompt`; `max_length`, `limit`, `maxChars` -> `max_chars`; `format`, `extract_mode` -> `output` with `html` -> `raw`, `md` -> `markdown`, `txt` -> `text`), URL cleanup (whitespace, `<>`/quote/backtick wrappers, a Markdown link, `//host`, `https:/host`, and a schemeless host such as `example.com/x` or `www.` gets `https://`), a URL passed as `ref`, a copied `next`/`more` object or line lifted into `ref`/`find`, a copied `[ref tmp_...]` label, and the legacy raw/include_links/output intersection. Anything unclear still rejects before any request.
- Several URLs: a one-item `url`/`urls` list is a single fetch. 2-5 URLs (from `urls`, a `url` list, or http(s) URLs named in a `prompt` when no url/ref is given - Gemini CLI style) are fetched concurrently in one call; each page gets `min(max_chars, 24000 / n)` characters (at least 2,000) and its own `[i/n] <url>` section with its facts, `ref` and follow-up, or its `Error (code): message`. The call fails only when every page fails. More than 5 URLs reject before any request.
- `prompt` is never applied (no summarizer); the result carries a note that web_fetch returns page text. `timeout` is ignored because every attempt has its own bounded timeout. `max_chars` is clamped to 200-30,000; a larger request that the token bound cut short gets a note pointing at the follow-up call.
- Site paths: a root-relative `url` (`/wiki/Iron`, also inside a copied Markdown link), as saved pages show links to their own site, is fetched on the site of the page this conversation read last (fetched, or read by ref), and the `note` names the full address. The handler remembers each conversation's last page address in memory (by the full Session address, Project included, as a saved page's owner: `page_owner`, the `artifact_owner` of other temporary files; at most 1,024 conversations): finding it in the saved pages would mean opening every snapshot of every conversation. So after a restart, or before any page, a path fails `invalid_url`, naming what to send. Every page result names its full `url` first, so the base of its paths and the address to cite are visible without further text (user decision 2026-10-13).
- `url` together with `ref` reads the owned snapshot without network access when the trimmed URL equals its final URL or the originally requested URL (stored as `requested_url`). A readable ref of another page, `output` with `ref`, and `ref` with several URLs reject. A ref that cannot be read (malformed, unknown, another conversation's, expired, unreadable) beside a url fetches the url instead, as the user decided (2026-10-12): the result's `note` says `ref <ref> was not used because <reason>; url was fetched instead.`, and a failed fetch carries that clause in its error. Evidence: an Agent sent `find` with a mistyped ref and the right url and was told the page had expired and to fetch it with url (Swarm run, 2026-10-12).
- A ref alone that cannot be read names what the store can tell, with the next call (`SavedPageError.state`): a malformed ref and an unknown one (no such file: mistyped, or removed after expiry; the store cannot tell these apart) fail `invalid_ref`; another conversation's page fails `invalid_ref` without naming its address; an expired page of this conversation fails `page_expired` with the ready call `{"url": <its url>[, "find": ...]}`; an unreadable file fails `storage_error`. For a malformed or unknown ref, `similar_refs` offers this conversation's readable, unexpired saved pages whose ref differs by at most 2 edits (only files that close are opened): one as `Did you mean ...` with the ready call (view suffix and `find` kept), several as a list. It offers rather than reads the close ref, since a wrong guess would quote the wrong page as evidence.
- A fresh fetch starts with main content. `find` on a fresh fetch or base ref searches all saved cleaned sections, including navigation, footers and sidebars. Excerpts default to 12,000 characters and are additionally bounded to approximately 4,000 content tokens of the calling Agent's Model: the shared estimator's count times that Model's input estimate factor (`UsageRecorder.input_estimate_factor`, `usage.md`; injected as `input_estimate_factor`, 1.0 without one). It is the Agent's own Model; a Run on a fallback route still uses it. Continuation refs carry their view and position for both reads and `find`; Agents copy them without calculating either. An explicit legacy `scope` change starts the other view at zero unless `offset` is supplied. A nonzero position at or beyond the view end fails `invalid_arguments` with a usable other-view ref or restart call.
- Page results (Model view in order): `url`, `title`, `author`, `published` when known, `ref`, `shown` (`characters a-b of total`, present unless the whole view fits), `more` (remaining characters and the copyable next call, e.g. `Continue with {"ref": "tmp_x.m.12000"}, or search the page with {"ref": "tmp_x", "find": "..."}`), `note` (limitations folded into sentences), then `content`. Extraction `source`, `description`, numeric offsets and warning lists stay in the snapshot. Main-content and embedded-content notes appear only on a view's first read; partial-content and service warnings repeat. Continuation instructions do not appear in the Tool description.
- Redirects (`_redirect_note`): when the call names a url (a fresh fetch, or url with ref) and the final page has another address, `note` names the requested url. Another address means another path (compared ignoring letter case, percent-encoding, a trailing slash and a trailing `index.html`/`index.htm`/`index.php`) or, on the same path, a requested query parameter that is missing or changed; scheme, host and `www.`, added parameters and `utm_*` parameters do not count, so a redirect that only adds a tracking parameter stays silent. The note says `This is not the requested page: <requested url> redirected here.` only where the address shows that: the same path without a requested parameter, the site root or a parent path, a shallower path with another last segment (a section's or site's index; a file extension is ignored), or a not-found or login page by its last segment (`404`, `page-not-found`, `seite-nicht-gefunden`, `login`, `sign_in`: `_STAND_IN_PAGE`) when the requested page is not one. Every other redirect reads `Redirected here from <requested url>.`, and the Agent judges by `url`, `title` and content. Evidence: element pages redirected to a site's home page and a metrology page to its not-found page were read as the requested pages (Swarm run, 2026-10-12). Documentation sites move a page to another section, rename it, or rename it and move it deeper; the rule of 2026-10-20 (the strong note unless the last segment stayed the same) gave 3 of its 4 strong notes on 2026-10-21 to such renamed pages. Of the 28 distinct redirects recorded until then, the current rule gives the strong note to exactly the 7 that served another page (site roots, a not-found and a suspended-account page, a project's landing page, a hub page) and names the 21 others, each the requested content at a new address.
- Find matching (`_web_fetch_find.py`): a saved page is a Markdown rendering, so text a reader sees in one piece is split by syntax. `find` matches the page's readable text and maps each match back to the Markdown passage shown. Presentation does not count: link and image targets and brackets, emphasis and inline code markers (`*`, `~~` and backticks that open or close a span), table separators (`|` between spaces) and rule rows, heading, quote and list markers, fence lines, `[colspan=2]` annotations, the `[Image: ...; embedded image omitted]` syntax (its alt text stays), backslash escapes, and through `fuzzy_match.fold_for_search` every kind and run of whitespace (one space), invisible characters (zero-width, BOM, soft hyphen), typographic quotes, primes, guillemets, ellipsis and ligatures. Every dash, the minus sign and en/em dashes included, reads as one `-`: they are typography for what a keyboard types as `-`, and conflating them can only show one more passage; `--` is not folded. Superscript and subscript digits and signs read as the plain characters, and `^` before a digit or sign is dropped, so `289Fl`, `²⁸⁹Fl` and `^289Fl` find one another (Extraction renders `<sup>`/`<sub>` that way). Every other character must match, ignoring case; a missing or extra space still counts. A literal match in the Markdown counts too, so a query copied from a result with its syntax finds that place. Only when neither finds anything is the query's own Markdown read as presentation (`| **Density** | 7.87 |`), and a link address it names must then stand in the matched passage; an absolute address also matches the root-relative form the page shows for links to its own site. Plain text and code (`source: direct`) and document text get the folds without the Markdown reading. A match may start or end inside a longer word, so a stem (`magnet`) finds `magnetic` and `Eisen` finds the compound `Gusseisen`. When every match from the searched position on starts inside a longer word, `shown` names up to three such words, so the Agent does not take `caused by` for a search for `used by`; scripts written without spaces between words (CJK, Thai, Lao, Myanmar, Khmer) have no word starts to judge. Swarm run 2026-10-12: a two-word phrase matched only inside a longer word, and the result read `1 passage matching` that phrase. Replaying that run's 179 `find` calls, showing only matches that start a word would have dropped compound matches on German pages in 5 calls and helped none; naming the words changes 1 result and no passage. Otherwise matches are silent (no note): the passage shows the page's own text, and presentation is a representation repair. A query not found as written with a `|` directly between two characters (`approval|deny`, alternation as the regular expressions of `search_files`) is searched as the alternatives it separates, each as above, and the result names them; `|` between spaces stays a table separator. Evidence: one Agent sent 7 such finds on 2026-10-21 after using `|` in `search_files` patterns; all missed, each cost a retry with one word, and it kept sending `|`. Replayed against their saved pages, 6 find passages and the seventh page holds none of the words. Other regular expression syntax is matched literally: none was sent in the 583 finds recorded until 2026-10-21. The readable text of the last 4 searched texts is cached (a 2,000,000-character page takes about 0.7 s once). Evidence: 35 of about 130 `find` calls in a 2026-10-12 Swarm run found nothing, about 29 of them on text the page held, split by a no-break space, table cells, bold markers or links; Agents concluded web_fetch could not verify quotes. Replaying every call against its saved page: 29 find their place, the 6 others are worded differently on the page, the 93 earlier finds show the same passages and 2 show one more correct passage.
- Find results: a passage shows its match with 180 characters before and 350 after, or 300 and 900 for plain text and code (snapshot `source: direct`), cut back to whole lines where a line break falls inside that window. Matches whose passages overlap or lie within 120 characters of each other share one passage, so no text appears twice (a 2026-10-12 search of a 64K C file showed 4 passages overlapping over 2.7K characters). Each passage that does not reach the end ends with `Read on with {"ref": "tmp_x.p.<end>"}`, which continues right after it; the Agent in that run sent 11 consecutive `find` calls and never built a read from the passage refs then shown. `shown` names the passage count, the alternatives when `|` separated them, and, when every match is inside a longer word, those words; `more` carries `{"ref", "find"}` for further matches (at most 12 passages and the excerpt bound per result); no match says so with the searched size, names navigation and footers only when the searched whole-page view differs from the main content, says that formatting is ignored but wording counts, and names a narrower search, or for a query with regular expression syntax (`.*`, `.+`, `\b`, `\d`, `\s`, `\w`: `looks_like_pattern`) that find takes literal text. On a view cut at a size limit (the 2,000,000-character saved limit, or HTML cut at its extraction limit), `shown` and the no-match text name `the saved part of the page` (`of the main content`; `after character N of the saved part`) instead. Search and paging use the saved snapshot, never another HTTP or billable service request. No-match results mean no match in the saved extraction, not proof that an interactive website has no such content.
- Display: the detail builder (`_display_details`) shows the user the returned text read from `data.content` - a `page` text block, or a `results` block when the call used `find` - plus an info notice when more remains (`Shows characters a-b of total.` for a page, `More matches follow on the page.` for a search). Refs, follow-up calls and notes stay in the raw result; a fetched image shows as media, with Args and Result behind the raw call. Coverage: `test_web_fetch_pages.py::test_the_user_sees_the_page_text_or_the_passages_and_whether_more_remains`.
- Image URLs retain the existing attachment-store and `read_media` artifact contract. Unsupported binaries return a short notice. Neither branch creates a textual page reference.

## Extraction and ownership

- `web_fetch.py` owns routing, document/media detection, and Tool dispatch. DNS and HTTP remain asynchronous; parsing, token budgeting, snapshot I/O and attachment persistence use the Tool worker boundary. `_web_fetch_walls.py` recognizes pages that stand in for the requested one: bot checks, login walls, firewall blocks and script-only shells (Transport constraints and recovery below).
- `_public_http.py` owns public-target validation and the bounded browser-impersonating GET (see Transport constraints below). Its interface is `fetch_public(url, *, accept, max_bytes, what, hosts, permissions)` (a successful `PublicResponse`, or `PublicFetchError` with `code`, message, `retryable`, `attempts_made` and `recoverable`) and `check_public_url(url)`; with `permissions` (a restricted Session's boundary) the address and every redirect hop are checked with `check_url` before they are requested, the address before any session opens, and a refusal raises `PermissionDenied` (`hop_refusal(permissions, url, hop)` names a hop other than the address as `<url>, which leads to <host>`). `analyze_image` downloads image URLs through the same function (see `tools/image.md`), so a transport or wording change affects both Tools; `what` names the expected content (`page`, `image`) in not-found and redirect messages and in the not-found code (`page_not_found`, `image_not_found`). It imports curl_cffi (about 0.1 s) inside the functions that send, so importing the Tools does not. Tests patch its `_http_get` seam, `_resolve_host_addresses` and `curl_cffi.requests.AsyncSession` (`tests/core/tools/web_fetch_test_support.py`).
- Cron watch checks (`core/tools/watch_checks.py`, `automation/cron-watch.md`) reuse the page tests `is_html_page`, `is_textual_content_type` and `looks_binary` of `web_fetch.py`, `_public_http._decoded` and the main view of `_web_fetch_html.extract_views`, so a watched page is compared as web_fetch shows it; a change there changes what a watching job sees as changed.
- `_web_fetch_html.py` uses BeautifulSoup for conservative noise removal and `markdownify` for structural conversion. The HTML worker imports it only for an HTML response; registration, raw reads and non-HTML responses do not load these parsers. Code inside lists, nested/ordered lists, table captions, table span annotations, inline spacing, base URLs and lazy images are preserved. Code fences adapt to embedded backticks. Non-fetchable image data becomes a compact notice; image bytes do not inflate Context.
- Main content uses all top-level semantic main/role=main landmarks or articles, without the navigation inside them (`nav`, `role=navigation`: Wikipedia's page toolbar and navboxes) and without language lists (a list whose every link carries `hreflang` and that holds no other text). Wikipedia puts its 200-odd interlanguage links inside `<main>`, where they filled the first ~9,500 characters of every article's main view (Swarm run 2026-10-12: 4 fetches of 2 articles, none showing article text). Header, footer and aside inside a candidate stay, as the content's own title, byline and notes. Without these, explicit navigation/header/footer/aside landmarks and language lists are removed only from the main view. The complete cleaned page is saved separately; the result explains that omitted sections remain searchable. Noise matching uses whole class/id tokens, avoiding false matches in thread/download containers and GDPR articles.
- Hidden elements (`hidden`, `aria-hidden="true"`, inline `display:none`, `visibility:hidden` and `color:transparent`: Wikipedia's mini periodic table, 118 links with invisible names in every element infobox), MediaWiki `[edit]` links (`mw-editsection`), scripts, styles, templates and comments are removed, and so is a table left without text or image (a layout grid).
- Links and images on the page's own scheme and host are written as root-relative paths (`/wiki/Iron`), which resolve against the page's url; other sites stay absolute, so external citations stay copyable. `utm_*` parameters are dropped from addresses. An image of at most 32x32 pixels is an icon: without alt text it is dropped, with alt text only that text shows. A link that holds only an image shows the image once. An image without alt or title text shows only inside a `<figure>` (as `Image`); elsewhere it is dropped, and the title is not rendered beside the alt text. Each view shows an image's address once: a repeat, also in another size (query parameters such as `width`, `v`, `w`, `q`, `dpr`, or a WordPress `-300x200` suffix), shows only an alt text not shown with it yet (`_image_key`). Swarm run 2026-10-20: image markup took 28-57% of shop pages' text, such as 69 images on one page with 65 undescribed and 53 on another showing 26 different images; replaying those results, the share falls to 12-35% on the pages with undescribed or repeated images. Wikipedia's Bromine article showed about 151 characters of article text in its first 12,000 (2026-10-13), about 3,960 after these changes; Technetium 95 -> 3,040, Flerovium 134 -> 5,490. A path passed as url is fetched on the site of the page read last (Interfaces -> Site paths).
- `<sup>`/`<sub>` holding only digits and `+-−–=()` become Unicode superscripts/subscripts (`²⁸⁹Fl`, `10⁻⁶`, `H₂O`), other content is marked `^x`/`^(xy)`/`_x`/`_(xy)` (`10^n`, `T_c`); content with a link (references), footnote symbols and an ordinal suffix after a digit (`1st`, `2ème`) stay plain. Flattening read `3.0×10<sup>5</sup>` as `3.0×105` (2026-10-13). Embedded visuals/interactives are represented by labels or links with an explicit limitation, not claimed as rendered. JavaScript is not executed locally.
- Native Markdown is requested through Accept negotiation. Legacy raw inspection prefers HTML. Missing/mislabelled content types are sniffed for HTML. A body labelled HTML without a tag, comment or doctype in its first 4,096 characters reads as plain text: Swarm run 2026-10-20, 76 results of a solar-data API's CSV, served as `text/html`, lost the tabs between their columns to HTML whitespace folding. HTML is limited to 4,000,000 input characters with an explicit partial-content warning; more than 100,000 nodes or depth 200 falls back to visible text with a layout/link limitation.
- PDF/Word/Excel/notebook extraction remains with `read_extract.py`, including its expansion bound. Extracted text uses the same saved-page/paging path; scanned PDFs still report no extractable text rather than promising OCR.
- `_web_fetch_pages.py` owns snapshot format and view coordinates. Temporary files live in `artifacts/temp/web_fetch/` under the existing 72-hour cleanup policy and canonical `tmp_` identities. References require both the originating Session and Agent. Unusable references fail by state with the next call (Interfaces above). `_web_fetch_find.py` owns where `find` matches (Find matching above); its read-side folds live in `fuzzy_match.fold_for_search`, which the edit Tools do not use. Each saved view is capped at 2,000,000 characters with an explicit partial-content warning; limits never masquerade as complete extraction.

## Local browser

- `_web_fetch_browser.py` owns `PageBrowser`, the server's own headless Chrome, Edge or Chromium (`find_local_browser`: Chrome, then Edge, then Chromium at their standard install paths on Windows and macOS, on `PATH` on Linux). Nothing is downloaded; the user's browser profile is never used. It is driven over the DevTools protocol through the existing `websockets` dependency (imported on first start), not Playwright, whose Node driver would add tens of MB to every package.
- When: a direct fetch that ended in `access_denied` (HTTP 401/403/407, a detected bot/login wall, or another 4xx showing a bot check), `no_content` (empty page or JavaScript shell) or `redirect_loop` (a login flow that needs JavaScript), unless `web_fetch.browser` is `false` (default `true`), the call asked for `raw` output, or no browser is installed. A firewall block (`rate_limited`, Transport constraints below) does not start it: the browser shares this machine's blocked address. It runs before any extraction service in both modes; in `prefer` mode it follows the direct fetch the failed service fell back to. The rendered HTML goes through the same shaping (bot-wall and shell detection, main/page views, snapshot `source: browser`). A success adds no Agent-visible note. A failure keeps the direct failure's code and appends `The local browser could not read it either: <reason>.`; a selected service then still gets its chance.
- Safety: the browser reaches the network only through a private HTTP proxy on 127.0.0.1 (`_GuardProxy`; `--proxy-bypass-list=<-loopback>` removes Chrome's implicit loopback bypass, QUIC and non-proxied WebRTC UDP are off). The proxy validates every CONNECT and plain-HTTP request with `resolve_public_address` (`_public_http.py`, same blocklist as the direct GET) and connects to exactly that address, so subresources, redirects and DNS rebinding cannot reach private or local addresses; it answers 403 otherwise, and 502 for a host that does not resolve. It remembers each refusal's host and code, so the failure reason names the unresolvable host instead of a generic network error. `redirect_unreachable` does not start the browser: the IOP bot-check host does not resolve for a real Chrome either (2026-10-13). Each fetch gets its own browser context (no cookies or storage from other fetches) with downloads denied.
- Lifecycle: one process (`--headless=new`, throwaway profile under `artifacts/temp/browser/`, leftovers removed at the next start) starts with the first fetch, serves up to 3 pages at once and exits after 120 s without one; Runtime shutdown stops it (`page_browser` step). Server containment kills it with the server (Windows job, POSIX guardian). A fetch waits for the page to settle (network almost idle and text length stable, or four stable checks), keeps waiting while a self-solving check page (`Just a moment...`, `Enodia Verification` and similar titles: `SELF_SOLVING_CHECK_TITLES` in `_public_http.py`) shows, and gives up after 35 s.
- Limits observed 2026-10-12: Reddit's bot check and JavaScript apps (Excalidraw) read through the browser; DataDome-protected sites (G2, Etsy) still answer 403. The status of the final document decides (`HTTP 4xx in the browser too`).

## Optional services

`settings.web_fetch` contains `provider`, `mode` and `browser` (Local browser above). Defaults are `direct`, `fallback` and `true`; an existing API key never opts users into paid extraction. Supported services are Firecrawl, Tavily, Exa and Parallel. Credentials stay out of `settings.json` and resolve through the central credential lookup (`FIRECRAWL_API_KEY`, `TAVILY_API_KEY`, `EXA_API_KEY`, `PARALLEL_API_KEY`; `core/fetch_config.py::WEB_FETCH_CREDENTIALS`); the Tool trims the resolved key, so a blank entry counts as missing. Settings can save or remove these keys among the data-directory credentials (Secret Store) through `settings.set_service_key`, and `settings.get` reports each one's `configured` and `source` in `web_fetch.services`; that contract is canonical in `tools/web_search.md` -> External Dependencies. Tavily, Exa and Firecrawl share one variable with web_search. A missing key fails the service call with `configuration_error`, telling the Agent to have the user enter the key in Settings under Web page reading or set the service back to Direct.

- `fallback`: direct fetch first; the selected service can recover transport/access/empty-page failures and firewall blocks (it fetches from its own address). Input rejection, blocked redirects, size-limit failures and HTTP 404/410 do not trigger it.
- `prefer`: selected service first for page URLs; failure falls back to direct fetch with an explicit warning. Recognizable image/document filename extensions and raw inspection use the direct route first to retain their media contracts.
- `_web_fetch_services.py` sends one bounded POST to one vendor. No automatic service retry or cascade occurs after uncertain billable delivery. Cancellation propagates. Responses are limited to 12 MB and a 65-second overall deadline. Missing keys, quota/auth errors, empty/malformed responses and service failures remain actionable and secret-free.
- Firecrawl uses `/v2/scrape`, Markdown, all page content and `maxAge=0`; Tavily uses advanced extraction without a relevance query; Exa uses full text and `maxAgeHours=0`; Parallel uses `/v1/extract` with full content and a 600-second maximum cache age, without stale-cache fallback. Full service output is saved rather than silently replaced by excerpts or an LLM summary.
- Service output identifies its source and explains that only the service's extraction is saved. Source sites and services can still omit inaccessible/dynamic sections; no route guarantees access to authentication or interactive challenges.
- Settings -> Tools -> "Web page reading" exposes selection, mode, the chosen service's write-only API key row (`webui/settings.md` -> Web Search and Web Fetch settings) and official pricing links; the URL-sharing and possible-charges explanation sits behind the service row's "?". Prices/allowances are not hard-coded. `settings.get` exposes configuration booleans and variable names, never secret values.

## Permission Rules

A restricted Session's fetch (`permissions.md`) is checked at every address it requests or ends on, each refusal a not-retryable `permission_denied` result with the `PermissionRefusal` text (`web_fetch was not run:` only for an address of a one-page call, else `The page was not fetched:`, since a redirect refusal comes after a request and several pages fail one by one): the address before the DNS preflight, so neither a lookup nor a fetch service sees a refused address; every redirect hop of the direct GET (`fetch_public(..., permissions=)`, no service or browser recovers it); the final URL a fetch service reports; and the page the local browser ended on (`hop_refusal`). Not checked: the browser's own redirect hops and the subresources a page loads in the browser (scripts, images, frames), which go only to public addresses through the guard proxy; the user's fetch service, which the user configured. Test: `test_web_fetch_transport.py::test_the_permission_rules_refuse_an_address_or_redirect_hop_before_it_is_requested`.

## Transport constraints and recovery

- Only public HTTP(S) targets are allowed. Validation rejects credentials in input and redirect URLs and non-global targets (including shared address space `100.64.0.0/10`), as well as loopback/link-local/multicast/reserved targets, including obfuscated IP forms and IPv4-mapped IPv6 addresses. This check covers literal addresses, every DNS answer and every redirect. The direct connection is pinned through curl RESOLVE to a validated address; each redirect is revalidated and repinned. DNS validation, the request URL and the pin use the host the permission rules compare (`core.permissions.normalize_host`: UTS46 nontransitional IDNA as in browsers, `faß.de` -> `xn--fa-hia.de`, no trailing dots); a host without such a form fails `invalid_url` (`permissions/rule-language.md` -> Bases, kinds and placeholders). Python's IDNA 2003 codec requested `fass.de` for `faß.de`, past a rule that denied `fass.de` (2026-10-22). IP-literal URLs use the canonical validated address directly (IPv6 bracketed in the URL), without a DNS pin. Cookies survive redirect hops. A redirect back to an address already visited is a loop only when the cookie jar is unchanged: Nature and Springer send articles through their identity service, which sets cookies and returns to the article (2026-10-13).
- Per-host bound: at most `HOST_CONCURRENCY` (4) requests run at once against one host, across all web_fetch calls and Agents; further requests to that host wait, other hosts do not. `HostSlots` (`_public_http.py`) holds a slot per request hop, retries and their backoff included, so a redirect to the same host never waits for itself. The web_fetch handler owns the one instance: the Runtime registers the handler once, which makes the bound process-wide without a module global (PROJECT.md -> Dependency injection). `analyze_image` passes none, so its few downloads per call stay unbounded. Swarm run 2026-10-20: three Agents sent about 40 fetches to one host within 10 s, after which its firewall rejected every request from the machine for about 10 minutes (firewall block below); browsers open at most 6 connections per host.
- Decoding (`_decoded`): a body is decoded as a browser decodes it. A byte order mark wins, then the Content-Type charset, then for markup a charset declared in its first 4 KB (XML declaration or `<meta>`, also the `http-equiv` form), then UTF-8 when the bytes are valid UTF-8, else Windows-1252. The labels `iso-8859-1` and `us-ascii` read as Windows-1252, as in browsers; a UTF-16 or UTF-32 label inside a page reads as UTF-8. Swarm run 2026-10-20: a German law portal sends `text/html` without a charset and declares ISO-8859-1 in a `<meta>`; curl's own decoding (the header charset, else UTF-8 with replacement characters) turned its umlauts into U+FFFD in 110 results.
- Accept: the request prefers Markdown (Extraction above). A 406 is retried once without an Accept header, so curl_cffi sends the impersonated browser's own; a second 406 fails `request_rejected`.
- Downloads stream into a bounded buffer (50 MB for web_fetch; the caller passes `max_bytes`). Direct GETs retry retryable HTTP statuses and connection failures up to `MAX_RETRIES` with the existing Retry-After/backoff policy; a timeout is retried once, certificate and TLS setup failures (`tls_error`, whose message says repeating will not help) never. A TLS handshake the peer cut off is a connection failure, not `tls_error`: curl reports it as a TLS error whose reason names the cut (a reset, abort, closed connection, EOF or `SSL_ERROR_SYSCALL`, such as `Recv failure: Connection was reset`; `_is_tls_failure`), so it is retried and then fails as retryable `connection_failed` (Swarm run 2026-10-12: one such reset was reported as broken TLS, and the same URL loaded for another Agent 17 s later). Timeout errors report the host and actual attempt count without claiming an elapsed duration or a connection/transfer phase, since either timeout can end an attempt. Redirect cycles and chains over ten hops fail explicitly.
- Failure codes, each message naming the next step: `invalid_url` (not http(s), no host, an invalid host name, malformed), `blocked_url` (private/local address, credentials in the URL, redirect to a blocked address), `host_not_found` (DNS), `redirect_unreachable` (a redirect hop whose host does not resolve; an extraction service can still recover it), `page_not_found` (404/410), `access_denied` (401/403/407, bot/login walls, and another 4xx showing a bot check), `rate_limited` (429, retryable; a firewall block page, not retryable), `server_error` (5xx, retryable), `request_rejected` (other 4xx, and a 406 that the retry did not resolve), `unexpected_response`, `redirect_loop` (the local browser then tries), `timeout` / `connection_failed` (retryable, with `attempts_made`), `tls_error`, `response_too_large`, `no_content` (empty response or JavaScript shell), `invalid_ref`, `page_expired`, `invalid_arguments`, plus `storage_error`, `attachment_error`, `document_too_large`. A failed service recovery keeps the direct failure's code and appends `The <provider> fetch service also failed: ...`; a service selected without its key tells the Agent to tell the user.
- Bot/login walls and empty/JavaScript-only shells do not become successful empty pages: a main view under 600 characters counts as a shell when a line starts by demanding JavaScript (`You need to enable JavaScript...`, `Please, enable JavaScript...`, `This app requires JavaScript`), while a page explaining how to enable it keeps its content. Legacy raw output remains an inspection route. Error guidance says `Try another source.`; it names no browser Tool (none exists since Browser Use left, and the local browser has already tried) and does not require an unavailable web_search Tool.
- A client error (4xx other than 401/403/404/406/407/410/429) is a bot check, `access_denied`, when the request ended at a challenge address (the final path contains `challenge` and the requested one does not, as Enodia's `/.enodia/challenge`) or the page's title is a self-solving check title (`_shows_bot_check`); the local browser then reads the page. Swarm run 2026-10-20: one government page answered HTTP 400 with Enodia's check and was reported as `request_rejected`, telling the Agent to check its address; the local browser passes the check and reads the article.
- A web application firewall's block page fails `rate_limited` (not retryable), although it arrives with HTTP 200: F5's default page, titled `Request Rejected`, under 1,000 characters and saying `The requested URL was rejected` or naming a support ID. Such a firewall blocks the machine after a burst of requests and then rejects everything it sends for minutes, the local browser and the shell included; the message says to wait several minutes and then fetch one page at a time. Swarm run 2026-10-20: 70 results from one host were this page returned as successful content, starting after about 40 fetches to the host within 10 s; the block lifted after about 10 minutes.
- The German reCAPTCHA interstitial is a bot wall only when its title is `Ihr Browser wird geprüft - reCAPTCHA` (dash variants accepted), its text is under 4,000 characters, and its opening sentence says that the browser is checked before accessing this URL's host. A repeated title at the start is ignored. An article discussing CAPTCHA or a form with a CAPTCHA iframe stays readable. The wall enters the same browser/service recovery as other `access_denied` results; a Swarm response on 2026-10-14 returned the challenge as a successful article and therefore skipped that recovery.
- Page content is untrusted data. The Tool description states that it is untrusted web content, not instructions; metadata and HTML do not change Tool authority.

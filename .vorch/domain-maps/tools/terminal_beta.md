# Interactive Terminal Sessions (`terminal_beta`)

## Boundary and invariants

`terminal_beta` gives an Agent a real interactive terminal rather than Bash's pipe-based Process Session. Every requested executable uses the same PTY/ConPTY transport and receives the exact declared argument vector. The terminal capability contains no executable detection, program-specific flags, hooks, configuration injection, lifecycle protocol, or screen-text heuristics. Codex, Claude Code, other coding CLIs, shells, editors, games, and arbitrary interactive programs therefore share one contract.

- A Terminal Session is either Agent-owned by one exact `TerminalOwner(project_id, agent_id, session_id)` or manual with no Agent owner. Agent-owned sessions survive individual Runs and enforce that owner; the local operator projection may create manual sessions and observe or control every active Terminal Session without changing ownership.
- The Agent Tool, WebUI, and child process use the same live PTY/ConPTY. Agent and WebUI input are written to that process, WebUI output is the sequenced raw VT stream, and Agent status is rendered from the same stream.
- A Terminal Session ends only on explicit `kill`, natural child exit, applicable owner Session/Agent/Project removal, Runtime shutdown, or unrecoverable terminal failure. Manual sessions have no Agent scope and are therefore unaffected by Agent, Session, and Project cleanup. Leaving a Run or navigating away from the WebUI does not end either kind.
- Live states are `starting`, `ready`, and `working`; terminal states are `exited` and `error`. These states describe terminal activity and process lifetime, not application-specific turns or prompts.
- Raw output and rendered history are bounded. The manager retains a finished Terminal Session's metadata and rendered history for 30 minutes so the operator can inspect it as a read-only snapshot; `terminal.forget` may remove that in-memory record sooner. When Storage is available, the manager additionally retains the raw output in a leased `<data_dir>/artifacts/temp/terminals/*.log` and starts the normal temporary-file retention clock after the Terminal Session ends.

## Agent Tool contract

`core/tools/terminal_beta.py` exposes one open flat action schema and performs action-specific accepted-field and semantic validation. `start` defaults to command `codex`, no arguments, the current working directory, 120 columns, and 32 rows; this is only a convenience default and does not select a different launch path. Its existing `workdir` string accepts ordinary absolute and relative filesystem paths plus the reserved exact prefix `project:<project-id>`, which resolves the registered Project's live `cwd` by stable id before spawn. The Project reference changes only the child start directory: it does not load Project Context, change Rooting, or reassign Terminal ownership, and a spawned process does not move if the Project is later re-pointed. A missing Project returns `project_not_found`; an invalid/unreadable Project record or unreachable Project `cwd` returns `project_unavailable`; all fail before process creation.

- `start`: launches exact `[command, *args]`; optional `text` waits for a stable initial TUI screen and then sends text followed by Enter. The result explains that the Terminal Session survives the Run and that output settling is not a semantic completion signal.
- `list`: returns compact retained Terminal Session summaries for the current owner, including the bounded title announced through the standard terminal protocol when present. Its Tool row derives an exact presentation-only `results` count from `terminals`; other actions and failures publish no count.
- `status`: returns the current rendered screen, up to 30 prior scrollback lines by default, at most 100 lines, an opaque signed cursor for older pages, process facts, dimensions, screen/activity revisions, the bounded program-announced title, and the raw-log path when available. Model-facing `workdir` and raw-log paths use the shared forward-slash presentation while spawn and manager state retain native paths. A cursor fixes Terminal Session and exclusive line boundary; optional `lines` independently selects the continuation page size within the same 1–100 bound. When older output remains, `scrollback.next_request` is a complete copy-ready `status` request carrying the signed cursor and current page size; callers should follow it until null rather than reading the raw VT log as ordinary rendered output.
- `wait`: waits at most 1,000 ms by default and 10,000 ms maximum for a newer generic activity revision, exit, or error. A timeout is a successful current snapshot with `timed_out=true`; it never owns or pauses the child.
- `input`: accepts either exact non-empty `data`, written unchanged in one PTY write, or the convenience combination of non-empty `text`, one named `key`, and `enter`. `data` cannot be combined with the convenience fields. Named keys cover navigation, Insert/Delete/Home/End/Page Up/Page Down, Shift-Tab, F1-F12, and Ctrl-A through Ctrl-Z; arbitrary sequences use `data`. Optional `expected_screen_revision` rejects stale input.
- `resize`: validates conservative bounds, resizes the host PTY/ConPTY and renderer together, and returns the new dimensions and screen revision.
- `kill`: terminates the complete child process tree, suppresses an automatic exit delivery caused by that explicit action, and leaves a bounded exited snapshot until finished-session expiry.

## Generic activity delivery

Generic terminal bytes cannot reliably distinguish a question, approval request, completed application-level task, idle animation, or prompt. `TerminalManager` therefore emits only `output_settled`, `exited`, and `error` attention kinds and never claims application semantics.

- Agent input starts one activity cycle, changes state to `working`, records the current Run as delivery origin, and arms a two-second quiet timer. Every later PTY output restarts that timer. When the stream stays quiet, state becomes `ready`, a monotonically revisioned `output_settled` record is created, and `TriggerService.submit_completion` wakes the owning vBot Session. The notification explicitly requires the Agent to inspect `status` and says that quiet output does not imply completion or a need for input.
- Operator input and spontaneous output use the same state and quiet detection, but do not independently request an automatic Agent wakeup. A manual Terminal Session has no Agent delivery target at all. Settled revisions remain observable through `wait` for an Agent-owned session.
- Natural exit and terminal failure create `exited` or `error` attention and request delivery. Explicit kill and scope shutdown suppress that delivery.
- `status`, `wait`, `input`, and `kill` acknowledge an equivalent pending delivery only through `ToolContext.after_result_persisted`; handler return alone is not durable acknowledgement. Scope transfer reroutes a pending delivery to the new owner.

## Transport, rendering, and local operator surface

`core/tools/terminal_manager.py` is the deep owner of Terminal Session identity, authorization, lifecycle, activity timing, attention delivery, retained output, stream sequencing, and cleanup. `core/tools/terminal_backend.py` hides the blocking platform adapter, VT renderer, alternate-screen handling, Windows launcher adaptation, and process-tree termination. Blocking adapter operations run through `asyncio.to_thread`.

- Windows uses `pywinpty`/ConPTY and POSIX uses `ptyprocess`/PTY. On Windows, resolved `.cmd` or `.bat` launchers use the platform command processor as a generic executable-format adapter; no command name receives special handling. Windows terminal descendants inherit the server's kill-on-close Job Object. POSIX PTY children run their exact declared command through the same parent-liveness guardian as Process Manager, inside the PTY process group, so abrupt server death kills the terminal tree even though Runtime shutdown cannot run.
- An omitted manual command selects an interactive host shell without changing the PTY path. Windows prefers PowerShell 7 (`pwsh.exe`), then Windows PowerShell (`powershell.exe`), and falls back to `%COMSPEC%`/`cmd.exe`; POSIX prefers `$SHELL`, then the account login shell, and finally `/bin/sh`.
- `pyte` owns bounded terminal rendering. The renderer preserves a separate primary and alternate screen, resizes both buffers, restores the primary screen on alternate-screen exit, serializes the retained primary-screen scrollback followed by the current active screen into one authoritative ANSI snapshot for late WebUI viewers, and exposes OSC title/icon metadata as one whitespace-normalized, single-line title capped at 160 characters. Title extraction is terminal-protocol behavior; the manager does not inspect process trees or add program-specific hooks.
- The manager publishes an authoritative ANSI history-and-screen snapshot followed by contiguous sequenced output/state events. A title change publishes a state event and catalog invalidation even for a non-selected background Terminal Session; finished-session expiry publishes the same invalidation. `server/rpc/terminal_methods.py` maps operator start/list/input/resize/kill/forget and `/ws/terminals/{terminal_id}` carries the selected live stream or one retained finished snapshot. `terminal.start` accepts an optional command, exact argument list, working directory, and dimensions; omitted command and working directory select the host user's default shell and home directory through the same generic launch path and return `owner: null`.
- `webui/src/lib/terminalsView.js` owns manual start, retained-catalog reconciliation, stream reconnect and gap recovery, exact xterm input batching, resize debounce, and teardown. `TerminalsView.svelte` dynamically mounts xterm.js, offers a New terminal dialog, starts manual terminals in focused direct-control mode, defaults live Agent-owned terminals to observe mode, makes a primary click on a live terminal take control and focus native xterm keyboard/paste input, rebuilds bounded scrollback from every authoritative snapshot after mount, selection, reconnect, or navigation, and confirms process-tree stop. Finished Terminal Sessions remain selectable as read-only history until manager expiry. The Secondary list and detail heading prefer the program-announced title; before one exists they humanize known default shell executable names while retaining the exact command in detail metadata. There is no secondary text composer or program-specific input path. Navigation and socket teardown never own the Terminal Session lifetime.

## Runtime and lifecycle integration

Runtime constructs `TerminalManager` after `TriggerService`, registers `terminal_beta` before System Prompt assembly, exposes it through `RuntimeServices`, and closes it before temporary-file cleanup. Run cancellation never closes Terminal Sessions. Session deletion, Agent removal, Project removal, and successful `/agent` moves close or transfer exact Agent-owned Terminal scopes inside their existing lifecycle boundaries; manual Terminal Sessions end only through explicit stop, natural exit, terminal failure, Runtime shutdown, or the server-level crash boundary. No Terminal Session or retained catalog survives a Runtime restart, and its OS process tree cannot survive separately. Ended sessions remain in the in-memory retained catalog until the 30-minute expiry or explicit operator forget. `terminal_beta` is an ordinary built-in Tool and is part of the default Project Tool allowlist. The bundled `coding-agents` Skill is the program-agnostic operating playbook for Codex, Claude Code, OpenCode, and future interactive coding-agent CLIs: it starts or reuses normal TUI commands through `terminal_beta`, handles questions and approvals against the current screen revision, and preserves the live `terminal_id` across Runs instead of requiring binary-specific headless modes.

Focused coverage lives in `tests/core/tools/test_terminal_backend.py`, `test_terminal_manager.py`, and `test_terminal_beta.py`, with Runtime, lifecycle, RPC, WebSocket, controller, rendered-component, and bundled-Skill contract coverage in their owning test trees. `tests/e2e/tests/terminal-lifecycle.spec.js` exercises the platform default shell and multiple simultaneous real PTY/ConPTY processes through browser start, native input, foreground and background title changes, background output, selection changes, stream reconstruction, navigation, and selective stop. Real Windows validation must use actual ConPTY programs and an unmodified installed Codex CLI because fake adapters cannot prove executable launch fidelity, alternate-screen rendering, browser keyboard/paste behavior, resize, or process-tree stop.

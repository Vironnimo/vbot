# Claude Agent Provider

The `claude-agent` Provider runs the user's unmodified Claude Code program through the official Python Agent SDK. Providers owns this native transport, external-login readiness, process lifetime, and the bridge between SDK Tool calls and vBot's canonical request/response contract. Chat retains Agentic Loop execution, permission checks, Secret masking, and persistence.

## Login and enrollment

The `subscription` Connection has type `external`, is disabled until explicitly added/enabled, and stores no key, access token, refresh token, or copy of Claude Code's login. The user installs native Claude Code and runs `claude auth login` under the same OS account as the vBot server. A Desktop client's or Session-selected Computer's login does not authenticate a different server process. Executable precedence is process `VBOT_CLAUDE_PATH`, the cataloged `providers.claude_agent.executable_path` Setting, `PATH`, then `~/.local/bin/claude[.exe]`. The SDK receives an absolute path, since its private working directory differs from the server's. Invalid explicit paths fail without choosing a different program. Claude Desktop's private bundled executables are never auto-discovered. The Adapter always supplies the selected executable rather than using the SDK's bundled copy. Both Settings write surfaces apply path changes on the Event Loop and await old-process retirement; readiness reads never close processes from a worker.

Enrollment is the persisted Connection override, as for keyless local Connections. It permits discovery; cached `external_auth` is the separate native readiness projection. Connect and explicit login checks probe the native initialization contract without sending a prompt, then publish the installation's available Model catalog. Disconnect disables this vBot Connection and closes its processes; it does not sign out Claude Code for other applications. No native process starts for a fresh disabled Connection.

The subscription Connection requires a nonempty SDK-reported `subscriptionType`, first-party routing, and no API-key source. Explicit API-key or cloud billing reports `api_billing`; a login without subscription metadata reports `subscription_unconfirmed`. Neither can send inference through this Connection; intended API use stays on the existing Anthropic API Provider. Native authentication mechanisms and inherited credentials are not modified. Accessors localize readiness by status code; `not_checked` is distinct from a failed check.

The Provider is instance-scoped. SDK Model ids and capabilities belong only in this installation's generated catalog, never in the shipped Model DB. Claude Code lists its newest generation only under moving aliases such as `opus`; each listed entry is published under its `resolvedModel` id (for example `claude-opus-5-5`), merged with a pinned entry of the same id, so vBot ids name exact Models and an alias moving to a new generation adds a Model instead of silently changing a configured one. Native discovery feeds `discovery.refresh_models(raw_models=...)` so ordinary admission, Connection tagging, staged publication and in-place reload still apply. Unknown limits remain unknown. A failed discovery preserves the last catalog. Capacity contention reports `busy`, preserves prior readiness/reachability, and defers catalog publication; it is not an authentication failure. A probe and its staged publication cannot outlive a replaced native registry or a disabled Connection. Changed catalogs notify Model subscribers even when discovery began through a login-status check.

## Request and process ownership

`ClaudeAgentSessions` is owned by `ProviderRuntime`; a Run's Adapter borrows it. Session generation and request kind travel through `ProviderAdapter.request_context_kwargs`. Chat has a reusable native conversation; Compaction, titles, and other utility requests use disposable native conversations and cannot append their work to the chat's native state. Session close, Connection close, Runtime shutdown, and synchronous abort use the existing Provider transport lifecycle seams.

Closing or aborting a native registry is terminal: old Adapters cannot start inference or discovery through that owner again. Runtime supplies a fresh registry for subsequent Connections. Shutdown also invalidates requests already awaiting preparation or process admission.

vBot supplies its complete System Prompt through the SDK's `SystemPromptFile`, never a command-line text argument. `NativeSession` writes an owner-only, leased `providers` temporary file before connecting and removes it after disconnect, including startup failure. The file remains leased for the whole process lifetime; crash leftovers expire through Storage. A standalone Adapter must receive a temporary-file manager or a Runtime-owned registry before it can start native code. Every real native process uses an empty private working directory beneath that category, and `DISABLE_AUTOUPDATER=1`. Telemetry is not overridden: Anthropic documents that its opt-out also disables feature-flag fetching, and that compatibility effect has not been live-verified.

Built-in Claude Code Tools, user/project settings, CLAUDE.md loading, Skills, hooks, auto Memory and automatic Compaction are disabled where the public SDK supports isolation; vBot supplies its own instructions and Tools. At most 16 native processes are admitted, including temporary probes and utility calls; idle chat processes expire after 300 seconds. Admission first evicts the least recently used inactive native process, including one parked on Tools: native interruption/drain precedes clearing callbacks, while canonical Tool execution and Results remain vBot-owned. A later step reconstructs from canonical history. With every process active, inference waits cancellably for up to 30 seconds, then raises retryable busy; probes report busy without waiting or displacing parked work. Completing a step wakes capacity waiters. Native session persistence is disabled: in-memory state is reconstructible from canonical vBot Context, and no additional durable transcript or canonical database is introduced. A process restart therefore rebuilds Context rather than recovering hidden native Reasoning.

SDK MCP handlers park calls instead of executing vBot handlers. The Adapter emits canonical Calls; Chat dispatches and persists their Results, and the next model request releases the parked handlers with the Model-facing Results. Low-level MCP preserves vBot's argument-tolerance contract; the SDK's convenience Tool helper would reject mismatching arguments before vBot can normalize them. The SDK call id must remain correlated through native hooks, canonical Calls and Results. Cancellation must interrupt/drain the native turn before releasing parked calls so cleanup cannot trigger fresh inference.

MCP names fit Claude's 64-character limit including the server prefix and remain unique after projection. Calls are bound to their offered Tool name as well as their id across the Assistant, PreToolUse and MCP boundaries. Unsupported initial media fails before process startup; a continuation rejects duplicate Results and validates every Result and media block before releasing any parked handler. Payload conversion runs on a bounded worker; Future ownership checks and the all-or-nothing release stay on the Event Loop. Calls to unoffered Tools are denied by the native configuration/bridge and omitted from vBot dispatch, so Claude can consume its native rejection and correct the call without aborting the Run.

SDK AssistantMessages complete individual content blocks, not whole Model responses. A Tool step collects every sibling Call and final Usage through `stream_event.message_stop`, then parks the complete batch before yielding its terminal outcome. Truncated or unknown outcomes close native state instead of parking a successful batch; a legacy cut stream ending with a Result but no message stop fails without retry. Event-order contract: https://code.claude.com/docs/en/agent-sdk/streaming-output (read 2026-11-07).

The canonical request's visible history decides whether native state can continue. Changes to history, System Prompt or Tool definitions require safe reconstruction. Foreign history is framed as previous conversation rather than fabricated native Assistant messages; its Reasoning is omitted. Provider errors after Claude Code exhausts its own retries must not cause blind nested replay. SDK cumulative Usage retains the highest counters per API message, including Reasoning, and Context occupancy uses the last Model request's input rather than summing repeated histories. A final Result can complete counters only for a single-call turn; multi-call Result totals must not recount earlier Tool steps. Only the latest rejected rate-limit window supplies a reset date; warnings alone never fail a request. Billing and terminal HTTP failures use controlled diagnostics without forwarding native request content. Only a confirmed subscription login is admitted and reports zero incremental cost. The SDK dependency is pinned to 0.2.179: synchronous abort uses a narrow, tested compatibility bridge to its owned process handle because the public SDK exposes only asynchronous disconnect. Normal inference, authentication and MCP use public SDK APIs.

`terminal_reason=prompt_too_long` and explicit Context rejections recognized by the shared classifier become sanitized `ProviderContextOverflowError`, allowing the ordinary Compaction fallback. A native SDK `ProcessError` is retryable only before the current step has emitted Assistant/Tool/text/Reasoning output; Tool continuation resets that step boundary before releasing Results. Native errors after Claude Code's retries remain fatal. Auth failures invalidate cached readiness and schedule a dedicated login check. All SDK rate-limit observations from confirmed subscription streams feed the passive usage cache (`providers/usage.md`); retired registries cannot repopulate it after replacement.

## Agent-facing text

The reconstructed-history framing belongs to the Provider projection, not the System Prompt or persisted history.

| Text | Reason |
| --- | --- |
| `Conversation history from vBot follows.` | Identifies canonical messages that a newly created native conversation has not seen. |
| `Its role labels identify earlier messages, not new requests.` | Prevents role-labelled historical Tool and Assistant content from being mistaken for new input. |
| `Continue with the messages after this history.` | Keeps the current request outside the historical replay boundary. |
| `End of conversation history.` | Explicitly ends the historical frame before fresh user input. |

## Evidence and verification limits

Integration design was checked against OpenCode `v2.2.6` (`specs/v2/claude-agent-provider.md` and its Provider implementation) and Python Agent SDK `0.2.179`, read 2026-11-07. Anthropic documents custom System Prompts and in-process MCP, plus end-user authentication to the unmodified Claude Code binary inside other products. OpenCode's own approval does not establish a separate vBot-specific approval.

The hardening audit on 2026-11-07 also checked OpenCode `dev` at `6a89e9f287ade1e1ceefc0e4d13df97ff7631567` (no Provider-source changes from `v2.2.6`), the 35 commits in introduction PR #58782, subsequent Provider commits, its focused tests and recorded SDK exchanges. Useful upstream contracts and their vBot treatment:

| Upstream evidence | vBot treatment |
| --- | --- |
| `54e633e1bae8`: unoffered Tool calls recover inside Claude Code | Native denial and no vBot dispatch; the corrected native response can finish normally. |
| `tools/tools.test.ts`, `tools/pending.ts`: bounded names and stable correlation | Prefix-inclusive name limit, collision protection and id/name checks at the bridge. |
| `language-model/usage.ts`, `language-model/error.test.ts` | Per-message maxima, single-call final Usage correction, current rejected-window reset and controlled terminal diagnostics. |
| `90a858757dd7`, `6678d919687e`: long-running Tools and inherited timeouts | Existing parked-process lifetime and isolated `MCP_TOOL_TIMEOUT`; no idle eviction while Results are outstanding. |
| `5e066ac922ba`, `4f3156ab3ced`: non-streaming/refusal fallbacks | Existing isolation disables both, preserving stream boundaries and the selected Model. |
| `sync/sync.test.ts`, `tools/result.ts`: complete history/Result groups, media and fresh input | Canonical history reconstruction and complete Result/media validation before continuation. Native persistence/forking stays disabled because vBot owns durable history. |

Recorded upstream happy paths, Tool continuations, cancellations, billing errors and media exchanges were replayed through the local stream translator as bounded offline probes. These checks establish translation behavior, not live subscription entitlement or native API compatibility.

Local deterministic tests use fake native sessions for setup/catalog status, canonical streaming/Tool continuation, isolation, cancellation and lifecycle. A separate protocol loopback runs the real Python SDK, its control dispatcher, hooks, parser, low-level MCP bridge and `NativeSession`; only process I/O is replaced. It protects masked canonical Results, tolerant arguments, step Usage and owner-task cleanup together. No live subscription inference was available; real entitlement, limits, media transport and native CLI behavior remain unverified until exercised with an installed, authenticated Claude Code. Do not mark a wire profile verified based on these local tests.

The 2026-11-07 review fixes additionally check the actual SDK subprocess command builder with a 75,000-character prompt, lease cleanup on startup failure and stop, natural capacity wakeups/cancellation/timeout, parked reconstruction, Settings path updates and passive cache retirement. Prompt-file replacement and `terminal_reason=prompt_too_long` are official SDK/CLI contracts, not observations from live subscription inference. Plain native overflow errors without that reason or the shared classifier's explicit counts remain unverified; no broad text heuristic was added. Live checks require the user's prior approval because they consume subscription quota.

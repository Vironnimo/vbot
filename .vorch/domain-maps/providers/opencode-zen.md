# OpenCode Zen Provider

OpenCode Zen is a hosted gateway whose one Model namespace spans OpenAI Responses, Anthropic Messages, OpenAI Chat Completions, and native Gemini `generateContent`; the models.dev catalog protocol hint and its wire profile `resources/wire/opencode-zen.json` decide the exact per-Model routing and admission, and `OpenCodeZenAdapter` dispatches on the resolved profile.

## Interfaces

- Provider config: `resources/providers/opencode-zen.json`
- Adapter selector and owner: `opencode_zen` / `core/providers/opencode_zen.py::OpenCodeZenAdapter`
- Wire profile: `resources/wire/opencode-zen.json` (per-Model protocol and admission, reasoning, optional parameters, media, prompt cache)
- Connections: `opencode-zen:api-key` and `opencode-zen:account`
- Discovery: public `GET https://opencode.ai/zen/v1/models`, normalized by `OpenCodeZenAdapter` and enriched from the models.dev `opencode` section, including the protocol hint `metadata.opencode_zen.npm`
- Generated projection: `resources/models/opencode-zen.json`

## Connections and Authentication

- `api-key` reads the shared OpenCode credential `OPENCODE_API_KEY` (also used by Go, including named Account suffixes); it never infers Connection type from credential text. The default request auth is `Authorization: Bearer`, while the Adapter replaces it with the exact header required by Messages (`x-api-key`) or Gemini (`x-goog-api-key`).
- `account` uses OpenCode's current JSON Device Flow at `https://opencode.ai/console/auth/device/code` and `https://opencode.ai/console/auth/device/token` with client id `opencode-cli`, as the official client uses since the console moved from `console.opencode.ai` (which now redirects there). The authorization answer carries a relative `verification_uri_complete` (`/console/device?user_code=...`); like the official client, vBot appends it to the server URL, giving `https://opencode.ai/console/console/device?...`. Observed and confirmed against the official client on 2026-10-08; a full login through the new host is not yet live-verified. Polling accepts the standard `authorization_pending` response, and refresh POSTs JSON and persists the rotated access/refresh pair. A definite refresh rejection (`invalid_grant`) quarantines the rotating token chain; server errors, other auth failures and ambiguous transport failures keep it and are not replayed automatically (`providers/connections.md`).
- Both Connections expose the same public Zen catalog and base URL. Both declare `catalog_requires_credentials: false`, so a refresh reconciles their projections even without an OAuth token; inference still requires credentials and enablement. Account identity changes only the credential slot and never the Model id, endpoint family, or catalog policy. Requests identify this client with `User-Agent: vBot`.

## Exact Model Routing

- Each Model's protocol (`chat_completions`, `messages`, `responses`, or `gemini`) and admission are wire-profile data. The catalog protocol hint `metadata.opencode_zen.npm` (`providers.md`) routes every Model the models.dev `opencode` entry names a package for (`@ai-sdk/anthropic` -> Messages, `@ai-sdk/openai` -> Responses, `@ai-sdk/google` -> Gemini; on 2026-10-02 all listed Claude, GPT, Grok, Muse Spark and Gemini Models plus `qwen3.5-plus`, `qwen3.6-plus` and `qwen3.8-flash`), and the first rule in `resources/wire/opencode-zen.json` admits such a Model (`when.npm`). The reviewed Chat Models carry no package (a missing package is no evidence for Chat), so a rule lists their ids with `protocol: chat_completions` and `admission: available`. Free Models are `restricted` with the `FreeTierError` explanation - generically every `-free` id plus `big-pickle`, ordered after the hint rule so a hint never admits a free Model, and before the Chat rule that re-admits `space-bunny-free` - and the retired ids `retired`; the file default refuses every other id (`restricted`, "This OpenCode Zen Model has no reviewed wire protocol in vBot; choose a listed OpenCode Zen Model."). `send`, `stream`, response normalization, media support, and the request body limit read the resolved profile; an unadmitted Model is refused before network I/O with `Model '<id>' is <state> on this Connection: <admission message>` (`ProviderAdapter._refuse_unadmitted_model`), and discovery does not write it (`providers/catalog-discovery.md`). Replay scope separately follows the shared Model -> Provider -> system hierarchy. Unknown or vendor-prefixed ids fail locally; vBot never guesses by prefix, silently aliases an id, or falls back to another Model. Model data names no wire: discovery no longer stamps `metadata.opencode_zen.protocol` (removed from the bundled catalog on 2026-10-02).
- Responses Models use `POST /responses` through the deep `OpenAIAdapter`; the Provider override hook classifies Zen errors on both non-streaming and streaming Responses paths.
- Messages Models use `POST /messages` through a borrowed `AnthropicCompatibleAdapter`, `x-api-key`, `anthropic-version: 2023-06-01`, non-strict Tool schemas, PDF/images, prompt-caching breakpoints (the Messages protocol's `request.prompt_cache`), only `temperature` when a request carries `temperature` and `top_p` (the Messages protocol's `request.exclusive_parameters`; Claude Haiku 4.5 rejected both, live 2026-10-03), and the outer connection-scoped HTTP client/token getter and wire-profile binding (`bind_wire_profiles` forwards it, so facts learned on the inner wire resolve into the same Connection profile).
- Chat Models use `POST /chat/completions` through `OpenAICompatibleAdapter` with bearer auth and the shared Tool, usage, terminal-outcome, and SSE contracts.
- Gemini Models use `POST /models/{model}:generateContent` and `POST /models/{model}:streamGenerateContent?alt=sse`. The Provider Adapter owns native `systemInstruction`, `contents`, `generationConfig`, Function declarations/calls/responses, inline media, usage, finish reasons, and opaque thought-signature replay. Gemini's JSON omits zero counters: `thoughtsTokenCount` counts separately from `candidatesTokenCount`, so either one makes the output (a turn that only thought reports no candidates), and with a reported `promptTokenCount` a missing `cachedContentTokenCount` is a measured cache miss (`cache_read_tokens: 0`).

OpenCode's gateway may fail over between upstream suppliers serving the same requested Model. That is same-Model infrastructure routing, not a vBot alias or cheaper-Model fallback, and vBot must continue sending the exact selected id.

## Catalog Policy

- The public endpoint returns ids but no endpoint family or trustworthy capability/limit detail. Refresh therefore fills context/output limits, modalities, family, Tool support, reasoning controls, and the protocol hint from the exact models.dev `opencode` entry and then writes only the ids the wire profile admits. A new listed Model whose models.dev entry names a known package is routed and admitted without a wire-file change (`test_opencode_zen_writes_admitted_models_and_merges_connections`); a new Model without a package stays unadmitted until a rule assigns a reviewed route. A refresh without models.dev writes no hint, so it drops every hint-routed Model from the written catalog (48 of the 63 on 2026-10-02) until a refresh with models.dev.
- Retired Models carry `retired` admission, so discovery and runtime refuse them even with a protocol hint, and are repeated in `catalog_exclusions`. This includes the retired Codex variants, `claude-sonnet-4`, `glm-5`, and the 2026-08-05 retirements `claude-opus-4-1`, `minimax-m2.5`, and `kimi-k2.5`. Stored selections are never silently retargeted.
- Restricted free Models, including historical promotions and the current LongCat/MiMo/Nemotron/Muse/Ling ids, remain in the public catalog response but are excluded from the usable projection; a new `-free` id is restricted by the suffix rule even when models.dev gives it a package (the Muse Spark contributor free ids carry `@ai-sdk/openai`). `space-bunny-free` is admitted after the live access check above. Runtime rejects stale selections of the restricted free Models before network I/O. `FreeTierError` is fatal access denial, never an authentication failure or a reason to renew a token. Tests cover both error name/type shapes on all four wires in streaming and non-streaming mode.
- The 2026-09-22 endpoint reconciliation adds GPT 6 Astra, Claude Fable 5.1, Gemini 3.7/3.8 Flash, Grok 4.6/4.7, Muse Spark 1.2/1.3, Qwen3.8 Flash, DeepSeek V4.1 Flash/vision-exp, and GLM 5.3/Flash. The later catalog refresh also advertises `gpt-6-sol`, `gpt-6-luna`, and `claude-opus-5-5`. They are selectable on both Zen Connections: the models.dev `opencode` entries identify the GPT-6 pair with `@ai-sdk/openai` and Claude Opus 5.5 with `@ai-sdk/anthropic`, and since 2026-10-03 that protocol hint (formerly explicit wire rules) assigns the existing Responses and Messages wires respectively. The published Zen endpoint table has not yet named these exact routes. Jev's `/systemone` structured-decision API is outside the chat Adapter and explicitly excluded. `test_models_resources.py` reconciles every raw id against the usable catalog and exclusions and checks both Connection projections; unknown routes cannot silently inherit Chat Completions.

## Reasoning, Replay, and Prompt Caching

- Responses, Messages, Chat, and Gemini inherit the shared `full_history` replay default unless a wire-file rule narrows it; GPT-6.1 Sol pins `none` after the accounting checks above. `space-bunny-free` on Chat maps an Agent `none` selection to its verified lowest `low` effort; `qwen3.8-max` instead uses its verified binary `thinking.type` control. Both preserve readable `reasoning_content` in history. Gemini renders through the `gemini_thinking` dialect: the Model's exact models.dev effort ladder (else the protocol floor `minimal..high`), the closest supported level as `thinkingLevel`, Agent `none` as the lowest level (`off: "lowest"`), and visible thoughts (`includeThoughts`) because Google requires opaque `thoughtSignature` parts to accompany later turns and Function responses. Replay scope is never Model data; a legacy `reasoning_replay` key in an older generated snapshot or override is an unknown field that load ignores.
- Gemini normalization persists the complete native parts in `reasoning_meta.gemini_parts`; replay sends those parts unchanged so signatures are not reconstructed or lost, except that the text of a part without a `thoughtSignature` has look-alike System Reminder tags neutralized (`chat/request-building.md`). Streaming emits progressively complete reasoning metadata before the terminal outcome. Id-less Function Calls use the response-wide native-part position for fallback identity, so separate chunks cannot collapse parallel Calls; explicit Provider ids and replay parts remain unchanged. A prompt-feedback block without candidates is a terminal `content_filtered` outcome in both response modes. A stream without either a Gemini `finishReason` or a prompt block is an unknown transport outcome and fails rather than inventing success. Encoded Function arguments retain their original string through streaming accumulation so completed and streamed responses apply the same canonical validation and recovery; native replay parts remain unchanged.
- The Messages protocol enables explicit compatible cache breakpoints (`request.prompt_cache: anthropic_breakpoints`). Responses and Chat retain their shared automatic-cache accounting. Gemini preserves `promptTokenCount` as total `input_tokens`, including the cached subset, and reports `cachedContentTokenCount` as `cache_read_tokens`; vBot does not invent a `cachedContent` resource or claim cache creation when Zen returned none. Missing or invalid Gemini primary counters remain absent so Chat can estimate them independently; explicit zero cache/Reasoning counters remain reported. Live cache effectiveness remains Provider/upstream-dependent. Cache-total, partial-counter, and cross-chunk id-less Call normalization are regression-tested in `test_opencode_zen_gemini.py`; the frequency of id-less Gemini chunks on live Zen remains unverified.

## Limits, Sampling, Tools, and Media

- Local Context estimation dispatches on the same resolved protocol as send and stream: Messages delegates to the inner codec, Responses/Chat use their inherited codecs, and Gemini counts native `contents`, `systemInstruction` and Function declarations. `_opencode_zen_gemini.py::gemini_input_payload` renders Gemini input for both estimation and sending, including media validation and Tool Result fallbacks. The shared token estimator reserves inline media and opaque thought signatures instead of counting encoded transport bytes as prose. Audio (WAV/OGG), video (MP4), and whole-request byte rejection are covered in both request modes by `test_opencode_zen_gemini.py`; these local regressions establish no new live gateway capability claim.
- Request output is clamped to the selected Model's catalog ceiling and remaining context. Gemini accepts exactly one effective output field and emits native `maxOutputTokens`; duplicate aliases collapse to the smallest valid value.
- Gemini validates `temperature` 0-2, `top_p` 0-1, positive integer `top_k`, penalties -2-2, integer seed, stop strings, supported JSON response formats, and Tool choice locally. Unknown request fields fail locally instead of leaking OpenAI-only parameters onto the Google wire. `parallel_tool_calls` is intentionally omitted because native Gemini controls parallel Function Calls without that OpenAI flag.
- Gemini supports inline PNG/JPEG/WEBP/HEIC/HEIF images, documented audio/video types, and PDF. Google's 20 MB inline request limit is the Gemini protocol's `media.request_max_bytes` (20,000,000), enforced before network I/O through `request_body_limit`; the Adapter enforces the 3,600-image maximum. The protocols' `media.types` declare the wire ceilings: Responses/Chat only their established image types, Messages images and PDF. Catalog modalities still intersect these wire ceilings at Chat ingress.
- All four wires preserve canonical non-strict Tool schemas and normalize Tool Calls, usage, and one terminal outcome. Gemini maps STOP, MAX_TOKENS, safety/content blocks, malformed/unexpected Tool Calls, and unknown reasons without treating every transport completion as successful generation. A malformed non-string `finishReason` becomes canonical `unknown` while preserving correlated Tool attempts for rejection.

## Errors, Regions, and Privacy

- Zen `AuthError` is reconnectable authentication failure. `CreditsError`, `MonthlyLimitError`, `UserLimitError`, and `ModelError` are fatal account/entitlement/Model-access failures even though Zen returns HTTP 401 for them. `RegionError` and `FreeTierError` are fatal HTTP 403 access failures. The latter preserves the status and explains that a replacement key cannot enable another client.
- All four account-authenticated wires use the shared OAuth recovery in `providers/connections.md`. The Messages error-detail hook preserves the complete error body so an error `name` or `type` survives even without a human-readable message; otherwise an entitlement 401 could incorrectly trigger token renewal. `test_opencode_zen.py` verifies the entitlement codes across all four wires and both request modes.
- After the Zen-specific checks, the Messages route keeps its Anthropic-compatible HTTP 529 `overloaded_error` retry; the other three wires use the shared status policy without 529 (`test_zen_error_policy_separates_auth_region_allowance_and_retryable_failures`).
- Gemini in-band error payloads remain fatal regardless of JSON shape, including errors arriving after a candidate finish; a prior `STOP` cannot hide a later explicit error.
- Gemini stream establishment uses the shared connector in `_http_shared.py`; an error-body read failure or cancellation closes the rejected response before propagating, with the shared transport-error classification.
- All four wires, send and stream, run through the shared rejection learning (`providers/request-policy.md` -> HTTP, retry, and streaming). On Gemini a sampling rejection is attributed under `generationConfig` (`temperature`/`topP`/`topK`) and an effort rejection by the `thinkingLevel` field name (also spelled `thinking_level`); the request applies the profile's parameter rules, configured or learned, before the sampling parameters move into `generationConfig`.
- Stable allowance exhaustion markers such as `FreeUsageLimitError`, `GoUsageLimitError`, `BlackUsageLimitError`, monthly/weekly usage limits, and quota exhaustion make HTTP 429 fatal. A genuine burst `RateLimitError` remains retryable and honors `Retry-After` through the shared bounded retry policy.
- OpenCode documents Zen hosting in the United States. Standard paid requests are described as zero-retention except that OpenAI- and Anthropic-routed requests may be retained for 30 days; free Models permit data collection. Treat these as product/privacy constraints, not Adapter behavior, and re-check them before making deployment or compliance promises.

## Constraints & Gotchas

- Do not replace this composite Adapter with a generic OpenAI-compatible JSON entry: header selection, protocol dispatch, Gemini translation/signature replay, terminal outcomes, and Zen error semantics are genuine Adapter code. Per-Model routing, admission, reasoning controls, parameters, media, and caching belong in `resources/wire/opencode-zen.json` (routing also in the projected catalog protocol hint), not in Adapter tables or hand-written Model metadata.
- Do not inherit OpenAI Codex discovery query parameters or ChatGPT account headers merely because the outer Adapter extends `OpenAIAdapter`; the inherited hooks apply them only to a `codex_responses` Connection, and Zen overrides `accepts_discovered_model` to keep every entry instead of the OpenAI Platform's embedding-only filter.
- The public catalog proves presence, not entitlement, regional availability, Tool correctness, caching, or successful inference. Regression tests use mocked provider responses; the dated live checks above cover authentication, route establishment, and free-tier rejection only.

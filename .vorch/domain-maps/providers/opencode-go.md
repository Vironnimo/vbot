# OpenCode Go Provider

OpenAI-compatible gateway with per-Model protocol/request profiles across **three wires** (`/chat/completions`, Anthropic-compatible `/messages`, and OpenAI `/responses`).

## Interfaces

- Provider config: `resources/providers/opencode-go.json`
- Adapter selector: `opencode_go`
- Adapter class: `OpenCodeGoAdapter`
- Default runtime endpoint: OpenAI-compatible `POST /chat/completions`
- Alternate runtime endpoint for selected models: `POST /messages` through an internal `AnthropicCompatibleAdapter`
- Alternate runtime endpoint for selected models: `POST /responses` through the shared stateless Responses machinery (`core/providers/github_copilot_responses.py`, same shape the OpenRouter adapter uses for its GPT-5.6 ids)

## Shared OpenCode credentials

Go uses `OPENCODE_API_KEY`, including named Account suffixes, in common with Zen. Key changes through either Provider affect both; enablement and billing endpoints remain independent. Go uses subscription allowance and may use Zen credits only when the user enabled OpenCode's upstream "Use balance" option. Enrollment, the explicit old-key converter, and the OpenCode-only free-tier restriction are documented in `opencode-zen.md` -> Go credentials and free-tier access.

## Runtime Behavior

- OpenAI-routed Assistant responses normalize readable Reasoning from the profiled inbound field and replay it as `reasoning_content`. The response carrier and historical carrier are independent: Kimi K3, Kimi K2.6, Hy3, and Hy4 currently respond with `reasoning` plus `reasoning_details`, but OpenCode's own compatible client sends readable history as `reasoning_content` and does not replay `reasoning_details`. `OpenCodeGoAdapter.reasoning_replay_fidelity()` therefore declares `readable_only` for the Chat route.
- **Protocol routing is DATA, not a hardcoded set.** The Adapter selects `/messages`, `/responses`, or `/chat/completions` from `metadata.opencode_go.protocol` through injected `model_lookup`. Bare discovery ids do not specify a wire; durable routing facts live in `resources/models/opencode-go.overrides.json`. An unprofiled Model takes the OpenAI fallback and logs one warning per process. The 2026-09-24 full refresh contains 35 Go ids: 34 have explicit profiles protected by the registry endpoint-matrix test; the existing live-only `omen-alpha` remains unverified and outside that matrix. The new ids are `space-bunny-free` (Chat) and `gpt-6-luna` (Responses). Historical observations below remain dated evidence, not claims of current availability.
- **Responses route mechanics:** the adapter reuses the shared `build_responses_payload` / `normalize_responses_response` / `iter_responses_sse_deltas_with_state` / `ResponsesStreamState` machinery. Requests are stateless - complete history as `input` every request, every original output item preserved for replay, `store: false`, structured in-band SSE error classification, and the provider-wide 429 subscription-limit classification applied to establishment failures. Effort rendering goes through `OpenCodeGoResponsesPolicy`; a Model with a documented `none` rung sends explicit `reasoning.effort: "none"`, because omission can select a reasoning-on Provider default. An always-reasoning Model's override fact `minimum_reasoning_effort` maps `none` to its cheapest supported rung, while another Model omits the reasoning object when no off rung exists. Provider config `defaults` merge under caller kwargs like on the Chat path; body-level session-routing kwargs are dropped because OpenCode Go receives cache affinity through `x-opencode-session`. Live verification on 2026-09-02 proved exact encrypted Reasoning item replay across three plain and Tool rounds for `gpt-5.6-luna`, `muse-spark-1.2-contributor`, and `muse-spark-1.3-contributor`; streaming produced terminal Usage and working Tool continuations for all three. GPT-5.6 Luna accepted `none` through `max` and reported `reasoning.context: "all_turns"`; both Muse versions accepted `minimal` through `xhigh` and have no verified off rung. A Muse 1.2 request with only 256 output tokens spent the allowance on Reasoning and emitted no message, while 1024 completed normally; inspect completion state and retry with a realistic budget before diagnosing a missing carrier or stream failure.
- OpenCode Go asks API clients to identify themselves. The bundled Provider config sends `User-Agent: vBot` on every wire. Every Chat request also sends `x-opencode-session` with an opaque `vbot-<prompt-cache-affinity>` value: one Prompt Epoch stays stable, a cache-compatible same-scope Session fork shares the value, and history edits or Compaction rotate it with the affinity. When Chat context is unavailable, the Adapter deterministically hashes Project/Agent/Session instead of exposing their raw ids. The header is request-only, is rebuilt alongside auth on retries, and is covered across `/chat/completions`, `/messages`, and `/responses` in streaming and non-streaming tests. Keep static identification in Provider config and dynamic conversation affinity in `OpenCodeGoAdapter.request_context_kwargs()` plus the compatible Adapter request-header hook.
- The internal Messages wire uses `x-api-key` with no prefix and `anthropic-version: 2023-06-01` while borrowing the outer adapter's HTTP client and sharing the exact token getter, runtime base URL, `model_lookup`, and debug recorder. The inner wire never closes the borrowed client; `OpenCodeGoAdapter` closes the one connection-scoped client exactly once.
- `send`, `stream`, `normalize_response`, and `wire_media_support` all use the same per-Model protocol decision. With `model_id`, response normalization routes by metadata; shape inference (`choices` = OpenAI, otherwise Messages) remains only for legacy callers that omit it. The Messages wire declares image media types only; the OpenAI wire declares images + WAV/MP3, and Chat still intersects that wire set with each Model's actual input modalities. PDF is not declared because OpenCode Go's gateway has not been verified for native PDF, even though the generic Messages encoder can shape a document block.
- When a catalog entry has a positive `max_output_tokens`, OpenCode Go uses it as request `max_tokens` unless the caller supplied `max_tokens`, `max_completion_tokens`, or `max_output_tokens`. The explicit-vs-ceiling logic now lives in the shared `OpenAICompatibleAdapter` base (`_apply_model_output_limit`; see `providers/request-policy.md` -> Request limits and context); this Adapter contributes only its flat vendor-prefixed candidate resolution (`_model_max_output_tokens` override + `_model_lookup_candidates`, matching `id`, the `::`-stripped id, and the post-`/` tail) and applies the resolution in `send`/`stream` so the ceiling is stamped before the request splits to the Anthropic sub-route as well.
- Both Tool wires preserve the canonical schema without Provider strict mode. The OpenAI route omits the field; a live `deepseek-v4-flash` request on 2026-07-31 accepted `strict: true`, but acceptance does not establish enforcement and does not change vBot's Provider-wide non-strict invariant. The Messages route also omits the field, and Runtime argument validation remains authoritative on both routes.

## Provider facts come from the models.dev section (rebuilt 2026-09-16)

The opencode-go endpoint returns **bare ids** - no context window, output cap, modalities, family, or reasoning info. But models.dev carries a per-provider **`opencode-go` section** with all of those, so refresh pulls them into the generated `opencode-go.json` (`discovery._enrich_provider_model` via `models_dev.provider_limits` / `provider_modalities` / `provider_family` / `provider_reasoning_supported`):

- **Limits**: the gateway's own `context.window` / `output` - which legitimately deviate from the lab (e.g. `glm-5` output **32768** vs the canonical 131072; `minimax-m3` **1000000/131072**). "Fill, don't overwrite": a provider that *did* report a limit keeps it.
- **Modalities**: widened to the models.dev set as a strict **superset** of what the endpoint reported (add, never drop) - so `minimax-m3`/`kimi`/`qwen*-plus` are correctly image/video-capable; `vision` is kept consistent.
- **Family** when the entry has none, and the bare **`reasoning: true`** flag (independent of a control ladder), so a Model the feed marks reasoning-capable is not flattened to `supported: false`. Where models.dev publishes `reasoning_options`, the typed control is stamped too; Models with no published control retain `{supported: true}` and use the Adapter's documented fallback behavior.

The **override** (`resources/models/opencode-go.overrides.json`) carries verified wire facts and corrections that cannot safely be inferred from a Provider-wide rule:

- **Replay hierarchy and per-Model protocol:** the root `reasoning_replay: "full_history"` is the Provider override, an optional top-level Model value can replace it, and `protocol` remains an independent metadata fact. Replay scope never lives inside `metadata.opencode_go`.
- **Response carrier:** `reasoning_response_field` records only the inbound Chat response field: `reasoning_content` for DeepSeek, GLM, LongCat, and MiMo; `reasoning` for Kimi K2.6/K3 and Hy3/Hy4. This is deliberately not the historical carrier, which the Chat serializer owns as `reasoning_content`. The metadata is repeated in the override because `metadata` is replaced wholesale at load. Responses-routed Models return reasoning items instead and carry no response-field profile.
- **DeepSeek V4.1 Flash controls:** the versioned gateway id `deepseek-v4.1-flash` and its current latest-Flash alias `deepseek-flash` carry the same explicit profile. `thinking_control: "toggle_with_effort"` renders `thinking.type` independently of the `low/high/max` effort ladder. `none` sends disabled without effort; enabled requests preserve the closest supported effort. An unspecified effort keeps the Provider default. Both ids retain their literal wire identity.
- **Binary controls:** MiMo V2.6 Flash/Pro and Kimi K2.6 use `thinking_control: "toggle"`; Agent effort `none` sends `thinking.type: "disabled"`, every other selection or omission sends `enabled`, and no `reasoning_effort` is sent. Their effective render description reports on/off accordingly. K2.6 additionally sends `thinking_keep: "all"`. K2.7 uses `always_enabled`, including for `none`, and its effective description reports on. K3 uses the `low/high/max` effort ladder.
- **Always-reasoning minimum:** Grok 4.6, Grok 4.7, and Kimi K3 carry `minimum_reasoning_effort: "low"` so an Agent-selected `none` becomes the cheapest valid level instead of omission falling back to the Provider's high/max default.
- **Responses controls:** GPT-5.6 Luna exposes `none`, `low`, `medium`, `high`, `xhigh`, and `max`; the explicit `none` value is transported instead of omitted. Muse Spark 1.2 and 1.3 expose `minimal`, `low`, `medium`, `high`, and `xhigh`; `none` remains omitted because no off rung is documented or live-verified.
- **Provider-default Messages controls:** `thinking_control: "provider_default"` makes the inner Messages Adapter omit thinking/effort controls and report `default` without stripping historical Thinking. The retired Union Alpha profile remains a test-owned fixture for this wire behavior; it is no longer a bundled Model.
- **Privacy expiry:** The Go page read on 2026-09-22 publishes its renewed monthly DeepSeek zero-retention agreement through 2026-09-30. Recheck the published term before making a later ZDR claim.

Since `metadata` is replaced **wholesale** by the highest layer at load (assembly contract), the override's `metadata.opencode_go` becomes the effective metadata.

## Reasoning Replay

- `reasoning_replay_policy()` uses the shared Model -> Provider -> system hierarchy. The Provider root is `full_history`; current official and legacy Models inherit it. Chat owns exact same-route history shaping.
- Re-verification on 2026-09-02 used Provider-reported input tokens, visible-content controls, real Provider-emitted Reasoning, and the exact vBot Adapter/history path. Positive exact later-Run or Tool-continuation transport was measured for `glm-5.3-flash`, `glm-5.3`, `glm-5.2`, `glm-5.1`, `kimi-k2.7-code`, `longcat-2.0`, `deepseek-v4-pro`, `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp`, `mimo-v2.5`, `mimo-v2.5-pro`, `minimax-m3`, `qwen3.8-max`, `qwen3.8-flash`, `qwen3.7-max`, `qwen3.7-plus`, and `qwen3.6-plus`. Exact output-item replay across three plain and Tool rounds was also measured for Responses-routed `grok-4.6`, `gpt-5.6-luna`, `muse-spark-1.2-contributor`, and `muse-spark-1.3-contributor`. These Models must remain `full_history` even when a different supported request shape ignores history.
- Kimi K3 is a gateway-divergence case, not a no-replay Model. Moonshot's official contract requires complete Assistant messages including `reasoning_content` and Tool Calls for preserved-thinking history. OpenCode and Hermes send `reasoning_content`. Current OpenCode Go live requests on 2026-09-02 nevertheless ignored exact model-generated readable Reasoning, exact `reasoning_details`, and both together: all carrier cases had the same input count as the absent case, while visible history increased input and recalled the hidden values. vBot retains `full_history` and the documented readable carrier so it satisfies the upstream contract and becomes effective if the gateway is corrected; do not relabel Kimi K3 itself as replay-incapable.
- Kimi K2.6 has the same kind of current gateway divergence. Its direct API contract supports `thinking.keep: "all"` and requires historical `reasoning_content` during thinking Tool loops. OpenCode Go honored `thinking.type: "disabled"` but ignored exact generated, readable, and native-meta historical carriers in controlled token comparisons. vBot retains `thinking.keep: "all"` plus `full_history` so the upstream contract is correct and will work when the gateway transport is corrected.
- MiniMax M2.5 and M2.7 emitted exact signed Thinking blocks that vBot replayed on both live and persisted Tool continuations, but current OpenCode Go input accounting added zero tokens while visible controls counted. MiniMax's official Anthropic-compatible contract says to append the full response content, including Thinking, text, and Tool Use blocks, to preserve the reasoning chain. Treat the zero delta as a current gateway observation, retain exact block replay and `full_history`, and do not downgrade the Models from acceptance alone.
- Hy3 and Hy4 similarly ignored `reasoning_content` in current plain-history probes while visible controls counted. This is recorded as a current gateway observation, not encoded as a narrower Model policy, because the official compatible-client path still emits the carrier and the Provider may correct transport behavior.
- OpenAI-routed Assistant messages with non-empty canonical `reasoning` are replayed as `reasoning_content`; Chat route fidelity strips `reasoning_details` rather than preferring opaque meta. This matches current OpenCode and Hermes serialization and avoids sending duplicate or rejected reasoning classes.
- Anthropic-routed Models render replayed `reasoning_meta.content_blocks` through the inner `AnthropicCompatibleAdapter`, including its thinking-disabled guard. Responses-routed Models (`grok-4.6`, `gpt-5.6-luna`, `muse-spark-1.2-contributor`, `muse-spark-1.3-contributor`, plus `grok-4.7`) replay whole original output items by design, including encrypted Reasoning, through the shared Responses input builder; Chat fidelity does not apply to them.
- MiMo V2.6 Flash/Pro and Kimi K2.6 render `thinking.type` from the Agent's on/off intent and never send generic `reasoning_effort`; K2.6 adds `keep: "all"` only while enabled. K2.7 always renders enabled and suppresses unsupported effort/disable fields. K3 and Grok use `reasoning_effort`, with `none` safely mapped to `low`.

## Prompt Caching

Prompt caching works on every current route and is accounted by vBot's Adapter path for the Models probed on 2026-07-09. OpenCode's compatible client contract and Go guidance were re-checked on 2026-09-03: `x-opencode-session` supplies stable gateway routing/cache affinity, while caching behavior and counters remain wire-specific below. Do not infer direct-xAI `x-grok-conv-id` support for Grok through this gateway without a separate probe.

- **OpenAI route** (`/chat/completions`): caching is **automatic upstream** - vBot sends no cache directive. Reads come back as `prompt_tokens_details.cached_tokens` and are read by the shared `_openai_cached_prompt_tokens` (`openai_compatible.py`) into `usage.cache_read_tokens`. Cold miss on the first turn, then near-full-prefix reads while the prefix is reused; a unique prefix per turn stays at ~0 (control). Verified: `deepseek-v4-flash` (0 -> 2304 -> 8064...), `kimi-k2.6` (cold 3 -> 7937). **`glm-5` caches but the gateway reports `prompt_tokens_details` as `null` on many turns** - vBot then honestly reports no read; this is an upstream reporting gap, not a vBot bug (`_openai_cached_prompt_tokens` tolerates the `null`).
- **Anthropic route** (`/messages`): OpenCode Go explicitly enables the compatible wire's `cache_control` breakpoints, and those markers **are effective on this gateway**. With markers on, the cold turn writes the whole prefix (`cache_creation_input_tokens` = full prefix) and later turns read it (`cache_read_input_tokens`); with markers off on a fresh prefix the write disappears and reads shrink or delay - verified on `qwen3.7-plus` (read 8480 with markers vs 6272 without) and `minimax-m2.7`. Some upstreams (`minimax-m3`) auto-cache regardless of markers, so the markers are redundant-but-harmless there. Counts are folded into `cache_read_tokens`/`cache_write_tokens` by `apply_anthropic_cache_usage`.
- **Streaming** surfaces the same reads on the OpenAI route and for `minimax-m2.7`/`minimax-m3`. OpenCode Go's MiniMax M3 Messages stream was observed on 2026-08-14 to report zero Usage at `message_start` and the complete fresh-input, cache-read, output, and Thinking counters only in the terminal `message_delta`; the shared compatible Messages decoder therefore prefers a usable terminal input/cache snapshot over the start snapshot. In an earlier probe `qwen3.7-plus`'s streaming `message_start` did not expose the cache breakdown (a gateway streaming detail), so absent counters remain unknown rather than being reconstructed as measured Provider values.

## Gateway Errors and Subscription Limits

- Live Swarm failures on 2026-09-20 returned HTTP 403 with `error.type` and `error.code` both `server_error` and the exact message `Upstream request failed: [server_error] Upstream response was not valid JSON`. Both affected Sessions later progressed with the same Connection. The Go Adapter classifies only this exact structured 403 combination as retryable `ProviderError`, retaining the original status, complete error body and parsed `Retry-After`. Plain, malformed or other 403 bodies and every 401 retain fatal authentication classification. The exact upstream cause remains unknown; recovery does not guarantee that another attempt succeeds.
- The policy is shared by Go's Chat, Messages and Responses request-establishment paths, for streaming and non-streaming calls. The Go Messages subclass preserves its raw error JSON instead of reducing it to type/message text, because classification also needs the code. Other Providers retain the shared status policy. Chat keeps its existing Run-local recovery budget; standalone callers keep their bounded utility retries. No additional retry loop or automatic Swarm Resume is introduced. Regression coverage: `tests/core/providers/test_opencode_go_errors.py`, with existing Chat recovery-budget, stream-recovery and fallback tests.
- OpenCode Go overload/throttling and exhausted subscription/account allowance can both arrive as HTTP 429. All three wires inspect the error detail before the shared status policy: stable limit identifiers (`GoUsageLimitError`, `FreeUsageLimitError`, `insufficient_quota`) and unambiguous monthly-limit, available-balance, quota, budget, or billing-hard-limit phrases raise a non-retryable Provider error immediately. Other 429 responses remain `ProviderRateLimitError`, retain `Retry-After`, and use the shared bounded retry policy.
- Keep this classification OpenCode-specific. A status-only global 429 change would disable valid transient retries for unrelated Providers, while broad error-word matching could misclassify recoverable throttling.

## Constraints & Gotchas

- Keep OpenCode-specific route selection and Chat `readable_only` fidelity in `OpenCodeGoAdapter`. The generic OpenAI-compatible Adapter owns serialization mechanics; do not infer the outgoing history carrier from `reasoning_response_field`, do not send both readable and opaque classes, and do not add history-wide Reasoning strips - Chat owns history shaping.
- Keep the compatible Messages owner borrowed and provider-neutral; do not replace it with the concrete native `AnthropicAdapter`, which would import native discovery, sampling, PDF, and cache defaults into OpenCode Go.
- Constructor signature intentionally matches runtime adapter factory injection, including optional `model_lookup` and `debug_recorder`.

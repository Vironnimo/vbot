# Provider Request Policy

Read this reference only for Adapter request/response/SSE translation, shared HTTP behavior, reasoning, CoT replay, media support, output/context limits, or Provider-backed task HTTP clients.

## Adapter ownership

`ProviderAdapter` defines `send()`, `stream()`, `normalize_response()`, `aclose()`, and the per-request policy hooks. `stream()` yields normalized delta types for content, reasoning, Tool calls, opaque reasoning metadata, usage, finish, and transport-only heartbeat; raw Provider frames stay private. Every production response and finish normalizes Provider stop state to `stop`, `tool_calls`, `output_truncated`, `content_filtered`, `error`, or `unknown`.

`OpenAICompatibleAdapter` deeply owns generic Chat Completions mechanics. `AnthropicCompatibleAdapter` deeply owns Messages-compatible requests, content blocks, SSE, usage/cache normalization, and retry. Concrete Provider Adapters extend or compose those mechanics only for verified Provider differences. A Provider-owned router may inspect its injected Model lookup and Connection mode, but Runtime never selects an inner wire per Model.

`normalize_response(response, *, model_id=None)` produces canonical assistant fields. The optional Model id supports data-driven wire selectors; shape inference is compatibility fallback only. Every Adapter routes recognizable Tool attempts through `normalize_tool_call_candidates()`: object or encoded-object arguments become canonical JSON objects, malformed names/arguments retain an addressable id and safe placeholder fields plus persisted rejection metadata, and sibling order is never collapsed by dropping a bad call. A string consisting entirely of multiple consecutive top-level JSON values expands into independently validated same-name canonical calls; the first keeps the Provider id, later calls receive deterministic synthetic ids, and internal index/length metadata preserves their authored sequence. A syntactically unsegmentable string remains one rejected attempt rather than executing a guessed prefix. Opaque `reasoning_meta` crosses only the Adapter/Chat boundary and is preserved, not interpreted.

## Tool-call terminal safety and correlation

Only the canonical `tool_calls` terminal outcome authorizes dispatch. When a Provider ends with `output_truncated`, Chat persists the partial Assistant turn and emits ordered, correlated `tool_call_truncated` Results without invoking Tool handlers or Extensions, then lets the Model recover. `content_filtered`, `error`, `unknown`, and inconsistent outcome/call combinations likewise produce correlated `tool_call_rejected` Results without dispatch before failing the Model step. Missing outcomes remain inferable only for source compatibility with legacy third-party/test Adapters; an explicit unrecognized outcome becomes `unknown` and fails closed.

OpenAI-compatible streamed Tool fragments carry a stable slot independently of the Provider id. Some Ollama-compatible servers reuse one raw wire index for every parallel Tool Call, distinguishing calls only by `id`; stream normalization tracks the last id per raw index and redirects a same-index/different-id fragment to a fresh virtual slot, while id-less continuation fragments keep the tracked virtual slot of their raw index. The accumulator groups by that slot, adopts a real id whenever a later fragment supplies it, and synthesizes a deterministic fallback only when finalization has no Provider id. Finalization preserves malformed/incomplete argument JSON as a rejected canonical Call; parsing failure is never a streaming exception once the Provider has completed the Tool Call.

Canonical Session Tool-call ids are Provider-origin evidence and remain immutable. `normalize_tool_call_ids()` deep-copies the outgoing request view, preserves already-valid unused ids, and deterministically allocates collision-free target-wire ids while rewriting each Assistant Tool Call together with the matching Results in its immediately following Tool batch. The explicit profiles are Anthropic Messages (`[A-Za-z0-9_-]`, at most 64 characters), Mistral (exactly 9 alphanumeric characters), and Responses (`[A-Za-z0-9_-]`, at most 64 characters, no trailing underscore); ordinary OpenAI Chat requests do not use this transform. Responses replay also rewrites matching `reasoning_meta.response_output` function-call `call_id` values and removes a Provider-owned item `id` only when the call identity changed, preventing a foreign item from falsely pairing with opaque reasoning.

## Reasoning and CoT

### Reasoning intent

`resolve_reasoning_intent()` is the single Provider-neutral decision layer. From Model support/control/levels/budget plus Agent effort and output allowance it returns `default`, `off`, `effort`, `budget`, or `on`. It owns snapping, `none`→off, effort-to-budget math, minimum/clamp behavior, and skip rules; each Adapter only renders the result onto its wire.

Adapters must not reimplement this decision policy. Provider-specific maps document each render (for example OpenRouter object fields, Anthropic adaptive/native budget, or binary thinking toggles).

### Chain of Thought

The governing rule is **replay minimality** (see `.vorch/PROJECT.md` → Context): return exactly the reasoning state the target Model needs to work optimally — opaque meta when the wire makes it contract state, readable text only when the Model demonstrably benefits from it on that wire. Replay decisions are per-Provider/per-Wire facts documented in each Provider map; an undocumented default-on replay is a gap to verify and fix, never a safe baseline.

CoT contains two different classes of state: readable Reasoning text and opaque signatures/encrypted/provider metadata required for native round-trip continuity. `reasoning_replay_policy(model_id)` resolves one explicit hierarchy: the Model's top-level `reasoning_replay` value, then the Provider root value loaded from `<provider>.overrides.json`, then the system default `full_history`. The only valid policies are `none`, `current_run`, and `full_history`; a bad Provider value rejects that override file, while a bad Model value isolates that Model record. Provider/Model overrides are compatibility escape hatches for a demonstrated wire limitation, not required opt-ins for full replay.

Serialization carries exactly **one** reasoning class per Assistant turn. Which class is an explicit adapter-owned wire fact: `ProviderAdapter.reasoning_replay_fidelity(model_id)` declares `meta_preferred` (opaque meta when the turn captured it, otherwise readable text), `meta_only`, or `readable_only`. The default `meta_preferred` matches OpenRouter's documented contract that `reasoning_details` supersede duplicated plaintext; raw-string-only wires keep readable continuity. Concrete adapters declare deviations (Kimi/OpenCode Go chat and Ollama Cloud: `readable_only`; Mistral and the Anthropic-compatible Messages base: `meta_only`). Fidelity is never encoded in Override files or provider metadata — it is code-owned like `wire_media_support`.

Keep three facts separate. Replay scope says which canonical Assistant turns vBot may return; wire fidelity says whether it must return exact original blocks/items instead of reconstructing them; Provider render scope says which returned historical reasoning the remote Model actually makes available to the next sample. A `full_history` replay policy does not by itself prove all historical reasoning is rendered.

Chat owns history shaping. `full_history` native replay survives only when the persisted `reasoning_scope` exactly matches the resolved Provider/Model/Connection/Account identity; an interrupted Assistant turn, Model switch, Connection or Account switch, run-local fallback, and textual vBot Compaction are hard native-state boundaries. On a route mismatch Chat always removes native `reasoning` and `reasoning_meta`; only non-empty readable Reasoning from a completed reasoning-only or Tool-associated turn may be escaped into a provider-neutral request-only reminder after its Tool batch. Ordinary answer reasoning is not duplicated, and opaque/meta-only, redacted, scope, and interrupted state are never projected. Interruption preserves native Reasoning only as canonical evidence and replays readable work solely through the separate provider-neutral Continuation reminder, never through `reasoning` or `reasoning_meta`. `phase` is semantic assistant history, not opaque reasoning state, so it survives ordinary request shaping and Compaction. Adapters serialize whatever native reasoning survives shaping and must not apply a second history-wide strip except for a documented wire incompatibility such as explicitly disabled thinking.

Responses-shaped adapters persist and replay every original response output item in order; that preserves encrypted reasoning, message `phase`, function/program items, ids, and future item kinds without lossy reconstruction. When one raw function item was canonically rejected, replay preserves all other opaque items/order but replaces that item with its safe canonical function call so malformed raw arguments cannot poison the recovery request. When one raw function item expanded from a consecutive argument sequence, replay replaces that item in place with every recovered canonical function call so each following Result remains correlated. The ABC and hook-less compatibility default is `full_history`. Within Tool loops, dropping Provider-required signatures or opaque blocks can break continuity even though vBot never reads them.

On OpenAI-compatible Chat wires, readable Reasoning normalization selects the first non-empty configured/provider alias across `reasoning_content`, `reasoning`, `reasoning_text`, and `thinking`; duplicate aliases therefore never duplicate readable Reasoning. The base serializer emits readable text only under its declared fidelity — never alongside opaque meta (`meta_preferred` sends meta when captured). Streamed `reasoning_details` remain message-level opaque metadata, but the Adapter accumulates the complete ordered list before it crosses into Chat: entries with a stable embedded `id` update their original slot, id-less entries retain arrival order, and each delta carries the cumulative list so Chat's intentionally shallow opaque-metadata merge cannot discard sibling Tool-associated details.

Reasoning rejection/ignored-effort warnings are diagnostic only. They may warn conservatively on a relevant HTTP 400 or zero reported reasoning tokens, but they do not reclassify status/retry behavior and never log token values.

## Request limits and context

None-valued caller kwargs mean unspecified and are removed before Provider defaults; falsy real values such as `temperature=0.0` remain explicit overrides.

Compatible Adapters resolve a positive output allowance in this order: explicit caller limit, Model catalog `max_output_tokens`, then flat Provider default. Before every request, `resolve_request_output_limit()` clamps that allowance so estimated Provider-visible messages, Tool definitions, a media-aware input reservation, an uncertainty reserve (`max(25% of estimated input, 1% of the effective context window, 256)`), and output fit inside the effective context window. The shared estimator (`core/utils/tokens.py`) also replaces oversized opaque reasoning-continuity blobs (`encrypted_content`/`signature`/`redacted_thinking`, and any non-text string inside `reasoning_details`) with fixed reservations instead of counting their encoded size as prose — providers bill those blobs by decoded content, and replayed details otherwise inflate the local estimate far beyond real prompt tokens (live evidence 2026-08-25: ~1.04M estimated vs ~220k real). It likewise compacts legacy per-delta `reasoning.text` fragments before counting. A catalog output ceiling equal to the entire context therefore cannot produce an invalid request. The uncertainty reserve only shrinks the output allowance. Exhausted input fails locally as a non-retryable `ProviderError` only when estimated input overflows the window even after removing its own uncertainty reserve — an estimate inside that margin goes out unclamped, because an inflated estimate must not kill a request whose measured Context still fits. The window check runs regardless of whether an output allowance exists: Models without any known ceiling send no `max_tokens` (their Provider default applies) but still fail locally on overflow instead of receiving a remote Provider rejection mid-Run. Independently, Chat runs a pre-send guard on every request: when the Session carries a measured Usage anchor, `latest_session_context_usage` (+ estimated system/Tool overhead) is checked against the window and fails locally before any Provider call, so measured reality — not the local estimate — decides the fatal case. The request estimator in `core/utils/tokens.py` is separate from persisted Usage estimation: native base64/data-URL media receives a fixed per-payload reservation instead of being counted as encoded prose bytes.

`resolve_context_window()` owns the read-side chain: positive Model fact, then positive Provider-config default, then `GLOBAL_CONTEXT_WINDOW_FLOOR`. `resolve_effective_context_window()` adds local-Model policy: positive user setting, else the chain capped by `LOCAL_CONTEXT_DEFAULT_CAP`. These helpers inform budgeting/status/payloads; only verified local Adapters enforce the effective value on the wire.

## Wire media and request context

`wire_media_support(model_id)` declares exact MIME types the concrete wire can carry. Chat intersects this with Model input modalities and degrades unsupported content; the ABC default is empty so a missing declaration degrades rather than crashes. PDF support is declared only on verified concrete wires, not compatible bases.

Run-local rich Tool Results retain their persisted JSON-string envelope and carry resolved media/path blocks in the request-only `tool_result_content` field. Anthropic-compatible and GitHub Copilot Messages adapters render it as nested Tool Result content; Responses-shaped adapters render it as the `function_call_output.output` content array. OpenAI Chat Completions and Ollama Tool roles are text-only, so `project_tool_result_content_fallbacks()` appends supplemental text to each correlated Result and emits all media in one request-only user message after the complete consecutive Result batch. This fallback never mutates canonical Session history and must preserve sibling Result order.

`request_context_kwargs(agent_id, session_id, project_id=None)` lets an Adapter derive Provider routing/cache hints from stable conversation identity. The default adds nothing. Chat supplies the Run's Project anchor and merges returned kwargs without knowing their Provider meaning. OpenAI Codex uses Agent + Session for its conversation headers; OpenRouter hashes Project + Agent + Session into its top-level sticky-routing `session_id`.

## HTTP, retry, and streaming

- Chat Adapters construct HTTP clients through `_http_shared.build_async_client()` so timeouts and optional debug capture are consistent. Task clients deliberately use their separate shared client path and have no chat debug capture.
- Non-streaming Adapter requests use the shared client's bounded connect/write/pool timeouts plus a 180-second read-inactivity timeout; this includes `ImageService.analyze()` because it uses `Adapter.send()`. Every HTTP streaming call builds its request through `_http_shared.build_streaming_request()`, which alone disables the HTTP read timeout so Chat can own open-stream stalls with separate transport and Model-progress clocks. OpenAI Codex `send()` is semantically non-streaming but consumes an SSE/WebSocket exchange internally, so it applies the same 180-second inactivity bound between normalized events and maps expiry to `ProviderTimeoutError`. Remote Chat streams allow 180 seconds without a normalized delta or transport heartbeat and 900 seconds without a normalized Model delta. The shared SSE framer exposes comments separately; the OpenAI-compatible Adapter normalizes comments as transport-only heartbeats because OpenCode Go was verified to buffer a 40,560-character GLM-5.2 `write` Tool Call for 18 heartbeat intervals before releasing it as one Tool delta. Heartbeats keep the connection alive and feed the transient Run status but never count as Assistant, Reasoning, Tool, Usage, or finish progress. Incomplete SSE events and arbitrary raw bytes reset neither clock. Local/loopback Providers disable both streaming windows.
- The shared default classifies HTTP 401/403 as fatal auth errors, 429 and 502/503/504 as retryable, HTTP 500 as retryable only for explicitly declared idempotent requests, and Provider POST 500 as fatal; `classify_http_status()` requires every caller to declare idempotency so read-only GETs and non-idempotent POSTs cannot silently share the wrong branch. Concrete Adapters or task clients can add verified codes through their explicit extra-status policy (Anthropic and embedding task requests opt into 529). Billed non-idempotent task generation applies the stricter `TaskRequestRetryPolicy` described below instead of blindly inheriting gateway retries. Retryable errors can carry parsed `Retry-After`, used as a capped floor over backoff with the attempt's bounded jitter added afterward so equal server hints do not synchronize clients.
- The shared default maps every `httpx.TimeoutException` to retryable `ProviderTimeoutError` and other transport failures to retryable `NetworkError`. Billed non-idempotent task generation overrides ambiguous read/write/remote-protocol failures as `ProviderOutcomeUnknownError`; malformed 2xx task results receive the same classification because the Provider may already have completed the operation. Chat malformed 2xx JSON and malformed SSE JSON remain non-retryable `ProviderError` with the decode error chained.
- Responses-shaped streams classify exact structured in-band error codes into the same auth, rate-limit, timeout, transient, or fatal exception taxonomy as establishment failures. A retryable error before visible Model output enters Chat's existing bounded restart/fallback policy; after visible output Chat preserves the partial turn and never replays the request. `response.incomplete` is a normal terminal event mapped to `output_truncated`, `content_filtered`, or `unknown`, and it can never authorize Tool dispatch.
- Generic OpenAI-compatible streams classify in-band `error` chunks through the shared `classify_in_band_provider_error()` (`core/providers/errors.py`), reading the typed `error_type` (top-level or under `metadata`), a string/numeric `code`, and an `availability.retryable`/`retry_after` router hint instead of treating every chunk as fatal. Classification is strict by default (unknown errors stay non-retryable); a concrete Adapter opts into lenient unknowns when its Provider can serve the identical request through another upstream. Every classified Mapping payload is embedded into the raised error's message as trailing JSON (`<summary>: {body}`, bare `{body}` when the payload has no message) so the Provider's structured detail — upstream message, code, router metadata such as OpenRouter's `metadata.raw` and `provider_name` — survives into persisted run failures, where the WebUI's existing trailing-JSON parser renders it in the collapsible details block. Non-Mapping payloads stay plain text. The code sets are single-sourced there and reused by the Responses-shaped classifier above.
- A Chat Completions `finish_reason=stop` is not trusted when `native_finish_reason` is `network_error` or `server_error`. Those chunks raise retryable `NetworkError` / `ProviderError` instead of a completed `stop`, so Chat's pre-visible stream restart can replay the request. A bare `finish_reason=network_error` still maps to terminal `error` (existing contract). Observed 2026-08-24 on OpenRouter `stealth/ox-alpha`: HTTP 200 SSE with empty `delta.content`, `finish_reason=stop`, and `native_finish_reason=network_error` — accepting that as `stop` made Chat persist an empty Assistant turn and die on `ChatMessageValidationError` with no retry.
- Adapter retry covers request/stream establishment. Once streaming has begun, mid-stream failures propagate to Chat, which owns preservation/recovery. Only `ProviderStreamingUnsupportedError` triggers the nonstreaming fallback.
- Both base adapters (`OpenAICompatibleAdapter`, `AnthropicCompatibleAdapter`) wrap their `retry_async` establishment in `execute_with_sampling_fallback` (`_http_shared.py`): a fatal `ProviderError` whose message names a rejected sampling parameter (`temperature`/`top_p`/`top_k` — detected by `unsupported_sampling_parameter`, which requires both a rejection marker and the parameter name in the detail) strips exactly that parameter from the built payload and retries once. The payload is built before the retry loop for this reason — a rebuild would let provider-config `defaults` refill the stripped key. This reactive net backs up the proactive per-model drops (Anthropic thinking/adaptive sampling strip, Kimi sampling strip, Responses allowlists) for backends that accept a parameter for one model and reject it for another; auth, rate-limit, network, and rejections of parameters never sent propagate unchanged. The native local Ollama wire is deliberately not wrapped — a local server accepts sampling in `options`.
- `retry_async()` stamps every caught `VBotError` with this retry loop's one-based `attempts_made` count before either retrying or rethrowing it. Provider-backed Tools may preserve that metadata in their failure envelope; a nested retry boundary reports its own operation-attempt count rather than an aggregate of lower-level HTTP attempts.
- Authorization headers are rebuilt inside every retry attempt so OAuth refresh remains effective.

## Provider-backed task clients

`ProviderTaskClient` is the shared HTTP base for speech, image, and embedding Provider clients. Its local structural Runtime/target Protocols avoid importing Runtime or `core/model_tasks/`. `from_runtime()` resolves the Connection and refresh-capable token getter; `post_and_parse()` puts request, status classification, and parsing inside `retry_async`, rebuilding headers per attempt. Keyed Connections contribute their configured auth header; a keyless `none` Connection contributes no auth header while still preserving Provider `extra_headers`.

`TaskRequestRetryPolicy` separates replay-safe calls from billed non-idempotent generation. The default preserves the historical retry behavior used by embeddings and STT. Image generation/editing and TTS use a non-idempotent policy: connect/connect-timeout/pool-timeout failures and HTTP 429 remain retryable because the operation was not accepted, while read/write/remote-protocol failures, unverified 5xx responses, and unusable 2xx results stop after one attempt with non-retryable `ProviderOutcomeUnknownError`. OpenRouter image generation explicitly verifies HTTP 503 as safe to retry; 502 and 504 remain ambiguous. Every call has one operation key; current image/TTS wires expose it only through the error and do not send an unverified idempotency header, while a future endpoint policy may name a verified header and `post_and_parse()` will reuse the same key on every attempt.

Task-specific payload/response semantics remain in `model_tasks.md` and its task references. `extra_options` is the common JSON escape hatch: empty placeholders are omitted while `0`, `0.0`, and `False` remain meaningful. Most task wires let non-empty entries override authored fields; embeddings explicitly reserve identity/input/encoding/dimension fields and reject attempts to override them.

## Usage normalization

Across Adapters, `input_tokens` means total prompt tokens including cached tokens. Optional `cache_read_tokens` and `cache_write_tokens` preserve Provider counters, while optional `reasoning_tokens` preserves a reported subset of output and never changes `output_tokens`. OpenAI Chat reads prompt/completion detail blocks, Responses-shaped wires read input/output detail blocks, and Anthropic Messages reads cache fields from input Usage plus `output_tokens_details.thinking_tokens` from final output Usage. OpenAI-compatible input and output counters are preserved independently: if either primary counter is absent or malformed, that field remains absent rather than becoming a measured zero. Adapters omit unsupported or malformed optional counters rather than inventing zero; canonical Session aggregation and display semantics live in `chat/usage.md`.
